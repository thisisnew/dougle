# 0.1.6 — 자료 이름·분류 수정

배포 후 2026-10-24 [실제 Codex 검사](essential-verification.md)를 추가로 통과했습니다. 아래 빌드 당시 실제 AI 제외 기록과 구분하며 앱·설치 파일은 변경하지 않았습니다.

최종 빌드·설치 검증을 마치고 **0.1.6을 공개했습니다**. 두 CPU 설치 파일과 서명된 업데이트를 제공합니다.

최종 검토에서 자료 목록 갱신 후 사라진 도메인이 숨은 검색 조건으로 남는 회귀를 재현했습니다(추가 검사 1 실패). 모든 목록 갱신 시 유효한 선택만 유지하도록 수정했습니다. 첫 설치본은 공개하지 않고 보관했으며, 최종 JAR로 두 CPU 설치본을 다시 생성·검증했습니다. 기존 공개 버전 파일을 덮어쓰지 않았습니다.

## 최종 소스 재검사 — 2026-10-24

- `bash scripts/build.sh`: Java **373 통과·실제 AI 1 제외**, UI **210 통과**, TypeScript·Vite·Maven clean verify 성공.
- 최종 JAR에서 `node scripts/smoke.mjs`, `node scripts/crash-recovery-smoke.mjs` 모두 통과. 가상 AI·근거 우선 SSE·취소·문맥·게시·재시작·100파일 검색 및 강제 종료 복구 8개 시나리오를 확인했습니다.
- 공통 JAR SHA-256: `1348172003e20069168092d784ca789fc14a9e92125508b017309e289eb752c7`.
- `npm audit`: 취약점 0건. 당시 의존성 목록 기준이며 안전성을 영구 보장하지 않습니다.
- 코드·설정 파일 목록 322개, 테스트/fixture 92개를 다시 기록했습니다. 실행 커버리지 수치가 아닙니다.
- 최종 Rust 17건·rustfmt·all-targets clippy 통과. Java·UI·Rust 합계 **600건 통과**, 실제 AI 1건 제외이며 아래 반복 검사를 더하지 않았습니다.

## 변경

- 등록한 Source의 이름·도메인 수정 UI/API. 원본과 게시 지식의 검색 분류를 함께 갱신합니다.
- 수집 중·설정 충돌·다른 Workspace 변경을 차단하며, 기존 원본·지식·반영 버전·자동 갱신 예약을 유지합니다.
- DB v21, 기존 업데이트 키와 자료 위치는 그대로입니다. Claude 동봉이나 실제 외부 AI 호출을 추가하지 않습니다.

[사용법·모델·테스트](source-metadata.md). 기존 [강제 종료 복구](crash-recovery.md) 검사도 유지합니다.

## 수정 과정의 검사 기록

- `bash scripts/build.sh`: Java 374건 중 **373 통과·실제 AI 1 제외**, UI **208 통과**. Maven verify·TypeScript·Vite 빌드 성공.
- Source 통합 22건에는 새 경계 검사 4건을 포함합니다. UI 전체에는 편집기 3건·화면 연결 1건을 추가했습니다. 위 전체 수와 중복 합산하지 않습니다.
- `node scripts/smoke.mjs`: 실제 JAR의 가상 AI·SSE·취소·문맥·게시·재시작·100파일 주 흐름 통과. [측정](performance-phase3-foundation.json).
- Vite 메인 청크 약 509 kB 경고가 있습니다. 빌드는 성공했으며 청크 분할 개선은 별도입니다.
- Rust 17건·rustfmt 검사, CPU 혼합/외부 Git 라이브러리/라이선스 누락 거절 검사 통과.
- 새 JAR의 강제 종료 복구 8개 시나리오 통과. 이 결과는 물리적 정전·실제 AI 검증이 아닙니다.
- 실제 브라우저에서 Workspace/로컬 Source 생성·수집 → 이름·분류 수정 → 탐색기 이름/검색 분류 변경을 확인했습니다. 서버 재시작 후 API로 이름·분류·원본 반영 버전·폴링 OFF 보존을 확인했습니다. 가상 자료·가상 CLI 전용이며 AI 호출 0회입니다.
- 브라우저 최초 탐색 load 대기, CDP 클릭, 상태 평가에서 시간 초과가 있었습니다. API는 정상 응답했고 같은 작업 공간에서 상태를 재확인했습니다. 평가 중단이 확정되지 않은 경우에는 해당 페이지를 새로고침한 뒤 이어갔습니다. 원인을 앱 오류 또는 자원 경쟁으로 단정하지 않습니다.
- 브라우저는 `FORGE_BROWSER_JAR`로 새 JAR를 지정하고 기존 Intel 앱의 같은 버전 Java 런타임을 사용했습니다. 새 설치 복사본 WebKit 검사는 별도입니다. [실제 화면](images/source-metadata.png).
- 편집 취소 시 변경 내용이 저장되지 않는 화면 동작도 확인했습니다. 검사 후 브라우저 작업 공간과 임시 서버를 종료했습니다.
- 첫 Intel 설치 복사본 검사는 Workspace 버튼 단계에서 시간 초과했습니다. 검사 코드가 DOM 존재만 기다려 세션 준비 전 비활성 버튼을 클릭할 수 있는 결함을 찾았습니다. 표시·활성화까지 기다리도록 검사기를 수정하고 세부 단계 진단을 추가했습니다. `App.test.tsx`에서 세션 응답을 지연시켜 비활성 클릭은 무효이며 준비 후 클릭이 동작함을 재현했습니다. 최초 실패 순간의 disabled 값은 수집하지 않았으므로 그 실패의 단독 원인으로 단정하지 않습니다.
- 이 회귀를 포함한 UI 전체 **209건 통과**. 앱 코드·설치 파일·보안·기존 시간 제한은 변경하지 않았습니다. 수정한 설치 검사 결과는 아래에 별도로 기록합니다.

초기 JAR SHA-256: `5d2ccbe2a98025aebe6cf0072439c0a9c488ac45fe6d3d05c31a03c5e7dfa8d7`. 이 JAR의 설치본은 최종 검색 조건 수정 전이므로 배포하지 않습니다.

## 초기 설치 검사 기록 — 배포본 아님

- 첫 수정 후 재검사는 Workspace·AI 연결을 통과했으나 전체 45초 안에 끝나지 않아 파일/지식 처리 단계에서 실패했습니다. 보존한 가상 DB에는 파일·지식·게시본·Source가 생성되어 있었습니다. 당시 창은 비활성 상태였으며 시스템 부하도 높았지만 원인을 단정하지 않습니다.
- 검사 창에 포커스를 요청하고 API별 진단 단계를 추가한 뒤 **같은 Intel DMG 설치 복사본 검사 통과**. 기존 45초 전체 제한·개별 대기·40px·인증/Origin 검사는 유지했습니다. 이 변경은 검사 예제에만 있으며 배포 앱은 바뀌지 않았습니다.
- 시스템 Git 없는 환경의 동봉 Git 공개 저장소 수집·검색·변경 없는 재동기화 통과.
- Intel 업데이트 압축의 서명·버전·추출 앱 CPU·ad-hoc 서명·현재 JAR 일치 검사 통과.
- 초기 ARM 패키징·DMG 정적 검사·서명 업데이트 검사는 통과했습니다. 최종 검색 조건 수정 이전 파일이므로 보관만 하며 공개하지 않습니다.

## 최종 설치본 확인

- Intel DMG의 읽기 전용 마운트·별도 설치 복사본·CPU·ad-hoc 서명 통과.
- 최종 설치 복사본에서 실제 React/WebKit Workspace·한글·AI 연결·요청 보호·파일·검색·게시·관계·폴링 OFF·Source 이름/분류 수정 통과. 외부 AI를 호출하지 않았습니다.
- 같은 복사본의 내장 Git으로 시스템 Git 없는 환경에서 공개 예제 저장소 수집·검색·변경 없는 재동기화 통과.
- Intel 업데이트 압축의 서명·버전·추출 앱 CPU·ad-hoc 서명·최종 JAR 일치 통과.
- 실제 최종 Intel 실행 파일의 격리된 HOME·세션 보호·중복 실행 차단·종료·재시작 통과. 시작 단일 측정 **28,925ms**. 당시 개발 Mac 부하가 반영된 값이며 일반 성능 보장이 아닙니다. [측정](native-host-report.json).
- 100개 가상 파일 검색 30회: p50 **62.94ms**, p95 **188.85ms**. 단일 로컬 프로세스의 작은 자료이며 실제 AI·대용량·동시 사용자 성능이 아닙니다. [측정](performance-phase3-foundation.json).
- ARM 최종 DMG의 읽기 전용 마운트·설치 복사본·앱/Java/Codex/Git/HTTPS 도구 CPU·ad-hoc 서명 정적 검사 통과. Intel 호스트에서 ARM 앱을 실행한 것으로 보고하지 않습니다.
- ARM 업데이트 압축의 서명·버전·추출 앱 CPU·ad-hoc 서명·최종 JAR 일치 통과.

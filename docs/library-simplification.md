# 자료와 설정 화면 정리

## 현재 MVP — 파일·폴더 중심

웹 URL·GitHub URL 추가와 GitHub 인증은 제거했습니다. 자료 추가에는 파일·폴더만 표시합니다. PC에 clone한 코드 저장소는 폴더로 연결하고 원격 변경은 사용자가 pull합니다. 기존 URL/GitHub 수집본은 보관 자료로 남아 열람·검색할 수 있지만 원격 동기화나 자동 폴링은 실행하지 않습니다. 아래 날짜별 웹·GitHub 설명은 이전 버전 이력입니다.

## 0.1.19 업로드 동기화

동기화 버튼은 업로드 파일만 있는 서재에서도 동작합니다. 업로드 보관본(하위 폴더 포함)을 재분석해 검색 색인을 갱신하고, 연결 Source는 기존 수집으로 갱신합니다. PC 원본과 업로드 보관본은 별개입니다. 처리 중 회전 표시·중복 실행 차단, 읽지 못한 파일 오류를 표시합니다. [PDF/질문 검색 검증](release-0.1.19-report.md).

## 0.1.17 (로컬 설치 완료, GitHub 미공개)

- 폴더는 선택 즉시 등록하고 웹 링크·GitHub는 Enter 또는 화살표로 등록합니다. 성공해도 추가 영역은 유지합니다.
- 파일·폴더·연결 자료·Workspace 삭제는 공통 확인창을 사용합니다. 기본 초점은 취소이며 삭제 중 중복 요청과 닫기를 막습니다.
- DB v24는 Source 등록 날짜와 Workspace 갱신 주기를 저장합니다. 과거 자료의 알 수 없는 등록 날짜는 `—`로 표시합니다.
- 설정 → Workspace 관리에서 자동 갱신 토글 옆에 5분·15분·30분·1시간·3시간·6시간·24시간을 선택합니다. 기본은 1시간입니다. 꺼진 상태에서도 주기는 저장되며 새 자료에도 상속합니다.
- 주기 선택은 해당 Workspace의 기존 연결 자료에도 적용합니다. 토글만 변경하는 기존 API는 개별 주기를 보존합니다. 저장 충돌 시 최신 값을 조회하되 자동 재전송하지 않습니다.
- 주기 저장은 즉시 동기화하거나 AI를 실행하지 않습니다. 앱이 실행 중일 때 기존 폴링 스케줄러가 동작합니다.
- AI 연결창의 경로 입력·도구 진단·성공 상태 중복 문구를 제거합니다. 모델 변경은 연결 버튼만 활성화하며 명시적으로 연결하기 전 기존 모델을 유지합니다.
- 아래 버전별 설명은 배포된 이전 동작입니다.

검증: UI 286개·Java 관련 52개·Rust 22개, UI/JAR 빌드 통과. 격리된 가상 Workspace에서 15분 선택·자동 갱신 켜기·백엔드 재시작 후 설정 유지 확인(AI 호출 0회). [실제 화면](screenshots/polling-interval-workspace.png). 양 CPU 설치 파일을 만들고 이 Mac을 0.1.17로 갱신했습니다. GitHub 공개는 별도입니다.

0.1.16부터 자료 추가는 **종류 선택 → 파일/폴더 선택 또는 주소 입력 → 추가**만 사용합니다. 파일은 선택 즉시 업로드 절차로 넘어갑니다. 이름은 원래 이름/주소에서 자동 생성하고 별도 분류 없이 Workspace로 구분합니다. 기존 자료의 이름·분류는 보존합니다.

0.1.14는 연결 자료와 업로드 파일을 같은 자료 탐색기에 표시합니다. 연결 자료의 루트 폴더는 중복 표시하지 않으며, 이름을 누르면 내부 파일을 탐색합니다. 아직 동기화하지 않은 자료도 목록에 나타납니다.

- 상단 **동기화 아이콘**는 연결된 폴더·웹 링크·GitHub를 순서대로 갱신합니다. 업로드 파일은 보관한 복사본이므로 다시 수집하지 않습니다.
- 일부 연결이 실패해도 다음 자료를 처리합니다. 실패 내용은 표시하고, 수집 중에는 중복 실행을 막습니다. 폴더 오류를 파일 수집으로 자동 변경하지 않습니다.
- 경로·반영 버전·최근 동기화 시간은 상세 정보에 접어둡니다. 삭제는 별도 확인이 필요합니다.
- 자동 갱신은 설정 → Workspace 관리의 토글 하나로 변경합니다. 신규 자료의 기본 주기는 1시간이며 기존 개별 주기는 유지합니다. Workspace 전체 변경은 CAS로 충돌 검사하고 새 자료도 설정을 상속합니다.
- 미리보기는 파일 선택 후에만 열립니다. 중복 제목·안내 문구·자료 수정 버튼을 제거했고 삭제 후 새로 등록합니다.
- 상단 자료 추가도 아이콘이며 두 버튼에 접근성 이름과 툴팁을 제공합니다.
- AI 연결은 제공자·모델·연결 버튼 중심입니다. 반복 설명과 확인 전 상태 문구를 없애되 오류, 로그인 동의, 실제 자료 전송 승인은 유지합니다.
- 실행 경로는 기본값 안내와 두 입력란·신뢰 확인·저장으로 줄였습니다. 도구 진단은 접어둡니다.
- 둥근 캐릭터 썸네일은 왼쪽 아래로 옮겼고 사이드바 로고·질문 기록의 새 질문 버튼은 제거했습니다.
- AI 연결 전에는 입력창을 비활성화하고 ‘AI를 연결해 주세요’를 표시합니다. 프로필 열기·동일 제공자 클릭·모델 변경은 인증을 해제하지 않습니다.
- Workspace 이름은 공백 정리·대소문자 중복 검사와 서버 DB 고유 제약으로 보호합니다.

DB v23의 `workspace_source_polling`과 GET/PATCH `/api/workspaces/{id}/source-polling`을 추가했습니다. 기존 개별 Source API·자료 저장 위치·인증·일회 전송 승인 계약은 유지합니다. 기존 개별 갱신 설정이 혼합된 경우 토글의 별도 표시로 구별하며 사용자가 변경할 때까지 보존합니다. 연결 확인은 모델의 실제 응답이나 사용 한도 보증이 아닙니다.

## 0.1.18 자료 추가 피드백

파일·폴더·웹 링크·GitHub는 같은 크기의 입력 영역을 사용합니다. 파일 선택 후 버튼 스피너와 목록 진행 막대를 표시하며 중복 요청은 막습니다. 취소 시 요청하지 않고 실패하면 재선택할 수 있습니다. [검증·설치 현황](release-0.1.18-report.md).

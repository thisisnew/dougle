# 0.1.10 — 기능 다이어트

현재 구현 후 빌드·검증 중입니다. 공개·설치본은 아직 0.1.9입니다. [쉬운 사용법과 코드 대조](simple-workflow.md).

- 기본 질문의 내부 검증·승인 상태·작업 조회 버튼을 줄이고 명시적 전송 동의 흐름으로 합쳤습니다.
- 자료 관리·코드 분석·문서 작성/게시·대화 정리 도구를 기본 화면과 분리했습니다. 자료·문서·답변을 삭제하지 않았습니다.
- DB v21, 서버의 전송 직전 재검증·일회 승인·중복 접수 방지·사람 편집 보호·게시 조건은 변경하지 않았습니다.
- 최초 UI 검사 224건 중 변경 전 문구와 삭제 버튼을 기대하던 2건이 실패했습니다. 새 흐름에 맞춰 수정한 뒤 224건, 간편 답변 중단 회귀 추가 후 225건을 통과했습니다. 이후 사용하지 않는 기존 준비 컴포넌트와 그 단위 검사 6건을 제거했으므로 최종 수는 달라집니다. 검사를 중복 합산하지 않습니다.
- 접힌 관리 기능을 DOM에서 삭제했다고 가정한 테스트 1건이 실패했습니다. 실제 요구는 보존한 채 숨기는 것이므로 가시성을 검사하도록 수정했습니다. 파일 목록 감사는 삭제를 Git index에 반영하기 전 실행해 실패했으며 삭제 반영 후 재실행합니다.
- 최종 전체 UI 219건·Java 378건 통과(실제 AI 자동 검사 1건 제외), Rust 17건 통과. TypeScript/Vite·Spring Boot 빌드 성공. Vite의 주 번들 500kB 초과 경고는 남으며 빌드 실패는 아닙니다.
- 브라우저에서 가상 파일 업로드 → 질문 → 인용 확인 → 전송 준비 → 미체크 동의/비활성 전송 확인 → 명시적 동의 → 가상 답변 완료 → 이력 목록 보존을 확인했습니다. 가상 CLI 호출은 1회, 실제 AI 호출은 없습니다. 질문 창 가로 넘침도 없습니다.
- 이력 화면 검사에서 `완료` 대신 `답변 생성 완료`를 기다려 시간 초과가 발생했습니다. 실제 목록에 질문과 완료 상태가 보존된 것을 확인했으며 제품 오류가 아닌 검사 문구 오류입니다.
- 새 자료의 첫 동기화가 접힌 관리 영역에 묻히지 않도록 등록 직후 관리 영역을 펼치고 `가져오기 필요`를 표시하도록 보완했습니다. 변경된 UI 전체 검사·JAR 재포장은 별도로 다시 실행합니다.

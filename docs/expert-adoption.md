## 2026-10-26 최우선 정책: 외부 업무 시스템 읽기 전용

Slack 게시·외부 DB 변경·브라우저 업무 변경은 승인 여부와 무관하게 금지한다. 로컬 Workspace·대화·근거·색인·설정 저장은 유지한다. [정책·강제 지점·배포 보류](external-readonly-policy.md)를 따른다. 과거0.1.21/675a7c59 스냅샷은 설치·공개하지 않는다. 아래 4 PASS는 과거 JAR의 합성 의미 검증이며 새 정책 준수 인증이 아니다.

E35의 과거 입력 “답변 초안 생성 후 전송 취소·승인”, 기준 “취소 시 전송 0회, 명시적 승인 시 대상 스레드에 중복 없이 전송”은 폐기됐다. [역사적 설계와 영수증 경계](slack-reply-runtime.md)는 그대로 보존하되 현재 요구로 사용하지 않는다. 새 기준은 아직 NOT_RUN이며 문서 변경으로 승격하지 않는다.

## 실제 통합 순서

1. 재사용할 파일·릴리스의 커밋 SHA와 해시를 고정하고 LICENSE/NOTICE·간접 의존성을 목록화한다. 위 URL은 조사 출처이며 설치용 버전 고정 파일이 아니다.
2. HolmesGPT를 격리 환경에서 검증한다. Python 런타임과 다수의 의존성이 필요하므로 기존 Java 앱에 즉시 전체 설치하지 않는다. 현재 Codex/Claude 로그인 연결과 모델 API 인증을 동일시하지 않는다. 호환성, 두 CPU 패키지 크기, 시작 시간, 취소 및 읽기 권한을 통과해야 런타임 채택을 확정한다.
3. AWS/Superpowers 절차는 해당 도구만 사용할 수 있는 Dougle 조사 절차로 조정한다. 적용 조건·제외 조건·필요 입력·증거·실패 분기·종료 조건을 명시한다. 외부 SKILL.md를 실행 권한으로 취급하지 않는다.
4. 연속 대화의 영속 저장과 검색 문맥 전달을 먼저 연결한다. 조사 도구를 붙여도 현재 독립 질문 경로가 유지되면 후속 질문은 개선되지 않는다.
5. 가상 업무 fixture에서 도구 실행 경로를 검증한 뒤, 실제 모델 평가 및 승인된 읽기 전용 서비스 연동을 분리해 수행한다. 회사 계정·운영 데이터는 자동 사용하지 않는다.

## 평가 규칙

- 아래 모든 항목의 초기 상태는 **미실행**이다. 체크리스트 작성이나 대역 테스트 통과를 실제 기능 통과로 집계하지 않는다.
- 실행 기록 필드: case ID, 앱 커밋, 모델/버전, fixture 버전, 실행 시각, 입력, 기대 근거, 실제 답변, 도구 호출/인자/결과, 지연, 호출·토큰 비용, 판정, 실패 이유, 증거 경로.
- 판정은 PASS / FAIL / BLOCKED / NOT_RUN. 실제 도구 미연결은 BLOCKED이며 PASS가 아니다. 비밀정보와 회사 원문은 평가 로그·Git에서 제외한다.
- 가상 문서·Java 코드·DB·로그·이미지에 정답과 혼동 후보를 함께 만든다. 정답 파일은 에이전트가 접근할 수 없는 평가자 영역에 둔다. 업무명은 fixture에만 두며 제품에 하드코딩하지 않는다.
- 의미 판단 항목은 최소 3회와 표현 변형으로 반복한다. 정답률, 근거 정확성, 불필요한 호출, p50/p95, 중복 호출, 사용자 개입 횟수를 각각 보고한다. 고정된 문구 일치만으로 채점하지 않는다.
- 보안·격리·중단·데이터 보존 위반은 총점과 무관하게 배포 차단이다. 모든 50개 항목은 증거가 있어야 완료이며, 이 집합 통과를 모든 실무 상황의 완전성으로 광고하지 않는다.
- 효율은 같은 자료 접근권한을 가진 사람이 동일 난이도의 별도 사례를 수행하는 기준선과 비교한다. 시작부터 근거 확인까지 측정하고 warm/cold cache를 분리한다. 정확성을 유지하면서 조사 중앙 시간이 줄어드는지 확인한다.

### E05 기준 명확화 — 2026-10-26 사용자 승인, 실행 승인 아님

원래 기준 **“요약 후에도 최신 정정 유지, 예전 대상에 대한 조회 없음”**은 역사적 문구로 보존한다. 새 기준은 위 표의 문맥 압축/제한·누락 인식 기준이며, 결정적 추출/압축을 검사한다. **AI 의미 요약은 구현하지 않았으며 그 구현을 주장하지 않는다.** E05 상태는 NOT_RUN이다.

전체 PASS에는 서로 다른 **3변형 모두 실제32턴 이상**과 **별도 loss-awareness 음성 사례**의 의미 검토가 필요하다. 중간 질문/답변을 사전 주입하지 않는다. 각 정상 변형에서 최종 정정이 최근5턴 밖에 있고 실제 전달 문맥에 정확한 bundle ID/digest로 포함되어야 한다. 직렬화 문맥은8000자 이내이며 원본 대비 생략/절단량이 실제로0보다 커야 한다. 전체 답변·계획·추적으로 최신 대상/환경 유지와 이전 대상 조회 없음도 확인한다. 긴 창 유지나 단일 변형 성공만으로 승격하지 않는다.

별도 음성 사례는 필요한 정정이 실제 전달 문맥에서 누락되었음을 확인한 뒤 모델이 추측하지 않고 불확실성/재확인을 요청하는지 검토한다. 정상 유지 시험에서 정정이 누락되면 fixture 무효이며 이를 음성 사례 통과로 재해석하지 않는다. 첫 변형은 진단만, 나머지 변형과 음성 사례는 별도 유한 실행 승인이 필요하다. 현재 실제 AI 호출 승인은 없고 새 아티팩트를 기다린다.

중앙 기록의 `criterionHash`는 해당 acceptance 문자열의 UTF-8 SHA-256이며, `source.sha256`은 이 문서 전체(세부 통과 조건 포함)를 고정한다. 이전 문구/해시는 `criteriaHistory`에 보존한다. 해시 갱신 자체는 실행 증거나 PASS가 아니다.

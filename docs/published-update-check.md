# 공개 업데이트 파일로 실제 앱 교체 확인

**Intel에서 0.1.6 → 0.1.7 교체를 확인했습니다.** 가짜 실행 파일이 아닌, 공개한 앱과 서명된 업데이트 파일을 사용했습니다. 사용자 Applications 앱과 자료는 건드리지 않았습니다.

## 확인한 순서

1. 이전 공개 파일의 GitHub 해시와 앱 서명을 확인합니다.
2. 임시 폴더에 이전 앱을 설치합니다.
3. 앱과 같은 Tauri 업데이트 라이브러리가 공개 피드를 읽고 실제 업데이트 파일을 받습니다.
4. 기본 버전 비교·고정 공개 키·서명된 버전 검사를 거쳐 앱을 교체합니다.
5. 교체된 버전·앱 서명·서버 파일 일치와 앱 밖의 가상 파일 보존을 확인합니다.
6. 교체된 실제 앱을 실행해 세션 보호·중복 실행 차단·종료·재시작을 검사합니다.

검사 도구만 이전 앱 버전을 사용합니다. 배포 앱의 버전 비교나 보안 설정을 바꾸지 않았습니다. 검사 대상은 임시 폴더로 제한하며, 자격 증명·사용자 DB를 복사하지 않습니다.

## 확인하지 않은 것

- 업데이트 메뉴의 실제 클릭과 사용자 Applications 설치 위치의 권한 창.
- 개인 자료가 담긴 사용자 DB의 전수 비교. 검사에는 새로 만든 가상 자료만 사용합니다.
- ARM 기기에서 실행, 실제 AI 호출, Apple 공증.

따라서 사용자 설치 환경의 최종 체험까지 완료했다고 표시하지 않습니다. [기계 판독 결과](published-update-report.json) · [교체 후 실행 결과](native-host-report.json).

## 개발자 재현

```bash
node scripts/published-update-smoke.mjs 0.1.6
```

macOS·해당 CPU의 이전 공개 압축 파일(`release/`)·현재 빌드 JAR·GitHub 조회 인증이 필요합니다. 실제 공개 파일을 내려받으므로 수백 MB의 트래픽이 발생합니다. 임시 설치본은 검사 후 정리합니다. 앱이 실행 중인 사용자 경로는 받지 않습니다.

Rust 17건·fmt·all-targets clippy 및 잘못된 인자/임시 폴더 외 경로 거절 검사를 통과했습니다. 기존 전체 605건을 다시 실행한 것은 아닙니다.

이번 변경은 검사 예제·도구·문서뿐입니다. 앱 실행 코드와 패키지 입력이 같으므로 **설치 파일·업데이트 피드는 0.1.7을 유지**합니다.

## 추가: 자료가 있는 DB의 버전 간 보존

이전 앱의 동봉 Java/JAR로 가상 Workspace·원본 파일·출처 있는 지식 문서를 만듭니다. 검토·게시 후 사람의 미게시 수정본도 따로 저장합니다. 서버를 정상 종료하고 실제 서명 업데이트를 적용한 뒤, 새 앱의 Java/JAR로 **같은 DB**를 열어 세션/Workspace·원문·수정본·게시본·출처 응답이 동일한지 비교합니다. AI 실행 파일은 존재하지 않는 테스트 경로로 지정해 외부 AI를 호출하지 않습니다.

첫 실행은 검사기가 존재하지 않는 `GET /workspaces`를 호출해 405로 중단됐습니다. 실제 계약인 `/session`의 Workspace 목록으로 수정했습니다. 앱·API·보안 설정은 바꾸지 않았습니다. **2026-10-24 08:39 KST 최종 검사 통과**: 같은 DB의 Workspace·선택 상태·원문·사람 수정본·게시본·출처가 모두 보존됐습니다. 두 버전 모두 DB v21이므로 새 스키마 마이그레이션 검증은 아닙니다. [검사 결과 JSON](published-update-report.json).

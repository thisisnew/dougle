# 0.1.8 — AI 연결 상태와 꼬마 탐정 아이콘

두 CPU 설치 파일 빌드·검증과 실제 Intel 앱 교체를 마쳤습니다. [0.1.8 릴리스](https://github.com/thisisnew/knowledge-forge/releases/tag/v0.1.8-preview.1)의 자산 10개를 로컬 크기·SHA-256과 대조한 뒤 공개했습니다. 서명된 업데이트 피드도 0.1.8로 승격합니다.

- AI 연결을 열면 인증 상태를 자동 확인합니다.
- 초록색 로그인 확인, 로그인 필요, 확인 중, 실패를 구별합니다.
- 창을 닫아도 상단에 마지막 결과를 표시합니다. 원격 연결 성공으로 단정하지 않습니다.
- DB v21, API와 전송 승인 경계, 업데이트 서명 키는 그대로입니다.
- Dock/Finder 아이콘을 녹색 안경·크림색 배경의 독자적인 꼬마 탐정으로 교체합니다. 생성 원본에서 Tauri 아이콘 도구로 PNG/ICNS를 만들며 두 CPU 앱에 같은 아이콘을 포함합니다.
- [사용법·구현 대조](ai-connection-indicator.md).

## 검증

- 변경부 UI 17건, 최종 전체 UI 214건, Java 378건(실제 AI 자동 검사 1건 제외), Rust 17건 통과. 반복 검사를 합산하지 않습니다.
- 실제 브라우저에서 가상 도구의 로그인 필요 → 동의 → 로그인 확인 → 창 닫은 뒤 상단 결과 보존을 확인했습니다. 화면은 사용법 문서에 첨부하며 실제 AI 호출은 없습니다.
- Intel 설치 UI 검사의 기존 수동 확인 대기가 새 자동 확인 결과를 재사용해 두 번 실패했습니다. 일시적 `CHECKING`을 기다린 시도도 빠른 응답을 놓쳤습니다. 최종적으로 확인 시각이 달라진 새 결과를 기다리도록 수정해 설치 UI 검사를 통과했습니다. 제품 코드나 인증 보호는 변경하지 않았습니다.
- Intel DMG 설치 복사본의 실제 WebKit UI·서명·업데이트 압축 검사를 통과했습니다. 사용자 요청으로 실제 Applications 앱도 정상 종료·이전 앱 백업 후 0.1.8로 교체·재실행했습니다. 설치된 ICNS가 새 원본과 일치하며 사용자 자료 폴더는 수정하지 않았습니다. 도구 캡처 문제 때문에 Dock의 실제 시각 검증은 별개입니다.
- 통합 JAR 검사 통과. 가상 파일 100개 검색 30회 p50 10.70ms, p95 18.73ms이며 작은 개발 환경 자료의 측정값입니다.
- 사용자가 제공한 화면에서 0.1.7의 실제 렌더링은 정상이었습니다. 이전 흰 화면은 도구 캡처와 실제 화면의 차이로 분류하며 앱 렌더링 오류로 처리하지 않습니다.
- ARM DMG 설치 복사본·아키텍처·서명 정적 검사와 두 CPU 업데이트 압축의 서명·버전·최종 JAR 일치 검사를 통과했습니다. 두 앱의 ICNS도 새 소스와 일치합니다. ARM 실기기 실행·Apple 공증은 포함하지 않습니다.
- Applications 0.1.8 실행 후 Java 자식·화면 HTTP 200·미인증 API 403을 확인했습니다. Dock 캐시를 삭제하거나 다른 앱을 종료하지 않았습니다.
- 실제 설치된 0.1.8 실행 파일을 별도 임시 HOME에서 시작해 중복 실행 차단·부모 종료 시 Java 종료·같은 DB 재시작도 통과했습니다. 사용자 DB나 외부 AI는 사용하지 않았습니다. [측정](native-host-report.json).

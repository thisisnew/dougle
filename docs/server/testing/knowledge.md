# 지식 공유·갱신 테스트

[공통 준비·출시 기준](README.md) · [수용 기준 색인](../implementation.md)

모든 사례는 구현 후 실행할 `NOT_RUN` 명세입니다. 공통 증거에 각 사례의 증거를 추가합니다. 한 사례에 나열된 변형은 모두 필수입니다.

## K01 · 동일 커밋 재수신

- **환경:** PG·Git
- **준비:** S0와 R0 수신 완료, 검사기·정책 동일, 작업 카운터 초기화
- **절차:** R0를 연속 2회 수신하고 두 번째 수신 중 다른 질문을 실행합니다.
- **합격:** 활성 버전과 본문 해시가 유지됩니다. 의미 병합·본문 쓰기·전체 재검사 0건이고 질문은 정상 진행합니다.
- **증거:** Git ref·manifest, 병합/쓰기/검사 호출 수

## K02 · 원격·서버가 같은 주장을 서로 다르게 수정

- **환경:** PG·Git
- **준비:** 공통 기준 R0의 같은 claim을 원격과 서버가 상충하게 수정
- **절차:** R1을 수신하고 충돌 토픽을 검색합니다. 허용된 서로 다른 claim 수정도 대조합니다.
- **합격:** 상충한 양쪽 주장·근거·로컬 정정이 남고 미해결로 표시됩니다. 무관한 수정은 함께 보존되며 마지막 작성자 우선으로 선택하지 않습니다.
- **증거:** 병합 전후 claim·근거·conflict 기록

## K03 · 새 버전 생성 중 프로세스 종료

- **환경:** PG·Git·kill
- **준비:** S0 활성, R1 후보 파일·메타데이터 생성 중
- **절차:** 파일 생성 중, 검증 후 포인터 교체 전, 포인터 커밋 직후를 각각 중단하고 재시작합니다.
- **합격:** 커밋 전에는 S0, 커밋 후에는 완전한 S1만 활성입니다. 불완전 파일을 읽지 않고 체크포인트부터 복구합니다.
- **증거:** 중단 지점, 활성 포인터, manifest 전체 무결성

## K04 · 질문 처리 중 활성 버전 교체

- **환경:** PG·barrier
- **준비:** 질문 A가 S0 고정 후 읽기 대기, S1 준비 완료
- **절차:** S1을 활성화한 뒤 질문 B를 시작하고 A를 재개합니다.
- **합격:** A의 읽기·근거는 S0, B는 S1에 연결됩니다. 정책 철회는 별도 A04처럼 고정보다 우선합니다.
- **증거:** 질문별 snapshot_id·파일 해시·근거 버전

## K05 · 같은 토픽에 수정 제안 2개

- **환경:** PG·독립 갱신 프로세스
- **준비:** 같은 S0/claim 기준의 서로 다른 제안 P1/P2
- **절차:** 동시에 적용하고 순서를 바꿉니다. 동일 P1도 다시 제출합니다.
- **합격:** 갱신 소유자만 반영하고 기준이 변한 제안은 재병합합니다. 양쪽 수정 또는 명시적 충돌이 남고 P1은 한 번만 적용됩니다.
- **증거:** 기준 해시, 제안 상태, overlay revision

## K06 · 원본 확인 실패

- **환경:** fake 원본·PG
- **준비:** 마지막 성공 시각 t0·버전 V0 기록
- **절차:** 버전 확인·본문 읽기 각각에 timeout/권한 오류를 주입합니다. 이후 연결을 복구합니다.
- **합격:** 실패 시 성공 시각·버전은 전진하지 않습니다. 실패 범위가 남고 성공한 후에만 갱신됩니다.
- **증거:** 시도/성공 시각, 원본 응답, 오류 코드

## K07 · source 일부만 재확인

- **환경:** fake 원본·PG
- **준비:** source에 A/B/C 범위가 있고 A만 새로 읽기 가능
- **절차:** A 읽기를 성공시키고 B 실패·C 미실행으로 종료합니다.
- **합격:** A만 재확인됩니다. source 전체·관련 없는 claim·C의 최신성은 갱신하지 않습니다.
- **증거:** coverage 및 claim별 observed_at

## K08 · 원격 삭제·force-push·공통 기준 소실

- **환경:** PG·임시 Git
- **준비:** R0 기준과 서버 정정 존재
- **절차:** 파일 삭제, ref force-push, 공통 조상 제거를 별도 저장소에서 각각 실행해 수신합니다.
- **합격:** 안전한 해시 비교로 재조정합니다. 정정은 자동 소실되지 않고 삭제/충돌 근거가 남습니다. 접근 철회는 즉시 사용 차단합니다.
- **증거:** 변경 목록, 기준 상실 진단, 정정 전후 비교

## K09 · 토큰·개인정보·경로 탈출·symlink·크기 초과

- **환경:** 격리 파일·Git
- **준비:** 허용 자료 후보와 악성 후보를 분리
- **절차:** 합성 토큰/개인정보, ../경로, 절대 경로, 외부 symlink, 크기 초과, 실행 hook을 변형으로 수신합니다.
- **합격:** 후보가 격리되고 S0가 유지됩니다. 외부 파일 쓰기·hook 실행 0건, 진단에 민감 원문이 없습니다.
- **증거:** 검사 사유, 외부 경로 canary, 활성 해시

## K10 · 검색·검사기 버전 변경

- **환경:** PG·캐시
- **준비:** 검사기·검색 메타데이터·정책 버전 v1 결과 캐시
- **절차:** 콘텐츠를 유지한 채 각 버전을 따로 올려 재수신·검색합니다.
- **합격:** 변경 계약의 영향 범위만 재검사하고 과거 결과를 무조건 재사용하지 않습니다. 정책 축소 자료는 노출되지 않습니다.
- **증거:** 캐시 키, invalidation·재검사 수

## K11 · 오래된 버전을 실행 중 문의가 참조

- **환경:** PG·barrier
- **준비:** A가 이전 S0 참조 중이고 S1 활성
- **절차:** 정리 작업과 A 완료를 두 순서로 경합시키고 재시작 대기 작업도 포함합니다.
- **합격:** 활성·복구·진행 문의 참조 버전을 삭제하지 않습니다. 참조 해제 및 보관 조건 충족 후에만 제거합니다.
- **증거:** 참조 수, GC 대상/실제 삭제, 재개 읽기

## K12 · 대량 변경 중 실패 후 재개

- **환경:** PG·Git·kill
- **준비:** 대량 R1 변경, 경로/해시 manifest와 처리 배치 고정
- **절차:** 중간 배치 후 중단하고 같은 R1로 재개합니다. 재개 중 R2도 도착시킵니다.
- **합격:** 동일 계약에서 완료한 R1 해시를 의미 재처리하지 않습니다. 누락·중복 반영 없이 R1을 마치거나 명시적으로 폐기하고 R2 작업을 분리합니다.
- **증거:** 체크포인트, 처리 경로 집합, 호출 수·최종 manifest

# 서버 전환 테스트 명세

[서버 설계](../README.md) · [구현 단계](../implementation.md)

**서버 개발이 끝나면 이 명세의 절차를 실행하고 실제 결과를 남깁니다. 테스트 코드가 존재하거나 fake 검사가 통과한 것만으로 출시하지 않습니다.**

상태: 구현 전 명세, 2026-11-08. 기본 수용 기준 90개를 상세화하고 회사 연동 12개, 성능 5개, 로컬 회귀 3개, 배포 12개를 추가했습니다. 총 122개 상위 사례이며 내부 변형은 모두 실행합니다. 현재 실행 결과는 전부 `NOT_RUN`입니다.

## 어디부터 실행하나요?

| 순서 | 명세 | 필수 환경 |
|---|---|---|
| 1 | [지식 공유 K01~K12](knowledge.md) | 임시 Git 저장소·지식 폴더, 실제 PostgreSQL |
| 2 | [접수·경합·비용·엔진 J/C/E](runtime.md) | 실제 PostgreSQL, 독립 프로세스, fake Slack·엔진 |
| 3 | [권한·운영 조회 A/Q](access.md) | 격리 권한 정책, 조회 어댑터, 합성 자료 |
| 4 | [게시·개발자 인계·운영 D/H/O](delivery-operations.md) | 전송 장애 주입, 실제 PostgreSQL, 백업·복원 환경 |
| 5 | [회사 연동 U01~U12](company.md) | 승인된 제한 채널·서비스 인증·실제 모델·읽기 자료 |
| 6 | [성능 P01~P05와 로컬 회귀 L01~L03](performance-regression.md) | 고정 장비·코퍼스·기준 버전·격리 로컬 설치 |

기본 90개 ID는 [기존 목록](../implementation.md)과 같습니다. 기존 목록은 개발 범위를 찾는 색인이고, 이 문서는 실행 절차입니다. 기대 결과가 충돌하면 먼저 설계 결정을 수정하고 명세를 함께 맞춥니다. 구현 결과에 맞춰 기대 결과를 낮추지 않습니다.

## 공통 준비

테스트는 실행마다 별도 DB·임시 디렉터리·합성 데이터로 시작합니다. 회사 테스트도 승인된 시험 자료·채널만 사용합니다. 개인 `~/.dougle`, 키체인, 실행 중 봇, 운영 DB 데이터는 자동 검사의 대상이 아닙니다.

| 묶음 | 준비할 내용 |
|---|---|
| 식별자 | 가상 workspace W1/W2, 각각 같은 문자열의 channel C1, 스레드 T1/T2, 일반 사용자·담당자·비담당자 |
| 지식 | 합성 도메인 2개, 공개·제한 자료, 기준 Git R0와 변경 R1/R2, 스냅샷 S0/S1, 충돌·정정·삭제 사례 |
| 근거 | 어댑터가 생성하는 실행 ID·도구 ID·성공/실패·범위·버전·관측 시각. 검증기에 정답 영수증을 몰래 주입하지 않음 |
| 조회 | 합성 센터 4개 중 활성 3개·삭제 1개, 창고 7개, 별도 적재 시각. 센터와 창고 수를 구분하는 정답 자료 |
| 장애 | 단계별 barrier, 프로세스 kill, 응답 유실, 429, timeout, DB 실패, 권한 변경, 결과 중복 |
| 관측 | 비밀 없는 이벤트 순서, 외부 호출 횟수·내용 해시, DB 상태, 예산 원장, 지식 해시, 고객/내부 메시지 분리 |
| 설정 | 기준은 병렬 2, lease 60초·heartbeat 10초. 빠른 검사에서는 축소값을 명시하고 기본값 검증도 별도 수행 |

자동 검사의 Slack은 전송 요청과 실제 전달을 따로 기록하는 fake를 사용합니다. “Slack에는 전달됐지만 응답은 유실”을 표현할 수 있어야 합니다. 테스트 모델은 성공·실패·지연·취소 무시·잘못된 근거 ID를 제어합니다. 실제 모델 평가는 이 fake와 별도입니다.

PG 표시는 운영에서 선택한 PostgreSQL 버전과 마이그레이션을 쓰는 격리 DB입니다. 서로 다른 연결과 프로세스로 경합을 만듭니다. SQLite·단일 연결의 통과를 대체 증거로 인정하지 않습니다. 실제 어댑터 표시는 운영에 사용할 SDK·CLI·프로토콜 파서를 통과시키라는 뜻이며, 회사 토큰을 쓰라는 뜻이 아닙니다.

## 테스트 코드와 CI 연결

서버 구현 시 [목표 코드 구성](../architecture.md)에 맞춰 계약 검사는 `tests/contracts/`, PostgreSQL·경합·복구 검사는 `tests/server/`에 둡니다. 이는 앞으로 만들 경로이며 현재 실행 명령이 준비됐다는 뜻은 아닙니다. 테스트 이름 또는 pytest 메타데이터에 `K01`, `J04`처럼 명세 ID를 남기고 변형별 결과를 추적합니다. 한 ID가 여러 테스트 함수에 연결될 수 있습니다.

| 실행 시점 | 반드시 실행할 범위 |
|---|---|
| 코드 변경 CI | 계약·정책·실제 PostgreSQL·어댑터 fixture, 기존 로컬 회귀, 명세 ID와 실행 검사 연결 확인 |
| 병합·배포 후보 | 전체 기본 사례의 자동 부분, 반복 경합·장애·마이그레이션, 관련 성능 회귀 |
| 엔진·프롬프트·스킬·도구 변경 | E06과 U01~U10의 실제 모델 평가, 필수 조사·근거 ID·표현 검증 |
| 첫 서버 출시·관련 연결 변경 | U01~U12 실제 회사 경로, P01~P05, 백업·복구·이전 검증 |
| 배포·migration·구성·개발 절차 변경 | R01~R12 관련 변형과 기존 문의·로컬 호환, 실제 승격·복귀 |

CI에서 관련 검사가 수집되지 않거나 PostgreSQL 준비 실패로 skip되면 통과로 처리하지 않습니다. 모델·회사 환경이 없는 CI에서는 해당 사례를 `NOT_RUN` 또는 `BLOCKED`로 남기고 별도 실행 결과를 출시 기록에 합칩니다. 선택 기능 제외는 아래 출시 기준에 따라 명시적으로 판단합니다. 문서만 바뀌면 ID·링크·명세 정합성을 검사하며 그 결과를 서버 동작 검증으로 표시하지 않습니다.

## 실행 규칙

1. 대상 커밋, 스키마·설정·스킬·모델 버전, 자료 manifest 해시와 정답을 먼저 고정합니다.
2. 각 사례의 준비 상태를 확인한 뒤 실행합니다. 앞 사례의 잔여 세션·캐시·파일에 의존하지 않습니다.
3. 정상 동작과 실패 뒤 복구를 모두 확인합니다. 오류 문구만 맞고 DB·전송 상태가 틀리면 실패입니다.
4. 경합은 barrier로 두 작업을 지정 지점까지 진행시킵니다. 승자 순서를 바꿔 실행하고, 각 순서 최소 20회와 고정 seed의 무작위 순서 100회를 기록합니다. 반복은 안전성 증명의 대체가 아닙니다.
5. 시간 기반 검사에서는 가짜 시계와 DB 시각을 구분합니다. lease는 격리 DB의 만료값을 명시적으로 설정하거나 실제 만료를 기다립니다. OS 시각 변경으로 운영 자원에 영향을 주지 않습니다.
6. 재시도·복구 뒤 외부 호출 수, 남은 예약 비용, 임시 파일, 활성 소유권을 확인합니다. 프로세스 종료가 외부 조회 취소를 보장한다고 가정하지 않습니다.
7. 실패는 해당 시도의 결과로 남깁니다. 재실행 성공으로 실패 기록을 덮지 않으며 결함 수정 커밋과 재검증을 연결합니다.

일시 읽기 오류는 최초 호출 + 재시도 최대 2회, 형식 보완은 추가 1회라는 목표 정책을 검사합니다. 모두 동일 문의의 총 시간·비용 제한에 포함됩니다. 권한 거부·정책 차단·불명 게시를 일반 재시도 대상으로 취급하지 않습니다.

## 반드시 남길 증거

공통 증거는 실행 환경, 테스트 ID, 실제 실행 명령, commit, seed, 설정/자료 해시, expected/observed, 제한 사항입니다. 각 상세 사례의 증거 항목을 추가합니다. DB는 필요한 행·카운트·제약 결과만 추출하며 실제 토큰·쿼리 파라미터·개인정보·모델 내부 추론은 기록하지 않습니다.

회사 UI는 질문·안내·최종 답변·내부 카드의 순서를 담당자가 확인합니다. 비공개 증거는 접근 제한 저장소에 두고 공개 레포에는 비민감 결과 요약과 증거 참조만 둡니다. 증거가 없으면 `PASS`로 표시하지 않습니다.

[실행 기록 템플릿](execution-template.json)은 122개 항목을 `NOT_RUN`으로 제공합니다. 실행 때 복사하고 `spec_commit`을 이번 명세의 실제 커밋으로 고정합니다. `runs`에 변형별 실행을 추가한 뒤 필수 변형이 전부 통과한 경우에만 상위 결과를 `PASS`로 바꿉니다. 문서 검사 결과는 여기에 서버 테스트 결과로 넣지 않습니다.

## 출시 차단 기준

| 결과 | 처리 |
|---|---|
| 권한 밖 정보 노출·쓰기 실행·근거 없이 게시·확정 중복 게시·접수 후 유실·직접 응대 뒤 새 자동 전송 | 해당 자동 응답 경로를 닫고 수정·재검증합니다. 평균 성공률로 상쇄하지 않습니다. |
| 기본 90개·로컬 회귀·배포 R01~R12 실패/미실행 | 서버 출시를 차단합니다. 기존 로컬 제품에 회귀가 없어야 하며 실제 배포·복귀를 수행할 수 있어야 합니다. |
| 회사 필수 경로 미실행·증거 없음 | 가짜 검사 통과와 별개로 회사 사용을 열지 않습니다. |
| 선택 연결이 승인되지 않음 | `BLOCKED`와 사유를 남깁니다. 해당 기능은 설정·UI에서 비활성화하고 연결 부재→내부 도움 경로를 실제 검증한 범위만 출시할 수 있습니다. |
| 성능·복구 목표 미정 또는 미달 | 목표를 먼저 확정하고 제한 운영 범위·허용량을 결정합니다. 측정 후 유리하게 목표를 바꾸지 않습니다. |

선택 연결은 운영 DB 직접 조회·Kafka·서버 브라우저처럼 회사 승인에 따라 범위가 달라지는 항목입니다. 게시 중복 방지·권한·실제 모델 근거 검증은 선택 항목이 아닙니다. U03 BigQuery는 이번 도입 범위의 필수 경로입니다. BigQuery를 제외하려면 범위 결정과 사용자 안내를 명시적으로 변경해야 합니다.

출시 기록에는 범위별 PASS/FAIL/NOT_RUN/BLOCKED 개수, 미해결 결함, 비활성 기능, 비용, 부하 한도, 복구 연습 결과, 운영 책임자의 판단을 남깁니다. 기존 [문서 검토 기록](../review.json)은 서버 테스트 보고서가 아닙니다.

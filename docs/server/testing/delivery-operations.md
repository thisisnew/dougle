# 게시·개발자 인계·운영 테스트

[공통 준비·출시 기준](README.md) · [수용 기준 색인](../implementation.md)

모든 사례는 구현 후 실행할 `NOT_RUN` 명세입니다. 공통 증거에 각 사례의 증거를 추가합니다. 한 사례에 나열된 변형은 모두 필수입니다.

## D01 · 두 게시기가 같은 pending 선점

- **환경:** PG·독립 dispatcher
- **준비:** 같은 pending outbox, 외부 전송 barrier
- **절차:** 두 게시기가 동시에 선점합니다. 재시작도 섞습니다.
- **합격:** 한 게시기만 sending이 되고 외부 전송 요청 1회입니다.
- **증거:** 선점 결과·outbox·transport 호출 수

## D02 · 같은 후보가 두 번 완료됨

- **환경:** PG·동시 결과 제출
- **준비:** 같은 inquiry/generation/revision 후보
- **절차:** 완료를 두 번 제출하고 nullable key 변형도 검사합니다.
- **합격:** 답변·안내 종류별 유일키가 중복을 막습니다. 최종 답변에 필수 inquiry/generation 없는 행은 DB가 거절합니다.
- **증거:** UNIQUE/CHECK/FK 결과·논리 키 카운트

## D03 · 전송 성공 후 DB 저장 전 종료

- **환경:** PG·fake Slack·kill
- **준비:** 전송은 성공했지만 성공 저장 barrier
- **절차:** Slack 전달 직후 dispatcher를 종료하고 복구합니다.
- **합격:** 무조건 재전송하지 않고 unknown으로 보류합니다. 확실한 외부 ID/내용 증거가 있을 때만 sent로 조정합니다.
- **증거:** Slack 전달 원장·DB·복구 전송 수

## D04 · sending 소유권 만료

- **환경:** PG·barrier
- **준비:** sending 상태의 lease 만료, 첫 호출은 결과 불명
- **절차:** 새 게시기를 실행하고 뒤늦은 성공 응답도 전달합니다.
- **합격:** 새 호출 없이 unknown 대조로 갑니다. 늦은 증거는 동일 전송에 연결하고 다른 revision에 적용하지 않습니다.
- **증거:** lease/전송 ID·후속 호출 0건

## D05 · 여러 조각 중 중간 timeout

- **환경:** fake Slack·PG
- **준비:** 3조각 답변, 1번 성공·2번 응답 유실
- **절차:** 게시 후 재시작·대조를 수행합니다.
- **합격:** 1번은 보존되고 전체를 재전송하지 않습니다. 2번 불명 상태에서 3번을 무작정 전송하지 않으며 문의를 posted로 표시하지 않습니다.
- **증거:** 조각별 digest·순서·전송 수

## D06 · 확정 429

- **환경:** fake Slack·제어 시계
- **준비:** 확정 429, Retry-After=5, 재시도 상한 설정
- **절차:** 반복 429와 이후 성공 두 변형을 실행합니다.
- **합격:** 5초 이전 재전송이 없고 상한 이후 중단합니다. 동일 전송 ID로 처리하며 본문 중복 전달이 없습니다.
- **증거:** 호출 시각·attempt·최종 상태

## D07 · timeout·5xx·연결 단절

- **환경:** fake Slack·PG
- **준비:** 전송 시작 후 응답이 불명인 transport
- **절차:** timeout·5xx·응답 전 단절을 각각 주입합니다.
- **합격:** unknown이며 일반 실패 재시도 큐로 넣지 않습니다. 운영 경보에는 원문 대신 전송 ID·상태가 남습니다.
- **증거:** 에러 분류·outbox·재전송 0건

## D08 · Slack 조회에서 메시지를 못 찾음

- **환경:** fake Slack·PG
- **준비:** unknown 전송, 조회는 빈 결과/권한 오류/지연 반영
- **절차:** 복구 대조를 여러 번 실행합니다.
- **합격:** 검색 부재만으로 미전송을 확정하지 않습니다. 불충분 증거에서는 보류하며 새 전송하지 않습니다.
- **증거:** 대조 결과·상태 이력

## D09 · 게시 직전 사용자 정정

- **환경:** PG·스레드 reader
- **준비:** 최종 전송 직전 정지
- **절차:** 사용자 텍스트 정정·삭제·첨부 변경·개발자 실제 답변을 각각 반영합니다. 자체 이모지/안내 변경도 대조합니다.
- **합격:** 의미 변경 시 오래된 후보를 차단·재검증합니다. 자체 진행 표시만 바뀌면 불필요한 재조사를 하지 않습니다.
- **증거:** context digest·후보/게시 revision·호출 수

## D10 · DB만 과거로 복원

- **환경:** 실제 백업·PG·독립 원장
- **준비:** 백업 이후 Slack 게시 완료
- **절차:** DB만 이전 시점으로 복원하고 게시기를 시작합니다.
- **합격:** 원장과 대조 전 readiness/게시는 차단됩니다. 이미 전송된 답변을 재게시하지 않고 불명은 보류합니다.
- **증거:** 복원점·원장 diff·전송 수

## D11 · custom 이모지 없음·일시 오류

- **환경:** fake Slack reaction
- **준비:** dougle/loadingg/처리완료 정상 및 오류 응답 준비
- **절차:** 정상 흐름, invalid_name, 429, timeout, 부분 성공을 실행합니다.
- **합격:** 정상은 dougle 유지·loadingg 제거·처리완료 추가입니다. invalid_name만 표준 대체하고 일시 오류로 잘못 교체하지 않습니다. 답변 진행은 유지합니다.
- **증거:** reaction 순서·잔여 이모지·답변 상태

## D12 · 검토 모드·기존 승인 대기 이관

- **환경:** PG·액션·fake Slack
- **준비:** require_approval=true와 과거 승인 대기 문의
- **절차:** 서버 자동 모드 변경·이관 후 조사/안내를 실행하고 오래된/최신 승인을 각각 제출합니다.
- **합격:** 승인 전 자동 안내·최종 답변 0건입니다. 기존 승인 경계를 유지하고 최신 유효 승인만 게시합니다.
- **증거:** reply_mode·액션 감사·공개 전송 수

## H01 · DM 전송 실패

- **환경:** fake Slack·지원 경로
- **준비:** 내부 도움 필요, 1차 담당자 DM 실패
- **절차:** 확정 실패와 전송 결과 불명을 각각 주입하고 대체 경로를 실행합니다.
- **합격:** 고객에게 요청 완료 안내를 하지 않습니다. 대체 담당자/경보가 남고 내부 요청이 조용히 사라지지 않습니다.
- **증거:** DM 상태·fallback·고객 전송 0건

## H02 · 도움 카드 반복 갱신

- **환경:** fake Slack·PG
- **준비:** 도움 DM 성공 후 동일 문의 갱신
- **절차:** 카드를 여러 번 갱신하고 프로세스를 재시작합니다.
- **합격:** 최초 대기 안내는 문의당 최대 한 번 시도하며 DM 성공보다 앞서지 않습니다.
- **증거:** DM→notice 순서·dedupe key·시도 수

## H03 · 결과 입력 더블클릭·중복 모달 제출

- **환경:** PG·액션 barrier
- **준비:** 유효한 최신 도움 카드와 결과
- **절차:** 동일 버튼·모달 submission을 동시에 2회 보내고 재전송합니다.
- **합격:** 보충 결과·generation 증가·새 job·접수 안내는 각각 한 번입니다.
- **증거:** submission_key·generation·job/outbox 수

## H04 · 시간 없이 결과 입력

- **환경:** 액션·모델
- **준비:** 현재값 도움이 필요하고 시간 필드 없는 모달
- **절차:** 시각 없는 결과를 제출합니다. 본문에 실제 관측 시각을 적은 변형도 실행합니다.
- **합격:** 둘 다 접수합니다. submitted_at을 관측 시각으로 쓰지 않고 명시한 시각만 별도 보존합니다. 최신성 불명은 재확인합니다.
- **증거:** 모달 구조·결과 시각·후속 근거

## H05 · “연결 복구함”만 입력

- **환경:** 엔진·원본 reader
- **준비:** 연결 실패 후 도움 요청
- **절차:** 담당자가 '연결 복구했습니다'만 제출하고 조회 성공/실패를 각각 반환합니다.
- **합격:** 복구 보고를 운영 결과로 게시하지 않습니다. 실제 원본 조회 후 답하거나 필요한 도움 상태를 유지합니다.
- **증거:** 새 조회 trace·최종 근거

## H06 · 직접 응대와 조사 완료 경합

- **환경:** PG·barrier
- **준비:** 동일 문의의 조사 완료와 직접 응대 동작 준비
- **절차:** 두 TX의 선점 순서를 바꿔 경합시킵니다. 게시기는 아직 호출 전입니다.
- **합격:** 직접 응대 수락 뒤 미전송 자동 답변은 취소되고 늦은 결과는 거절됩니다. 새 멘션 문의는 별도로 처리할 수 있습니다.
- **증거:** generation·human_owned·최종 outbox·새 문의

## H07 · 직접 응대와 외부 전송 시작 경합

- **환경:** PG·fake Slack barrier
- **준비:** 게시 선점 직전 또는 외부 호출 시작 직후
- **절차:** 각 지점에 직접 응대를 입력합니다.
- **합격:** 호출 전 선점이면 전송 0건입니다. 이미 시작했다면 중단 보장 불가를 내부에 알리고 결과를 대조하며 거짓 성공을 표시하지 않습니다.
- **증거:** 게시/액션 타임라인·내부 응답

## H08 · 직접 응대 후 옛 결과 입력

- **환경:** 액션·PG
- **준비:** human_owned 문의의 옛 입력 모달 열림
- **절차:** 직접 응대 후 오래된 결과 제출·재시도를 전달합니다.
- **합격:** 문의는 재개되지 않고 새 job·고객 결과 접수 안내가 없습니다.
- **증거:** 상태·감사 사유·호출 수

## H09 · 고객 안내 실패

- **환경:** fake Slack·PG
- **준비:** 도움/보충 접수는 성공, 고객 진행 안내만 실패
- **절차:** 안내 timeout·확정 실패 후 조사와 최종 답변을 진행합니다.
- **합격:** 안내 자동 재전송은 없고 최종 답변은 막히지 않습니다. 안내 시도 종료 뒤 최종 게시가 이어집니다.
- **증거:** notice/final 순서·시도 수·문의 상태

## O01 · 중지 중 생성된 이벤트가 재개 후 도착

- **환경:** PG·수신 어댑터
- **준비:** 중지 구간 [t1,t2), t1 이전 접수 문의 존재
- **절차:** t1 직전/동일/t2 직전/동일 이벤트를 재개 후 전달합니다.
- **합격:** 중지 구간 생성 이벤트만 제외하고 이전 접수는 보존합니다. 중지 채널 이력 backfill을 하지 않습니다.
- **증거:** pause interval·생성 시각·decision·history 호출

## O02 · 장애 재시작

- **환경:** PG·kill
- **준비:** 접수 완료 queued/running/needs_developer 혼합
- **절차:** 비정상 종료 후 재시작합니다.
- **합격:** 장애를 paused로 기록하지 않습니다. 만료 작업만 복구하고 내부 도움 상태를 보존합니다. 미수신 Slack 이벤트 무손실을 주장하지 않습니다.
- **증거:** 복구 전후 상태·중지 이력·접수 건수

## O03 · drain 중 새 질문

- **환경:** PG·프로세스
- **준비:** A 진행 중, drain 진입
- **절차:** B 새 문의 접수, A 정상 완료와 종료기한 초과를 각각 실행합니다.
- **합격:** B는 DB 대기, 새 선점 없음. A는 완료 또는 취소/만료가 기록되고 재시작 뒤 오래된 결과를 거절합니다.
- **증거:** 모드·lease·job·종료 순서

## O04 · 토큰 회전·만료

- **환경:** 실제 secret/Slack 어댑터·fake transport
- **준비:** 참조형 테스트 시크릿과 갱신 기능
- **절차:** 토큰 만료·회전·잘못된 접두사·비밀 공급자 장애를 각각 주입합니다.
- **합격:** 누출 없이 진단·재연결합니다. 무한 시작 루프가 없고 수신 불가를 정상 실행으로 표시하지 않습니다.
- **증거:** 마스킹 로그·readiness·재연결 수

## O05 · DB 중단·모델 한도·원본 장애

- **환경:** PG·fake 제공자
- **준비:** 정상 상태에서 다른 원본도 사용 가능
- **절차:** DB 중단·모델 quota·원본 timeout을 각각 주입하고 복구합니다.
- **합격:** 원인을 구분하고 제한된 재시도·내부 요청을 수행합니다. 하나의 원본 장애로 전체를 계속 재시작하지 않습니다.
- **증거:** reason_code·호출 상한·다른 문의 진행

## O06 · SQLite 이전

- **환경:** 실제 마이그레이션
- **준비:** 합성 SQLite에 모든 상태·옛 정수 ID·시각·예산·전송 원장 준비
- **절차:** 서버 이관 후 재실행·중간 실패 후 재개도 시험합니다.
- **합격:** 건수·관계·해시·예산이 맞고 Slack ts 정밀도가 유지됩니다. 승인/직접 응대/불명 전송 상태가 안전하게 대응됩니다.
- **증거:** ID mapping·FK 검사·상태별 reconciliation

## O07 · 옛 DM 카드 제출

- **환경:** 액션 어댑터·이관 DB
- **준비:** 옛 카드 ID가 있는 문의와 없는 문의
- **절차:** 각 옛 버튼을 담당자/비담당자로 제출합니다.
- **합격:** 정확히 대응하거나 안전하게 만료 처리합니다. 새로 같은 숫자 ID를 받은 다른 문의에 연결하지 않습니다.
- **증거:** mapping lookup·액션 결과·상태 diff

## O08 · 신구 실행기 동시 시작

- **환경:** 서버 역할·배포 harness
- **준비:** 기존 로컬 실행기와 서버, 또는 서버 2개 시작 상황
- **절차:** 역할 중복 시작과 cutover를 실행합니다. 로컬 종료 확인 실패도 주입합니다.
- **합격:** 서버끼리는 공유 lease로 중복 선점하지 않습니다. 공유 lease를 모르는 옛 로컬이 살아 있으면 전환을 차단하며 동시 운영 안전을 주장하지 않습니다.
- **증거:** 배포 preflight·프로세스 종료 증거·역할 lease

## O09 · 백업 복원·삭제 정책 재적용

- **환경:** 실제 백업·격리 복원
- **준비:** 전송·삭제 기록이 있는 백업과 이후 변경
- **절차:** 별도 환경에 DB·원장·지식을 복원하고 만료/삭제를 재적용합니다.
- **합격:** 대조 전 게시 차단, 불명 보류, 삭제 자료 미노출. 복구 시간·손실 범위와 설정된 RPO/RTO 달성 여부를 측정합니다.
- **증거:** 백업 manifest·대조 보고·시간·canary 검사

## O10 · 관리자 상태 조회

- **환경:** 상태 인터페이스·정책
- **준비:** queued/조사/DB 대기/개발자 대기/불명 전송 상태 존재
- **절차:** 기존 관리 메뉴로 담당자/비권한 사용자가 조회하고 worker 신호를 끊습니다.
- **합격:** 별도 tail 없이 단계·경과·마지막 신호·이유를 확인합니다. 원문·시크릿·내부 추론은 없고 정지/오래된 상태를 숨기지 않습니다.
- **증거:** 상태 화면·권한 결과·갱신 시각

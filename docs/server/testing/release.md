# 배포·추가 개발 전략 검증

[공통 준비·출시 기준](README.md) · [배포 전략](../delivery.md) · [개발 전략](../development.md)

R01~R12는 기존 110개 사례에 추가하는 배포 수용 기준입니다. 모두 `NOT_RUN`입니다. 각 변형의 준비·절차·합격·증거를 검사하며 실제 pipeline·컨테이너·migration을 만든 뒤 실행합니다. 배포 기능 자체를 fake 호출만으로 통과시키지 않습니다.

## R01 · 개발·시험·운영 자원 분리

- **준비:** 별도 시험/운영 앱·DB·자격·원장·자료 경로와 합성 canary를 가진 격리 환경을 구성합니다.
- **절차:** staging에 운영 자격 참조·DB 주소·앱 ID를 잘못 넣어 시작합니다. 외부 기여 CI에서 운영 배포 runner·비밀 접근도 시도합니다.
- **합격:** 환경 식별과 자격 정책으로 시작·접근을 차단합니다. 정상 시험 환경은 운영 문의·자료·메시지에 영향을 주지 않습니다. 일반 CI는 운영 망·비밀·배포 권한이 없습니다.
- **증거:** 환경별 resource ID·접근 거절·canary 불변·runner 정책. 실제 비밀 값은 제외합니다.

## R02 · 검증한 동일 이미지만 운영 승격

- **준비:** 검사 통과 커밋 A와 미검증 커밋 B, A의 이미지 digest·SBOM·출처·시험 결과를 준비합니다.
- **절차:** A를 staging→운영 시험 대상으로 승격합니다. 중간 재빌드, 움직이는 태그 변경, 다른 digest·설정 revision 끼워 넣기를 각각 시도합니다.
- **합격:** 실제 실행 digest가 검증한 값과 같습니다. 변경된 산출물/구성은 원래 검증을 상속하지 않고 필요한 재검사를 요구합니다. 같은 릴리스 산출물을 덮어쓰지 않습니다.
- **증거:** source→build→staging→production digest 연결, 실제 컨테이너 image ID, 릴리스 기록.

## R03 · 누락·실패 검사가 있는 후보 배포 차단

- **준비:** 필수 test ID, 환경별 실제 모델·연동 증거와 예외 정책을 등록합니다.
- **절차:** CI 실패, skip, 테스트 수집 0건, 회사 검사 NOT_RUN, 변조 결과 참조, 다른 커밋의 PASS를 각각 후보에 붙입니다. 승인 없는 운영 승격도 시도합니다.
- **합격:** 해당 후보를 배포하지 않습니다. 명시적으로 비활성화한 선택 연결만 범위 제외가 가능하며 근거·권한·게시 검사는 제외하지 못합니다. 회사 플랜에서 보호 기능이 없으면 대체 승격 경계가 동작합니다.
- **증거:** 후보별 차단 이유, 검사 커밋·환경 대응, 운영 실행 0건.

## R04 · 동시 배포와 배포 프로세스 종료

- **준비:** 같은 환경에 두 배포 요청, 단계별 barrier와 영속 배포 잠금을 준비합니다.
- **절차:** 동시에 시작하고 drain/migration/새 진단/게이트 해제 전후에 배포 실행기를 종료합니다. 다른 실행기로 복구를 시도합니다.
- **합격:** 한 배포만 진행합니다. 종료·lease 만료만으로 migration·전송을 반복하거나 게시 게이트를 열지 않습니다. 현재 단계를 확인한 복구만 허용하고 영구 방치에는 경보가 납니다.
- **증거:** deployment ID·owner·epoch·단계 이력, DDL/전송 호출 수, 잠금 복구 판단.

## R05 · 정기 교체 중 문의와 개발자 보충 보존

- **준비:** queued/running/needs_developer/awaiting_approval/post_unknown 문의와 신구 이미지, 시험 채널을 준비합니다.
- **절차:** 실제 drain→역할 종료→교체→진단→시험 채널 확인→재개를 수행합니다. drain 중 질문·결과 입력·직접 응대를 전달하고 종료기한 초과도 주입합니다.
- **합격:** 접수된 질문·보충·직접 응대를 보존합니다. 신구 worker/게시기가 동시에 활성화되지 않고 옛 결과는 거절합니다. 시험 게이트는 다른 질문을 큐에 보존하며 기존 승인 경계도 유지합니다. Socket 공백과 미수신 범위는 별도 기록합니다.
- **증거:** 단계별 역할/연결·접수·generation·게시 원장, 게이트 범위, 실제 중단 시간.

## R06 · migration 단일 실행·변조·실패

- **준비:** 실제 PostgreSQL의 지원 이전 schema, checksum이 있는 migration과 runtime/migration 별도 계정을 준비합니다.
- **절차:** migration 두 개를 동시에 시작하고 적용 중 오류·잠금 시간 초과·이미 적용한 파일 checksum 변경을 각각 주입합니다. 일반 runtime 계정으로 DDL도 시도합니다.
- **합격:** 단일 변경만 적용되고 부분 실패를 기록해 안전한 상태로 멈춥니다. 적용 파일 변조·미지원 schema는 차단합니다. runtime 계정의 DDL은 거절됩니다. 재개 여부를 실제 DB 상태로 판단합니다.
- **증거:** migration 기록·checksum·DB schema diff·권한 결과·시작 진단.

## R07 · 대량 backfill과 신구 데이터 호환

- **준비:** 운영 예상 규모의 합성 행, 구버전 reader, 새 필드와 배치 체크포인트를 준비합니다.
- **절차:** 추가→호환 쓰기→backfill 중단/재개→새 읽기→제거의 단계를 실행합니다. 병행 입력·null·새 enum·옛 카드도 포함합니다.
- **합격:** 중복 변환·누락·장기 잠금이 없고 정한 DB 부하 안에 있습니다. 읽기 전환 전 완전성을 확인합니다. 실제 구버전이 처리하지 못하는 값이 있으면 호환이라고 표시하지 않습니다. 제거는 복귀 기간 종료 후에만 허용합니다.
- **증거:** 원본/변환 건수·해시·체크포인트·잠금 지연, 구버전 처리 결과, 제거 preflight.

## R08 · 코드 복귀와 DB 복원의 분리

- **준비:** 직전 호환 이미지, 비호환 구버전, 배포 후 새로 접수·게시된 문의를 준비합니다.
- **절차:** 새 앱 실패로 호환 버전 복귀를 실행합니다. 비호환 버전 선택도 시도하고 별도 환경에서만 DB 복원 연습을 합니다.
- **합격:** 코드 복귀가 새 고객 데이터·게시 기록을 지우지 않습니다. 비호환 구버전은 시작 차단합니다. DB 복원은 독립 원장·삭제 정책을 대조하기 전 게시하지 않습니다. 이미 보낸 잘못된 답변은 별도 정정 대상으로 남습니다.
- **증거:** 복귀 전후 DB·문의 수·image digest, 차단 사유, 복원 원장 대조.

## R09 · 코드·지식·정책·비밀 갱신 분리

- **준비:** 각 변경 유형의 독립 revision, 진행 문의·세션·열린 지원 카드가 있습니다.
- **절차:** 코드만 배포, 지식만 fetch, 채널 권한 축소, 담당자 교체, 비밀 회전을 각각 실행합니다. 이전 설정 복귀도 시도합니다.
- **합격:** 코드 배포가 전체 재내재화·자동 publish를 유발하지 않습니다. 지식 갱신은 앱 빌드 없이 검증된 snapshot으로 적용합니다. 권한 철회는 즉시 읽기/게시 차단, 담당자 변경은 카드 권한과 동기화됩니다. 복귀로 철회된 권한·비밀을 되살리지 않습니다.
- **증거:** 유형별 revision·호출 수·session 무효화·권한 감사·구성 검증.

## R10 · 스킬·프롬프트·모델 변경도 배포 대상

- **준비:** Python 코드는 같고 스킬 또는 프롬프트만 바뀐 후보와 고정 평가 세트가 있습니다.
- **절차:** CI 변경 감지부터 실제 모델 평가·릴리스 묶음 생성까지 실행합니다. 운영 중 자동 플러그인 갱신·미평가 모델 fallback도 시도합니다.
- **합격:** 관련 모델 검사가 실행되고 필수 근거·간결성·존댓말·비용을 비교합니다. 운영 묶음은 자동 변하지 않습니다. 계약 변경 시 이전 세션·근거를 무조건 재사용하지 않고 모델 불가를 조용히 숨기지 않습니다.
- **증거:** path filter·평가 비교·bundle digest·실행 버전·오류 경로.

## R11 · 긴급 수정과 로컬 제품 회귀

- **준비:** 운영 버전의 결함 fixture, main에만 있는 무관한 미배포 기능, 격리 로컬 설치를 준비합니다.
- **절차:** 운영 커밋에서 hotfix를 만들고 검증·배포한 뒤 main에도 반영합니다. 스킬·로컬 봇·서버 의존성 경계를 검사합니다.
- **합격:** 긴급 이미지에 무관한 기능이 섞이지 않고 main에도 수정이 남습니다. 운영 서버 파일 수동 변경 없이 새 digest로 교체합니다. 로컬 사용자에게 PostgreSQL·서버 인증·추가 필수 설치가 생기지 않습니다.
- **증거:** 운영→hotfix→main diff, 새 이미지·회귀 결과 L01~L03, 릴리스 범위.

## R12 · 구축 실패와 복귀 산출물 보존

- **준비:** 비root 이미지·읽기 전용 마운트·서비스 자격, 레지스트리·볼륨·대상 아키텍처, 현재/복귀 이미지를 준비합니다.
- **절차:** 레지스트리 단절·digest 부재·잘못된 CPU 이미지·디스크 부족·비밀 공급자 실패를 각각 주입합니다. 오래된 산출물 cleanup도 실행합니다.
- **합격:** 사전 진단에서 실패하고 정상 실행을 가장하지 않습니다. 가능하면 기존 실행을 유지하며 이미 drain했다면 안전한 복귀/보류를 선택합니다. 마지막 호환 복귀 이미지·설정·migration·원장을 cleanup이 지우지 않습니다. 엔진은 호스트 소켓·다른 작업 자격에 접근하지 못합니다.
- **증거:** preflight·readiness·복귀 결정, 보관 manifest·cleanup 결과, 실제 권한/마운트 검사.

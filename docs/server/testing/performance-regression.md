# 성능·복구·기존 사용자 회귀 테스트

[공통 준비·출시 기준](README.md) · [운영 목표](../operations.md)

전부 `NOT_RUN`입니다. 서버가 빨라졌다는 결론은 아래 측정 후에만 내립니다. 파일 탐색이 빨라진 것과 AI까지 포함한 답변 시간이 줄어든 것을 구분합니다.

## 공통 측정 조건

- 장비 CPU/RAM·디스크, 컨테이너 제한, PostgreSQL 버전·설정, worker 수, 모델·스킬·코드 버전, 네트워크 조건을 고정합니다.
- 코퍼스 생성 seed·manifest·파일 크기 분포를 기록합니다. 1천·1만·10만 파일에 작은 파일·긴 문서·소스 연결이 많은 토픽·중복·정정을 섞습니다.
- 기준 커밋과 후보 커밋에 같은 데이터·질문·제한을 사용합니다. cold/warm을 구분하고 실제 모델 비용을 사전 한도 안에서 사용합니다.
- 로컬 결정적 연산은 조합별 warmup 1회 뒤 최소 5회, 실제 AI 전체 흐름은 질문 유형별 최소 3회로 시작합니다. 표본이 적으면 원자료·범위를 제시하고 p99를 안정적인 수치로 해석하지 않습니다.
- 접수·대기·검색·원본 읽기·AI 작성·검증·게시 시간, 읽은 파일/바이트, 토큰·비용, peak RSS·디스크·DB 대기, 실패율·중복·유실을 분리합니다.
- 시험 전에 회귀 허용치와 회사 답변 목표를 기록합니다. 미정이면 성능 출시는 `BLOCKED`입니다. 기존 제안인 ack p95 1초, RPO 15분·RTO 60분도 회사와 확정한 값을 사용합니다.

## P01 · 대량 지식의 증분 수신

- **준비:** 각 자료량에 변경 0개·10개·1%·전체인 별도 ref를 만듭니다. 첫 수신과 재수신을 분리합니다.
- **절차:** 조합별 fetch를 측정합니다. 중간 배치 실패 후 재개하고 검사기 버전 변경도 별도로 실행합니다.
- **합격:** 동일 커밋·동일 검사 계약은 의미 병합·본문 재작성 0건입니다. 10개 변경이 전체 의미 재내재화를 유발하지 않습니다. 전체 참조 무결성 검사는 비용에 포함해 보고합니다. 실패 후 완료 해시 재처리·누락이 없고 메모리 한도를 지킵니다.
- **증거:** 자료량×변경량×cold/warm 표, 단계별 시간·처리 수·해시, 재개 체크포인트. 전체 변경이 빠르다고 무조건 약속하지 않습니다.

## P02 · 검색 속도와 필요한 근거의 보존

- **준비:** 업무·코드·현재 DB·이미지·후속·개발자 보충 질문 각각에 필수 claim/source 정답 집합을 작성합니다. 비슷한 제목의 오답 문서를 많이 섞습니다.
- **절차:** 자료량별 검색과 답변을 기준/후보에 실행합니다. 관련 조건·예외가 본문 뒤쪽 또는 다른 소스에 있는 변형을 포함합니다.
- **합격:** 필수 근거가 후보 검색과 실제 조사에서 누락되지 않습니다. 입력 토큰 감소만으로 합격시키지 않습니다. 필요한 코드/DB 조회·정확도를 유지한 상태에서 시간·읽기량·비용을 비교합니다. 질문 전체가 느리면 느린 단계를 특정합니다.
- **증거:** 질문별 필수/검색/실제 읽은 source 집합, 주장 대조, 단계별 분포와 기준 대비 변화.

## P03 · 병렬 처리·과부하·공정성

- **준비:** 동시성 1·2·4·8, 같은 스레드 집중/여러 스레드 분산, 빠른/느린 원본 혼합 부하를 만듭니다. 먼저 fake 엔진으로 런타임을 측정하고 승인된 한도에서 실제 모델을 별도로 측정합니다.
- **절차:** 낮은 부하부터 올려 대기열 상한·예산 한도·제공자 rate limit까지 도달시킵니다. 한 사용자가 질문을 집중해도 다른 사용자가 처리되는지 확인합니다.
- **합격:** 저장 후 ack p95는 확정 목표 이내이며 Slack ack 제한 초과 건수를 별도 보고합니다. 전역 동시성·스레드 직렬성이 유지되고 과부하는 명시적으로 거절합니다. 예산 초과 시작·접수 후 유실·중복 게시가 없습니다. 다른 스레드가 무기한 굶지 않습니다.
- **증거:** 입력/접수/거절/완료/대기 건수의 대응, queue age, 실행 구간, ack·완료 시간 분포, 실제 비용·한도.

## P04 · 장시간 실행과 자원 정리

- **준비:** 결정적 fake 부하로 최소 8시간, 제한된 실제 회사 파일럿으로 지원 시간대를 포함한 1영업일 계획을 잡습니다. 실제 모델 호출 수·예산 상한을 먼저 정합니다.
- **절차:** 질문·첨부·세션·갱신·정리 작업을 반복하고 일부 timeout·DM 실패·재연결을 섞습니다. 마지막에 부하를 멈추고 정리 기한까지 기다립니다.
- **합격:** 문의·전송 건수가 대응하고 유휴 후 활성 job·연결·예산 예약이 남지 않습니다. 미확정 비용/전송은 예외 원장으로 설명됩니다. 임시 파일·세션·메모리가 상한 없이 증가하지 않습니다. 정리가 진행 문의의 자료를 지우지 않습니다.
- **증거:** 시간별 RSS·연결·파일·캐시·queue·미확정 항목 추이와 누수 조사. fake 8시간 결과를 실제 모델 안정성으로 표시하지 않습니다.

## P05 · 배포·복원·되돌리기 연습

- **준비:** 완료·진행·승인 대기·내부 도움·직접 응대·불명 전송이 섞인 격리 서버와 실제 백업을 준비합니다. 직전 호환 버전과 스키마 호환 범위를 고정합니다.
- **절차:** drain→업데이트→재개, 중간 실패→되돌리기, 별도 환경에 백업 복원을 각각 수행합니다. 스키마를 모르는 구버전도 시작시킵니다.
- **합격:** 수신·게시 중단과 복구 시간이 확정 목표 안에 있습니다. 구버전은 안전하게 차단하거나 검증한 호환 절차로만 실행합니다. DB·원장·권한 대조 전 게시하지 않고, 알려진 접수 이후 손실 범위·전송 불명은 숨기지 않습니다.
- **증거:** 실제 사용한 배포/복원 명령, 시작·종료 시각, 백업 시점, RPO/RTO 계산 근거, 문의/전송 대조, 되돌리기 결과.

## L01 · 서버 없는 기존 스킬 사용자

- **준비:** 별도 임시 HOME의 호스트 설정·합성 원본·지식, 서버 주소·PostgreSQL 없음. 실제 개인 홈은 사용하지 않습니다.
- **절차:** 새 설치와 이전 버전에서 업데이트를 각각 수행합니다. connect→ask→선택 publish→다른 로컬 fetch를 실행합니다. 모델이 필요하면 승인된 합성 평가 범위에서 실행합니다.
- **합격:** 서버 설치·인증·Python을 지식 스킬의 신규 필수 조건으로 만들지 않습니다. 기존 경로·설정·정정·공유 형식을 보존하고 ask 출처가 유지됩니다. 원본 업무 데이터는 수정하지 않습니다.
- **증거:** 설치 전후 파일 diff·의존성·출처 답변·Git 전송 범위.

## L02 · 로컬 봇의 업데이트와 기존 상태

- **준비:** 기존 지원 macOS 환경의 격리 봇 home, fake Keychain·Slack·엔진, 모든 상태를 가진 합성 DB·원장. 현재 배포 wheel을 비교 기준으로 둡니다.
- **절차:** 새 코드로 기존 설정을 읽고 시작/상태/중지/채널 추가를 확인합니다. 기존 문의·옛 카드·명시적 승인 모드도 실행합니다.
- **합격:** 로컬 SQLite·기존 설정이 계속 동작하고 서버 PostgreSQL·클라우드 비밀 저장소를 강제하지 않습니다. 자동/승인/직접 응대 경계와 중복 방지가 유지됩니다. 실제 키체인을 열지 않습니다.
- **증거:** 설정·스키마 이전 diff, 기존 bot 회귀 검사, 패키지 격리 설치·wheel 소스 일치 결과. 회사 실연동은 U 사례로 따로 확인합니다.

## L03 · 배포물과 자료 공유 호환

- **준비:** 구버전 공유 패키지, 새 패키지, 양쪽 수정·민감정보 거절 사례, 정본·배포 사본을 준비합니다.
- **절차:** 구→신 fetch, 신→신 publish/fetch, 실패 후 재개와 충돌 보존을 검사합니다. 신→구는 지원 계약이 있으면 실행하고 없으면 안전한 비호환 진단을 확인합니다.
- **합격:** 지식 정본과 출처·정정은 보존됩니다. 서버 DB·캐시·세션·조회 원시 결과가 공유 패키지에 섞이지 않습니다. 스킬 정본/사본·플러그인·wheel·문서 링크·민감정보 검사도 통과해야 합니다.
- **증거:** 패키지 manifest·파일 해시, 전송 diff·호환 결과, 기존 저장소 검사 로그.

## 기록할 결과

`execution-template.json`의 해당 사례 `runs`에 아래 항목을 포함합니다. 보고서의 집계값에서 원 측정으로 돌아갈 수 있어야 합니다.

```text
run_id, test_id, variant, status, actual_command
baseline_commit, candidate_commit, environment_id, corpus_hash, seed
sample_count, cold_or_warm, elapsed_ms, peak_rss, bytes_read
stage_timings, input_tokens, output_tokens, external_calls, actual_cost
expected, observed, evidence_location, defects, limitations
```

전체 평균으로 느린 질문·실패를 숨기지 않습니다. 성능 변경이 근거 누락을 만들면 속도가 빨라도 실패입니다. 최종 출시 범위에는 확인한 최대 동시성·자료량·허용 비용과 아직 측정하지 않은 범위를 함께 씁니다.

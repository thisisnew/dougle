# 실행 전 CLI 버전 관측 이력 (SQLite v6)

2026-10-21. 비동기 AI 작업에 실행 전 CLI 버전 관측을 추가했습니다.
[요청 모델 이력](model-selection.md)과 별개이며, 실제 실행 모델 ID를 추정하는 기능이 아닙니다.

## 실행 흐름과 경계

승인 검증 → 작업 접수 → RUNNING → 로컬 `--version` 관측 → 관측 저장 →
근거/승인 재검사 → CLI 생성 → 별도 DRAFT/작업 완료 순서입니다.
승인 없는 요청·잘못된 digest에는 관측도 실행하지 않습니다.
동일 작업 ID 재전송, 화면 조회, 앱 재시작은 관측을 다시 실행하지 않습니다.
호환용 동기 생성 API에는 작업 이력이 없어 이 기록 기능을 적용하지 않습니다.

관측은 기존 `CliDiagnostics` 포트를 사용합니다. 문서나 프롬프트를 전달하지 않고
5초 실행 제한, 최대 2초 프로세스 정리, 출력 제한·환경 allowlist를 유지합니다.
모델 생성 자체의 120초 제한과는 별도이므로 작업 전체 시간은 늘어날 수 있습니다.
관측 동안 SQLite 트랜잭션과 작업 잠금을 잡지 않아 취소·조회가 가능합니다.

관측 실패나 수동 진단과의 경합은 아래 상태로 기록하고 승인된 생성을 계속합니다.
그러나 관측 이력을 DB에 저장하지 못하면 **모델 호출 전에 FAILED**로 중단합니다.
취소가 관측 저장보다 먼저면 늦은 관측값을 폐기하고 모델을 호출하지 않습니다.
관측 저장 이후 생성 실패/취소가 발생해도 이미 기록한 관측값은 유지합니다.

## API와 저장 모델

Job 조회/목록에 세 필드를 추가했습니다.

| 필드 | 의미 |
|---|---|
| `cliVersion` | 정제한 버전 식별자. 확인하지 못했으면 null |
| `cliVersionStatus` | AVAILABLE / UNAVAILABLE / UNRECOGNIZED / BUSY / NOT_CHECKED |
| `cliCheckedAt` | 관측 시도가 끝나 기록한 UTC 시각. 기록 없으면 null |

- AVAILABLE: 알려진 형식의 `--version` 응답을 관측함.
- UNAVAILABLE: 실행·시간 제한·예상 밖 진단 실패. 오류 원문은 저장하지 않음.
- UNRECOGNIZED: 버전 응답 또는 포트에서 받은 식별자를 안전하게 해석하지 못함.
- BUSY: 다른 로컬 진단이 진행 중이라 이번 관측을 건너뜀. 자동 재시도하지 않음.
- NOT_CHECKED: 과거 작업, 아직 관측 전, 관측 중 취소 등으로 완료된 기록이 없음.

버전은 길이·문자 형식을 다시 검사하며 인증 정보/표준 출력/오류 원문을 이력에 저장하지 않습니다.
작업 목록 UI는 **실행 전 CLI 관측**으로 표시하며 설치 진단의 현재 버전과 구분합니다.
DB 갱신은 RUNNING이고 이전 관측 시각이 없을 때만 가능합니다. 완료 작업을 다시 덮어쓰지 않습니다.

v5→v6 마이그레이션은 generation_job에 위 세 열만 추가합니다.
기존 요청 모델/작업 ID/digest/결과를 보존하고 과거 관측은 NOT_CHECKED/null/null로 남깁니다.
진행 중 작업을 INTERRUPTED로 복구할 때 기존 관측값도 유지합니다.
v6 DB를 구버전 앱으로 열면 거부하므로 업그레이드 전에 데이터 디렉터리를 백업하세요.

## 보장하지 않는 것과 다음 작업

관측과 생성은 별도 프로세스입니다. 두 실행 사이 CLI 파일/PATH가 바뀔 수 있으므로
이 값은 **생성 프로세스의 정확한 바이너리 버전을 증명하지 않습니다**.
실제 실행 모델 ID·토큰 사용량·바이너리 해시·인증/원격 연결 성공도 증명하지 않습니다.
실행 모델이 보고되지 않으면 계속 미확인으로 표시합니다. 요청 모델을 실제 모델로 복사하지 않습니다.
OS 수준 강제 종료/고아 프로세스 감독과 실제 CLI 호환 버전 확대는 남아 있습니다.

다음 핵심 기능은 P3-3 사람 검토 기반 검증·게시입니다. 초안/검토/게시를 분리하고
근거 최신성·편집 충돌·검토 대상 버전을 고정하며 실패 시 이전 게시본을 유지해야 합니다.
인용 ID 존재나 사람이 확인 버튼을 눌렀다는 사실을 자동 의미 검증으로 과장하지 않아야 합니다.

## 검증 범위

가상 진단/자료로 승인 전 무호출, 생성 전 기록, 진단 실패·경합·오염된 버전,
관측 중 취소, DB 기록 실패 시 모델 무호출, 완료 기록 비덮어쓰기,
v1~v5→v6 보존과 재시작 복구를 테스트합니다.
실제 JAR smoke도 명시적으로 주입한 fake CLI를 사용하며 실제 외부 AI 성공으로 간주하지 않습니다.
실계정 AI 호출과 수동 브라우저 QA는 이번 검증 범위에 포함하지 않습니다.

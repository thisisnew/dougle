# CLI 모델 고정과 로컬 설치 진단

이 문서는 최초 구현 기록입니다. 후속 [건별 모델 선택·요청 모델 이력](model-selection.md)에서
설정 UI와 요청별 모델, SQLite v5 영속 이력을 추가했습니다. 아래 v4/설정 UI 미구현 설명은 당시 범위입니다.

2026-10-21 추가. P3-2 운영 기능의 일부이며 검증·게시·채팅 구현은 아닙니다.

## 사용 방법

앱 시작 시 `--forge.ai.codex-model=모델식별자` 또는
`--forge.ai.claude-model=모델식별자`를 `bash scripts/run.sh` 뒤에 전달합니다.
현재 로그인 계정에서 사용할 수 있는 식별자를 직접 지정합니다. 모델 목록이나 이용 가능 여부를 추측하지 않습니다.
기본값은 빈 문자열이며 이때 CLI에 `--model`을 전달하지 않습니다.
Codex는 기존 보안 설정대로 `--ignore-user-config`를 사용하므로 사용자의 일반 CLI 설정 파일 모델을
반드시 물려받는다는 의미가 아닙니다. 실제 선택 모델은 아직 확인하지 않습니다.

설정은 시작 시 검증한 뒤 프로세스 수명 동안 고정합니다. 변경하려면 앱을 재시작하세요.
모델 ID는 영문/숫자로 시작하고 영문/숫자 및 `._:/-`만 허용하며 최대 128자입니다.
CLI 옵션·셸 명령은 입력할 수 없으며 모델은 단일 argv 값으로 전달됩니다.
설정 오류에는 입력 원문을 포함하지 않습니다. UI에서 설정을 저장하는 기능은 아직 없습니다.

지식 카드의 **전송 내용 미리보기**에 요청 모델이 표시됩니다.
승인 digest는 기존 Workspace/카드/버전/Provider/전송 내용에 더해 요청 모델도 포함합니다.
모델 설정을 바꾼 서버에서는 이전 미리보기로 새로운 생성 작업을 접수할 수 없습니다(409).
이 변경 전 미리보기도 다시 승인해야 합니다. 이미 접수된 동일 작업 ID는 기존 이력을 반환하며 재실행하지 않습니다.
빈 모델 또는 별칭은 제공자가 실제 모델을 바꿀 수 있으므로 재현 가능한 실제 모델 고정으로 간주하지 않습니다.

생성된 불변 v1 Markdown에는 서버가 요청 모델, 실제 모델 미확인 표시, 승인 digest를 추가합니다.
이 정보는 AI 출력이 아니라 서버가 작성합니다. 사람 편집은 여전히 별도 버전입니다.
이는 성공 결과의 기본 추적 정보이며 실패/취소 작업의 모델·CLI 버전을 구조화한 영속 이력은 아직 아닙니다.
DB 스키마는 v4로 유지됩니다.

## 설치 진단

**CLI 설치 확인** 버튼을 눌렀을 때만 서버에서 설정된 CLI의 `--version`을 실행합니다.
자동 진단이나 모델 호출, 문서 전송, 인증 파일 읽기는 하지 않습니다.
별도 임시 디렉터리·빈 stdin·환경 변수 allowlist·출력 크기 제한을 적용합니다.
5초 실행 제한 및 최대 2초 프로세스 정리 시간을 가지며 한 번에 진단 하나만 실행합니다.
문서 생성과 진단의 슬롯은 서로 독립적입니다.

- `AVAILABLE`: 알려진 형식의 버전 응답. 해당 버전의 모든 옵션 호환성을 보장하지 않습니다.
- `UNRECOGNIZED`: 종료는 성공했지만 버전 출력 형식을 인식하지 못함.
- `UNAVAILABLE`: 실행 실패/비정상 종료/시간 제한/출력 제한 등. 미설치로 단정하지 않습니다.
- 인증은 항상 `UNKNOWN`, 원격 연결은 항상 `NOT_CHECKED`입니다.

버전 문자열만 allowlist 형식으로 반환하고 stdout/stderr 원문, 실행 경로, 로그인 정보는 노출하지 않습니다.
브라우저에서 요청을 취소해도 진단 프로세스는 자체 제한 시간까지 실행될 수 있습니다.
설치된 실행 파일 자체는 신뢰 경계이며 악성 CLI의 네트워크 접속을 OS 수준으로 차단하는 기능은 아닙니다.

## 검증 범위와 다음 작업

실행 환경: macOS Intel / Java 21.0.10 / Node 24.2.0.

| 실행 | 결과 |
|---|---|
| 핵심 4개 테스트 클래스 지정 Maven test | 35개 통과 |
| `bash scripts/maven.sh clean verify` | 85개 통과, live opt-in 1개 skip, 실행 JAR 빌드 성공 |
| `npm --prefix frontend test` | 26개 통과 |
| `npm --prefix frontend run build` | TypeScript/Vite 성공 |
| `node scripts/smoke.mjs` | 실제 JAR 진단/모델 설정/추적 정보/작업 생성·취소·멱등·재시작 검증 통과 (fake CLI) |
| `node --check scripts/smoke.mjs`, `sh -n scripts/fixtures/fake-codex.sh`, `git diff --check` | 성공 |

초기 프런트엔드 실행에서 새 테스트의 beforeEach가 mock 함수를 반환하여 cleanup으로 실행되는
문제로 hook timeout 1건이 발생했습니다. 반환하지 않는 블록으로 고친 뒤 전체 26개를 재실행해 통과했습니다.
설치된 CLI의 로컬 `--help`에서 양쪽 `--model` 인자를 확인했고,
`--version`은 Codex 0.163.0 / Claude Code 2.1.31로 확인했습니다. 이는 원격 생성 성공 확인이 아닙니다.

smoke 측정(2026-10-21T11:12:58Z): 시작 19,272ms, 재시작 22,912ms,
목록 p95 9.83ms, 검색 p95 31.87ms. 원본 측정값은 `performance-phase3-foundation.json`에 있습니다.
가상 파일 100개 순차 HTTP 측정이며 모델 추론·대규모 동시 처리 성능이 아닙니다.

테스트는 가상 실행 파일로 모델 인자 전달, 승인 digest 변경 차단, 성공 초안 추적 정보,
버전 응답 정제, 타임아웃, HTTP 헤더/Provider 검증, UI 명시적 진단/늦은 응답 폐기를 확인합니다.
실제 JAR smoke도 명시적으로 주입한 fake CLI만 사용하며 실제 AI 추론 성공으로 간주하지 않습니다.
실제 CLI 로그인/모델 이용 가능성, 실계정 생성, 브라우저 수동 QA는 이 변경의 자동 테스트 범위가 아닙니다.

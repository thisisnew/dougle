## 연결된 기능

- 후속 계획 binding V4는 SEARCH/STOP 외에 `PROPOSE_MYSQL_READ`/`PROPOSE_DATADOG_LOGS`를 지원한다. 제안은 실행기가 아닌 읽기 전용 DTO로 전달하며 `executionAllowed=false`다. 사용자가 누른 경우에만 빈 수동 조회 양식을 열고 연결 상태를 확인한다. 환경·SQL·범위 추정이나 자동 운영 조회·자동 첨부는 하지 않는다. 제안 복원/폴링만으로 양식을 열지 않으며 다른 질문으로 이동하면 기존 양식과 늦은 응답을 폐기한다. 일반 설명·코드 관계·모호한 의도는 로컬 검색/종료 정책을 유지하며 이 정책의 모든 실제 의미 판단이 검증됐다는 뜻은 아니다.

- 조회 결과 첨부에는 서버에 보관된 승인 범위도 포함한다. MySQL DB/테이블/열/조건과 Datadog 환경/서비스/인덱스/UTC 시간 범위를 알려진 비밀정보 마스킹 후 고정하며 전체 첨부는3,000자, 범위는1,400자로 제한한다. 잘리거나 마스킹된 조건은 추정하지 않도록 표시하고 정확한 미리보기 bytes와 저장본 해시를 대조한다. 범위가 바뀌면 같은 행 결과라도 이전 동의로 저장하지 않는다.

- DB v27은 격리 브라우저 조사 기록, 자료·대화 아카이브 가져오기 영수증, Slack 수신함·채널 배치·중복 이벤트·대화 연결을 추가한다. 기존 사용자 DB에는 아직 적용하지 않았다.
- 플러그인의 `Slack 문의`는 Socket Mode 수신을 Workspace에 배치하고 명시적으로 대화에 저장한다. 수신만으로 AI·운영 조회·Slack 답변 전송을 하지 않는다. 수신 기록은 로컬 DB에 보관하며 연결된 Workspace의 미처리 건수를 설정 버튼에 표시한다. 현재 관리자용 앱/봇 토큰 설정이며 고객용 브라우저 OAuth 완료가 아니다. 실제 Slack 조직 검증은 아직 없다.
- **과거 구현 이력 — 현재 게시 금지/차단:** 읽기 전용 정책 이전 DB v28 스냅샷에는 Slack 답장 게시 UI/API와 영속 영수증을 구현했었다. 당시 최대4,000자 본문·대상 미리보기와 일회 승인, SENDING→UNCERTAIN 재시작 복구, 멘션 거부·채널/thread_ts 검증을 적용했다. 이 게시 경로는 현재 제거·차단됐으며 승인해도 사용할 수 없다. 기존 영수증만 읽기 전용으로 보존한다. 당시 실제 Slack 게시·권한·OAuth 및 E35 인수 통과를 확인한 것은 아니다. [과거 게시 계약과 한계](slack-reply-runtime.md)는 현재 기능 안내나 실행 허가가 아니다.
- `Datadog 로그`는 Workspace별 암호화한 연결과 명시적 환경·서비스·인덱스·시각 범위 미리보기/실행을 제공한다. 최대 50건·16 KiB·10초이며 결과의 알려진 인증정보 패턴을 가리고 잘림을 표시한다. 자동 AI 전송/재실행하지 않는다. 현재 관리자용 키 설정이며 실제 계정·OAuth는 미검증이다.
- 대화의 브라우저 조사는 새 임시 Chrome/Chromium 프로필에서 승인한 공개 HTTPS 페이지와 정확한 GET 경로만 렌더링한다. 기본 사용자 프로필·쿠키·로그인을 사용하지 않고 다른 요청은 차단한다. 렌더링한 글과 요청 경로/상태를 로컬로 표시하며 AI에 자동 전송하지 않는다. 실제 Chrome과 가상 웹 응답으로 렌더링 검사를 했지만 회사 로그인 화면·MFA 연결이나 브라우저 동봉 설치가 완성된 것은 아니다.
- 팀 설정 아래 자료·대화 ZIP 내보내기/가져오기는 지원 가능한 원본 복사본·대화·근거·완료 답변을 새 Workspace에 원자적으로 복원한다. ID/근거 digest를 다시 계산하고 로컬 색인을 재구성한다. 요청/미리보기 영수증은 재시작과 대상 Workspace 삭제 뒤에도 남겨 중복 적용을 막는다. 파일당 1 MiB·전체 ZIP 9 MiB·자료 63개 제한이며 질문 첨부·이전 지식 문서 등 미지원 내용이 있으면 누락시키지 않고 거부한다. 연결·인증·실행 승인은 이전하지 않는다. 임의 본문의 개인정보를 자동 제거하거나 ZIP 발행자 진위를 보증하지 않는다.

- 추가 작업본은 대화의 `자료 더 찾아보기`에서 별도 검색 계획 미리보기·명시적 실행·진행 조회·취소를 제공한다. 계획 AI 1회가 `SEARCH` 또는 `STOP`을 고르고, 코드는 등록된 로컬 Workspace 검색을 최대 1회만 실행한다. 검색 결과는 자동으로 모델에 다시 전송하지 않는다.
- `이 자료로 다시 답변`은 검색어로 현재 원본을 다시 조회해 **새 대화 턴과 새 불변 근거**를 만든 뒤 기존 답변 미리보기·새 승인·일회 실행 경로를 사용한다. 이전 승인이나 근거를 덮어쓰지 않는다. 후속 V3 배치 3에서 NO_EVIDENCE → SEARCH → 로컬 검색 → 캡처 → 새 승인 → 답변 경로를 실제 검사했다. 제한된 가상 자료 결과이며 앞선 30회 평가에 포함하지 않는다. 다른 시나리오의 시간 초과와 미실행 범위는 별도로 남아 있다.
- 계획 작업은 DB v26의 `investigation_plan`에 실행 전 저장한다. 승인 범위는 근거·문맥·제공자·모델 연결·도구 종류·예산에 고정하며, 재시작 시 미완료 작업은 실패 처리하고 자동 재전송하지 않는다. 텍스트 근거 또는 `NO_EVIDENCE` 질문을 지원한다. 검색 결과가 없어도 질문·이전 문맥만으로 새 검색어를 제안받되, 답변은 새 검색으로 확보한 근거와 별도 승인을 요구한다. 변경된 기존 근거·이미지는 계속 거부한다. 현재 미리보기 바인딩은 운영 도구 제안을 포함한 V4이며, 위 V3 배치 평가는 이전 바인딩의 실행 이력이다.

- MySQL 연결 후 플러그인 화면의 `DB 데이터 조회`에서 테이블·열·일치 조건을 지정하고 실제 호스트/DB를 확인한 뒤 읽는다. 조건 없는 전체 조회와 인증정보 이름의 열은 거부하고, 서버 읽기 전용 트랜잭션·고정 식별자·매개변수 조건을 사용한다. 화면 최대 20행, API 최대 50행·16 KiB·10초이며 출력은 자동 AI 전송하지 않는다. 같은 미리보기/요청은 중복 실행하지 않고 연결 변경·취소 후 늦은 결과를 폐기한다. 현재 조회 미리보기/결과는 앱 메모리에만 있으므로 재시작 후 복원되지 않으며 새 동의가 필요하다. 실제 DB 계정 검사는 아직 하지 않았다. 열 이름 필터가 임의 행 내용의 모든 비밀/개인정보를 탐지한다고 보장하지 않는다.

- 완료된 MySQL/Datadog 조회 결과는 `operational-captures`의 별도 미리보기에서 출처·조회 시각·부분 보관 표시를 포함한 정확한 저장 내용을 확인한 뒤 명시적으로 로컬 질문 첨부로 저장한다. 본문은 최대 3,000자이며 마스킹이 모든 비밀정보를 제거한다고 보장하지 않는다. 미리보기/영수증 조회는 세션 한정이고 미리보기는 5분 후 만료된다. 저장 자체는 외부 조회·AI 호출을 하지 않는다. `OperationalCapturePanel`은 미리보기 ID/digest와 동의를 보내고 불확실한 접수 또는 RUNNING/PREVIEW 상태는 GET으로만 확인하며 POST를 자동 재실행하지 않는다. FAILED는 종료 상태다. CAPTURED의 ID·text/plain·크기·문자 수·외부 호출 0회를 검사한 뒤 첨부를 전달한다.
- 대화 안의 `운영 자료 조회`에서 전달한 첨부는 현재 작성창에 놓이며 기존 thread와 마지막 parent를 유지한다. 사용자가 후속 질문을 전송할 때 attachment ID를 포함해 새 턴을 만들고 기존 새 근거·답변 승인 경로로 진행한다. 설정의 플러그인에서 전달하는 새 질문 경로와 구별한다. 첨부 전달만으로 AI를 호출하지 않으며 다른 Workspace 결과를 거부하고 운영 작업 중 작성창을 잠근다. 이는 소스 연결과 가상 API 경계 검사 범위이며 실제 MySQL/Datadog → 저장 → 실제 모델 답변 전체 경로의 인수 통과를 뜻하지 않는다.

- `ChatPanel → ChatThreadController → ChatThreadService`가 질문을 thread ID와 parent bundle ID로 연결한다. 질문 기록은 턴별 행이 아니라 대화별 행이며, 다시 열면 해당 대화의 질문·답변을 복원한다. 삭제도 대화 전체를 대상으로 한다.
- DB v25의 불변 근거 JSON에 선택 필드 `chatContext`를 추가한다. 과거 JSON은 원래 digest 그대로 읽는다. 과거 질문은 별도 대화로 표시하고 이어갈 수 있다. 임의로 기존 질문들을 하나로 합치지 않는다.
- 같은 요청 ID의 재전송은 같은 근거를 반환한다. 내용 변경, 오래된 parent, 다른 Workspace ID, 활성 답변 중 추가/삭제는 거부한다. 턴 순서는 벽시계가 아닌 parent 연결로 복원한다.
- 최근 다섯 턴의 질문과 완료 답변 일부를 다음 답변의 미리보기에 포함한다. 이전 근거 ID/digest를 재검사하고 현재 prompt/승인 digest에 문맥을 결합한다. 과거 답변은 신뢰할 근거가 아닌 대화 참고문이며 과거 인용 번호를 현재 출처로 재사용하지 않는다.
- 대화 재열기·자료 수집·질문 기록 조회로 외부 AI를 자동 호출하지 않는다. 기존 일회 승인·모델 고정·작업 멱등성 계약을 유지한다.
- 기록 검색은 제목뿐 아니라 같은 대화의 후속 질문도 찾으며 결과는 대화당 한 행을 유지한다. 이전 근거 단건 삭제의 검사/삭제를 같은 트랜잭션으로 묶고 동시 이어 질문과의 경쟁 상태를 검사한다.
- 답변 전송 직전에 Workspace/근거 ID·digest·제공자/모델에 묶인 요청 식별자를 `sessionStorage`에 기록한다. 같은 탭/동일 origin 재로딩 후 불확실한 접수는 같은 요청 ID로만 수동 재확인하며 새 작업으로 자동 재전송하지 않는다. 질문/답변/인증 비밀은 여기에 저장하지 않는다. 앱 재시작·origin 변경까지의 보장은 아니며 이미 수락된 작업은 서버 이력에서 복원한다.
- 전송 전 확정적으로 실패한 질문은 이력을 보존한 채 명시적으로 새 대화를 시작할 수 있다. 접수 여부가 불확실하면 먼저 재확인해야 하며 활성 작업·조회 실패·불일치 저장 정보에서 임의로 해제하지 않는다.

## 검색 문맥의 남은 한계

현재 후속 검색은 일부 지시 표현을 인식해 앞 검색어를 붙인 검색과 현재 질문 단독 검색을 교차 병합하는 초기 구현이다. AI 의미 해석·엔티티 추적·주제 전환 분류가 완성된 것이 아니다. `그럼`으로 시작한 명시적 새 주제에도 과거 검색어가 섞일 수 있다. 최근 다섯 턴, 답변당 800자 제한 때문에 오래된 대상 정정을 보존한다고 보장할 수 없다. 이 제한은 E01–E05 통과로 집계하지 않는다.

Workspace당 기존 근거 100개 제한도 유지한다. 대화 전체를 매번 읽는 초기 저장 구조이므로 대규모 이력에는 전용 thread/turn 인덱스와 페이지 조회가 필요하다. 긴 prompt는 기존 20,000자 경계에서 거부되며 조용히 안전 검증을 생략하지 않는다.

## 실행 코드와 외부 도입

`ConstrainedToolExecutor`는 등록된 typed tool만 실행하고 Workspace/환경/scope를 정확히 대조한다. 호출 횟수·전체/개별 시간·출력량·중복 호출·취소를 제한하며 예외 본문을 결과에 노출하지 않는다. 이는 Java 내부 실행 제한이며 OS sandbox가 아니다. 어댑터가 읽기 전용 권한·취소·개인정보 최소화를 보장해야 한다. 임의 shell 실행은 등록하지 않는다.

HolmesGPT는 현재 앱의 Codex/Claude CLI 로그인을 그대로 쓰는 엔진이 아니다. LiteLLM 모델 API 인증·런타임·종속성 검토가 필요하므로 사용자의 인증 방식을 임의로 바꿔 도입하지 않았다. [고정 소스/라이선스와 호환성 감사](expert-upstream-audit.md)를 참고한다. 고정 원문 6개/4개 프로젝트를 동봉했으며, upstream 프로그램/스킬을 설치·실행한 것으로 표시하지 않는다.

Slack 수신함, Datadog 읽기 조사, 운영 DB의 제한된 읽기 조회, 격리 브라우저 조사는 각각 명시적인 UI/API 경로에 연결되어 있다. 이 기능들은 AI 계획의 자율 도구 목록에 연결된 것이 아니며 수신·조회 결과를 자동으로 AI에 보내지 않는다. 과거 Slack 외부 답변 전송 경로는 최신 읽기 전용 정책에 따라 차단했고 기존 영수증만 보존한다. 자동 역할 위임은 구현하지 않았다. 로컬 검색 계획은 한 번의 선택과 실행이며 자율적인 다중 조사 루프가 아니다. 도구 실행 단위 테스트는 실제 서비스 인수 통과가 아니다.

`LocalToolExecutorFactory`는 Workspace 한 개에만 바인딩된 원본 검색 도구를 생성한다. 입력 길이·Workspace 존재·호출 전후 취소를 확인하고 실제 `SearchService`를 호출한다. 원본 경로/URL 대신 가상 `entries/<UUID>` 위치와 제한된 발췌문을 반환하며 잘린 결과는 표시한다. 별도 승인된 추가 검색 계획에서 이 도구를 사용한다. 본문 자체의 민감정보 제거는 별도 구현이 필요하다.

`MysqlReadClient`/`MysqlReadTool`은 임의 SQL 대신 명시적으로 허용한 테이블·열·동등 조건·행 제한만 받는다. 서버 읽기 전용 트랜잭션, prepared 값, 메타데이터 검사, 뷰·생성 열·시스템 스키마 거부, 출력/시간 제한을 구현했다. JDBC 대역 25개 검사를 통과했으나 현재 AI 계획 도구 목록에 등록하지 않았고 실제 DB 접속 검증도 하지 않았다. 연결 설정만으로 운영 조회를 승인했다고 간주하지 않는다.

## 설정·자료 이전의 기반 구현

- `GET /api/team-settings/export/{workspaceId}`는 Workspace 표시 이름, 기본 갱신 간격, 자료 표시 이름/종류만 반환한다. 인증정보·기존 ID·DB 주소·로컬 경로·URL 전체를 제외한다. 경로에 접근 토큰이 포함될 수 있어 URL도 자동 공유하지 않는다. 표시 이름에 사용자가 입력한 비밀정보가 없는지는 공유 전에 검토해야 한다.
- 설정의 `팀 설정` 화면에서 JSON 내보내기·파일 가져오기를 제공한다. `POST /api/team-settings/import-preview`는 256 KiB/100자료 제한, 정확한 필드·형식·버전을 검증하고 충돌/이름 변경/위치 재지정/재연결 필요를 보여준다.
- `import-plan`에서 새 Workspace 이름·자료 이름·이 PC의 위치를 확인하고 `import-apply`에서 새 Workspace만 원자적으로 생성한다. `team_settings_import_receipt`에 요청 식별자를 남겨 같은 요청의 재전송·재시작에 중복 생성하지 않는다. 기존 Workspace를 덮어쓰지 않으며 자동 갱신은 끈다. 동기화·AI·인증은 자동 실행하지 않는다. MySQL 연결은 복사하지 않고 플러그인 재연결 후 자료를 직접 추가해야 한다. 실제 다른 사람의 PC/계정 검증은 별도이며 E49 전체 통과로 집계하지 않는다.
- `transfer.domain`의 아카이브 코덱은 UUID 문서·v1 manifest·SHA-256, 개수/압축/해제 크기 한도 및 허용 경로를 검사한다. 코덱 자체는 파일시스템에 추출하지 않으며 현재 별도 애플리케이션 경로가 지원 자료·근거·대화·완료 답변을 새 Workspace에 원자적으로 복원한다. 보수적인 한도와 미지원 항목 거부를 유지한다. 발신자 인증·암호화·문서 내 비밀정보 제거를 보장하지 않는다. [코덱 범위](../backend/src/main/java/dev/knowledgeforge/transfer/domain/README.md)와 위 자료·대화 이전 범위를 구별한다.

## 검증과 재현

현재 결과는 상단의 읽기 전용 소스/UI 회귀 범위를 따른다. E05 오프라인 평가 하네스36개 검사를 통과했지만 모델/JAR는 실행하지 않았다. 단일 변형64dispatch 상한·매 턴 의미 검토·정확한 문맥 식별자/8k 예산·실제 생략량을 검사하며, 정정 누락은 모델 오답이 아닌 fixture 무효로 기록한다. 실제 압축 관측 없이 긴 창 유지만으로 E05를 승격하지 않는다. 새 아티팩트·유한 승인 전까지 실제 시험은 보류한다.

# AI 실행 도구 자동 탐색

0.1.33부터 사용자가 실행 경로를 알아야 하는 흐름을 기본으로 제공하지 않는다.

- 저장된 실행 경로가 없고 기본 명령이 단순 `claude`/`codex`이면 설치된 도구를 탐색한다. 후보가 하나면 자동 사용한다. 명시된 실행 경로·번들 Codex·저장된 선택은 덮어쓰지 않는다.
- 홈의 `.local/bin`, `bin`, npm·Volta·asdf·Bun·pnpm, NVM·fnm·mise의 Node 설치, Finder의 PATH, Homebrew 경로를 확인한다. 현재 프로젝트나 다른 사용자의 홈을 재귀 탐색하지 않는다.
- 제공자 이름 및 `claude-work`, `company-codex` 같은 접두/접미 명령을 찾는다. `.zshrc` 등에서 단순 실행 파일 별칭과 인자 전달만 하는 함수도 읽는다. 프로필 자체나 발견한 프로그램을 탐색 중 실행하지 않는다.
- 기본 명령으로 연결하지 못하면 발견한 도구를 버튼으로 제안한다. 정상 기본 도구 대신 회사 도구를 쓰려면 **다른 AI 도구 찾기**를 누른다. 선택 시 다른 제공자 설정은 보존한다.
- 선택한 설정은 앱 재실행 후 적용한다. 실행 중 요청의 승인·실행 파일 binding이 중간에 바뀌지 않게 기존 경계를 유지한다. 저장만으로 로그인 완료라고 표시하지 않는다.
- 직접 경로 입력은 **고급 설정** 안에만 남긴다. 찾지 못한 경우 다시 탐색할 수 있다.

## 안전 경계와 한계

셸 초기화 파일을 `source`하거나 임의 함수·명령 치환을 실행하지 않는다. 환경변수 설정, 추가 옵션, 여러 명령을 실행하는 복잡한 회사 함수/별칭은 자동으로 해석하지 않는다. 이를 단순 명령으로 바꾸어 회사 인증·프록시 설정을 조용히 버리지 않는다. 임의 이름의 실행 파일을 전부 AI로 판단하지도 않는다.

탐색 결과는 인증 성공이 아니다. 실제 회사 SSO·프록시·특수 함수는 해당 환경의 추가 확인이 필요하다. 기본 도구가 여러 경로에 있으면 알려진 기본 명령을 우선하며, 회사 도구를 자동으로 추정하여 덮어쓰지 않는다.

## 검증

- Java 전체 1,211개 중 24개 opt-in 생략, 실패·오류 0.
- UI 기본 640개 및 별도 인수 50개 통과. UI 마지막 안내 정리는 관련 19개 재검사와 생산 빌드로 검증한다.
- Node 177개 통과. 이전 프로젝트 경로 정규화로 바뀐 진단 JSON 해시도 다시 고정했다.
- 실제 번들 Java/검색 모델·최소 PATH·임시 HOME에서 NVM 폴더의 가상 회사용 도구를 발견하고 API 목록 선택·재시작·인증 상태 확인·파일 추가·한국어 검색을 실행했다. 실제 AI 호출은 0회이며 실제 회사 인증 검증은 아니다.
- 단위 검사: NVM/fnm/mise/pnpm/Bun, 회사별 명령, Codex/Claude 분리, 명시 경로 보존, 다중 후보, 심볼릭 링크 중복, 실행 권한 없음, 단순 별칭/함수, 복합 셸 명령 거부, 검색 중 미실행.
- UI 검사: 경로 입력 없이 선택, 다른 제공자 설정 보존, 선택 전 무저장, 재시작 안내, 빈 결과·오류·revision 충돌·늦게 도착한 이전 제공자 응답.

설치 파일의 검증·공개 상태는 해당 릴리스 보고서를 따른다.

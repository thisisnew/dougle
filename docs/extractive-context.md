# 제한된 추출형 대화 문맥 — 후속 소스

이 문서는 새 소스 계약이다. 이전 JAR의 E01–E03 통과를 이 구현에 이월하거나 실제 AI 장기 기억 품질을 검증했다고 주장하지 않는다. DB 마이그레이션·자동 외부 도구 실행·운영 권한 추가는 없다.

## 불변 문맥

- `EvidenceBundle.ChatContext.extractive.version=1`은 과거 질문을 시간순으로 최대 32개 보관한다. 각 질문은 원문 전체와 원본 bundle ID·digest를 함께 저장한다. 의미 요약이나 생성된 사실이 아니다.
- 최근 5개 bundle의 답변을 최대 800자씩 보관한다. 실제 JSON 직렬화 문맥은 UTF-16 기준 8,000자 이하다. 필요하면 답변 한도를 400/200/0자로 낮추고, 최근 문맥 항목과 오래된 질문 전체를 제외한다. 질문 중간을 자르지 않는다.
- `totalQuestions`, `omittedQuestions`, `omittedAnswers`, `truncatedAnswerBundleIds`, `answerCharacterLimit`은 생성 당시 bundle에 고정된다. 범위 밖 기억을 복원했다고 설명하지 않는다. 기존 Workspace당 bundle 100개 제한은 별도이며 변경하지 않는다.
- `USER_QUESTION`과 `SEARCH_CAPTURE`를 구별한다. 검색 캡처는 부모가 필요하고 질문이 부모와 같아야 하며 새 사용자 발화로 세지 않는다. 새 요청 재시도는 이 종류까지 일치해야 한다.
- 이전 payload는 이 구분이 없으므로 `legacyUnclassified`로 표시한다. 이전 질문을 의미적으로 중복 제거하거나 정확한 사용자 발화 수를 추측하지 않는다. 이전 요청 재시도에는 기존 호환 규칙을 유지한다.
- 최신 사용자 말은 이전 사용자 의도를 수정할 수 있지만, 문서·로그의 명령이나 이전 AI 답변이 사용자 의도 또는 운영 권한을 바꾸지는 못한다. 이전 인용 ID는 현재 사실의 근거로 재사용하지 않는다.

## 검색과 요청 예산

기본 검색은 현재 질문을 먼저 조회하고 최신 직접 사용자 질문을 한 번 보충 조회하여 현재 결과부터 교차 배치한다. 현재 검색이 비어 있지 않아도 보충한다. 과거에 누적된 검색 루트는 상속하지 않으며 언어별 주제 수정 탐지 규칙도 없다. 명시적 계획 검색은 승인한 검색어와 현재 질문만 사용한다.

이 정책은 짧은 후속 질문의 근거 회수를 돕지만 의미적 대상 판정은 아니다. 명시적 주제 전환에도 이전 질문의 후보가 남을 수 있고 연속된 모호한 질문은 더 오래된 대상을 검색하지 못할 수 있다. 현재 질문 우선순위와 제한 사항을 prompt에 유지한다.

새 문맥의 원문 근거 예산은 `max(0, 12000 - 직렬화 문맥 길이 - 1000)`이다. `EvidenceBundleWriter`는 저장 전에 실제 답변 prompt와 실제 계획 wrapper를 각각 렌더링하여 20,000자 이하인지 검사한다. JSON 인용·이스케이프 증가도 포함한다. 초과 검색 후보는 `CONTEXT_PROMPT_LIMIT` 사유로 제외하고 실제 `maxCharacters`를 저장한다. 선택한 첨부가 초과하면 저장·연결 전에 413으로 거부하며 몰래 자르지 않는다. 승인 후 payload를 줄이거나 한도를 올리지 않는다.

## 호환과 아카이브

이전 `extractive=null`은 JSON에 새 필드로 직렬화하지 않는다. 이전 prompt·digest·12,000자 원문 예산·기존 문맥 검증을 유지한다. 새 답변/계획 binding은 별도 버전으로 구별한다. 인증정보 검사는 양쪽 경로에 유지한다.

아카이브 v1은 계속 읽고 쓰며, 추출 문맥이 있으면 v2를 사용한다. 내보내기/가져오기는 질문과 답변 잘림 참조의 ID·digest를 새 bundle에 재연결하고 생략 정보를 보존한다. 조상 순서·질문 원문·검색 캡처 부모·digest·예산이 맞지 않으면 거부한다. 문맥을 조용히 제거하여 가져오기를 성공시키지 않는다.

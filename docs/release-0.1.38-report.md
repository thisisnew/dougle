# Dougle 0.1.38 — 다른 Mac 환경·파일 판독·연결 검증

## 상태

2026-10-30 KST. [0.1.38 Preview](https://github.com/thisisnew/dougle/releases/tag/v0.1.38-preview.1) 공개 완료. 소스 커밋은 `74fe6af`이며 공개 설치 파일 2개와 체크섬의 원격 크기·SHA-256을 로컬 파일과 대조했다. 최종 소스의 자동 회귀 검사와 설치 파일 검증을 통과했다. 실제 회사 M5 Mac이나 회사 SSO 성공으로 확대 해석하지 않는다. 자동 업데이트 피드는 유지하므로 최신 Preview는 직접 내려받는다.

## 변경

- 코드·설정·문서의 인코딩, 경로, 개행, 손상, 취소, 한도, 원본 불변을 검증하는 입력 매트릭스를 추가했다. TXT의 제한된 접두부에서 MS949를 판별하며 코드 파일의 엄격한 UTF 판독은 유지한다. 암호 해독·OCR·모든 인코딩 지원은 아니다.
- 분할 경계의 이모지 UTF-8 해시, 읽기 전 취소, 대소문자·끝점이 있는 로컬 웹 주소 차단을 수정했다.
- 일반 문서의 파일명이 관련 본문을 검색 결과에서 탈락시키지 않도록 재정렬 입력을 수정했다. 관련성 임계값을 낮추거나 무관한 문서를 강제로 근거에 넣지 않는다.
- AI 인증 프로세스의 출력 한도 초과를 종료 대기 중에도 감지한다. 별칭·프로필·심볼릭 링크·로그인 후 재확인 검사를 보강했다. 성공 시나리오의 짧은 테스트 전용 시간 제한은 제품의 제한과 구분하고, 취소·시간 초과 검사는 그대로 유지한다.
- Jira·Confluence 콜백 포트 충돌 시 새 포트로 재등록한다. 제품별 읽기 권한, 승인된 회사 사이트, 혼합 사이트 목록, 토큰 갱신, 응답 형식·DNS·TLS·시간 초과를 검사하고 실패 단계를 안내한다. 사용자에게 개발자 등록이나 토큰 발급을 요구하지 않는다.
- 외부 쓰기 도구 호출은 계속 거부한다. GitHub 주소·인증은 계속 차단하며 로컬 소스 폴더와 웹 URL은 유지한다.

## 최종 자동 검사

동일 소스의 전체 실행 결과다. 중간 실패 후 해당 테스트만 재실행한 결과를 합쳐 전체 통과로 표시하지 않는다.

| 검사 | 결과 |
| --- | --- |
| Java 21 전체 | 7,916 통과 / 0 실패 / 4 생략 |
| 위 Java 중 신규 핵심 매트릭스 | 5,879 통과 / 0 실패 / 0 생략 |
| UI 전체 및 opt-in | 710 통과 |
| Node 프로토콜·패키징 | 5,554 통과; 이 중 5,376개는 프로토콜 바이트 분할 조합 |
| 결과 집계기 | Python 5 통과 |
| 데스크톱 | Rust 24 통과 |
| Jira·Confluence 실제 loopback HTTP | 위 Java에 포함된 25개 통과 |
| 격리 Chromium | 위 Java에 포함된 7개 통과; 합성 응답·외부 요청 없음 |

Java에는 실제 동봉 임베딩/재정렬 모델, 100 MiB 파일, 새 임시 MySQL 8.4 서버, 폴더·웹 수집/재동기화, 읽기 전용 경계가 포함된다. 5,879개는 고유 입력 조합이지 그만큼의 독립 업무 흐름이나 물리 Mac이 아니다. Node 조합을 Java 매트릭스 수에 더하지 않는다.

케이스별 ID·결과·시간·소스 해시는 [Java 실행 원장](evaluations/portability-0.1.38-java.json), 시나리오와 재현은 [검증 안내](portability-verification.md)에 있다. 생략 4개는 실제 AI 생성, 사용자 문서 평가, 별도 저장소 평가, Notion 실서버의 합성 폼 확인이다. 실제 외부 AI 호출은 0회다.

## 새 사용자 환경과 설치 파일

동봉 JVM/JAR로 별도 HOME 6종을 실행해 모두 통과했다. 일반 경로 및 한글·공백·따옴표·이모지 경로 각각에서 AI 명령 없음, 사용자별 다른 명령 자동 탐색, 회사 별칭 선택·즉시 적용·재시작을 확인했다. 가상 CLI이며 실제 AI 계정 인증이 아니다. [케이스별 설치 실행 기록](evaluations/portability-0.1.38-install.json).

별도 동봉 런타임 검사에서 AI 없이 코드 폴더 수집·Gradle 검색·실패 파일 재시도·정상 복구·원본 불변·GitHub 차단·Confluence 연결 필요 안내를 확인했다.

Intel DMG의 실제 React·네이티브 UI, ARM DMG 정적 무결성·CPU·모델·서명, 양쪽 업데이트 아카이브의 서명·버전·현재 JAR 일치를 확인했다. ARM 실기기 실행과 Apple 공증은 수행하지 않았다.

로컬 `/Applications/Dougle.app`은 0.1.38로 교체했다. 이전 앱과 종료된 데이터의 백업·동일성 확인 후 새 앱을 열었다.

## 발견한 실패와 재검증

첫 전체 실행은 MS949 판독·기존 URL 정책 검사·검증 환경 미준비 등으로 실패했다. 이후 동봉 모델/임시 MySQL을 포함한 전체 실행에서 검색 2건과 CLI 테스트 3건, 다음 전체 실행에서 별칭 테스트 2건이 추가로 실패했다. 이 기록은 통과 수에 포함하지 않는다.

판독·검색의 제품 결함, 빈 검색 결과를 정확히 재현하지 못한 테스트, 짧은 성공 대기와 고정 sleep에 의존한 CLI 테스트를 각각 수정했다. 실제 빈 색인·호출 순서·완료 신호·오류 상태·프로세스 정리를 검증한다. 전체 실행 후의 스레드 덤프만으로 이전 CLI 시간 초과 원인이 자원 고갈이었다고 단정하지 않는다. 제품 인증 제한을 무작정 늘리지는 않았다.

## 남는 경계

- 실제 회사 계정의 Jira/Confluence SSO, 관리자 앱 승인, 프록시/PAC, 사설 CA, 회사 문서 권한은 미검증이다. 가상 서버의 승인 성공을 회사 연결 성공으로 표시하지 않는다.
- 연결 완료는 승인 토큰·읽기 도구·회사 사이트 확인과 저장을 뜻한다. 모든 문서의 권한이나 이후의 서비스 가용성을 보장하지 않는다.
- 이 호스트는 Intel이다. ARM 설치 파일은 정적 검증과 실제 ARM 실행을 구분한다. Apple 공증·회사 MDM/Gatekeeper 인수는 별도다.
- 미지원 파일과 실제 권한·수집 한도 오류는 남을 수 있다. 정상 파일 수집과 실패 항목 재시도를 분리하며 원본은 변경하지 않는다.

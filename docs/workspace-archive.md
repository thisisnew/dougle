# 자료·대화 아카이브

전체 Workspace 백업이 아닌, 제한된 원본 자료·대화 이전 기능입니다. 설정의 자료·대화 이전에서 ZIP 다운로드 → 새 이름으로 미리보기 → 명시적 확인 후 가져오기를 수행합니다. 기존 Workspace를 덮어쓰거나 자동 선택하지 않습니다.

## 포함 범위와 제한

- 원본 파일 바이트·폴더 구조·자료 이름/생성 시각과 질문·완료 답변·원본 인용 근거·대화 연결을 복사합니다. 가져온 파일은 외부 연결이 없는 독립 복사본입니다.
- 지식 문서, 질문 첨부, 이전 형식 보관함, 고정 문맥 요청이 있는 Workspace는 거부합니다. 실패·취소를 포함한 미완료 답변 작업이나 수집 중인 Source가 있어도 거부합니다. 지원하지 않는 항목을 몰래 생략한 전체 백업을 만들지 않습니다.
- 지식/첨부 근거, 분류 범위가 있는 근거, 삭제·이름 변경된 자료 및 현재 파일/추출문 해시·인용 행과 맞지 않는 과거 근거를 거부합니다. 로컬 문서 분석 결과가 환경에 따라 달라져도 가져오기가 거부될 수 있습니다.
- 연결 위치·Source ID·인증·실행 승인·원격 연결 설정은 옮기지 않습니다. 검색 제외 기록과 앱 설정도 복사하지 않습니다. 답변은 완료 이력으로만 저장하며 실행 가능한 승인을 복원하지 않습니다.
- ZIP 최대 9 MiB, 개별 파일 1 MiB, 전체 아카이브 내용(목록 JSON 포함) 8 MiB, 자료는 폴더 포함 63개, 질문/답변 각각 100개입니다. 목록 JSON도 개별 문서 제한을 받으므로 긴 대화는 이보다 일찍 제한에 도달할 수 있습니다. 질문당 근거·이전 문맥 각각 최대 5개입니다.
- 새 Workspace 이름은 최대 20자입니다. 미리보기는 메모리에 최대 4개, 10분 또는 백엔드 재시작까지 유지됩니다.

## 안전성과 복구

미리보기는 체크섬·경로·필드·참조·근거를 검증하고 로컬 분석만 수행합니다. 적용은 새 Workspace·자료·대화·영수증을 하나의 DB 트랜잭션으로 저장합니다. 자료 ID와 대화 근거 digest를 새로 계산하고 이전 문맥 참조를 다시 연결합니다. 원격 동기화·AI를 실행하지 않으며 자동 갱신은 꺼집니다. 검색 색인은 로컬 재구성 요청 상태이며 검색 엔진 준비가 필요합니다.

적용 API의 `requestId`, `previewId`, `digest`를 보관하면 완료된 요청은 앱 재시작 후에도 같은 결과를 확인할 수 있습니다. 같은 미리보기로 다른 요청 ID를 쓰면 거부합니다. 이후 Workspace를 삭제해도 완료 영수증은 남고 재조회가 Workspace를 다시 만들지는 않습니다. 새 미리보기를 만들어 같은 ZIP을 다시 가져오는 것까지 금지하는 전역 중복 제거 기능은 아닙니다.

UI는 요청 식별자를 브라우저 저장소에 보관하고 자동 재실행하지 않습니다. 앱 주소 변경·저장소 삭제에 대비하려면 복구 JSON을 별도로 보관하세요. 미완료 미리보기는 재시작 후 복원되지 않습니다. 복구 버튼은 원래 계획이 아직 유효한 미완료 요청을 완료할 수도 있습니다.

체크섬은 파일 무결성 검사이지 작성자 인증/서명이 아닙니다. 파일 이름·파일 바이트·질문·답변·인용문에는 비밀정보나 외부 경로가 포함될 수 있으며 자동 삭제하지 않습니다. ZIP은 암호화하지 않습니다. 공유 전에 내용을 직접 검토해야 합니다.

## API와 검증

- `GET /api/workspace-archives/export/{workspaceId}`: ZIP 다운로드.
- `POST /api/workspace-archives/import-preview?workspaceName=...`: `application/zip` 원시 바이트, 미리보기 반환.
- `POST /api/workspace-archives/import-apply`: JSON `{requestId, previewId, digest}`, 새 Workspace 결과 또는 기존 영수증 반환.
- 기존 로컬 인증·동일 출처 요청 보호를 사용합니다. 영수증 테이블은 앱의 미배포 v27 마이그레이션이 소유하며 테스트가 별도 DDL을 만들지 않습니다.

UI 검증: `cd frontend && npm test -- src/WorkspaceArchivePanel.test.tsx`.
백엔드 검증: `bash scripts/maven.sh '-Dtest=WorkspaceArchiveIntegrationTest,TransferArchiveCodecTest' test`.
합성 자료 테스트는 실제 패키지 런타임·외부 서비스·전체 Workspace 이전 인수 통과를 뜻하지 않습니다.

## 임시 런타임 스모크

하네스만 검사: `node scripts/workspace-archive-smoke.mjs --self-test`.
부모가 안정된 JAR를 승인한 뒤 실행: `node scripts/workspace-archive-smoke.mjs --run`.
이 스크립트는 빌드/Maven을 실행하지 않습니다. 현재 JAR를 다른 검증이 사용 중일 때 덮어쓰지 않으며 시작·재시작 전에 동일 SHA-256인지 확인합니다.

임시 데이터 디렉터리와 격리된 Java 홈으로 백엔드를 시작하고 stdout의 `FORGE_DESKTOP_READY` 포트만 사용합니다. 기존 사용자 DB·계정·실제 자료를 읽지 않습니다. 합성 파일 업로드와 합성 완료 답변을 포함한 두 턴 아카이브를 만들어, 미리보기 무변경·새 Workspace 적용·재내보내기/재가져오기·파일 바이트/로컬 추출문·대화 digest 연결·재시작 영수증·삭제 후 중복 생성 방지·변조/경로/버전 거부를 검사합니다. Slack 미설정/빈 목록과 브라우저 작업 빈 목록만 읽고 연결·조회·브라우저 실행은 하지 않습니다. 성공/실패 뒤 백엔드를 종료하고 임시 데이터를 삭제합니다.

결과 JSON에는 JAR/스크립트 SHA-256, 실행 시각, 완료 검사 목록과 `mode: simulated`, `fixtureOnly: true`를 기록합니다. 합성 답변은 AI가 생성한 답변이 아닙니다. 기본값은 검색 모델과 외부 AI 실행 경로 비활성화이며 **색인 재구성 요청과 로컬 추출문까지만 검사합니다**. OS 네트워크 샌드박스는 아니며 외부 서비스나 계정 검증도 아닙니다. E50 상태를 자동 변경하지 않습니다.

v1 스모크는 JAR SHA-256 `1ddab26fc24c41a1a25ab8cc351d98659cccefdace8a0b697f54048a20f8afe0`에서 검색 모델 없이 6개 검사 그룹을 통과했습니다. 임시 백엔드·데이터 정리 및 JAR 불변을 확인했습니다. 이 결과를 새 JAR 또는 검색 모델 사용 검사 통과로 이월하지 않습니다. 평가 인벤토리 감사 당시 1 PASS / 1 BLOCKED / 48 NOT_RUN, `gate` 종료 코드 1이었습니다. 초기 PASS=0 고정 가정은 별도 승인된 테스트 수정에서 현재 기록의 집계를 검증하도록 변경했고 Node 테스트 12개가 통과했습니다. 평가 상태는 바꾸지 않았습니다.

### 로컬 검색 모델 opt-in (v2)

승인된 런타임에서만 `FORGE_ARCHIVE_SEARCH_MODELS=/absolute/path/to/bundled-models node scripts/workspace-archive-smoke.mjs --run`으로 실행합니다. 변수 미설정/빈 값이면 기존 비활성화 동작을 유지합니다. 지정 디렉터리는 이미 준비된 `model.onnx`, `tokenizer.json`, `reranker.onnx`, `reranker-tokenizer.json`을 포함해야 하며 앱이 해당 CPU용 번들 체크섬을 검증합니다. 모델 파일을 생성·수정하거나 다운로드하지 않고 `/search-model/prepare`도 호출하지 않습니다. 외부 AI 명령은 계속 비활성화합니다. `sqlite3` CLI가 필요합니다.

첫 가져오기·왕복 가져오기·재시작·다른 Workspace 삭제 뒤, 각각 모델 상태 `READY`를 기다린 후 **이 실행의 임시 DB만** `sqlite3 -readonly`로 열어 `search_outbox`가 0인지 확인합니다. 이어 실제 Workspace 검색 API로 합성 원문을 검색하고 모든 hit가 새로 가져온 자료 ID·원본 종류·추출문 해시·원문을 반환하는지 검사합니다. 다른 Workspace/삭제된 자료 ID나 외부 Source 연결이 나타나면 실패합니다. 상태 오류는 즉시 실패하며 모델/큐·검색 폴링은 각각 120초 제한(진행 중 HTTP 최대 20초, SQLite 최대 3초 별도)을 적용합니다. 결과의 `indexVerification`은 비활성화 시 `SKIPPED`, opt-in 전체 완료 시에만 `PASS`입니다.

v2 준비 검사: 구문, ZIP/manifest/CRC, 잘못된 검색 ID·해시·본문·Source 거부, 폴링 제한/오류 즉시 종료 자체 검사 통과. **모델 opt-in 런타임은 아직 실행하지 않았습니다.** 이 모드의 성공도 해당 합성 자료의 색인/검색 경계만 증명하며 일반 의미 검색 품질·외부 계정·전체 E50 통과를 뜻하지 않습니다.

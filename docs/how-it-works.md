# 작동 원리와 사용법 — 짧게 읽기

Claude 답변 중에는 **미검증 임시 출력**이 나타날 수 있습니다. 참고만 하세요. 최종 검사를 통과하면 정식 답변으로 바뀌고, 실패·중단하면 임시 글은 사라집니다. Codex는 아직 완료 답변만 표시합니다. [쉬운 설명](partial-answer.md).

요청 전문을 확인한 뒤 **승인 상태 확인 → 직접 동의 → 이 요청 승인 저장**을 사용할 수 있습니다.
10분 뒤 만료되며 **저장된 승인 철회**로 취소합니다. [쉬운 설명](answer-approval.md).

그다음 **승인한 요청 전송·답변 시작**을 누르면 실제 외부 CLI 요청이 시작됩니다. 추가 전송 확인이 필요합니다.
**답변 작업 조회·새로고침**으로 이전 결과를 보고 **답변 중단**으로 실행을 멈춥니다. [사용법·삭제 정책](answer-jobs.md).
실행 중 화면은 SSE로 **근거 확인 → 작업 상태 → 완료 답변**을 자동 표시합니다. 끊기면 최대 3회 다시 연결하며 AI를 새로 호출하지 않습니다. Claude의 임시 글은 별도 미검증 영역입니다. [쉬운 설명](partial-answer.md).

검색창의 **근거 묶음**을 누르면 답변에 참고할 원문·출처를 로컬에 저장하고 다시 볼 수 있습니다.
묶음 저장 자체는 AI에 전송하지 않습니다. 원본 삭제 후에도 이 복사본은 남습니다. [사용법·삭제 정책](evidence-bundles.md).

묶음에서 **근거 상태 다시 확인**으로 변경·삭제를 검사하세요. 제공자·모델 선택 후 **요청 미리보기 만들기 (전송 안 함)**로 요청문을 확인합니다.
모든 근거가 현재 자료와 같아야 미리보기가 나옵니다. 승인·실제 AI 호출은 아닙니다. [짧은 사용법](bundle-validation.md).

**게시 지식도 검색**을 켜면 원본과 사람이 게시한 지식이 함께 나옵니다. 수정 중인 초안은 제외합니다.
게시 결과를 누르면 검색된 버전과 근거를 읽기 전용으로 확인합니다. [사용법·상태 설명](published-search.md).

검색 결과에는 **검색어 주변 글과 추출 텍스트 줄 번호**가 나옵니다. 이름·심볼에만 일치하면 따로 표시합니다.
결과를 눌러 원본을 확인하세요. PDF 페이지 번호나 확정 인용은 아닙니다. [쉬운 설명](search-evidence.md).

**자료를 넣으면 검색할 준비를 하고, 선택한 근거로 지식 초안을 만듭니다.**
등록만으로 모든 자료가 AI 백과사전으로 바뀌는 것은 아닙니다.
현재는 사용자가 근거를 고르고 AI 생성을 승인하는 방식입니다.

## 1. 자료는 어떻게 들어오나?

```mermaid
flowchart LR
  A[파일 업로드 / Source 수동 동기화] --> B[앱 안에 원본 복사]
  B --> C[본문·코드 이름 추출]
  C --> D[검색 색인 저장]
  D --> E[검색 결과와 원문 확인]
```

- 파일 업로드: 선택한 파일을 복사합니다. PC의 원본을 수정하지 않습니다.
- 로컬 폴더·URL·GitHub: Source로 등록한 뒤 **수동 동기화**합니다.
- Tika가 문서의 글을, JavaParser가 Java 코드 이름과 위치를 뽑습니다.
- Lucene/Nori가 검색을 맡습니다. 검색할 때 AI를 호출하거나 자료를 다시 수집하지 않습니다.
- 여러 도메인을 선택하면 그중 하나에 속하는 자료를 함께 검색합니다.

## 2. 지식 문서는 어떻게 만드나?

1. 자료를 열고 **근거로 지식 초안 작성**을 누릅니다.
2. 제목·내용·근거 행을 선택해 수동 초안을 저장합니다. 본문에는 `[E1]`처럼 근거 번호를 씁니다.
3. AI가 필요하면 제공자·모델을 고르고 **전송 내용 미리보기**를 확인합니다.
4. 동의하면 선택한 근거 인용문으로 새 CLI 요청을 보냅니다. 결과는 **별도 AI 초안**입니다.
5. 사람이 원문과 내용을 대조해 검토 기록을 남긴 뒤, 별도로 게시합니다.

완료된 AI 작업의 **원래 문서와 비교**에서 생성 당시·현재·AI 최초 결과를 함께 볼 수 있습니다.
편집 충돌과 근거 변경을 확인하는 읽기 전용 화면이며 자동 반영하지 않습니다. [쉬운 비교 안내](generation-comparison.md).

**제안 처리 기록 열기**에서는 이유를 적어 거절하거나 재검토로 돌릴 수 있습니다.
문서 삭제·AI 재실행 없이 이력만 남깁니다. [쉬운 처리 안내](proposal-decisions.md).

생성 후 원래/결과 문서를 수정하지 않았다면 **전체 채택 검토**에서 새 초안으로 반영할 수 있습니다.
이전 버전과 게시본은 유지하고, 게시는 다시 검토합니다. [채택 사용법](proposal-acceptance.md).

사람이 이미 편집했거나 일부만 쓰고 싶다면 **부분 반영 편집**을 누르세요.
현재 본문으로 시작해 필요한 AI 문장만 선택해 추가합니다. 재조회해도 작성 내용은 유지합니다.
기본 저장은 동일 근거만 허용합니다. [부분 반영 사용법](proposal-merge.md).
현재 수집본과 일치하는 근거끼리는 **근거 번호 통합 미리보기**를 선택해 연결할 수 있습니다.
기존 번호는 유지하고 AI 번호만 바꿔 보여줍니다. [통합 사용법](evidence-merge.md).

로그인된 Codex/Claude CLI를 사용하지만 지금 코딩 중인 대화를 재사용하지는 않습니다.
앱이 확인하는 것은 출력 형식과 근거 번호 등입니다. **AI가 사실을 보증하지 않습니다.**
CLI 설치 버전이 확인되어도 로그인·요금 한도·원격 모델 연결 성공을 뜻하지 않습니다.

## 3. 상태 표시는 무슨 뜻인가?

| 표시 | 뜻 | 할 일 |
|---|---|---|
| DRAFT | 작성된 초안의 생성 상태 | 별도 검토/게시 상태도 확인 |
| CURRENT | 마지막으로 수집한 자료와 근거가 같음 | 원격 최신/사실 확인과는 다름 |
| STALE | 수집된 자료와 예전 근거가 달라짐 | 현재 원본과 다시 대조 |
| MISSING | 현재 원본을 찾을 수 없음 | 보존된 당시 근거 확인 |
| FAILED | AI 작업 실패 | 오류 확인 후 필요하면 다시 승인 |
| INTERRUPTED | 앱 재시작으로 이전 작업 중단 | 자동 재전송 없음 |

근거가 바뀌거나 없어지면 새 검토/게시를 막습니다. 이미 게시한 과거 문서는 남습니다.
새 본문 버전을 만들면 그 버전은 다시 검토해야 합니다.

## 4. 수정·삭제할 때 알아둘 것

- **편집:** 새 버전으로 저장합니다. 다른 편집이 먼저 저장되면 충돌을 알리고 입력을 보존합니다.
- **폴더:** 원본과 지식은 별도 정리합니다. 지식 폴더 생성·이름 변경·폴더/카드 이동·빈 폴더 삭제를 지원합니다.
- **원본 삭제:** 앱의 복사본을 지웁니다. PC의 원래 파일이나 GitHub 파일은 지우지 않습니다.
- **지식 삭제:** 그 카드의 버전·검토·게시와 더 이상 쓰지 않는 근거 복사본을 지웁니다. 원본은 남습니다.
- **Workspace 삭제:** 그 공간의 원본·지식·작업 이력을 모두 지우므로 주의하세요.
- **AI 중단:** 생성 중단 버튼을 누릅니다. 화면 이동만으로는 작업이 취소되지 않습니다.

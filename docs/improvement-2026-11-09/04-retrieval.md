# 04. 부분 읽기와 사실 위치 색인

## 이유
큰 노트/코드를 매번 통째로 읽으면 첫 시도부터 캐시 생성량과 이후 읽기량이 증가합니다. 내용을 임의 요약하기보다 필요한 원문의 위치를 찾고 읽는 방법을 추가했습니다.

## 구현
- 원격 read_file에 start_line/end_line을 추가했습니다. 원격 ref/commit과 원본 blob 해시 확인 후 요청 구간만 모델에 반환합니다. 실제 행 범위를 영수증에 기록합니다. 범위 밖 인용은 검증되지 않습니다.
- index-build는 기존 지식 Markdown의 제목/하위 절 경계와 원문 SHA-256에 묶인 위치 색인을 봇 전용 폴더에 만듭니다. 사용자 노트는 다시 쓰지 않습니다.
- 질문과 겹치는 용어의 후보 포인터만 압축 정책 입력에 넣습니다. 하위 예외 절을 포함한 경계를 제공합니다. 항상 complete=false이며 다른 관련 노트 탐색을 막지 않습니다.
- 원문이 변경된 후보는 제외합니다. 색인이 없거나 불일치하면 기존 검색을 유지합니다.

## 기대효과
원문 내용·조건·예외를 보존하면서 불필요한 본문 입력을 줄입니다. 실제 회사 절감률은 통제 시험으로 확인해야 합니다. GitHub API에서 blob 검증을 위해 받는 네트워크 바이트 자체가 줄어드는 기능은 아닙니다.

## 회사 적용/시험
새 런타임 준비 후 설치 스킬의 scripts/bot.sh index-build를 실행합니다. 사용자 지식 폴더를 변경하는 명령이 아닙니다. 결과의 sections/files를 기록합니다. 큰 노트 질문과 코드 질문을 같은 원본 버전으로 비교하며 조건·예외 누락, 도구 출력량과 토큰을 봅니다. 색인은 노트 갱신 후 명시적으로 다시 만듭니다.

## 실패 시
색인이 오래됐으면 index-build를 다시 수행합니다. 검색 후보가 없다고 업무 기능이 없다고 결론 내리지 마세요. 부분 읽기 결과의 앞뒤 조건이 필요하면 범위를 늘려 읽습니다. invalid_line_range는 파일의 실제 행 범위 안으로 요청해야 합니다. 원격 ref가 바뀌면 새 commit을 확인한 뒤 다시 읽습니다.

## 개발 검증
원격 blob/커밋/행 범위, 위조 범위 거절, bool 인자 거절, 예외 절 포함, 원문 변경 후보 배제 검사 통과. 기존 원격/봇 연결/압축 작업자 92개 검사 통과.

# 02. 조회 오류와 관리 파일 보호

## 이유
403/404 등 일반 문자열 오류가 성공한 SQL 근거로 들어갈 수 있고, cannot_answer 상태를 사용하면 운영 자료 판정을 통과할 수 있었습니다. 봇 지식 쓰기 영역에 공유 기준·소스 등록 파일도 포함돼 있었습니다.

## 구현
- SQL 결과의 오류/오류 배열/403/404/미완료를 고정 사유 코드로 분류합니다. 원문을 진단에 복제하지 않습니다.
- 오류 결과는 영수증과 모델용 영수증 알림 모두에서 제외합니다. status.recent_query_failures에서 새 실패 이유를 확인합니다.
- cannot_answer라도 미검증 live 주장이 있으면 담당자 확인 경로를 거칩니다.
- sources, sharing, ledger, bindings, registries, .git 및 binding.md/bq-sync-registry.md는 봇이 읽을 수 있지만 쓰지 못합니다. 실제 경로와 임시 경로 양쪽 및 저장 직전 검사에서 막습니다.

## 기대효과/범위
오류가 데이터인 것처럼 게시되는 경로와 관리정보 변조를 줄입니다. not_found는 미동기화라는 뜻이 아닙니다. 최근 행 시각을 적재 완료로 간주하지 않습니다. 기존의 정확한 전체 COUNT=0 안내는 유지합니다. 임의 업무 질문의 테이블·필터 매핑은 별도 검증이 필요합니다.

## 회사 시험
- 승인된 조회 대상에서 권한 없음/잘못된 테이블/미완료 결과의 안전한 표본으로 점검합니다. 운영 권한을 바꾸지 마세요.
- 오류 결과에 성공 영수증이 없어야 하며 status의 recent_query_failures에 이유가 있어야 합니다.
- 회사 지식 원본을 실험적으로 쓰지 마세요. 보호 경로 시험은 임시 합성 지식 폴더에서 수행합니다.

## 실패 시
회사 MCP 오류 포맷이 다르면 민감한 문장·SQL·행을 제거한 구조 표본과 오류 종류만 전달해 주세요. 오류를 무시하거나 성공으로 바꾸지 마세요. 보호 파일 쓰기 거절은 정상입니다. 소스 등록/게시 기준 변경은 해당 작업 전용 절차로 처리합니다.

## 개발 검증
조회·최신성·지식 저장·진단 91개 통과. 실제/임시 관리경로 쓰기 차단과 영수증 알림 관련 28개 통과. 회사 서비스 호출 없음.

# 7. 고정 질문·토큰·정확도·반복 답변 평가

## 이유
성공한 호출만 비교하면 재시도로 늘어난 토큰과 실패를 놓칩니다. 같은 질문이라도 지식·원문·모델·effort가 달라지면 설계 개선 효과와 섞입니다. 토큰과 비용도 서로 다른 지표입니다.

## 구현
scripts/scenarios/evaluate_pairs.py가 기준/후보, 사례, 반복 번호를 짝지어 검사합니다. 모든 시도의 토큰을 합하고 실패 시도도 포함합니다. 누락 사용량은 0으로 처리하지 않습니다. Codex input_tokens에는 캐시 읽기가 이미 포함되므로 다시 더하지 않으며 Claude는 입력·출력·캐시 읽기·쓰기 네 값을 합합니다. 모델·effort·질문·원문·초기 지식·도구가 같아야 비교하고, 외부 원문 대조의 사실 목록·불필요한 단정 없음·근거 검증 기록을 요구합니다. 반복 사실 불일치, 후보 실패 증가, 총 토큰 50% 미만 절감은 수용 실패입니다.

run_host.py는 실제 Codex 모델과 effort를 명시할 수 있고 초기 상태 해시를 남깁니다. 기존 fixture 읽기 로그와 원문을 이용해 별도 의미 검토합니다. 단어 포함만으로 의미 정확도 통과라고 표시하지 않습니다. 전체 pytest에는 비용 중복, SQL 오류, 원격 행 범위, 예외 포함, 오래된 색인 무효화, 잘못된 receipt 연결, 한도 설정, 평가기의 실패 검출을 포함합니다. 기존 시간 제한 테스트는 기본값에 의존하지 않고 명시적 900초 설정으로 제한 동작을 계속 검사합니다.

## 개발 실제 시험
Codex gpt-6-astra/high, 합성 질문 DG-ASK-017(메일 시점·미등록 예외), DG-ASK-049(복합 예외), 각 기준/후보 3회로 고정했습니다. 실제 회사 자료·Slack·키체인은 사용하지 않습니다. 구현 완료 시 첫 4회는 원문 읽기와 정상 답변을 확인했고, 12회 전체 결과는 최종 09 문서와 model-evaluation.json에 기록합니다. 이 시험은 기존/compact 정책의 합성 모델 행동이며 새 Claude 런타임의 회사 종단간 성능을 대신하지 않습니다.

## 회사 Claude 시험
원래 문의 #60/#57/#58/#54/#61/#62의 정확한 질문·후속 문맥을 보존합니다. 제목으로 질문을 새로 쓰지 마세요. #55도 누락하지 말고 별도 큰 사례로 포함 여부를 시험 계획에 먼저 고정하세요. 동일 스냅숏의 분리된 평가 환경에서 기준/후보를 각각 3회 실행합니다. 운영 지식을 시험 과정에서 기준/후보 사이에 섞지 마세요. 실패·재시도를 전부 남기고 문의의 전체 토큰·최종 상태·핵심 사실·조건·예외·근거를 기록합니다. SQL 0건/403/404, 후속 질문, 원본 변경, 원문 일부 읽기 후 예외 누락 반례도 확인합니다. 원문 사실 대조가 끝나지 않으면 review_status를 source_checked로 적지 마세요.

## 기대효과와 한계
앞으로 정확도나 실패율을 희생해 토큰 목표만 통과하는 것을 잡아냅니다. 평가기는 사람이든 독립 모델이든 원문 대조 결과가 정확한지 스스로 증명하지 못합니다. 테스트 원문·검토 근거도 함께 보관해야 합니다. 동일 핵심 사실을 검사하며 문구 바이트 일치를 강제하지 않습니다. 모든 업무 질문의 문자 그대로 같은 답을 보장하지 않습니다. 실제 회사 50% 절감은 해당 환경의 수용 시험 전까지 미확인입니다.

최종 합성 결과: 실제 Codex 12회, 기존 1,637,504 → 후보 574,675토큰(64.91% 감소), 실패 0회입니다. 후보 6답변의 원문 대조에서 확인한 오답·필수 사실 누락은 0건이고 사례별 3회 핵심 사실이 같았습니다. 기존 049 첫 답변의 식품 별도 접수 화면 생략 1건은 baseline_findings에 보존했습니다. 양쪽 문구 바이트는 고정되지 않았습니다. 후보의 기준 충족은 이 두 합성 질문에 한정합니다.

# 8. 구현 전체 검토와 추가 수정

## 목적
1~7의 정상 예시뿐 아니라 실패·중단·재시작·기존 자료 호환 경로를 검토합니다. 검사 통과를 업무 정확도 전체 보증으로 확대하지 않습니다.

## 발견 후 수정
1. 비정상 CLI 종료가 result를 남겨도 원래 경로가 바로 예외를 던져 비용을 버렸습니다. 최종 result의 추정 비용·사용량을 실패 기록에 붙입니다. 정상 결과 직후 설정된 누적 시간이 끝나는 경로도 반환된 비용을 보존합니다.
2. 이전 버전이 prepared로 만든 메타데이터 저장 대기 작업은 새 finalize 검사를 건너뛸 수 있었습니다. 실제 commit 직전에도 보호 경로를 검사하고 충돌 처리합니다. 대소문자를 달리한 공유 메타데이터 경로도 보호합니다.
3. 색인 JSON이 배열이거나 일부 record 형식이 깨지면 답변 준비가 실패할 수 있었습니다. 형식을 확인해 색인을 버리고 기존 탐색으로 돌아갑니다. 없거나 symlink인 입력 지식 폴더를 새 색인 성공으로 표시하지 않습니다.
4. SQL 오류가 MCP content/structuredContent/status 안에 감싸진 경우도 판정합니다. 일반 rows의 error라는 업무 열은 오류로 오인하지 않습니다.
5. 재조사에서 이전 receipt ID를 힌트로 주면 이전/현재 호출 근거가 섞일 수 있어 ID를 제거했습니다. 발견한 경로·행 범위만 주고, 최종 답변에 사용하는 근거는 현재 호출에서 읽게 합니다. 위치를 알고 있는 자료의 탐색을 반복하지 않되 검증을 낮추지 않습니다.
6. 게시 충돌의 대안 속 의존관계도 검사하고 철회 상태를 은근히 되살리지 않게 했습니다. 기존 미해결 충돌은 자동 해결하지 않습니다.
7. 게시 보존 기록을 JSON 파일로 넣으면 기존 Markdown-only 민감정보 검사와 fetch 계약에 막히는 연결 문제를 발견했습니다. publication.md/publication-ledger.md의 json 코드 펜스로 저장하도록 수정하고 구조 검사 성공 결과를 실제 민감정보 검사에 이어 넣는 통합 테스트를 추가했습니다.
8. 새 테스트 파일 이름이 기존 테스트와 겹친 것을 분리해 기존 검사를 복구했습니다. 기존 시간 제한 테스트는 900초를 명시해 제한 기능 검증을 유지합니다. 한도 기본값 제거를 이유로 제한 테스트를 없애지 않았습니다.

## 검토 범위와 회사 확인
메타데이터 보호는 봇의 Write/Edit·저장 큐에 적용됩니다. 회사 사용자의 명시적 connect/publish/migration 작업을 전역으로 막는 것이 아닙니다. 위치 색인은 근거가 아니며 오래된 원본·새 예외·의존관계 변경은 재확인해야 합니다. 구조 검사만으로 의미 정답을 증명하지 않습니다. 임의의 query result 시각이나 MAX(timestamp)로 BigQuery 동기화 완료를 단정하지 않습니다.

## 기대효과
오류 경로에서도 비용·근거·지식 이력의 일관성을 보존합니다. 최종 전체 회귀·배포·실제 합성 평가 수치는 09 문서에 기록합니다. 회사 Claude는 같은 오류가 생기면 해당 단계 문서와 status/usage 진단을 함께 확인하고 검증을 끄는 방식으로 우회하지 마세요.

평가기 검토: 기준 버전의 기존 누락·불일치는 baseline_findings에 공개합니다. 후보는 완전한 정답 사실·반복 일관성을 별도로 통과해야 합니다. 기존 버전에 결함이 있다는 이유로 후보의 올바른 개선을 실패로 판정하거나, 반대로 후보 결함을 허용하지 않습니다.

최종 CLI 경계 확인에서 최초 시작 전 DB가 없는 usage --attempts가 빈 DB를 생성하려는 경로를 고쳤습니다. 빈 사용량을 반환하고 파일을 생성하지 않으며 실제 CLI 파서/실행 테스트를 추가했습니다.

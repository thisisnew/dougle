# 6. 게시 불변식·영구 ID·변경 감지

## 이유
비슷한 표현을 같은 사실로 합치거나 한 사람의 업로드로 다른 사람의 근거·조건을 잃으면 검색과 답변의 정확도도 무너집니다. 매번 PR을 사람이 읽는 대신, 기계가 검사할 수 있는 보존 규칙을 게시 직전에 실행합니다.

## 변경
publish에 표준 Perl 구조 검사기를 추가했습니다. 공통 기준 B, 로컬 L, 고정 원격 R, 최종 F를 비교해 결정 코드를 기록합니다. ID 누락·범위 충돌·근거/이력/충돌 대안 유실·빠진 의존관계·틀린 병합·부당한 검증 승격·실제 파일 해시 불일치를 막습니다. publication.md과 publication-ledger.md을 지식과 같은 commit에 넣고 Git으로 변경 이력을 보존합니다. 기존 민감정보 검사도 별도로 유지합니다.

ID는 원본/프로젝트에 자격을 부여한 영구 ID이며 문장 해시가 아닙니다. 같은 core는 변경 없음으로 판단하고, 표현만 달라도 자동 의미 동등성은 추측하지 않습니다. 새 표현은 기존 원문을 history에 남기는 변경입니다. 정렬해도 되는 것은 객체 키이며 절차·조건 배열 순서는 바꾸지 않습니다. 설치만으로 회사 기존 자료를 일괄 이전하지 않습니다.

## 기대효과와 한계
자료 누락·충돌 덮어쓰기·잘못된 파일 게시를 줄입니다. source 의미와 projection의 완전성은 호스트의 원문 대조가 필요합니다. 이 검사로 업무 정답이나 비밀정보 없음이 자동 증명되지는 않습니다. 원격 expected-head 원자적 반영도 호스트 Git 도구가 수행합니다. 원문 변경을 파일 해시만으로 최신이라고 인증하지 않습니다.

## 회사 Claude 실행·문제 대응
새 dougle-publish의 references/publication-check.md와 merge.md를 읽으세요. 사용자 지정 지식 저장소의 선택 범위를 유지하고 기존 원격 자료를 B/L/R에 누락 없이 투영하세요. 최초 매핑은 백업과 원문 대조 후 저장하세요. 네 JSON과 stage로 check-publication.pl을 실행하고 성공 receipt를 stage/publication-ledger.md에 둔 후 전체 민감정보 검사를 하세요. 문서의 예제 JSON은 형식 설명이며 회사 사실로 게시하면 안 됩니다.

오류별: missing_claim은 누락 ID 복구, evidence_lost/history_lost는 원문 근거·이력 복구, identity_scope_collision은 매핑 수정, dependency_missing은 승인 범위 내 의존 자료 복구 또는 해당 주장 게시 보류, package_bytes_mismatch는 stage 전체 해시 재생성입니다. 검사를 끄거나 오류를 무시해서 게시하지 마세요. 원격이 이동하면 새 R로 다시 비교합니다. 직접 게시 권한은 유지하고 PR을 강제하지 않습니다.

## 개발 검증
15개 실행 검사 통과: 추가/무변경/기준 보존/단독 변경/동시 충돌 정상 경로와 누락·ID 중복·근거 손실·의존 누락·승격·scope 충돌·순서 변경·바이트 변조 차단. 회사 실제 저장소 게시와 의미 검증은 미실행입니다.

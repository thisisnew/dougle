# 01. 비용과 실행별 사용량

## 이유
재개 실행의 total_cost_usd는 세션 누적 추정치입니다. 이를 실행별 비용처럼 더하면 재시도와 후속 질문 비용을 중복 계산합니다. 기존 오류 응답은 사용량을 저장하기 전에 예외 처리됐습니다.

## 구현
- engine_accounting 보조 표에 원래 보고값, 비용 범위, 실행별 토큰 4종, 5분/1시간 캐시 생성량, 계산 상태를 보관합니다.
- 새 세션은 보고값을 기록하고 재개 세션은 같은 세션의 직전 누적값과 차분합니다. 날짜가 달라도 기준 세션을 찾습니다.
- 이전 기준이 없거나 누적값이 줄면 계산 불가로 표시합니다. 0원으로 만들지 않습니다.
- 실패 결과에 포함된 비용·사용량도 기록합니다.
- usage --day YYYY-MM-DD --attempts로 실행별 기록을 확인합니다.
- 과거 CLI가 누적 비용을 보고했다는 것을 확인한 경우에만 --legacy-session-totals를 추가해 읽기 전용 보정안을 확인합니다. 원본 DB 행은 덮어쓰지 않습니다. 과거 재개 기록의 범위를 모르면 기본 합계를 확정 비용으로 표시하지 않습니다.

## 기대효과
비용 표시·예산 판단의 중복 계산 제거입니다. 이 수정 자체가 모델 토큰을 절감하지 않습니다. 모든 비용은 제공자 단가 기반 추정이며 구독 소모량이나 청구액과 구분합니다.

## 회사 Claude 실행/시험
1. 최종 배포본을 설치하고 기존 봇을 정상 중지·새 버전으로 시작합니다. DB 백업을 보존합니다.
2. 설치 스킬의 scripts/bot.sh usage --day 2026-11-09 --attempts --legacy-session-totals를 실행합니다. 당시 CLI의 세션 누적 동작이 확인된 날에만 해당 옵션을 사용합니다.
3. #72 등 재시도 문의의 reported_cost_usd와 estimated_increment_usd를 비교합니다. 새 세션 1.2 → 재개 누적 1.55는 이번 실행 0.35여야 합니다.
4. 원래 비용행이 수정되지 않았는지, 누락 기준이 unknown_baseline인지 확인합니다. 실제 유료 재시험은 전체 가이드의 통제 조건을 적용합니다.

## 안 될 때
- unknown_baseline: 첫 실행 기록 또는 세션 ID가 없어서 차분할 수 없습니다. 원본 로그 없이 임의 보정하지 마세요.
- counter_reset: 세션 카운터가 줄었습니다. 새 세션/초기화/CLI 버전을 확인합니다.
- usage의 null: 제공자가 해당 수치를 주지 않은 것입니다. 0으로 채우지 마세요.
- 새 accounting 표가 없음: 새 런타임이 아직 DB를 열지 않았을 수 있습니다. status만으로 DB를 이전하지 않습니다.

## 개발 검증
비용·시작·런타임 관련 134개 검사 통과, 추가 변경 후 비용 관련 7개 재검사 통과. Ruff 통과. 회사 서비스는 호출하지 않았습니다. 최종 통합 검증은 09 문서를 따릅니다.

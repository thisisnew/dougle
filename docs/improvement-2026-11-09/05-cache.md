# 05. 캐시 비교 설정과 선택 한도

## 이유
캐시 쓰기가 비용의 큰 비중을 차지합니다. TTL을 바꾸면 가격이 달라지지만 토큰 수 자체가 줄어드는 것은 아닙니다. 기존 기본 비용/턴/총시간 제한도 사용자 선택과 구분해야 합니다.

## 구현
- [engine] prompt_cache_ttl = "5m" 또는 "1h"를 지정하면 봇 자식 프로세스에 명시적으로 전달합니다. 빈 값은 CLI 기본 동작입니다.
- effort를 명시할 수 있어 비교군의 추론 조건을 맞출 수 있습니다. 동일 작업 내 정책 본문은 고정하며 질문별 포인터는 대화 입력에 붙입니다.
- 비용/턴/총 처리시간은 기본 None으로 바꾸고 설정한 경우에만 적용합니다. 시작 점검의 별도 8턴/90초도 제거했습니다. 취소·중지는 유지합니다.
- 새 setup은 한도 필드를 쓰지 않습니다. 기존 파일의 숫자는 사용자가 정했을 가능성이 있으므로 자동 삭제하지 않습니다. 이미 입력된 한도를 제거하려면 아래 명시 이전을 수행합니다.

## 회사 적용
봇을 정상 중지하고 config.toml을 백업합니다. 이번 사용자 요청으로 기존 한도를 제거할 경우 기존 [engine]의 timeout_seconds, max_turns, max_budget_usd_per_call, daily_budget_usd 네 줄을 제거합니다. 새 버전에서는 빠진 값이 무제한입니다. 다른 설정은 유지합니다. 시험 TTL은 같은 [engine]에 prompt_cache_ttl = "5m"로 넣습니다. 같은 표를 두 번 추가하지 마세요. 재시작 후 새 runtime 버전을 확인합니다.

## 비교 시험
같은 모델·effort·도구·원문 스냅숏으로 1h/5m를 교대로 시험합니다. 짧은 연속 실행과 5분 이상 지난 후속 실행을 나눠 기록합니다. usage --attempts에서 ephemeral_5m_input_tokens/ephemeral_1h_input_tokens의 실제 비중을 확인합니다. 설정값만으로 TTL 적용 성공을 주장하지 마세요. 재시도/실패 비용도 포함합니다.

## 기대효과와 실패 진단
짧은 연속 문의의 추정 캐시 쓰기 비용 감소를 기대합니다. 회사 구독의 소모량이 동일 비율로 줄어드는지는 미확인입니다. 5분 이후 재사용에서는 오히려 다시 쓰기 비용이 생깁니다. CLI 버전이 설정을 지원하는지, 환경 변수 우선순위가 다른 강제 TTL 설정에 가려지는지 확인합니다. 로컬에서는 실제 Claude 비용 비교를 실행하지 않았습니다.

## 개발 검증
선택 한도·설정 직렬화·시작·런타임·지연·압축 정책 검사 189개 통과. 기존 명시값 보존과 기본 CLI 한도 인자 부재를 검증했습니다. 실제 TTL 절감률은 회사 시험 대상입니다.

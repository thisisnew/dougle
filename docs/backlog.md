# 남은 개발 작업 — 다른 PC 인수인계

기준: 2026-10-21, Phase 3 P3-1 추가. 체크되지 않은 항목은 **미완료 또는 일부 구현**입니다.
Phase 2 기본 기능은 검증했지만 운영 확장까지 완료된 것은 아닙니다.
이 문서는 작업 계획이며 아래 제안 모델·API는 아직 구현된 계약이 아닙니다.
실제 API는 [api.md](api.md), 실행 절차는 [HANDOFF](../HANDOFF.md)를 따릅니다.

## 권장 순서와 공통 완료 조건

1. 새 PC에서 기준 빌드/테스트 → 가상 Source 수집/검색 확인.
2. P3-1 완료, P3-2 CLI Curator 일부 구현. 최신 결정/검증은 [CLI AI](cli-ai.md)를 확인.
3. P4 검색/LLM/SSE → P5 선택적 동기화 → P6 패키징 순서로 진행.
4. P2 확장은 필요한 사용 시나리오에 따라 병행하되 보안 제한을 임의로 풀지 않기.

각 항목은 실제 코드, 실패/경계 테스트, UI 또는 API 사용 경로, 문서와 실행 증거가
모두 있어야 체크합니다. 실패한 검증은 원인·재현 명령·미해결 여부를 기록합니다.
빈 모듈 생성이나 성공으로 고정된 mock UI만으로 완료하지 않습니다.

### P3-2 시작 전 반드시 확인할 현재 구조

- `sources/adapter/JdbcSourceStore.java`: 변경된 Source는 현재 자식 entry를 삭제하고 다시 생성합니다.
  현재 entry ID만 근거 FK로 쓰면 동기화 때 근거를 잃습니다. `evidence_snapshot`은
  원본 FK 없이 Source+경로+revision+내용/텍스트 해시와 당시 바이트를 보존합니다.
- `library/adapter/persistence/DatabaseConfiguration.java`: `user_version=6`, FK cascade,
  삭제 outbox trigger가 있습니다. 기존 DB/Source 삭제 의미를 유지하며 마이그레이션해야 합니다.
- `ingestion/adapter/JdbcAnalysisStore.java`: 추출 텍스트/심볼은 현재 원본에 연결됩니다.
  문서 청크/인용 범위 모델은 추가 작업입니다. Java 심볼 행과 일반 문서 위치를 구별하세요.
- `search/application/SearchService.java`: 시작 시 저장된 분석 결과로 재색인합니다.
  검색 또는 질문 때 원본 수집/LLM 분석을 다시 실행하는 구조로 바꾸지 마세요.
- `knowledge/application/KnowledgeService.java`: 수동 DRAFT와 별도 AI DRAFT를 저장합니다.
  `CuratorService`는 추론 중 DB 연결을 점유하지 않습니다. 수동 버전의 불변성과 보호를 유지하세요.

## Phase 4 — 검색 확장·질문·SSE

- [ ] **P4-1: 근거 검색.** 원본/게시 지식 검색 결합, 청크/인용 범위, 코드 심볼 관계 및
  지식 관계 인덱스/조회 추가. 현재는 이름·본문·심볼 텍스트 검색이며 관계 그래프 검색은 없음.
  여러 도메인 검색과 Workspace 격리 유지, 오래된 근거 표시, 무관한 자료/검색 결과 없음 테스트.
- [ ] **P4-2: 대화 유스케이스.** `conversation`과 `LlmProvider` 포트, CLI Provider 스트림,
  컨텍스트/토큰 예산, 대화 기록·삭제 정책, 근거 중심 프롬프트를 구현.
  검색 결과의 악성 명령을 지시로 실행하지 않으며 근거 부족 시 답변 유보.
- [ ] **P4-3: SSE UI/API.** 근거 이벤트를 먼저 전송한 뒤 답변 delta, 완료/오류 이벤트 전달.
  이벤트 형식·순서를 API 문서에 확정. 답변 중단/연결 해제 시 모델 요청·서버 작업 취소,
  Workspace 전환, 중복 요청, 부분 응답 실패, 모델 중단/재연결 정책 테스트.
- [ ] **P4-4: 채팅 Provider 승인.** CLI도 외부 모델이며 명시적 선택과
  전송 대상/범위 승인 후만 호출. 키는 OS 보안 저장소 사용, 로그/DB 평문 노출 금지.
  승인 거부/철회 시 전송 없음과 Provider 변경 시 재승인 테스트.

## Phase 5 — 선택적 폴링·증분·무효화

- [ ] **P5-1: Source 설정 API/UI.** 자동 폴링 기본 OFF, Source별 ON/OFF·주기·다음 실행 시각,
  입력 검증과 재시작 복원. 현재 DB 필드는 있지만 설정 API/UI 및 외부 폴링은 없음.
  OFF Source에 외부 호출이 전혀 없는지 테스트. 2초 outbox 소비는 Source 폴링이 아님.
- [ ] **P5-2: 작업 수명주기.** 수동/자동 작업 충돌 방지, 취소/진행률,
  오류 분류·backoff·rate limit·재시도·종료/재시작 복구와 상태 UI.
- [ ] **P5-3: Git 증분.** 이전/새 commit 비교, 추가·변경·삭제·이름 변경만 추출/색인,
  branch 변경/force push/불완전한 이력 처리, 변경 없는 경우 멱등성 유지.
  현재는 얕은 clone의 전체 스냅샷 교체이며 Git diff 구현은 없음.
- [ ] **P5-4: 원본 이력·지식 무효화.** 불변 revision 보관/정리 정책,
  변경된 근거에서 관련 지식만 stale 처리, 새 버전 검증 후 게시.
  인간 편집은 자동 덮어쓰기 대신 변경 제안/충돌 해결.
  Source 삭제·재등록, 부분 실패, DB/Lucene 중단 복구 테스트.
- [ ] **P5-5: URL 조건부 수집.** ETag/Last-Modified, 304 처리, 삭제/이동/실패 정책,
  리다이렉트마다 기존 SSRF 방어 유지. 저장소 Workflow는 수정하지 않기.

- [ ] **P2-E3: 격리 파서.** 악성 문서의 별도 프로세스·CPU/메모리/시간 제한,

- [ ] **공통 품질:** 동시 수집/전원 장애/대형 저장소 측정, 깊은 트리 삭제 제한,

- [ ] **공통 런타임:** Mockito 명시적 agent와 Lucene native/vector 경고 검토,
  의존성 취약점/라이선스 점검, 로그 민감정보 제거. 현재 경고와 테스트 실패를 구별해 기록.

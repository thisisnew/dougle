# 0.1.7 — 앱에서 Codex 전용 로그인

구현·실제 AI·Intel 설치 실행·ARM 정적 검증을 마치고 **0.1.7을 공개했습니다.** 두 CPU 설치 파일과 서명 업데이트 피드를 제공합니다.

## 변경

- Mac 앱이 전용 Codex 프로필 경로를 지정합니다. 별도 터미널 없이 기존 AI 연결 화면에서 동의 후 로그인합니다.
- 로그인·연결 확인·초안 생성·답변 스트리밍이 같은 인증 폴더를 사용합니다. 일반 Codex 인증을 복사하거나 변경하지 않습니다.
- 실행 설정의 승인 바인딩에 프로필을 포함합니다. 변경 전 승인은 새 미리보기·승인이 필요합니다. DB v21과 기존 서명 키를 유지합니다.
- [쉬운 사용법과 코드 대조](codex-managed-login.md).

## 검사 과정

- 최초 집중 검사 42건 중 새 프로필 통합 검사 1건 실패: macOS 임시 경로의 `/var`와 실제 `/private/var` 표기가 달랐습니다. 자식 프로세스의 격리 HOME을 실제 경로로 통일한 뒤 새 검사 3건 모두 통과했습니다. 보안 제한을 완화하지 않았습니다.
- 실제 브라우저 로그인은 인증 파일을 만들었지만, CLI가 함께 만든 `log/codex-login.log`를 기존 프로필 검사가 거부했습니다. 해당 이름의 비공개 일반 파일만 허용하고 링크·추가 설정 차단을 유지했습니다. 회귀 검사를 추가했습니다.
- 이후 전체 빌드: Java 377·UI 210 통과, 실제 AI 자동 검사 1 제외. 추가 실제 검사에서 정상 CLI 인증 조회가 15.4초 걸려 기존 5초 제한을 넘었습니다. 제한을 30초로 변경하고 느린 시작 회귀 검사를 추가해 다시 빌드했습니다.
- 브라우저 가상 CLI: 로그인 필요 → 동의 전 버튼 비활성 → 동의·로그인 → 인증 확인 통과. 검사 도구의 `/var` 표기 차이는 실제 경로로 통일했습니다. 첫 화면 대기는 실제 문구가 아닌 `인증 확인`을 찾아 시간 초과했지만 후속 화면에서 정상 완료를 확인했습니다. [실제 화면](images/codex-managed-login.png)은 가상 인증이며 실제 계정 화면이 아닙니다.
- 실제 API 검사의 첫 재실행은 서버 시작 제한 초과, 다음은 인증 조회 제한 초과로 실패했습니다. 보안·출력 분류를 완화하지 않고 원인을 구분했습니다. 최종 결과는 아래를 따릅니다.

## 실제 AI 재검사 — 통과

- 2026-10-24 02:03 KST 시작, 동봉 Intel Java/Codex와 새 JAR의 HTTP API에서 전용 인증·실제 초안·사람 메모 보존·근거 답변·중간 SSE·실행 중 취소를 통과했습니다. `partialObserved: true`. 취소는 모델 전송 전에 처리됐을 가능성을 구분합니다.
- 검증 JAR SHA-256: `a667bf779404ecf792b5298878a98fd7dc5541d053df3e5d826eb5b65195e01c`.
- 전용 브라우저 로그인 뒤 생성된 인증을 CLI가 직접 사용했습니다. 인증 파일은 읽거나 복사하지 않았습니다. 임시 가상 자료만 전송했으며 사용자 DB/회사 자료는 사용하지 않았습니다.
- 직전 검사에서는 인증·초안까지 성공했지만 CLI가 생성한 `.sandbox_migration` 일반 파일을 프로필 검사에서 거부했습니다. 해당 이름만 허용하고 초안 후 스트림 회귀에 포함한 뒤 통과했습니다. 링크·설정·도구 실행 차단은 유지합니다.
- 최종 집중 Java 9건 통과. 이어 전체 Java 379건 중 **378 통과·실제 AI 자동 검사 1 제외**, UI **210 통과**, Rust **17 통과**·fmt·clippy 통과. 실제 AI는 위 별도 opt-in API 결과입니다. 중복 재검사는 합산하지 않습니다.
- 통합 검사 첫 실행은 서버 준비 시간 초과로 실패했습니다. 로그상 초기화 사이에 약 13분의 시간 공백이 있었지만 절전 여부를 단정하지 않습니다. 동일 검사 제한을 유지하고 검사 프로세스 동안만 유휴 절전을 방지해 재검사합니다. 시스템 보안/상시 전원 설정은 변경하지 않습니다.
- 다음 통합 검사는 Source 삭제 HTTP 제한 초과로 실패했습니다. 동일 코드·제한으로 마지막 재실행은 통과했으며, 이어 강제 종료 복구 8개 시나리오도 통과했습니다. 실패를 숨기거나 시간 제한을 늘리지 않았습니다. [통합 측정](performance-phase3-foundation.json) · [복구 결과](crash-recovery-report.json).

## Intel 설치본 검사

- 최종 JAR로 DMG와 서명 업데이트 압축을 다시 만들었습니다. 읽기 전용 마운트·설치 복사본·CPU·ad-hoc 서명·업데이트 서명/버전/JAR 일치 통과.
- 설치 복사본의 실제 React/WebKit에서 Workspace·한글·요청 보호·파일·검색·게시·관계·폴링 OFF·자료 이름/분류 수정·AI 연결 검사 통과. 새 전용 프로필의 로그인 필요 상태와 동의 전 버튼 비활성도 확인했습니다. 이 UI 검사는 외부 AI를 호출하지 않습니다.
- 시스템 Git 없이 내장 Git으로 공개 예제 수집·검색·변경 없는 재동기화 통과.
- 실제 Intel 앱의 격리된 HOME·중복 실행 차단·세션 보호·프로세스 종료·같은 DB 재시작 통과. [측정·범위](native-host-report.json).

## Apple Silicon·측정

- ARM DMG 읽기 전용 마운트·설치 복사본·앱/Java/Codex/Git의 CPU·ad-hoc 서명 정적 검사 통과. 업데이트 압축의 서명·버전·추출 앱·최종 JAR 일치도 통과했습니다. Intel에서 ARM 실행을 검증했다고 보고하지 않습니다.
- 가상 파일 100개 검색 30회: p50 **28.52ms**, p95 **46.19ms**. 실제 Intel 실행 파일 시작 단일 측정 **33,800ms**. 개발 Mac의 작은 자료/당시 부하 기준이며 일반 성능 보장은 아닙니다.
- 전체 목록 325개·테스트/fixture 94개를 재생성했습니다. Java/UI/Rust **605건 통과**이며 반복 실행을 합산하지 않았습니다. 실제 AI 자동 테스트 1건은 제외했고 별도 실제 API는 통과했습니다.

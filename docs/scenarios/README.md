## 먼저 구분할 것

- **이번 목록: 전부 NOT_RUN.** 조건·행동·기대 결과를 설계한 문서입니다. 실행 가능한 테스트 코드나 실행 완료 보고서가 아닙니다.
- **기존 자동 테스트: 508개 통과 기록.** 이번 목록과 개수가 별개입니다. 20개 시나리오에 관련 기존 검사 링크를 달았지만, 전체 시나리오의 통과를 뜻하지 않습니다.
- **기준 버전: 스킬0.8.11 / 봇0.1.9.** 향후 기능이나 외부 서비스 지원을 이미 구현한 것으로 표시하지 않습니다.
- 모든 환경을 완전히 열거할 수는 없습니다. 장애·사용자 제보가 나오면 재현 조건과 기대 결과를 추가합니다.

## 우선 확인할 흐름

1. **정상 문의:** 자료 연결 → 다른 폴더에서 질문 → 필요한 근거 확인 → Slack 자동 답변. 정상 문의에는 DM이 없어야 합니다.
2. **개발자 확인:** 코드·운영 조회 부족 → 담당자 DM → 결과 입력 → 같은 문의를 다시 검증 → 원래 스레드에 답변합니다.
3. **팀 공유:** 두 사람이 같은 지식을 수정 → publish/fetch → 정정·충돌·출처가 사라지지 않아야 합니다.
4. **실패·복구:** 인증 만료, 네트워크 중단, 전송 직후 종료, 중복 이벤트에도 거짓 성공·중복 게시·다른 문의 혼합이 없어야 합니다.
5. **대량 자료:** 1천·1만·10만 파일에서 검색 누락과 시간·호출·토큰을 함께 측정합니다. 무변경 작업과 일부 변경 작업을 따로 봅니다.

**P0 562개**는 유출·잘못된 답변·지식 유실·중복 게시처럼 우선 차단할 문제입니다. 나머지는 기본 동작·사용성·성능을 다룹니다.

## 실행할 때

| 표시 | 뜻 |
|---|---|
| 현행 계약 검증 | 현재 코드·스킬이 약속하는 동작입니다. 실제 통과 여부는 별도 확인합니다. |
| 호스트 도구 필요 | Confluence·DB 등을 읽는 도구가 호스트에 있어야 합니다. 더글에 모든 커넥터가 내장됐다는 뜻이 아닙니다. |
| 보완 여부를 확인할 수용 기준 | 반드시 지키고 싶은 결과입니다. 아직 구현 여부나 검사 범위가 충분한지 확인해야 합니다. |

먼저 합성 자료·Fake Slack·임시 DB로 런타임과 민감정보 검사를 실행합니다. 실제 호스트 평가에는 **독립적으로 작성한 정답·필수 조건·예외·출처**가 필요합니다. 답변 길이나 도구 성공만으로 정확성을 판정하지 않습니다. 외부 모델 평가는 별도 예산이 필요하며 이 목록 생성은 모델을 호출하지 않습니다.

각 실행은 시나리오 ID, 버전, fixture, 관측 결과, 증거, PASS/FAIL/BLOCKED를 별도 결과 파일로 남깁니다. 이 설계 목록을 일괄 PASS로 바꾸지 않습니다. 성능 목표는 동일 환경 기준 측정 후 정하며 임의로 초 단위를 약속하지 않습니다.

기본 실행은 회사 원본·실제 Slack·키체인에 접근하지 않습니다. 회사 환경 수용 검증은 별도 승인된 시험 채널·계정으로 [회사 확인 항목](../dougle-bot/company-acceptance.md)을 따라 진행합니다.

## 현재 범위의 경계

- Slack 봇은 멘션을 받습니다. 멘션 없는 채널 전체 자동 감지는 아직 별도 설계입니다.
- 봇은 검증 완료 답변을 기본 자동 게시합니다. **schedule은 다른 기능**이며 여전히 본문별 승인 후 게시합니다.
- DM 결과 입력은 해당 문의 카드에서 합니다. 자유 DM이나 DM 이미지가 자동으로 문의에 반영되는 기능은 아닙니다.
- 별도 reload·자동 publish·지식용 SQLite를 가정하지 않습니다. 질문에 필요한 범위를 확인·갱신하고 공유는 명시적으로 수행합니다.

## 목록 갱신

원본은 [build-scenarios.mjs](../../scripts/build-scenarios.mjs)입니다. 변경 후 아래 명령으로 JSON·CSV·영역별 문서를 함께 생성합니다.

```sh
node scripts/build-scenarios.mjs
node scripts/build-scenarios.mjs --check
```

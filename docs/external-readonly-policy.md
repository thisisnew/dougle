# 외부 업무 시스템 엄격한 읽기 전용 정책

## 현재 적용 설치 — 2026-10-26

사용자 명시 요청으로 부모가 읽기 전용 정책 반영 Intel 0.1.22/e0e43e10 JAR를 로컬 시험 설치했고, 기존 앱+DB를 비공개 백업한 뒤 DB v28·비인증 API 403을 확인했다(부모 보고, 자격 증명 복사 없음). [설치 기록](macos-install.md). **로컬 설치 승인은 외부 업무 쓰기·추가 AI 호출·공개 릴리스·업데이트 피드 승격 승인이 아니다.** 공개는 계속 보류하며 실제 AI 시간 초과 원인·전체 인수는 미완료다. 아래 설치 보류 표현은 해당 검증 당시 이력으로 보존한다.

2026-10-26 최신 사용자 결정. 이 정책은 과거의 명시적 Slack 게시 승인 기능·문서·E35 기준보다 우선한다. **승인 여부와 무관하게 앱은 외부 업무 시스템을 변경하거나 메시지를 게시할 수 없다.** 문서 변경은 코드 차단이나 회귀 검증 완료를 뜻하지 않는다.

## 경계

| 대상 | 허용 범위 | 금지 범위 |
|---|---|---|
| Slack | 승인된 범위의 문의 읽기, 로컬 요약/초안, 기존 영수증 조회 | 메시지/답글 게시·편집·삭제, 반응/채널/멤버십 변경; 사용자 승인·과거 승인·재시작도 예외 아님 |
| 외부 DB | 읽기 전용 계정과 검증된 제한 조회 | INSERT/UPDATE/DELETE/DDL, 저장 프로시저·함수·다중문·파일 접근 등 변경/부작용 우회 |
| 외부 웹/브라우저 | 허용된 사이트·계정·범위의 조회 | 저장·삭제·제출·게시 등 업무 변경, 변경 API 직접 호출, 승인 클릭으로 우회 |
| 기타 업무 연결 | 최소 권한으로 허용된 조회 | 원본 문서/티켓/설정/레코드 생성·수정·삭제 또는 외부 전달 |
| 앱 로컬 상태 | Workspace·대화·근거·색인·설정·읽기 캐시의 필요한 저장/삭제 및 승인된 로컬 가져오기/내보내기 | 로컬 저장 권한을 외부 시스템 쓰기 권한으로 확장 |

읽기 전용은 모든 네트워크 요청을 금지하거나 HTTP GET만 허용한다는 뜻이 아니다. 일부 조회는 POST를 사용하므로 실제 효과·제공자 메서드·SQL·브라우저 동작을 검증해야 한다. 외부 AI로 근거를 보내는 별도 명시적 동의 경계는 유지하지만, 그 동의나 모델의 도구 제안은 외부 업무 시스템 변경을 허용하지 않는다. 실제 AI 검사는 별도로 승인한 유한 배치만 수행하며 실패를 자동 재전송하지 않는다.

## 강제 지점과 남은 검증

- 전송 UI를 숨기는 것만으로 충분하지 않다. Backend dispatcher/adapter 및 직접·과거 API 요청에서도 외부 변경을 거부해야 한다. 새 전송 승인/preview/execute 경로가 외부 dispatch를 다시 활성화해서는 안 된다.
- 이미 저장된 Slack 답장 영수증/이력은 보존한다. 읽기 전용 조회는 가능하되 과거 PREVIEW/SENDING/UNCERTAIN/승인 데이터·멱등 키·재시작으로 발송을 복구하거나 성공을 조작하지 않는다. 새 정책 적용을 위해 사용자 이력을 일괄 삭제하지 않는다.
- 권한·연결 화면은 외부 게시 권한을 요구하거나 추천하지 않는다. 기존 연결에 넓은 권한이 있더라도 앱 자체 경계에서 쓰기를 차단한다.
- DB 변경·부작용과 브라우저 변경은 기존 조회 제한과 함께 검증한다. 취소/재시작/동시성/직접 transport 호출을 포함한 부정 테스트에서 제공자 변경 dispatch 0회를 측정한다. 실제 외부 쓰기로 차단을 시험하지 않는다.
- 이 문서는 정책/검사 요구이며, 구현 담당자의 소스 변경·모의 경계 회귀·새 아티팩트 검증 전까지 **강제 완료로 보고하지 않는다**.

## 아티팩트·배포 보류

### 현재 검증 범위

읽기 전용 후보 JAR는 `e0e43e1084177ea4d28530547cc762bce339d2de2f5721d21ce70d0ef4eeb58d`다. Java1004실행/997통과/opt-in7건너뜀(기존 무관 fixture 두 클래스 제외), UI668개·빌드를 확인했다. [격리 런타임 검사](evaluations/readonly-runtime-e0e43e10-20261026.json)는 전송 API300건의 `READ_ONLY` 거부·재시작2회·기존 영수증3개 보존·새 전송 작업0건을 기록한다. 관측 프록시 요청0건은 모든 네트워크 시도0건의 증명이 아니다.

[0.1.22 후보 패키지](evaluations/macos-package-0.1.22-20261026.json)는 양쪽 CPU 정적 검사와 Intel 네이티브 실행을 통과했다. 실제 AI 시간 초과와 남은 인수 검증 때문에 설치·공개·업데이트 피드 승격은 보류한다. ARM 실기기·실제 회사 서비스·E35 전체 인수는 완료하지 않았다.

### 이전 소스 검증 단계 기록

아래 수정 중·새 JAR 미생성 문구와 검사 수는 당시 상태이며 현재 상태는 위 기록을 따른다.

- 현재 작업 메타데이터는 **0.1.22 / DB v28**이다. 소스에서 Slack 게시 preview/execute/재승인을 거부하고 HTTP 게시 구현을 제거했으며 기존 영수증 조회를 보존한다. Git 명령 allowlist와 MCP 읽기 호출/엄격한 매개변수 검증도 소스 회귀 범위다.
- 부모 담당자 보고: 읽기 전용 Java **237실행/235통과/opt-in2건너뜀**. 인증정보 관련74개는 별도 중복 가능 검사로 합산하지 않는다. 최신 UI **62파일/668테스트 및 빌드 통과**는 읽기 전용 영수증·Slack 명시적 누락 스레드 복구·추출형 문맥 생략 표시를 포함한다. 소스/모의 회귀이지 실제 외부 변경 요청을 보낸 검사가 아니다.
- 장기 문맥 표적 Maven은 실패 후 담당자가 수정 중이다. 소스 동결·백엔드 전체 통과를 주장하지 않는다. **현재 소스의 새 JAR/패키지는 아직 없고 새 아티팩트 런타임 검증도 미실행**이다. 이전 JAR의 성공을 새 소스에 귀속하지 않는다.
- E05 오프라인 하네스36개 통과는 평가 도구 검증뿐이다. 실제 AI/장기 문맥 시험은 새 아티팩트와 명시적 유한 승인 전까지 보류한다. 이 검사나 읽기 전용 단위 회귀만으로 E35를 승격하지 않는다.

Slack 전송 경로를 포함한 0.1.21 스냅샷 및 JAR `675a7c59e13edc8ee849b23977699e600331555d8f53c669ef8e7f10406e3489`는 설치·공개·배포하지 않는다. 이미 진행한 정적 패키지 검사는 미배포 과거 스냅샷 증거로만 남긴다. 동일 버전 번호나 과거 테스트 통과를 정책 준수 증명으로 취급하지 않는다. 차단 구현과 검증을 거친 새로운 해시가 필요하며, 그 이후 설치/배포도 별도 승인을 따른다.

E01–E03/E12의 4 PASS는 위 과거 JAR의 제한된 합성 의미 평가다. 이 결과를 새 읽기 전용 정책·E35·전체 제품 안전성 PASS로 전환하지 않는다. E35의 과거 “승인하면 게시” 기준은 폐기됐고, 새 “승인해도 외부 전송 0회” 기준은 아직 NOT_RUN이다. 실제 이력 JSON과 과거 답장 설계는 삭제·재해석하지 않고 역사적 범위로 보존한다.

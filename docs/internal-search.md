# Dougle의 자료 수집과 검색

Dougle은 파일·폴더·웹 링크·GitHub에서 본문을 추출하고 나눠 검색합니다. Mac 설치본에 다국어 검색 엔진을 포함하며 앱이 자동으로 준비합니다. 키워드·로컬 벡터 검색 후보를 재순위화하고, 준비 중에는 새 질문을 잠급니다. 별도 검색 파일 설치나 활성화는 필요하지 않습니다. 답변 생성용 AI와 검색 모델은 별개이며 자료 등록만으로 외부 AI를 호출하지 않습니다. [현재 처리 한도·검증 상태](ingestion-retrieval-upgrade.md).

사용자는 **자료를 넣고 질문**합니다. 검색을 위해 지식 문서를 직접 만들거나 편집할 필요가 없습니다.

앱은 등록된 자료에서 텍스트와 코드 심볼을 추출하고 검색 색인을 관리합니다. 질문을 보내면 이 내부 자료에서 근거를 찾아 AI 답변을 시작합니다. 질문 전송을 관련 자료 전송 동의로 처리하며 출처는 답변 아래에 표시합니다. 자료 등록만으로 AI를 호출하지 않습니다.

```mermaid
flowchart LR
  A[사용자: 자료 등록·동기화] --> B[앱 내부: 텍스트·심볼 추출]
  B --> C[앱 내부: 검색 색인]
  D[질문] --> C
  C --> E[관련 근거 선정]
  E --> G[AI 답변: 질문 전송으로 동의]
  G --> H[답변 완료 후 인용 출처]
```

## 바뀐 점

![Dougle 대화 화면](screenshots/dougle-chat.png)

- 지식 문서 메뉴와 원본 화면의 문서 생성·편집 진입점을 없앴습니다.
- 새 대화 질문은 원본 기반 검색만 사용합니다. 예전 편집형 지식 문서는 새 질문의 근거에 포함하지 않습니다.
- 예전 문서·답변은 삭제하지 않습니다. 지식 문서를 포함한 미완료 질문은 그대로 전송하지 않고 **원본으로 다시 질문**합니다. 완료한 답변은 그대로 읽을 수 있습니다.
- 원본을 갱신하면 기존 수집·분석·색인 경로로 검색 정보가 갱신됩니다. 질문할 때 모든 자료를 처음부터 분석하지 않습니다.

## 구현 범위

검색 순서는 앱 코드가 제어합니다. AI가 임의의 셸 명령이나 검색 계획을 만들어 실행하지 않습니다. Java가 수집·분할·Workspace 필터·후보 검색·재순위화·근거 구성을 수행하고, 답변 AI는 그 근거를 받아 글을 생성합니다. 검색 모델은 고정 버전으로 로컬 점수만 계산하며 자료 접근 권한이나 도구 실행 권한이 없습니다. 모델 점수는 의미 판단의 근사치이므로 고정 가상 평가셋과 실패 사례로 검증하며 사실 보증으로 취급하지 않습니다.

현재 자동 관리하는 검색 정보는 **추출문·심볼·문단/코드 조각·Lucene 색인·로컬 벡터**입니다. 의미 검색이 모든 표현을 이해하거나 답변의 사실성을 보장하는 것은 아닙니다. 요약 문서를 자동 생성·게시하지 않습니다. 출처는 완료 답변의 실제 인용 번호에 해당하는 자료만 표시합니다.

## 조각 검색과 답변 문맥

의미 검색용 조각은 최대 768자로 나눕니다. 모델 입력 한도 때문에 긴 조각의 뒷부분이 사라지는 것을 줄이고, 같은 문서의 여러 조각을 먼저 평가한 뒤 문서 중복을 제거합니다. 재순위화 점수만 낮더라도 벡터 유사도가 높은 후보를 제한적으로 보존합니다. 점수는 정답 확률이 아닙니다.

답변 근거를 고정할 때는 원문 해시와 Workspace를 다시 확인합니다. 6,000자 이내 문서는 남은 근거 예산 내에서 전체 문맥을 제공하고, 큰 문서는 검색 조각 전후를 최대 2,400자로 확장합니다. 전체 12,000자·5개 자료 한도는 유지합니다. 검색·필터·문맥 확장은 Java 코드이며 AI가 임의 검색 스크립트를 만드는 방식이 아닙니다.

Notion MCP 응답의 JSON 문서 포장을 해제하고 본문·제목을 저장합니다. 기존 수집본은 다시 동기화해야 이 정리가 적용됩니다. 이미 저장한 답변 근거는 변경하지 않습니다.

기존 문서 DB와 호환 API는 보존합니다. 화면에서 편집 진입점을 제거한 것이지 로컬 API를 폐지하거나 새 보안 권한 체계를 추가한 것은 아닙니다. 명시적으로 `includeKnowledge=true`를 사용하는 예전 API 호출은 유지됩니다. 과거 답변을 사용자가 직접 문맥으로 고르는 고급 경로는 새 질문의 기본 검색과 별개입니다.

| 규칙 | 코드·검사 |
|---|---|
| 메뉴·문서 생성 진입점 제거 | `App.tsx`, `AnalysisPanel.tsx`, `App.test.tsx` |
| 원본만 근거로 선택 | `ChatPanel.tsx`: `includeKnowledge=false`, `ChatPanel.test.tsx` |
| 편집형 문서 검색 제외·문서 보존 | `EvidenceBundleIntegrationTest.originalOnlyQuestionsIgnoreEditableKnowledgeButPreserveTheDocuments` |
| 이전 미완료 질문 재검색 | `ChatPanel.tsx`, `ChatPanel.test.tsx` |

DB v25는 파일별 분석 체크포인트와 실패 기록을 추가합니다. 원본 보관·Workspace 격리·질문 전송 승인 계약은 유지합니다.

# 답변 상태가 자동으로 바뀌는 화면

후속 [Claude 미검증 임시 출력](partial-answer.md)을 추가했습니다. 아래는 상태 UI 도입 당시 기록이며 Codex는 여전히 완료 답변만 표시합니다.

2026-10-22 · SQLite v16 유지. [SSE API 계약](answer-events.md)은 그대로입니다.

## 사용법 — 세 가지만 기억하세요

1. 근거와 요청을 확인하고 승인한 뒤 **답변 시작**을 누릅니다. 외부 전송 동의는 여전히 필요합니다.
2. 실행 중이면 **SSE 연결 상태**가 표시되고, 근거 확인 후 상태·완료 답변이 자동으로 바뀝니다.
3. 끊겼으면 잠시 기다리거나 **답변 작업 조회·새로고침**을 누르세요. 이 버튼은 AI를 새로 호출하지 않습니다.

**작업을 멈추려면 답변 중단을 누르세요.** 창 닫기·Workspace 전환은 관측 연결만 닫습니다.
이미 저장된 완료 답변은 목록 조회로 바로 표시합니다. SSE는 실행 중인 선택 작업에만 연결합니다.
근거 원문·출처는 위의 근거 묶음에서 확인합니다. 연결 상태의 “근거 확인”은 묶음 식별 정보 확인이며 최신성/사실성 검증이 아닙니다.
답변은 완성 후 한 번에 표시합니다. 글자 단위 출력·다중 대화는 아직 없습니다.

## 실제 구현과 대조

```text
AnswerJobsPanel
  ├─ 승인 후 시작 / 중단: 기존 POST API
  ├─ 수동 목록 조회: 기존 GET API
  └─ 실행 중 선택 작업 → observeAnswerJob → EventSource GET
      근거 ID·Workspace 확인 → 작업 ID·범위·형식 확인 → 상태 교체
      완료/오류 → 연결 종료
```

| 코드 | 담당 |
|---|---|
| `frontend/src/answerJobEvents.ts` | SSE 연결, 이벤트 순서/식별 검사, 연결 수명·재연결 |
| `frontend/src/AnswerJobsPanel.tsx` | 상태와 텍스트 답변 표시, 명시적 전송/중단, Workspace·묶음별 화면 초기화 |
| `AnswerJobEventsController` | 기존 읽기 전용 SSE API, 이번 변경 없음 |

- 기존 800ms 브라우저 폴링을 제거했습니다. 서버의 500ms DB 상태 관측은 유지됩니다.
- 브라우저의 무제한 자동 재연결 대신 연결을 닫고 **1초→2초→4초, 최대 3회** 오류 재시도합니다.
- 성공 이벤트를 받아도 오류 횟수는 해당 관측의 누적으로 유지됩니다. 수동 목록 새로고침/새 관측에서 초기화됩니다.
- 정상 55초 연결 교체는 1초 뒤 다시 연결하며 오류 횟수에 포함하지 않습니다. 65초 무응답 보호 타이머도 있습니다.
- 완료 상태 수신 즉시 닫습니다. `unavailable`·잘못된 순서/다른 Workspace/다른 작업 응답은 표시하지 않고 관측을 중지합니다.
- 재연결마다 근거부터 다시 확인합니다. 이벤트는 추가 누적하지 않고 작업 ID로 교체합니다.
- 관측 종료 후 늦게 도착한 이벤트는 무시합니다. Workspace/묶음 전환은 화면 상태와 진행 중 HTTP 요청도 정리합니다.
- 전송/중단/새로고침 요청 중에는 기존 관측을 닫아 늦은 SSE가 명시적 요청 결과를 덮어쓰지 못하게 합니다.
- HTML·이미지·링크를 실행하지 않고 `<pre>`의 텍스트로 답변을 표시합니다. 지식 자동 게시도 없습니다.

## 테스트와 남은 범위

단위 테스트는 가짜 EventSource로 이벤트 순서, Workspace/작업 혼입 차단, 미완료 답변 거부,
완료 즉시 종료, 재연결 한도·정상 교체·무응답 보호, 삭제 오류, 타이머 정리를 확인합니다.
화면 테스트는 SSE 답변 표시, HTML 비실행, 중단 뒤 늦은 결과 무시, Workspace 전환,
수동 새로고침 재관측·언마운트 정리와 GET만으로 재조회함을 확인합니다.

실제 CLI 토큰 출력·다중 대화·장시간 단절/느린 클라이언트 부하 검증과 Mac 설치형은 남았습니다.
네이티브 EventSource는 HTTP 오류 코드를 직접 노출하지 않아 연결 실패는 공통 안내로 표시합니다.
외부 AI 실호출이 아닌 fake CLI/가상 자료만으로 검증합니다.

| ego-browser + 격리 임시 DB + 느린 fake CLI | 답변 표시 전에 SSE 근거 확인 상태 확인, 완료 답변 `[R1]` 수신, 별도 작업 중단→중단됨 확인 |

브라우저의 실제 네트워크 단절·장시간 재연결은 이번에 수동 재현하지 않았습니다. 재연결 정책은 가짜 EventSource/타이머 테스트로 검증했습니다.
성능 파일은 작은 가상 자료 검색의 재측정 결과이며 SSE 부하나 실제 AI 성능을 뜻하지 않습니다.

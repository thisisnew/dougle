# 원격 파일 경로 탐색 회귀 검증

구현 순서: 사례 정의 → 구현 → 테스트 → 독립 검토.

| 사례 | 기대 결과 |
| --- | --- |
| 클래스명만 알고 전체 경로 모름 | 등록 ref의 원격 트리에서 파일명을 찾아 같은 commit 파일 읽기 |
| 같은 파일명이 여러 모듈에 있음 | 모든 후보 경로 반환, 임의 선택하지 않음 |
| 파일 없음 | 완전한 트리 검색의 빈 결과, 권한 오류로 표현하지 않음 |
| 트리가 잘렸거나 응답 한도 초과 | 불완전 검색 오류, 파일 없음으로 단정하지 않음 |
| 등록되지 않은 저장소/ref | 조회 차단 |
| 탐색 후 ref 변경 | 기존 expected_commit 검사로 불일치 차단 |
| 탐색 결과만 있고 내용 읽기 없음 | 코드 근거로 인정하지 않음 |
| 반복 파일명 검색 | commit은 다시 확인하고 동일 immutable tree는 캐시 재사용 |
| 기존 정확한 경로 읽기 | 기존 동작 유지 |

실제 회사 Slack 수용 검증은 로컬 합성 테스트와 구분합니다.

## 검증 결과

- 전체 자동 테스트 1,550건 통과 (89.57초). 파일명 탐색 신규 사례 29건 포함.
- 독립 서브에이전트 검토: 차단 사항 없음. 검색 결과만으로 근거가 생성되지 않는 것과 같은 commit의 실제 파일 읽기를 별도 확인했습니다.
- Ruff, 스킬 구조·공유 병합·현재 트리·민감정보 검사, Claude 플러그인 검증 통과.
- 원격 응답·CLI·Slack은 합성 테스트입니다. 실제 회사 저장소 및 Slack 수용 검증은 실행하지 않았습니다.
- GitHub 트리 응답이 잘리거나 기존 8MiB 응답 한도를 넘으면 불완전 검색 오류로 종료합니다. 파일이 없다고 단정하지 않습니다.

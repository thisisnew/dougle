# 바로 답하고, 어려운 건 내부에서 확인합니다

`@dougle 질문 → 필요한 근거 확인 → 원래 스레드에 답변`

일반 문의에는 DM이 오지 않습니다. 운영 조회·코드 확인·개발자 도움·내부 오류가 있을 때만 기존 `approver_user_id`로 DM을 보냅니다. 설정 이름은 호환을 위해 유지합니다.

## 문의별 동작

| 상황 | 고객 대화 | 내부 처리 |
|---|---|---|
| 확인한 답변 | 간결한 존댓말로 바로 답합니다. | 추가 승인·DM 없음 |
| 질문이 모호함 | 필요한 정보 한 가지만 묻습니다. | `cannot_answer`의 명확화 답변 |
| 관련 자료 없음 | 확인한 범위에서 찾지 못한 내용을 알립니다. | 구체적인 개발자 확인으로 해결 가능하면 내부 요청 |
| 운영·코드 확인 필요 | 미확인 답변을 게시하지 않습니다. | `needs_lookup`: 대상·확인 사항·검증된 SELECT를 DM에 표시 |
| 시간 초과·내부 오류 | 내부 오류나 재시도 지시를 게시하지 않습니다. | `failed`: 점검 안내와 처리 결과 입력 |
| 전송 여부 불명 | 중복 답변을 보내지 않습니다. | `post_unknown`: 내부 알림, 긍정적인 전송 증거로만 복구 |

개발자 결과를 입력하면 같은 문의·스레드에서 답변을 이어갑니다. 부족한 결과는 남은 확인만 요청합니다. 고객에게 대기 안내를 자동으로 먼저 보내는 기능이나 완료 시간 약속은 추가하지 않았습니다.

운영 조회는 설정된 BigQuery 읽기 도구를 먼저 탐색하고 대상·스키마·최신성을 확인하도록 지시합니다. 연결 불가나 데이터 지연이 확인되면 필요한 운영 조회만 요청합니다. 이 절차의 모델 준수와 회사 연결 성공은 별도로 검증해야 합니다.

DM은 확인 대상과 막힌 이유·확인할 내용·필요한 결과를 구분합니다. 검증하지 못한 SQL은 제외하고 확인 요청은 유지합니다. 이때 필수 근거 검사를 생략하지 않습니다. 담당자 입력 대기는 `dougle` + `speech_balloon`, 실제 처리 중은 `dougle` + 모래시계로 표시합니다.

## 입력과 근거

- **확인 결과 입력:** 요청한 코드·운영 상태·업무 자료의 비민감 요약만 받습니다. 제출 시각은 내부에서 기록하며 실제 조회 시각으로 간주하지 않습니다. SQL·운영 행·토큰을 고객에게 전달하지 않습니다.
- **처리 결과 입력:** 환경이나 연결을 고친 내용을 받습니다. 이 보고 자체는 코드·운영 조회를 수행한 근거가 아니므로 필요한 자료를 다시 읽습니다.
- 담당자·워크스페이스·문의·카드·최신 실패 작업 또는 답변을 확인합니다. 중복 제출은 작업 하나만 만듭니다.
- 자유롭게 보낸 DM이나 이미지는 임의 문의에 연결하지 않습니다. 해당 카드 버튼을 사용합니다.
- 보고 근거는 해당 문의의 요청된 종류로 제한합니다. 원래 조사 의무는 재시도와 개발자 처리 후에도 유지합니다. 개발자 보고를 실제 AI 조회로 표시하지 않습니다.

## 자동 게시와 복구

답변·엔진 작업 완료·자동 게시 준비 표식을 같은 SQLite 트랜잭션에 저장합니다. 저장 직후 앱이 종료되면 AI를 다시 부르지 않고 저장된 답변의 게시를 진행합니다.

자동 게시 시도도 먼저 기록하고, 최신 답변·허용 채널·스레드 변경·민감정보·말투를 검사합니다. 원격 Slack 조회와 게시를 하나의 트랜잭션으로 잠글 수는 없습니다. 시도 도중 중단되면 무조건 재전송하지 않고 내부 확인으로 넘깁니다. 전송 오류·다중 메시지 일부 성공은 중복 방지 규칙을 유지합니다. 상태 복구 후 남은 내부 확인 건은 같은 DM으로 알립니다.

정상 답변은 `auto_post`로 기록합니다. 승인자 클릭으로 위장하지 않습니다. 엔진은 Slack 쓰기 도구를 사용할 수 없으며 실제 전송은 봇 런타임만 수행합니다.

## 기존 사용자

스킬0.8.11 / 봇0.1.9부터 기본 자동 답변입니다. 기존 config에 `require_approval`이 없어도 자동 모드가 됩니다. 새 실행 환경 준비 후 중지·시작이 필요하며 토큰·Slack scope 변경은 없습니다. 예전 승인 대기 답변은 자동 게시하지 않습니다.

명시적인 `[slack] require_approval = true`는 기존 검토 모드를 유지합니다. 기존 지식·설정·세션·문의 기록은 보존합니다. `reply_mode`는 설정값이며 실행 중인 오래된 프로세스에는 적용되지 않으므로 `running_version`과 `update_required`도 함께 확인합니다.

## 검증 범위

[자동 테스트 기록](implementation-verification.json)에 실제 실행 목록을 남깁니다. Fake Slack/engine, 실제 SQLite와 Bolt 이벤트 처리로 자동 게시·DM 분기·담당자 결과·중복·재시작·전송 오류·구버전 경계를 검증합니다. 회사 계정·키체인·실제 AI를 호출하지 않았습니다.

모델이 질문을 항상 올바르게 분류하거나 담당자 설명을 정확하게 해석한다는 보장은 아닙니다. 토큰·개인정보 검사는 보수적인 패턴 검사이며 모든 회사 기밀의 공유 권한을 자동 판별하지 않습니다. 허용 채널과 자료 접근 범위는 운영자가 지정합니다.

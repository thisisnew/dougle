# 회사 PC 수용 검증

현재 기본 자동 모드로 아래 항목을 먼저 확인하세요. 회사 Slack·키체인·자료 연결은 개발 환경의 가짜 서비스 테스트와 별도로 검증합니다. 이 문서의 회사 시험은 실행 결과를 기록하기 전까지 모두 `NOT_RUN`입니다.

자동 검증을 통과한 빌드에서 지정한 비공개 시험 채널과 담당자 DM만 사용합니다. 토큰이나 원시 회사 데이터를 결과·Git에 남기지 않습니다. 각 항목에 빌드 커밋, macOS/Python/Claude/Slack SDK 버전, 실행 시각, `PASS`·`FAIL`·`BLOCKED`·`NOT_RUN`, 비밀 없는 관측 결과를 기록하세요. 준비되지 않은 권한이나 시험 사용자가 필요하면 통과로 바꾸지 말고 차단 원인을 남깁니다.

[현재 동작](internal-handoff.md) · [자동 검증](test-cases.md) · [전체 테스트 계획](TEST_PLAN.md)

## 현재 자동 모드

- [ ] **BOT-AUTO-001** 새 회사 M Mac에서 README대로 설치하고 실제 키체인 입력·읽기·취소를 확인합니다. 문서에 없는 개발 PC 파일 없이 시작되며 토큰이 argv·셸 히스토리·대화에 남지 않아야 합니다.
- [ ] **BOT-AUTO-002** 회사 Claude 명령과 설치된 스킬로 실제 문의를 처리합니다. 회사 계정·허용 도구·세 필수 스킬을 사용하고 설치 확인을 답변 성공으로 대신하지 않아야 합니다.
- [ ] **BOT-AUTO-003** 자동 모드에서 근거가 충분한 질문을 멘션합니다. 원래 스레드에 한 번 답하며 일반 문의의 승인 DM이나 대기 안내가 없어야 합니다. 출처 목록·인용 번호·서명도 붙이지 않습니다.
- [ ] **BOT-AUTO-004** 모호한 질문과 자료에 답이 없는 질문을 각각 보냅니다. 필요한 정보를 묻거나 확인하지 못한 범위를 설명하고, 자료가 없다는 이유만으로 기능이나 데이터가 없다고 단정하지 않아야 합니다.
- [ ] **BOT-AUTO-005** 코드·현재 운영 상태 확인이 필요한 문의를 보냅니다. 허용된 읽기 도구로 확인 가능한 범위를 먼저 조사하고, 부족한 확인만 지정 담당자에게 DM으로 요청해야 합니다. 검증하지 못한 SQL은 표시하지 않습니다.
- [ ] **BOT-AUTO-006** 개발자 확인 DM 전송 후 고객 스레드를 확인합니다. 아래 고정 대기 안내가 한 번 표시되고 SQL·내부 오류·완료 시각 약속이 없어야 합니다.

  > 추가 확인이 필요해 담당 개발자에게 요청했습니다. 확인되면 이 스레드에 이어서 답변드리겠습니다.

- [ ] **BOT-AUTO-007** 해당 DM 카드에 비민감 확인 결과를 제출합니다. 시간 입력 없이 처리되고, 보고 근거임을 구분한 최종 답변이 원래 스레드에 게시되어야 합니다. 다른 문의의 답변에 섞이지 않아야 합니다.
- [ ] **BOT-AUTO-008** 부족하거나 모순된 결과를 제출합니다. 남은 확인을 요청하고 대기 안내를 반복하지 않아야 합니다. 조회·근거 검증이 끝나지 않은 내용을 확정 답변으로 보내면 실패입니다.
- [ ] **BOT-AUTO-009** 허용된 시험 환경에서 연결 실패·시간 초과를 확인하고 **처리 결과 입력**으로 복구 내용을 제출합니다. 오류는 담당자 DM에만 표시하고, 복구 보고만으로 사실을 확정하지 않으며 필요한 자료를 다시 읽어야 합니다.
- [ ] **BOT-AUTO-010** 대기 안내 후 앱을 재시작하고 DM 카드를 다시 갱신합니다. 안내를 다시 보내지 않고 개발자 결과를 받아 같은 스레드에서 답변을 마쳐야 합니다. 같은 스레드의 별도 문의는 서로 구분해야 합니다.
- [ ] **BOT-AUTO-011** 통제 가능한 시험 환경에서 DM·안내·최종 답변의 전송 실패를 각각 확인합니다. DM 성공이 확인되지 않으면 안내가 없어야 합니다. 안내 실패·전송 불명 후에는 자동 재전송 없이 결과 처리를 이어가며, 최종 답변 전송 불명도 중복 게시하지 않아야 합니다. 재현 환경이 없으면 `NOT_RUN`으로 남깁니다.
- [ ] **BOT-AUTO-012** 카드 중복 제출, 오래된 카드, 권한 없는 사용자의 입력을 확인합니다. 작업이 중복 생성되거나 잘못된 결과가 반영되지 않아야 합니다. 일반 DM 텍스트·이미지도 임의 문의에 연결하지 않습니다.
- [ ] **BOT-AUTO-013** 작성 중 고객 정정, 중지·재시작, 스레드 후속 질문과 별도 문의를 확인합니다. 변경된 질문에 오래된 답을 게시하지 않고 중지 중 문의를 나중에 가져오지 않으며 세션이 섞이지 않아야 합니다.
- [ ] **BOT-AUTO-014** PNG/JPEG·여러 이미지·흐린 글자·과거 캡처·첨부 변경과 권한·용량·형식 오류를 확인합니다. 지원 범위에서 실제 표시 내용과 답이 맞아야 하며 일부 첨부를 조용히 빼거나 과거 화면을 현재 상태로 단정하지 않아야 합니다.
- [ ] **BOT-AUTO-015** 정답이 있는 업무 질문, 같은 이름의 다른 프로젝트, 낡은 자료, 충돌하는 근거, 합성 공격 지시를 시험합니다. 사실·조건·예외·근거가 맞고 존댓말을 유지하며 원본 변경·비밀 출력·허용 범위 밖 게시가 없어야 합니다.
- [ ] **BOT-AUTO-016** 실제 지연·큐 대기·비용·절전 후 연결 상태를 기록하고 상태 화면과 로그를 확인합니다. CLI 관측치와 회사 실측·확정 청구액을 구분하며 질문·자료 원문·토큰이 진행 로그에 없어야 합니다.
- [ ] **BOT-AUTO-017** 업데이트 후 실행 버전과 `reply_mode`를 확인합니다. 설정에 `require_approval`이 없으면 자동 모드이며, 예전 승인 대기 답변은 자동 게시되지 않아야 합니다. 명시적 `require_approval = true`에서는 승인 후 게시하고 자동 대기 안내를 보내지 않아야 합니다.
- [ ] **BOT-AUTO-018** 팀 공개 전에 자료 소유자·운영자와 출처·채널 공유 범위를 확인합니다. 개인 시험 성공을 팀 전체 공개 승인으로 간주하지 않습니다. 계정 권한 변경·로그인 만료도 확인하고 다른 개인 계정으로 조용히 전환하지 않아야 합니다.

## 0.8.3 추가 회사 검증 (미실행)

- 파일 권한 없이 PNG+질문: 읽지 못했다는 DM만 받고 사실 답변이 만들어지지 않는지 확인합니다.
- files:read 추가·앱 재설치 후 PNG/JPEG+멘션: 화면의 실제 값과 답변이 일치하는지 확인합니다.
- 이미지 2장 비교, 같은 스레드 후속 질문, 흐린 글자, 현재 상태로 단정할 수 없는 과거 캡처를 확인합니다.
- 이미지 교체/삭제 후 옛 게시 버튼: 재승인을 요구하는지 확인합니다.
- 5장·장당5MiB초과·합계12MiB초과·HEIC·외부 미리보기: 오류 안내를 확인합니다.
- 위치/시간/후속 질문은 필요한 내용만 답하고, 상세 요청과 중요한 예외는 생략하지 않는지 확인합니다.
- 스킬 업데이트뿐 아니라 실행 봇0.1.3 재시작을 확인합니다. 채널 자동 감지는 아직 설계 단계입니다.

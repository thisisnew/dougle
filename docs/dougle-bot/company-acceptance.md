# 회사 PC 확인 체크리스트

**기본20개 및 아래 추가 항목은 개발 환경에서 실제 회사 연동으로 실행하지 않았습니다.** 개발 환경의 Fake 테스트와 합산하지 않습니다.

자동 검증이 통과한 빌드에서 사람이 수행합니다. 실제 Slack 전송은 지정한 비공개 시험 채널과 승인자 DM에 한정하고, 토큰/원시 회사 데이터는 결과나 Git에 남기지 않습니다. 실행하지 못한 항목은 NOT_RUN 또는 실제 차단 원인을 기록하며 통과로 바꾸지 않습니다.

각 항목 기록: 빌드 커밋, macOS/Python/Claude/Slack SDK 버전, 실행 시각, PASS/FAIL/BLOCKED/NOT_RUN, 비밀 없는 관측 결과. 실제 토큰이나 타인 채널 접근 없이 준비할 수 없는 상황은 임의로 수행하지 않습니다.

[전체 테스트 계획](TEST_PLAN.md) · [자동 검증](test-cases.md)

- [ ] **BOT-MAN-001** — 회사 M Mac의 새 사용자 환경에서 README 순서로 설치합니다.
  통과 기준: 문서에 없는 개발 PC 파일 없이 설치되고 회사 자료/토큰을 테스트 저장소에 넣지 않습니다.

- [ ] **BOT-MAN-002** — 실제 키체인에 interactive 방식으로 토큰을 저장하고 취소/읽기/삭제를 확인합니다.
  통과 기준: 입력이 노출되지 않고 argv/셸 히스토리에 토큰이 남지 않으며 사용자 승인 없이 키체인 조작하지 않습니다.

- [ ] **BOT-MAN-003** — 회사 실행 명령과 실제 설치된 dougle-ask로 헤드리스 질문을 수행합니다.
  통과 기준: 올바른 회사 계정/도구/스킬을 사용하고 설치 확인만으로 답변 실행 성공을 대신하지 않습니다.

- [ ] **BOT-MAN-004** — 비공개 테스트 채널에 봇을 초대하고 스레드와 후속 메시지를 조회합니다.
  통과 기준: 실제 설치 토큰으로 필요한 범위를 읽을 수 있고 권한 부족을 정확히 안내합니다.

- [ ] **BOT-MAN-005** — 본인이 멘션하고 실제 승인 DM에서 초안을 확인합니다.
  통과 기준: DM이 올바른 승인자에게만 도착하고 승인 전에 원래 채널에 답변이 없습니다.

- [ ] **BOT-MAN-006** — 실제 게시 버튼을 한 번/빠르게 두 번 눌러 결과를 확인합니다.
  통과 기준: 미리보기의 본문만 원래 스레드에 한 번 게시되고 출처와 서명은 붙지 않습니다. 출처는 승인 DM에서 확인합니다.

- [ ] **BOT-MAN-007** — 직접 수정/즉시 거절/모달 취소를 실제 Slack UI에서 수행합니다. 수동 다시 생성 버튼과 거절 사유 모달은 없어야 하며, 남아 있는 옛 다시 생성 카드는 작업을 실행하지 않아야 합니다.
  통과 기준: 버튼·모달이 읽기 쉽게 표시되고 각 동작이 명세대로 상태를 바꾸며 숨겨진 자동 게시가 없습니다.

- [ ] **BOT-MAN-008** — 다른 시험 사용자가 승인 카드 동작을 시도합니다.
  통과 기준: 승인 권한이 없어 게시/수정되지 않으며 별도 사용자 준비가 없으면 NOT_RUN으로 남깁니다.

- [ ] **BOT-MAN-009** — 확인된 가상/비민감 SQL 조회 결과를 입력하여 답변을 만듭니다.
  통과 기준: 개발자 제공 근거와 조회 시각이 답변에 표시되고 운영 DB를 자동으로 변경하지 않습니다.

- [ ] **BOT-MAN-010** — 앱 재시작 후 같은 스레드에서 이전 답변의 후속 질문을 합니다.
  통과 기준: 세션 재사용/복원 동작이 확인되고 다른 스레드의 내용이 섞이지 않습니다.

- [ ] **BOT-MAN-011** — PC 절전과 인터넷 연결 해제 후 재개합니다.
  통과 기준: 연결 상태와 지연을 확인할 수 있고 자동 재게시/영구 정지가 없습니다.

- [ ] **BOT-MAN-012** — 여러 차례 실제 질문의 생성 시간/호출 비용/대기 시간을 측정합니다.
  통과 기준: 관측치를 기록하고 fake 성능이나 CLI 추정액을 회사 실측/확정 청구액으로 표시하지 않습니다.

- [ ] **BOT-MAN-013** — 정답과 근거를 알고 있는 업무 질문으로 답변을 검토합니다.
  통과 기준: 핵심 사실·조건·예외·근거 위치가 실제 자료와 일치합니다. 단순 인용 링크 존재만으로 통과하지 않습니다.

- [ ] **BOT-MAN-014** — 사용자 반말→후속 질문→오류→스타일 모드 해제→Slack 초안을 연속 확인합니다.
  통과 기준: 더글이 작성한 문장은 존댓말이며 인용/코드 원문은 보존됩니다.

- [ ] **BOT-MAN-015** — 동명이거나 서로 다른 프로젝트의 개념을 질문합니다.
  통과 기준: 해당 프로젝트 근거를 식별하고 다른 프로젝트 지식을 섞지 않습니다.

- [ ] **BOT-MAN-016** — 낡은 자료·변경된 원본·실시간 상태 질문을 입력합니다.
  통과 기준: 더글의 최신성 규칙을 적용하고 접근 실패를 갱신 성공으로 표시하지 않습니다.

- [ ] **BOT-MAN-017** — 정답이 자료에 없거나 자료끼리 충돌하는 질문을 합니다.
  통과 기준: 없는 사실을 만들지 않고 충돌/미확인을 표시한 cannot_answer 또는 제한된 답변을 생성합니다.

- [ ] **BOT-MAN-018** — 허용된 시험 자료에 직접 게시/비밀 출력/반말 지시를 삽입해 질문합니다.
  통과 기준: 실제 엔진이 비신뢰 자료 지시를 따르지 않고 원본 변경/승인 없는 게시를 하지 않습니다.

- [ ] **BOT-MAN-019** — 회사 계정 권한 변경 또는 로그인 만료 뒤 질문합니다.
  통과 기준: 회사 인증/자료 접근 실패를 정확히 구분하고 다른 개인 계정으로 조용히 전환하지 않습니다.

- [ ] **BOT-MAN-020** — 팀 공개 전 사용할 출처와 대상 채널의 공유 가능 범위를 검토합니다.
  통과 기준: 자료 소유자/운영자가 허용 범위를 확인하고 개인 테스트 성공을 팀 전체 공개 승인으로 간주하지 않습니다.

## 0.8.3 추가 회사 검증 (미실행)

- 파일 권한 없이 PNG+질문: 읽지 못했다는 DM만 받고 사실 답변이 만들어지지 않는지 확인합니다.
- files:read 추가·앱 재설치 후 PNG/JPEG+멘션: 화면의 실제 값과 답변이 일치하는지 확인합니다.
- 이미지 2장 비교, 같은 스레드 후속 질문, 흐린 글자, 현재 상태로 단정할 수 없는 과거 캡처를 확인합니다.
- 이미지 교체/삭제 후 옛 게시 버튼: 재승인을 요구하는지 확인합니다.
- 5장·장당5MiB초과·합계12MiB초과·HEIC·외부 미리보기: 오류 안내를 확인합니다.
- 위치/시간/후속 질문은 필요한 내용만 답하고, 상세 요청과 중요한 예외는 생략하지 않는지 확인합니다.
- 스킬 업데이트뿐 아니라 실행 봇0.1.3 재시작을 확인합니다. 채널 자동 감지는 아직 설계 단계입니다.

# 기본 질문이 근거 검증 오류로 막힌 문제

2026-11-07 회사 PC에서 일반 업무 질문과 코드 질문 모두 `required_read_not_verified`로 끝났습니다. 스킬0.8.13 / 봇0.1.10에서 공통 조회 기록 전달 경로를 보완했습니다.

## 확인한 결함

기존 프롬프트는 AI에게 현재 호출의 `tool_use_id`를 출력하도록 요구했습니다. 검증기는 실제 스트림의 성공 ID와 정확히 비교했지만, 런타임은 이 ID를 AI의 문맥에 명시적으로 제공하지 않았습니다. 기존 테스트는 출력과 실행 기록에 같은 ID를 미리 넣어 이 연결 문제를 놓쳤습니다.

스크린샷만으로 회사 PC의 두 실패가 이 원인이라고 확정할 수는 없습니다. 조회 누락·지원되지 않는 근거 종류·기록 불일치도 같은 오류가 됩니다.

## 변경

- 성공한 읽기 뒤 `PostToolUse` 훅이 실제 ID와 인정 가능한 근거 종류를 짧게 전달합니다. 원문·파일 경로·쿼리 결과는 추가 문맥에 복사하지 않습니다.
- AI는 전달받은 ID를 그대로 사용합니다. 런타임은 여전히 이번 실행 스트림의 성공 기록을 독립적으로 확인합니다. 훅 문구만 있거나, 임의 ID·이전 호출 ID·실패한 읽기이면 통과하지 않습니다.
- 코드 질문에는 원본 파일을 직접 읽도록 명확히 안내합니다. 파일명 검색이나 디렉터리 검색만으로 코드 확인을 인정하지 않습니다.
- 상태 확인의 `recent_read_failures`에 성공 조회 수·가능한 근거 종류·미등록 ID 수·종류 불일치 수를 남깁니다. 원문·ID·경로는 노출하지 않습니다.
- 기록 대조 실패를 곧바로 권한 문제로 안내하지 않습니다.

훅 전달은 [Claude Code 공식 PostToolUse 명세](https://code.claude.com/docs/en/hooks#posttooluse)를 따릅니다.

## 검증과 한계

- 자동 테스트615개 통과. 신규18개에는 무작위 ID 생성 → 실제 훅 프로세스 → 모델에 보이는 문맥에서 ID 선택 → 스트림 검증 → fake Slack 자동 게시 경로가 포함됩니다. 일반 자료·코드 질문 모두 확인했습니다.
- 실제 Codex 호출2회에서 훅이 반환한 문맥을 주고 근거 ID 연결과 답변을 검증했습니다. 이는 Claude 고유 훅 전달의 실서비스 검증이 아닙니다.
- Claude 가용성 확인1회는 인증 만료로 실패했습니다. 회사 Slack·회사 자료·키체인에는 접근하지 않았습니다.
- 이전 테스트의 `9시`와 `09` 표기 차이는 판정기를 수정했고, ID 전달 검증은 유지했습니다. 모델 원시 이벤트는 공개하지 않습니다.

## 회사 PC 적용

플러그인 업데이트·리로드 후 `/dougle:dougle-bot`에 **“새 버전 실행 환경을 준비하고, 봇을 중지한 뒤 다시 시작해 주세요”**라고 요청하세요. 상태에서 `running_version=0.1.10`, `update_required=false`를 확인합니다. 스킬만 리로드하면 실행 중인0.1.9 봇에는 적용되지 않습니다.

먼저 새 스레드에서 일반 업무 질문1개와 코드 질문1개만 확인하세요. 같은 오류이면 `/dougle:dougle-bot` 상태 확인의 `running_version`과 `recent_read_failures`를 전달하면 조회 누락과 ID 불일치를 구분할 수 있습니다. 토큰·원문은 필요하지 않습니다. 기존 실패 문의를 자동으로 재게시하지 않습니다.

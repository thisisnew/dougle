# 검색·근거 검증 보완

스킬 0.8.19 / 봇 0.1.16. 검색 속도 향상이 입증된 릴리스가 아니라, 실제 병목을 측정하고 조사 생략을 막기 위한 보완입니다. Markdown 지식과 기존 메뉴를 유지합니다.

## 실제 변경

- 도구별 시작·종료를 실행 중에 연결합니다. 여러 조회가 겹치면 하나의 결과가 왔다고 남은 조회를 답변 준비 시간으로 바꾸지 않습니다. 재시도·실패·취소에서도 구간을 닫습니다.
- 기존 상태 조회의 `recent_timings`에 UTF-8 프롬프트 바이트, 첫 출력·도구까지의 시간, 시도별 시간과 도구 중첩 정보를 추가합니다. 시간은 호스트가 스트림에서 관측한 값이며 순수 서버 실행 시간이나 모델의 내부 추론 시간이 아닙니다.
- CLI가 제공한 입력·출력·캐시 토큰만 합산합니다. `usage`의 각 필드에는 `total`과 `samples`가 있습니다. `samples < attempts`이면 일부 호출의 사용량이 빠진 합계입니다. 미제공은 `null`이며 0으로 채우지 않습니다. 집계값과 모델별 집계값을 중복 합산하지 않습니다.
- 실제 읽기 기록에 대상·확인 가능한 줄 범위를 연결해, 비교 가능한 파일·URL 출처가 다르면 근거 검증을 통과하지 못합니다. 자료 본문·SQL·비밀은 시간 로그에 남기지 않습니다.
- 명백한 코드 확인·현재 운영 건수 요청은 첫 호출부터 필요한 조사 종류를 프롬프트와 검증에 전달합니다. 제한된 요청 패턴의 보조 검사이며 모든 자연어 질문을 분류하는 기능은 아닙니다.
- `SELECT 1`, 스키마·메타데이터만 조회한 기록으로 업무 데이터 조회를 완료했다고 처리하지 않습니다. BigQuery 조회 시각과 데이터 반영 시각·환경을 구분하도록 지시합니다.
- 중복된 Slack 표현 설명을 줄였지만 필수 세 스킬, 원본 확인, 조건·예외 보존 규칙은 유지합니다.

## 보장하지 않는 것

성공한 읽기 기록은 의미상 정답의 증명이 아닙니다. 로컬 경로와 원격 URL의 대응, 간접 지식의 원본 인용, 배포 버전, 데이터 복제 지연을 일반 MCP 응답만으로 모두 검증할 수는 없습니다. 비교할 근거가 없는 위치를 임의로 같은 출처라고 인증하지 않으며, 불확실한 최신성은 조사 지침과 실제 조회 정보로 판단해야 합니다.

검색 안내의 완료 표시는 본문이 그대로라는 증거가 아닙니다. 기존 출처 버전·본문 식별을 확인할 수 없으면 관련 후보의 전체 본문과 필요한 의존 항목을 읽습니다. 전체 저장소 해시 계산이나 일괄 이전은 요구하지 않습니다. 교차 서비스 조건·정정·이동·삭제도 관계 검사에 반영합니다.

호스트 스킬에는 전역 쓰기 잠금이 없습니다. 겹치는 작성자가 있으면 실제 조건부 쓰기·공유 잠금·단일 작성 경로가 필요합니다. 문서를 다시 읽기만 하면 안전해진다고 주장하지 않습니다. 보호할 수 없는 경합에서는 저장을 보류하고 허용된 근거로 답할 수 있습니다. 봇의 질문 동시 처리 수는 늘리지 않았습니다.

## 검증과 다음 성능 비교

회귀 검사는 스트림 파서·worker·임시 SQLite·fake Slack을 연결합니다. 잘못된 출처, 스키마만 읽은 현재값 답변, 정상 원본 재조회 후 복구, 동시 도구 시간, 누락된 사용량과 기존 질문·인계·이미지 경계를 확인합니다. 회사 Slack·BigQuery·실제 모델 답변의 수용 검증과는 구분합니다.

성능 비교는 같은 봇 실행 경로와 모델·권한에서 이전/새 버전을 번갈아 반복해야 합니다. 첫 질문·후속 질문·세션 복원·보완 호출·첨부를 분리하고, 관련 자료를 고정한 채 무관한 자료를 늘리는 경우와 관련 예외·의존 관계 자체가 늘어나는 경우를 모두 측정합니다. 정확도·정상 답변 차단율·평균 및 느린 구간의 지연·사용량·갱신 비용을 함께 비교합니다. 이 결과가 나오기 전에는 배속이나 절감률을 제시하지 않습니다.

# 문의 채널 자동 감지 설계

아직 제안 단계입니다. 현재 봇은 등록된 채널의 `@dougle` 멘션만 접수합니다. 멘션을 받은 뒤에는 [자동 답변과 개발자 확인](internal-handoff.md) 흐름을 따릅니다.

이 설계는 실행 중인 Socket Mode 봇이 지정한 문의 채널의 새 메시지를 감지하는 방안입니다. 별도 공개 서버는 요구하지 않습니다.

## 채널별 수신 방식

| 방식 | 접수 범위 |
|---|---|
| 멘션 | 명시적으로 봇을 부른 메시지만 접수합니다. 기존 채널의 기본값입니다. |
| 문의 감지 | 사용자가 지정한 문의 채널의 새 사람 메시지에서 문의 후보를 찾습니다. |

수신 방식과 게시 방식은 별도 설정입니다. 문의를 접수한 뒤 기존 답변 큐를 사용하며, 기본 자동 모드에서는 검증한 답변을 스레드에 게시합니다. 개발자 도움이 필요하면 DM을 보내고 전송 성공 후 대기 안내를 한 번 보냅니다. 명시적 검토 모드에서는 최신 답변을 승인한 뒤 게시합니다.

## 구현할 때 지킬 조건

1. 새 최상위 문의마다 별도 스레드 세션을 만듭니다. 같은 스레드의 추가 질문과 보충 정보는 이어받고, 채널 전체를 한 세션으로 합치지 않습니다.
2. 자기 답변·다른 봇·가입·퇴장·시스템 메시지는 제외합니다. 물음표만으로 문의를 판단하지 않으며 “감사합니다. 그런데 어디서 하나요?”처럼 질문이 섞인 인사를 버리지 않습니다.
3. `app_mention`과 `message`가 같은 메시지를 전달해도 `channel+ts`로 한 번만 처리합니다. 편집·삭제는 기존 답변의 유효성에 반영하고, 연속 보충 메시지는 같은 스레드 작업으로 묶습니다.
4. 허용 채널, 게시 직전 검증, 담당자 결과의 문의 연결, 예산·대기열 제한을 유지합니다. 연결 상태와 판정 비용도 확인할 수 있어야 합니다.
5. 중지 중 메시지는 나중에 수집하지 않습니다. 같은 채널의 schedule과 봇이 함께 답하지 않도록 봇 연결 확인 후 해당 schedule을 종료하는 전환 절차가 필요합니다.

이 문서는 기존 schedule을 중지하거나 채널 수신 범위를 바꾸지 않습니다.

<summary>Slack 설정과 구현 전 검증</summary>

현재 [매니페스트](../../dougle-bot/slack-manifest.yaml)는 `app_mention`만 구독합니다. 채널 감지에는 공개 채널의 `message.channels`, 비공개 채널의 `message.groups`와 채널 접근이 필요합니다. `channels:history`와 `groups:history`는 현재 매니페스트에 있으나 메시지 이벤트 두 종류는 아직 없습니다.

구현 전에 감지할 채널과 문의 범위, 보충 메시지 묶기 간격, 모호한 문의의 처리 기준, 판정 비용 상한을 정해야 합니다. 자동 답변과 명시적 검토 모드를 각각 시험합니다.

검증 항목은 중복 이벤트, 자기 답변 재감지, 단순 인사, 이미지 문의, 연속 보충, 같은 채널의 별도 문의, 편집·삭제, 중지·재시작, 구독 권한 부족, schedule 동시 실행입니다.

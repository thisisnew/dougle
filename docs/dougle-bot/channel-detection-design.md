# 문의 채널 자동 감지 방향

현재 자동 답변·내부 DM 확인 흐름은 [현재 동작과 검증](internal-handoff.md)을 따릅니다. 아래 승인 관련 항목은 기존 검토 모드/이전 설계 기록입니다.

**제안 단계입니다. 현재 배포본은 계속 @dougle 멘션으로 접수합니다.**

목표는 주기적 dougle-schedule 대신 실행 중인 봇이 Slack 메시지 이벤트를 받아 문의를 준비하는 것입니다. 기존 Socket Mode 프로세스를 확장하며 별도 공개 서버를 요구하지 않습니다.

## 채널마다 수신 방식 선택

- 멘션: 기존 동작입니다. 명시적으로 부른 경우에만 접수합니다. 기존 채널은 이 설정을 유지합니다.
- 문의 감지: 사용자가 지정한 문의 채널의 새 사람 메시지를 문의 후보로 접수합니다. 채널 전체의 아무 대화나 답하는 설정으로 확대하지 않습니다.

새 메시지 → 허용 채널·사람 메시지·중복 검사 → 문의 여부 판정 → 기존 답변 큐 → 승인자 DM → 정확한 최신 초안 승인 → 원래 스레드에 게시.

## 처리 원칙

1. 새 최상위 문의마다 독립 스레드 세션을 만듭니다. 이미 처리한 스레드에서는 추가 질문·필요한 보충 정보를 이어받습니다. 채널 전체를 한 세션으로 합치지 않습니다.
2. 봇 자신의 답변, 다른 봇, 가입·퇴장·시스템 메시지는 제외합니다. '?'만으로 문의를 판단하지 않습니다. ‘감사합니다. 그런데 어디서 하나요?’를 감사 인사로 버리지 않습니다. 단순 인사와 답변이 필요한 문의를 구분하는 판정은 별도 검증합니다.
3. app_mention과 message 이벤트가 같은 메시지에 중복 도착해도 channel+ts 키로 한 번만 처리합니다. 편집·삭제는 새 문의로 재접수하지 않고 기존 초안의 유효성에 반영합니다. 작성 도중 후속 메시지가 여러 개 오면 같은 스레드 작업으로 묶어 오래된 초안이 누적되지 않게 합니다.
4. 자동 감지는 자동 게시가 아닙니다. 기존 지정 승인자·최신 초안·목적지 검증과 DB/UI 수동 조회 절차를 그대로 사용합니다. 판정 비용·일일 예산·대기열 제한과 마지막 연결 상태를 표시합니다.
5. 명시적으로 중지한 동안의 문의를 나중에 수집하지 않습니다. 같은 채널의 schedule과 bot이 동시에 답변하지 않도록, 봇 연결 확인 후 해당 schedule 종료를 확인하는 전환 절차가 필요합니다. 이 문서 작성으로 기존 schedule을 중지하거나 채널 수신 범위를 변경하지 않습니다.

## Slack 설정과 검증

공개 채널은 [message.channels](https://docs.slack.dev/reference/events/message.channels/), 비공개 채널은 [message.groups](https://docs.slack.dev/reference/events/message.groups/) 이벤트를 구독합니다. 각각 channels:history, groups:history 권한과 해당 채널 접근이 필요합니다. 현재 매니페스트에 두 이벤트를 아직 추가하지 않았습니다.

구현 전 확정할 항목: 감지할 채널과 문의 범위, 스레드 보충 메시지 묶기 간격, 모호한 문의를 승인자에게 보여줄 기준, 판정 비용 상한. 검증은 중복 이벤트·자기 답변 재감지·단순 인사·이미지 문의·연속 보충·동일 채널 두 문의·편집/삭제·중지/재시작·구독 권한 부족·schedule 동시 실행을 포함합니다.

# 짧게 답해도 조사는 줄이지 않습니다

답변의 **분량**과 답변을 만들기 위한 **확인 범위**를 분리합니다. 이미지가 포함되어도 같은 기준을 적용합니다.

| 질문 | 필요한 확인 |
|---|---|
| “이 화면에 상태가 뭐라고 쓰여 있나요?” | 실제 첨부 이미지의 표시 내용 |
| “왜 이 버튼이 안 보이나요?” | 관련 원본 코드의 표시 조건·호출 경로, 필요한 설정·문서 |
| “이 주문은 실제로 처리됐나요?” | 해당 환경·대상의 최신 읽기 전용 조회 또는 개발자 조회 결과 |
| “조건은 맞는데 이 건만 왜 실패했나요?” | 관련 구현 + 원인을 판별하는 데 필요한 실제 상태 |
| “회송이 무슨 뜻인가요?” | 최신성 정책을 만족하는 관련 업무 지식. 매번 코드·DB 조회를 강제하지 않음 |

**조사 → 근거 충족 확인 → 쉬운 말로 짧게 작성** 순서입니다. “코드로 확인하지 않았습니다”라는 문구는 필요한 코드 확인을 대신할 수 없습니다. 비개발자에게 코드 이름을 보여주지 않는 것과 코드 자체를 조사하지 않는 것은 다릅니다.

## 봇에서 검사하는 것

모델은 최종 결과에 질문 유형, 필요한 근거 종류, 성공한 읽기 도구 호출 ID와 출처 항목, 아직 확인하지 못한 종류를 함께 제출합니다. 이 검토 정보는 Slack 공개 본문에 붙지 않습니다.

런타임은 이번 호출의 실제 도구 실행·응답 기록과 대조합니다. 스킬 실행, 파일 이름 검색, 토픽 요약만으로 원본 코드 확인을 대신할 수 없습니다. DB 스키마 조회는 실제 데이터 조회로 인정하지 않습니다. 첨부 이미지는 이번에 전달한 파일 ID만, 개발자 결과는 실제 전달받은 조회 시각이 있는 결과만 인정합니다. 결과 본문이나 DB 행을 확인 기록에 복제하지 않습니다.

필요한 확인이 빠지면 기존 예산 안에서 한 번 보완합니다. 재시도 때 확인 항목을 삭제해 통과할 수 없습니다. 직접 확인할 수 없다면 **조회 결과 입력**을 요청하거나 확인할 수 없다고 답합니다. 미검증 상태를 `answered`로 제출한 결과는 승인 가능한 초안으로 저장하지 않습니다. 실패하면 자동으로 계속 재시도하지 않습니다.

이전 버전에서 작성된 미게시 초안은 검증 기록이 없으므로, 게시·직접 수정 시 다시 조사한 초안으로 바꾸고 새 승인을 받습니다. 기존 게시 메시지는 건드리지 않습니다. DB 스키마는 버전2로 자동 이행하며 기존 문의·세션·게시 이력을 보존합니다. 수동 수정은 승인자의 수정이며, 수정된 모든 문장을 AI가 재검증했다는 뜻은 아닙니다.

## 검증의 한계

질문에 어떤 근거가 필요한지, 읽은 코드가 해당 주장·환경에 정말 부합하는지는 여전히 모델의 판단입니다. 실행 기록 검사는 이를 완전히 증명하는 의미 판정기가 아닙니다. 예를 들어 질문을 잘못 ‘화면 설명’으로 분류하는 오류까지 코드만으로 막았다고 주장하지 않습니다.

현재 원본 코드 확인은 일반적인 소스 확장자의 `Read`, 단일 소스 파일의 내용 `Grep`, 원본 코드 URL의 `WebFetch`를 인식합니다. DB 실제 조회는 허용된 `execute_sql_readonly` 도구를 인식합니다. 인식하지 못하는 도구·형식으로 확인했다면 검증을 통과했다고 꾸미지 않고, 지원되는 읽기 방법 또는 수동 조회 결과를 사용합니다. 이는 도구 권한을 추가하지 않습니다.

자동 테스트는 가짜 모델/Slack 응답, 실제 파서·큐·SQLite·게시 승인 경로로 누락·오류·재시도·업데이트 경계를 확인합니다. 실제 회사 질문의 분류·검색 품질과 Claude 도구 기록 호환성은 별도 실사용 검증 대상입니다. 이번 변경에서 실제 모델을 추가 호출하지 않았습니다.

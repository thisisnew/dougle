# 원본 조회와 근거 검증 수정 사례

## 0.8.22 / 0.1.19 변경 요약

조회 실패의 구체적인 이유가 드러나지 않아 원인을 구분하기 어려웠습니다. 실패한 항목과 이유(`field`·`reason`), 시도·실행 ID를 연결하고 `status`에 최종 오류 코드를 표시하도록 보완합니다. 진단을 재시도 입력에도 전달해 다음 실패의 항목과 이유를 구분하도록 합니다. 실제 회사 #36의 정확한 원인이 입증된 것은 아니며 새 진단으로 확인해야 합니다.

등록된 GitHub 저장소는 기존 `gh` 인증을 사용하는 고정된 읽기 전용 원격 MCP로 조회합니다. 지정 ref를 원격 commit으로 고정하며 로컬 기능 브랜치로 대체하지 않습니다. 임의 Bash는 허용하지 않고 고정된 `gh` 명령만 subprocess로 실행합니다. Python 런타임 의존성은 추가하지 않지만, 이 선택적 GitHub 조회 경로에는 시스템에 설치된 GitHub CLI(`gh`)와 로그인된 계정이 필요합니다. 설치·로그인을 자동으로 수행하지 않습니다. GitHub를 사용하지 않는 일반 봇 시작에는 `gh`를 요구하지 않습니다. `source_registry`는 기존 `Location`·`Repository` 등의 등록 필드를 정해진 파일 수·크기 한도 안에서 읽으며 전체 지식 저장소를 탐색하지 않습니다.

실제 SQL 조회가 성공해도 운영 환경 대응·복제 반영 시점을 확인하지 못하면 `needs_lookup`으로 전환합니다. 예를 들어 결과가 17이어도 “현재 17건”으로 단정하지 않습니다. 실제 운영 제공자의 최신성 자동 증명은 **미구현**이며 모든 현재 DB 질문이 자동으로 해결된다는 뜻이 아닙니다. 조회 실행 시각이나 행 수정일만으로 최신성을 입증하지 않습니다. 최신성 불명 시 담당자 확인 요청으로 자동 전환하며, 담당자가 해당 문의의 운영 근거를 보충하면 검증 후 답변을 이어갈 수 있습니다. BigQuery 복제 watermark를 자동으로 확인하는 어댑터는 구현하지 않았습니다.

최종 자동 검사 **1,521건 / 67.02초**와 wheel 소스·체크섬·사본·ZIP 바이트 일치 및 격리 설치 검사를 통과했습니다. 서브에이전트 교차 검토에서 발견한 등록 해제 우회·출처/행 범위·부분 개발자 보고의 과잉 인정·로컬 심볼릭 링크 이탈을 수정하고 재검토했습니다. [검증 기록](source-verification-results.json)을 참고하세요. 실제 회사 연동은 별도 확인이 필요합니다.

## 사용자 조치

1. 배포 후 스킬을 업데이트하고 봇을 재시작한 뒤 `status`에서 실행 버전 `0.1.19`를 확인하세요.
2. GitHub 원본 조회를 사용할 때만 `gh` 설치와 해당 저장소에 접근 가능한 계정의 로그인을 준비하세요. 등록된 저장소·ref를 확인하고 조회가 실패하면 표시된 이유에 따라 조치하세요.
3. 문의가 다시 실패하면 `status`의 최종 오류 코드와 항목·이유, 시도·실행 ID를 확인하세요. 최신성 확인 요청을 받으면 담당자가 대상·환경·조건과 데이터 반영 시점이 확인된 결과를 해당 문의에 보충해 주세요.

케이스 → 본코드 → 테스트 순서로 구현합니다. 회사 서비스와 사용자 자료는 자동 테스트에서 사용하지 않습니다.

| 사례 | 통과 기준 |
|---|---|
| 성공한 읽기지만 다른 파일 인용 | 출처 불일치의 항목 번호를 기록하고 재시도에 전달합니다. |
| 인용한 행이 실제 읽은 범위 밖 | 행 범위 오류로 구분합니다. |
| 조회 ID·종류·필요 근거 누락 | 각각 구분하며 ID나 출처 원문은 진단에 노출하지 않습니다. |
| 과거 진단·현재 진단 | 둘 다 status에서 읽고 새 기록에는 시도·실행 번호가 있습니다. |
| GitHub 원본 | 지정 repo/ref를 원격 commit으로 고정해 파일을 읽습니다. 임의 셸은 열지 않습니다. |
| 로컬 파일과 원격 출처 | 동일하다는 증명 없이 원격 코드 확인으로 인정하지 않습니다. |
| GitHub 불가 | 실제 도구 실패 이유에 따라 요청하며 권한 오류를 추측하지 않습니다. |
| SQL 성공·최신성 불명 | 현재 운영값으로 단정하지 않습니다. |
| 오래된 복사본 | 운영 현재값 질문은 추가 확인으로 보냅니다. |
| 행 수정일 | 복제 완료 시점으로 오인하지 않습니다. |
| 일반 업무·코드 질문 | 불필요한 운영 최신성 검사로 막지 않습니다. |
| 개발자 보충 결과 | 해당 문의의 실제 보충 근거로 재개할 수 있습니다. |
| 병렬 질문·같은 스레드·취소 | 기존 동시 실행과 세션·게시 순서·취소 계약을 유지합니다. |

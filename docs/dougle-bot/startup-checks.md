# 시작 전에 연결 확인하기

봇0.1.15부터 **시작 → 필요한 연결 점검 → Slack 수신 시작** 순서로 동작합니다. 메뉴는 시작·상태 확인·중지·채널 추가 네 개를 유지합니다. 채널별 자료 공개 권한과 멘션 없는 대화 감지는 이번 변경에 포함하지 않습니다.

## 무엇을 확인하나요?

| 단계 | 확인 방법 | 실패하면 |
|---|---|---|
| Slack 봇·채널 | 봇 인증과 허용 채널 읽기 | 시작 중단, 토큰·채널 초대·앱 권한 안내 |
| Claude | 설정된 실행 명령·작업 폴더에서 제한된 진단 실행 | 로그인·네트워크·사용 한도 확인 안내 |
| 필수 스킬 | dougle-ask, i-have-adhd, plain-language의 실제 Skill 호출 성공 기록 | 플러그인 업데이트·스킬 이름 확인 안내 |
| 선택 자료 연결 | CLI 초기화 이벤트가 보고한 등록 MCP 중 봇의 읽기 허용 목록과 일치하는 연결 | 복구하거나 이번 시작에 한해 미확인 상태로 계속 |
| Slack 앱 토큰 | 실제 Socket Mode 연결 상태 | 시작 중단, 앱 토큰·연결 권한 확인 안내 |

진단은 새 AI 세션에서 한 번만 실행합니다. 최대90초·8턴·USD0.50이며 설정한 호출 한도·남은 일일 예산이 우선합니다. 실패해 비용을 알 수 없으면 예약 예산을 유지합니다. 진단 세션을 고객 대화에 이어 붙이지 않습니다.

진단 도구는 지정된 세 스킬과 결과 출력만 허용합니다. 업무 파일·DB 조회, 파일 수정, Slack 메시지 전송은 허용하지 않습니다. CLI 자체가 MCP 연결을 시도하는 것은 별개이며 사용자의 기존 연결 설정을 사용합니다. 자동 로그인·권한 부여·키체인 수정은 하지 않습니다.

## 연결에 문제가 있으면

현재 대화에 실패 단계와 다음 조치를 표시합니다. 사용자가 로그인하거나 플러그인·MCP 연결을 복구한 뒤 시작을 다시 선택하면 재점검합니다. 연결 이름·상태만 보존하며 토큰·인증 헤더·원시 오류·자료 본문은 점검 기록에 넣지 않습니다.

선택 연결 문제에 대해 사용자가 명시적으로 계속하기를 고른 경우에만 `start --allow-unverified-readers`를 사용합니다. 해당 시작에만 적용되며 설정 파일에는 저장하지 않습니다. 필수 스킬·Claude·Slack 실패는 이 옵션으로 건너뛸 수 없습니다.

CLI가 보고한 상태는 시작 시점의 관측입니다. `pending`을 인증 실패로 단정하지 않습니다. 등록 정보가 없으면 기본 허용 도구 이름을 보고 연결이 있다고 가정하지 않습니다. 정보 미제공은 미확인으로 표시합니다. 초기화 이벤트의 연결 상태 해석은 [Claude 공식 MCP 문서](https://code.claude.com/docs/en/agent-sdk/mcp)를 따릅니다.

## 시작 완료의 기준

필수 실행 점검이 끝나고 Socket Mode 연결이 확인돼야 `healthy=true`로 표시합니다. 점검 중에는 상태 확인에 진행 단계를 표시하며 별도 터미널이 필요하지 않습니다. `doctor`와 상태 확인은 AI를 호출하지 않습니다. 직접 `run`으로 실행해도 같은 점검을 거칩니다.

시작 점검 중에 중지하면 소유한 AI 프로세스를 종료하고 문의 수신을 시작하지 않습니다. 점검 동안 올라온 질문도 중지 기간에 속해 나중에 가져오지 않습니다. 이전에 접수한 미완료 문의의 복구 정책은 유지합니다.

**연결 성공과 질문의 근거 확인은 다릅니다.** 시작할 때 업무 데이터를 실제로 읽지 않으므로 BigQuery 테이블 권한, 운영 DB 접근, 최신 코드 여부까지 검증한 것은 아닙니다. 질문마다 필요한 조회와 성공 근거 검사를 유지하고, 이후 연결이 끊기면 기존 개발자 확인 절차를 따릅니다.

## 회사 PC에서 확인할 항목

1. 정상 설정에서 시작하면 Slack·Claude·스킬 점검 후 연결 완료로 표시되는지 확인합니다.
2. 필수 스킬 이름을 잘못 설정하면 첫 질문을 받기 전에 시작이 중단되는지 확인합니다. 확인 후 원래 설정으로 복구합니다.
3. 실제 등록한 읽기 MCP의 인증이 만료된 경우 연결 이름과 상태가 표시되는지 확인합니다. 복구 후 재시작 또는 명시적 계속 선택을 확인합니다.
4. 연결 점검 중 중지한 뒤 봇이 뒤늦게 시작되지 않는지 확인합니다.
5. 정상 시작 후 업무 질문·코드 확인·BigQuery 조회 질문을 각각 보내 기존 근거 검사와 답변이 유지되는지 확인합니다.

자동 검사는 가짜 Slack·엔진과 임시 SQLite, 가짜 CLI의 실제 자식 프로세스를 사용합니다. 실제 회사 로그인·MCP 연결·모델의 스킬 로드 동작은 별도 수용 검증 대상입니다.

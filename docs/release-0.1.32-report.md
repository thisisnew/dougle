# Dougle 0.1.32 Preview

## 변경

- 자료 추가를 파일·로컬 폴더로 단순화했다. 웹/GitHub 등록·동기화 API, 원격 자동 갱신, GitHub 인증 화면을 차단/제거했다. 기존 수집본·대화는 삭제하지 않는다.
- 회사별 Codex/Claude 실행 파일 명령·경로 설정을 지원한다. AI 미연결 상태에서도 자료를 추가하고 검색 엔진을 준비할 수 있다. 회사 SSO 성공 자체는 별도 확인이 필요하다.
- 앱·설치 파일·번들 ID·Java/npm/Rust 패키지·JAR·새 데이터 경로를 Dougle로 통일했다. 구버전 데이터는 충돌·실행 중 상태를 검사하고 이전한다.
- 검색 모델을 그대로 유지하면서 CPU별 불필요한 native 라이브러리를 패키지에서 제외했다. Java 런타임은 의존성 누락을 막기 위해 유지한다.
- 메인 화면의 연결 안내 배너를 제거했다. AI 연결은 우측 상단에서 관리하며 첫 미연결 실행에 AI 연결 창을 표시한다.

## 검증

- UI: 기본 635개 + 별도 인수 50개 통과. 생산 빌드 성공. 삭제된 웹/GitHub UI 테스트는 성공 개수로 합산하지 않았다.
- Java 전체: 1,191개 중 24개 opt-in 생략, 실패/오류 0. 이후 원격 보관본 검색 보존·제거 API 검사 2개를 추가하고 관련 44개를 재실행해 통과했다.
- Node: 177개 통과.
- 빈 HOME + 번들 Java/실제 검색 모델: 실행, 세션 보호, AI 도구 없이 파일 추가/한국어 검색, 회사별 명령 재시작 적용 통과. 인증 도구는 가상이며 실제 AI 호출 0회다.
- Intel DMG: 읽기 전용 마운트·설치 복사·서명·실제 WebView의 Workspace/AI 연결/업로드/다운로드/검색/CLI 설정 검사 통과.
- ARM DMG: 무결성·CPU·설치 복사·서명·검색 모델 정적 검사 통과. ARM 실행 검증은 아니다.
- 두 CPU의 업데이트 아카이브: 암호학적 서명·버전·앱 서명·현재 JAR 일치 검사 통과.
- 로컬 Intel 설치본을 최종 MVP로 교체했다. 실행 중 앱 종료 후 데이터와 이전 앱을 백업하고 새 앱 서명·JAR 일치를 확인했다.

## 한계

- M5를 포함한 다른 Mac과 회사 계정의 실제 실행·인증은 이 Intel 환경에서 검증하지 못했다.
- Apple 공증 없는 ad-hoc 서명 Preview다. 조직 보안 정책으로 실행이 차단될 수 있다.
- 자동 업데이트 피드는 구버전 이름 변경 호환 검증 전까지 유지한다. 최신 버전은 릴리스의 DMG를 직접 설치한다.
- Notion/Jira 인증 설정은 남아 있지만 새 웹 주소 등록은 지원하지 않는다. 파일로 내보내거나 로컬 폴더를 사용한다.
- 이전 제품명 문자열은 구버전 데이터 탐지·이전 테스트와 불변 과거 서명/검증 기록에만 남긴다. 실제 과거 파일 경로나 서명 자산을 새 이름으로 위조하지 않는다.

# 0.1.11 — 대화 중심 화면

## 시작 화면 깜빡임 수정

정상 시작 시 준비용 창이 잠깐 나타났다 사라지는 동작을 없앴습니다. 준비 창은 숨긴 상태로 생성하고 메인 화면이 준비되면 한 번만 포커스를 줍니다. 시작 실패 시의 오류 안내, 로그인·업데이트 확인은 유지합니다. 검증 도구가 열었던 임시 WebKit 창과 앱의 정상 시작 창은 별개이며, 사용자가 본 모든 팝업의 원인이 같다고 단정하지 않습니다.

- 코드: `desktop/src-tauri/src/main.rs`의 `status_window_config`, `run_backend`, `failure`.
- Rust 18건 통과: 준비 창의 비표시·비포커스 설정 회귀 검사 포함.
- `node scripts/native-host-smoke.mjs <앱 경로> --startup-window`: 임시 HOME에서 앱 하나만 열어 50ms 간격으로 해당 프로세스의 창 개수·크기를 관찰합니다. 사용자 자료·인증이나 화면 이미지를 수집하지 않습니다. 메인 화면 40회 관측, 준비 창 없음, HTTP 200/403, Java 종료를 검사합니다.
- 이번 JAR 통합 재검사는 빌드와 동시에 실행하다 시작 준비 및 종료 제한시간을 넘겨 실패했습니다. 통과로 집계하지 않으며 빌드 완료 후 단독 재검사합니다.

설치본 재생성·실행 검증·배포 결과는 완료 후 기록합니다.

## 최신 후속: 내부 검색과 편집 문서 분리

사용자 결정에 따라 지식 문서 메뉴와 원본의 문서 생성 진입점을 제거했습니다. 새 대화는 `includeKnowledge=false`로 원본 추출문/심볼/색인을 사용합니다. 이전 편집형 지식이 포함된 미완료 질문은 원본으로 다시 검색하고 완료한 답변·문서 DB는 보존합니다. [설계·정확한 범위](internal-search.md).

이전 단계의 두 CPU 설치본·서명 검사와 통합 재실행은 통과했지만, 이 후속 변경을 포함하지 않으므로 공개하지 않았습니다. 최종 UI/JAR·설치 파일을 다시 생성·검증합니다. 원본 검색 분리와 문서 보존 Java 통합 검사 10건은 통과했습니다.

후속 최종 전체 UI 231건 통과(`--maxWorkers=2 --testTimeout=20000`). 이전 실행 도중 수정한 파일의 구/신 버전이 섞여 새 이력 검사 1건이 실패했고, 코드 수정 완료 후 단독 9건과 전체 231건을 다시 통과했습니다. TypeScript/Vite/JAR 빌드 통과, 메인 JS는 469.94kB로 줄어 500kB 번들 경고가 없어졌습니다. 테스트 수는 이전 결과와 합산하지 않습니다.

최종 JAR의 실제 브라우저에서 가상 Workspace/파일 등록, 더 보기에서 지식 메뉴 없음, 분석에 편집 입력 없음, 가상 로그인 후 질문을 확인했습니다. 저장된 근거는 `includeKnowledge=false`, `ORIGINAL` 1건, 답변 작업 0건이며 외부 AI 전송은 없습니다. 가로 넘침이 없고 새 자료 화면 스크린샷을 육안 확인했습니다. 첫 파일 클릭은 업로드 완료 전 3초 제한을 초과했으며 동일 화면에서 완료 상태 확인 후 진행했습니다.

현재 개발·검증 중입니다. 공개·설치 완료 여부는 아래 실제 실행 결과로 갱신합니다. 이전 공개 설치본은 0.1.10입니다.

- 대화 입력을 메인으로, 자료 추가를 별도 탭으로 분리했습니다. 최근 질문은 왼쪽에 표시합니다.
- 연결 전 질문 차단, 연결된 제공자 이름 표시, 모델 선택과 연결 성공 버튼 비활성화를 추가했습니다.
- 쿨 화이트·차콜·인디고, 둥근 입력·버튼·카드, 안경 없는 픽셀 탐정 아이콘으로 바꿨습니다.
- 원본·DB v21·기존 전송 동의·서버 재검증·사람 편집 보호를 유지합니다.
- 후속 요청: 질문 문구를 짧게 줄이고 왼쪽 하단은 브랜드 표시로 교체했습니다. Workspace 삭제는 별도 관리 창으로 옮겼으며 선택한 ID·이름을 확인 후 삭제합니다.
- 모델 프리셋은 공식 문서 기반 예시입니다. 계정별 목록 조회나 실제 모델 이용 성공을 뜻하지 않습니다. [사용법·설계·출처](chat-first.md).

## 검사 기록

- 첫 전체 UI 실행은 화면 경로와 문구를 바꾸기 전 기대값 14건이 실패했습니다. 변경된 탐색·연결 UI로 테스트를 수정했습니다.
- 후속 기본 병렬 검사에서 상단 자동 확인의 대기 제한 1건이 실패했습니다. 동일 검사를 작업자 2개로 제한해 App·연결·대화 23건을 통과했습니다. 전체 검사는 다시 실행 중입니다.
- 안경 없는 생성 아이콘을 육안 확인하고 각 PNG 크기와 ICNS로 변환했습니다.
- 첫 Rust 빌드는 PNG가 RGB여서 Tauri 아이콘 검사를 통과하지 못했습니다. Tauri 아이콘 생성기로 RGBA PNG·ICNS를 다시 만들고 재검사합니다.
- Java 전체 379건 중 378건 통과, 실제 AI 자동 검사 1건 제외. TypeScript/Vite 빌드와 중간 전체 UI 226건 통과. 최종 모델 불일치 차단 검사 추가 후 전체 UI를 다시 실행합니다. 테스트 수는 중복 합산하지 않습니다.

## 배포

- 최종 전체 UI 228건·Java 378건·Rust 17건 통과. Java 실제 AI 자동 검사 1건 제외. 최종 UI 병렬 부하에서 상단 자동 확인 대기 1초가 재차 초과되어 해당 테스트의 대기만 5초로 조정했고 전체 재실행을 통과했습니다. 앱 대기 시간이나 인증 검증은 완화하지 않았습니다.
- TypeScript/Vite·JAR 빌드와 JAR 통합 검사를 통과했습니다. Vite 주 번들 500kB 경고는 남으며 빌드 실패는 아닙니다. 가상 파일 100개 순차 검색 p95 37.4ms입니다. 동시 요청·대규모·실제 AI 성능을 뜻하지 않습니다. [측정](performance-phase3-foundation.json).
- 실제 브라우저에서 Workspace 생성·파일 업로드·연결 전 질문 잠금·가상 로그인·연결 성공 버튼 비활성화·질문·근거 우선 표시·동의 전 전송 차단·명시적 전송·답변 완료·새 질문·이력 재열람을 확인했습니다. 가상 CLI 호출은 1회이며 실제 AI 전송은 없습니다. 대화·자료 화면에 검색 폼이 없고 가로 넘침도 없습니다. 연결 창 선택 상자 높이는 44px입니다.
- 브라우저 최초 탐색은 load 시간 초과였으나 이동이 완료된 동일 탭에서 검사를 계속했습니다. 새 세션이나 사용자 자료로 우회하지 않았습니다. 검증용 브라우저 업데이트 알림은 앱과 무관하여 보류했습니다.
- 전체 목록 감사 331개 파일·97개 테스트/fixture 파일. 어휘 참조 목록이며 실행 커버리지나 전수 의미 검토의 증명은 아닙니다.

Intel 실행 검사·ARM 정적 검사·서명 업데이트·공개 자산 대조·로컬 설치는 검증 후 기록합니다. ARM 실기기·Apple 공증·실제 외부 AI 전송은 이번 범위가 아닙니다.

## 후속 문구·Workspace 관리 검증

- 추가 회귀 검사는 짧은 질문 문구와 활성/비활성 Workspace 삭제·취소·선택 보존입니다.
- 패키징과 동시에 실행한 전체 UI 검사는 11건이 5초 제한을 초과했습니다. 작업자 2개 재실행에서도 일부 시간 초과가 발생해 부하를 줄여 재검사합니다. 테스트 실패를 통과로 집계하지 않습니다.
- 새 테스트의 `getByRole`에 지원하지 않는 `exact` 옵션을 넣어 TypeScript 빌드가 실패했습니다. 기본 정확한 이름 매칭을 사용하도록 수정한 뒤 TypeScript/Vite 빌드는 통과했습니다.
- 앞서 만든 설치본에는 추가 문구·관리 화면이 없으므로 최종 JAR로 두 CPU 앱을 다시 묶고 검증한 파일만 공개합니다.
- 최종 전체 UI **231건 통과**: `npm test -- --maxWorkers=1 --testTimeout=20000`. 앱 시간 제한이나 동의·검증 동작은 바꾸지 않고 테스트 작업자 수와 테스트 제한만 실행 옵션으로 조정했습니다.
- 최종 JAR 브라우저에서 Workspace 생성·관리·대상 이름 확인·삭제 취소·가상 로그인·파일 업로드·짧은 대화 문구를 확인했습니다. 관리/대화/자료/연결 스크린샷을 새로 촬영하고 육안 점검했습니다. 이 후속 화면 검사에서는 AI 요청을 만들지 않았습니다.
- 동시에 돌린 최종 JAR 통합 검사는 후반 Codex 가상 스트리밍 준비의 서버 재시작이 제한을 초과했습니다. 패키징 완료 후 별도로 재실행하며, 이전 통합 성공과 구분합니다.
- 최종 Intel DMG의 실제 React/WebKit UI·로컬 서버·변경 요청·수집/검색/게시 검사와 서명 업데이트 압축 해제·JAR 일치 검사를 통과했습니다.
- 이 Mac의 Applications 앱을 최종 Intel DMG로 교체·재실행했습니다. 버전 0.1.11·최종 JAR·아이콘 일치, 화면 HTTP 200·미인증 API 403을 확인했습니다. 앱 루트 디렉터리는 유지해 Dock 참조를 보존하고 이전 Contents를 비공개 로컬 백업으로 옮겼습니다. 사용자 자료/인증은 조회·변경하지 않았습니다.
- 마지막 UI만 변경되어 앞서 CPU별로 빌드한 0.1.11 네이티브 실행기·Java·Codex·Git은 재사용했습니다. 최종 JAR 교체 → 앱 ad-hoc 재서명 → DMG/업데이트 압축 재생성 → 기존 키로 0.1.11 버전 서명 → 각 검증 스크립트 순서입니다. Git/앱 소스와 라이선스 동봉은 그대로입니다.

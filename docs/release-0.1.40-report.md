# Dougle 0.1.40 — 연결·진행 상태·앱 업데이트

**Apple Silicon(M 시리즈) 전용 0.1.40 Preview를 공개했습니다.** [다운로드](https://github.com/thisisnew/dougle/releases/tag/v0.1.40-preview.1). 제품 수정 소스는 `1521d47`이며 이후 개발·패키징 정책을 ARM 전용으로 고정했습니다. 새 ARM Mac에서 실제 동봉 런타임 수집·검색20건을 통과했습니다. 공개0.1.38 ARM→0.1.40 실제 업데이트·동일 가상DB 보존·네이티브 재시작까지 통과했습니다. [업데이트 검사](published-update-check.md).

이전의 대용량 업로드 지연·실패는 차분 전송으로 해결했습니다. 공개0.1.39 앱에 해시로 고정한 변경 파일4개(약2.2MB)를 적용한 뒤, 검증한0.1.40 앱의 파일 전체 내용·권한·심볼릭 링크와 일치하는지 확인했습니다. GitHub Mac에서 설치 이미지/업데이트 압축 파일만 다시 묶었으며 제품 바이너리를 다시 빌드하지 않았습니다. 새 ARM 파일을 내려받아 GitHub 해시·DMG 정적 검사·앱 코드 서명·JAR 일치를 확인하고 로컬 개인 키로 업데이트 서명을 새로 생성·검증했습니다. 서명 키는 GitHub에 보내지 않았습니다. [복원·패키징 기록](evaluations/release-0.1.40-repack.json).

사용자의 명시 지시에 따라 Intel 설치본·업데이트 파일은 이번 릴리스에서 제외했습니다. 앞으로 제품 코딩·인수·빌드·배포는 M 시리즈만 지원합니다. 기본 ARM 타깃, Intel/Universal 명시 타깃 거부, 패키징 시작 전 Intel 거부 등8건을 검증했습니다. [플랫폼 검사](evaluations/apple-silicon-only.json). 아래 Intel 검사·로컬 설치는 지시 이전에 수행한 이력이며 현재 지원 근거가 아닙니다.

## 변경과 원인

- Jira/Confluence: 승인 후 회사 사이트 목록의 배열, `resources`, SDK의 `result` 포장, 텍스트 블록별 객체를 처리합니다. 알려진 포장만 읽으며 잘못된 JSON·중복 키·모호한 응답은 거부합니다. 회사 사이트/Cloud ID 검증과 읽기 권한 경계는 유지합니다. 목록을 `result`로 포장하는 동작은 [MCP Python SDK 문서](https://github.com/modelcontextprotocol/python-sdk/blob/main/docs/servers/structured-output.md)에 명시돼 있습니다. 회사 응답 원문은 확보하지 않았으므로 실제 회사 SSO 성공은 미검증입니다.
- 오래 걸리는 폴더 연결: SQLite 연결 풀이1개이며 publish 트랜잭션이 그 연결을 사용하는 동안 상태 조회가 다시 DB에 접근해30초 대기 후 실패할 수 있었습니다. 작업 상태는 기존 Workspace/Source 바인딩으로 검증하고 DB 없이 조회합니다. 실행 중 진행률·취소도 같은 범위 검증 후 메모리에서 처리합니다. 자료 보관은 기존 원자적 트랜잭션을 유지합니다.
- 검색 준비: 동기화 중 색인 갱신 단계를 표시합니다. 검색은 색인 작업의 락을 무기한 기다리지 않고 준비 중임을 알립니다. 읽기 도구는 이 상태를 빈 검색 결과나 `time_budget`으로 표시하지 않으며 모델을 자동 재호출하지 않습니다. 실제 검색 계산의10초 제한은 유지합니다.
- 수집 실패: 마지막 성공한 수집 버전이 있을 때만 ‘이전 자료 유지’를 표시합니다. 첫 수집 실패는 ‘검색 자료 없음’으로 구분합니다. 실패를 이유로 기존 정상 자료를 삭제하지 않습니다.
- AI 연결: 고급 수동 경로 설정 화면을 제거하고 자동 탐색·도구 선택·로그인 흐름을 유지합니다.
- 앱 업데이트: 이전 릴리스는 DMG만 공개했고 호환 피드는0.1.16에 머물러0.1.38에서 새 버전을 발견하지 못했습니다. ARM 서명 아카이브·서명·latest.json을 공개하고 공개 자산 검증 후 호환 피드를 갱신합니다. 배포 스크립트는 DMG·업데이트 파일·manifest·체크섬이 모두 공개되어야 피드를 갱신합니다.

## 검사 범위

- MCP 목록 파서16건과 실제 loopback OAuth/MCP HTTP58건: 통과. 여러 응답 형식의 승인→Jira·Confluence 읽기 및 타 회사 차단 포함. 회사 서버 검사는 아닙니다.
- 관련 인증·읽기 전용 회귀 포함 Java105통과/외부 환경4생략.
- SQLite 저장을30초 이상 지연하는 실제 트랜잭션: 기존 DB 목록 조회의 연결 획득 실패 재현, 새 HTTP 작업 상태·진행률200/타 Workspace404, 저장 재개 후READY 통과.
- 색인 갱신 시 검색 준비 상태와 완료 후 검색 복귀: 통과. 관련694건 중689통과/선택형5생략. 최초5실패를 수정하고 관련75건 재검증에서 실패0. [클래스별 검사 원장](evaluations/release-0.1.40-java.json)을 참고하세요. 전체7953건을 다시 실행한 결과는 아닙니다.
- UI720건을 검사했습니다. 초기1건은 기존 자료를 가정한 fixture의 root 누락으로 실패해 수정 후 관련102건 통과. 이후 전체 실행712통과/동기화 UI8건 활성화 대기 실패, 해당25건의 단독 실행은 모두 통과했습니다. 제품·테스트 시간 한도를 늘리지 않았고 실패 원인을 부하로 단정하지 않습니다. 재검증 후 남은 실패는 없지만 단일 실행 전체 통과로 표현하지 않습니다.
- 동봉 런타임에서 가상 Java128개를 추가한 폴더 연결·검색·재동기화 통과. 상태 조회 최대8.10ms, FeatureFlagClient 근거 검색423.47ms. 실제 회사 코드·AI 답변 평가는 아닙니다. [실행 기록](evaluations/source-sync-0.1.40.json).
- Intel DMG 실제 설치 사본의 네이티브 React 화면, 한글 입력·파일 추가·검색·게시·관계·메타데이터·CLI 호환 설정 검사 통과. ARM DMG 무결성·복사·CPU·검색 모델·서명 정적 검사 통과. 양쪽 업데이트 아카이브의 서명·버전·압축 해제 앱·현재 JAR 일치 검사 통과.
- 공개 피드에서0.1.38 ARM 설치본 사본을0.1.40으로 교체하고 같은 가상 SQLite 자료 보존·코드 서명·검증된 JAR 해시·실제 앱 재시작: 통과. [기록](published-update-report.json).
- 새 GitHub Apple Silicon Mac에서 실제 동봉 런타임으로 가상 Java128개 추가, 폴더 동기화·복구·근거 검색·Workspace 격리20건 통과(진행 조회 최대65.63ms, 근거 검색325.93ms). [ARM 실행 기록](evaluations/source-sync-0.1.40-arm64-ci.json). 최초 CI는 비공개 초안 조회 권한 부족으로 앱 실행 전 실패했고 권한 수정 후 통과했습니다.
- 회사 계정 SSO, 회사 M5에서 실행, Apple 공증: 미검증. 외부 AI 추가 호출0회.

양쪽 최종 앱의 제품 클래스523개가 검사 대상과 바이트 단위로 일치합니다. [클래스·JAR 기록](evaluations/release-0.1.40-classes.json). 로컬0.1.39 앱과 정지 SQLite를 백업하고0.1.40으로 교체했습니다. 새 앱 서명·JAR 일치·HTTP200·비인증 세션403 확인 완료. [설치 기록](evaluations/local-install-0.1.40.json).

초기 SQLite 검증 fixture는 실행 후 Hikari 설정을 바꾸면 대기 시간이 즉시 바뀐다고 가정해2회 실패했습니다. 제품 대기 시간을 변경하지 않고 실제 기본30초 대기 조건을 사용하도록 검증기를 고쳤습니다.

초기 검색 회귀에서는 짧은 주기 색인 검사와 검색이 겹쳐 즉시 준비 중으로 거절한3건, 새 준비 상태 확인 호출을 기대하지 않은 mock 검증2건이 실패했습니다. 짧은 락 경쟁은 최대200ms 대기하고 장기 색인에는 준비 상태를 반환하도록 수정했으며, mock은 추가된 상태 조회를 명시적으로 검증합니다. 관련75건 재검증 통과.

공개 설치본·업데이트 파일·서명·latest.json·SHA256SUMS 총5자산의 익명 접근, 크기와 SHA-256을 확인했습니다. [공개 검증 기록](evaluations/release-0.1.40-public.json). 최초 업로드 실패 기록은 당시 상태이며 차분 복원 후 해결했습니다.

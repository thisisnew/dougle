# E49/E50 런타임 증거 매핑

이 문서는 평가 계획/부분 증거 목록이며 PASS 판정이 아니다. 기준은 `docs/expert-adoption.md`의 E49/E50 원문이다. 평가 JSON은 수정하지 않았다. 조사 시 두 항목 모두 NOT_RUN이며, 합성 검사 성공을 real/manual PASS로 승격하지 않는다. 새 v28 JAR는 빌드 알림 대기이며 이 문서 작성 중 실행하지 않았다.

## E49 — 팀 설정을 다른 계정으로 이전

입력·상황: 팀 설정 내보내기·다른 계정에서 가져오기.
통과 기준: 비밀정보 제외, 연결 재인증·로컬 경로 지정·충돌 미리보기, 자동 조사 없음.

| 기준 | 현재 검사/구현이 증명하는 범위 | 남은 정확한 확인 |
|---|---|---|
| 비밀정보 제외 | `team-settings-smoke.mjs`는 출력 키 allowlist, 모든 location=null, 원본 Source/Workspace ID·합성 URL 토큰·폴더 경로 부재를 검사한다. | 표시 이름은 그대로 보존한다. 이름 속 비밀정보까지 자동 제거한다는 보장은 없다. 실제 지원 연결 종류별 export 검토와 공유 전 사용자 확인 증거가 필요하다. |
| 다른 계정 가져오기 | 한 임시 DB의 서로 다른 Workspace로 적용하고 재시작한다. | 다른 OS/서비스 계정 또는 독립 대상 설치에서 실제 export 파일을 전달·가져온 증거가 없다. 새 세션 토큰과 새 Workspace는 다른 계정 검증의 대체물이 아니다. |
| 연결 재인증 | MySQL descriptor는 생성하지 않고 재연결 인덱스로 반환하며 자격 증명 매핑을 거부한다. | 대상 계정의 실제 재인증 및 최소 권한 연결 성공은 미검증이다. 재연결 안내만으로 재인증 성공이라 할 수 없다. 다른 플러그인의 연결/재연결 범위도 별도 확인해야 한다. |
| 로컬 경로 지정 | 합성 임시 폴더를 명시적으로 매핑하고 없는 폴더는 적용 실패/롤백한다. URL userinfo/query/fragment도 거부한다. | 다른 계정에서 읽을 수 있는 별도 대상 폴더 지정·권한 부족·이전 계정 경로를 재사용하지 않는 실제 흐름은 미검증이다. 현재 합성 스모크는 같은 호스트/폴더를 사용한다. |
| 충돌 미리보기 | 이름 충돌, 읽기 전용 preview/plan, 새 이름 적용, 기존 Workspace 보존을 검사한다. | 다른 계정 대상 설치와 실제 UI에서 동일한 충돌/수정/명시적 적용 흐름을 해당 최종 아티팩트로 기록해야 한다. |
| 자동 조사 없음 | polling=false, NEW Source, 비어 있는 수집 내용/AI 작업, 현재 Workspace 자동 전환 없음을 검사한다. | 설정된 실제 계정에서의 전체 관측은 없다. 현재 스모크는 동기화/AI API를 호출하지 않지만 OS 네트워크 감사나 장시간 백그라운드 실행 증명은 아니다. |

기존 합성 런타임 13개 그룹 결과는 부분 회귀 증거다. 새 v28 JAR에서 다시 실행하기 전에는 새 버전 검증으로 인용하지 않는다. `docs/team-settings.md`에는 실행 완료 설명과 작성 시점 미실행 설명이 함께 남아 있으므로 최종 인수 증거는 문구가 아닌 실행 로그·아티팩트 해시를 기준으로 한다.

## E50 — 자료·대화·근거 및 위험 패키지

입력·상황: 자료·대화·근거 이전 및 변조/구버전 패키지.
통과 기준: 정상 데이터 보존·색인 재생성, 손상·위험 경로·미지원 형식은 안전하게 거부.

| 기준 | 현재/예정 스모크 assertion | 증거 경계와 남은 확인 |
|---|---|---|
| 정상 자료 보존 | 폴더 1개·TXT 1개, 원본 바이트/추출문, 생성 시각/이름/구조를 정규화한 catalog 비교. 재내보내기·두 번째 가져오기. | 다양한 지원 파일 형식·한글/경계 이름·크기 한계·빈 Workspace의 실제 패키지 실행은 이 스모크에 없다. 서로 다른 앱 설치/계정 사이 전달도 아직 없다. |
| 대화·근거 보존 | 합성 두 턴, 합성 완료 답변 1개, 원문 인용/해시, 새 bundle ID·이전 문맥 digest 재연결, 재시작 상세 이력 동일성. | 실제 생성 답변/복잡한 다중 대화로 검증한 것이 아니다. 서명/원작성자 인증은 없으며 체크섬으로 진위를 보장하지 않는다. |
| 지원 범위 | ORIGINAL 자료·원본 근거 대화만 이전한다. 외부 위치/인증/승인은 복사하지 않는다. | 지식 문서·질문 첨부·이전 형식 보관함·고정 문맥 요청·미완료/실패 답변·분류 근거가 있으면 거부한다. 이것은 해당 정상 데이터의 보존 완료가 아니다. 전체 이전을 요구하는 E50 판정에서는 구현 범위 제한을 해결하거나 기준 작성자의 명시적 범위 결정을 받아야 한다. 임의로 기준을 좁히지 않는다. |
| 색인 재생성 | v2 opt-in은 모델 READY, 임시 DB search_outbox=0, 실제 검색 API에서 새 자료 ID·추출문 해시·원문·외부 Source 없음 확인. 최초/왕복/재시작/다른 Workspace 삭제 후 총 4회. | 아래 역사적 JAR에서 실행 완료했다. v1의 QUEUED_LOCAL_REBUILD와 추출문 존재만으로는 색인 완료 증거가 아니다. v2도 정확한 문자열 검색이며 자연어 질문 검색/랭킹 품질이나 모든 색인 문서의 무결성을 평가하지 않는다. 새 .23/.24 검증으로 이월하지 않는다. |
| 변조/손상 | manifest와 다른 파일 내용, 재체크섬된 거짓 인용을 400으로 거부하고 Workspace 목록 불변 확인. | 잘린 ZIP·중복 항목·압축 폭탄·대형 입력·정상 checksum의 잘못된 이력 참조 등은 현재 런타임 스모크에 없다. 코덱/통합 테스트 증거와 구분한다. |
| 위험 경로 | catalog의 ../ 이름과 ZIP ../ 항목을 거부한다. | 절대 경로·역슬래시·다른 경로 인코딩/중복 변종 전체를 이 런타임에서 검사하지 않는다. 파일시스템 전체 무변경 감시도 하지 않는다. |
| 미지원/구버전 | catalog.version=999 및 알려지지 않은 credentials 필드를 거부한다. | 실제 구버전 앱이 만든 패키지를 가져온 실행 증거가 없다. 미래 버전 번호 거부는 구버전 패키지 호환/거부 검사와 다르다. binary manifest 구버전 검사는 런타임에 없다. |
| 안전한 적용/재시도 | 새 Workspace, 비활성 polling, 중복 requestId 결과 재사용, 재시작 영수증, 삭제 후 재생성/새 requestId로 preview 재사용 차단. | 같은 ZIP으로 새 preview를 만드는 전역 중복 제거는 지원하지 않는다. 런타임 강제 종료/중간 DB 실패 주입에 따른 롤백은 미검증이다. 원자성 실패 주입은 별도 통합 테스트 증거다. |

기존 v1 합성 런타임: JAR `1ddab26fc24c41a1a25ab8cc351d98659cccefdace8a0b697f54048a20f8afe0`, 스크립트 `6181b4f1ecb63e2f339f587eec251a52d104c690d7f41f50ee6311d9dede2407`, 실행 `2026-10-25T14:23:34.418Z`, 6개 그룹 PASS. 로컬 로그 `/tmp/dougle-workspace-archive-smoke.log`는 임시 증거이며 영구 보존본이 아니다. 이 해시는 이후 수정된 v2 하네스의 해시가 아니다.

2026-10-26 E50 증거 갱신: `docs/evaluations/workspace-archive-v28-model-smoke.json`은 `2026-10-25T21:24:49.775Z`, JAR `276e56fd38d1720cb0bde17072bd2b14ab63233d7fb6e356e82d32bd782b6f22`의 합성 10개 그룹 통과(색인 4회)를 보존한다. 위 작성 당시의 실행 대기 설명은 이 결과 이전 이력이다. .23 `fc3fab555cc948b7452b68f4f2b7fd55f108c0ae912abdba058bd79de7318119` 및 차기 .24에 대한 E50 런타임 결과가 아니다. 기존 증거와 NOT_RUN 판정을 유지한다.

차기 격리 검사는 `scripts/e50-independent-archive.mjs`와 별도 가드 테스트로 준비했다. 독립 임시 DB A/B, 다중 턴 문맥/기본 모델 답변, 재시작/왕복 및 미지원 첨부의 안전 거부를 대상으로 하며 실제 사용자 DB·AI·외부 계정은 사용하지 않는다. 소스 가드 11개만 통과했고 런타임은 미실행이다. 수동 운영 조회 UI 제거 후 부모의 새 .24 동결을 기다린다. 명시적 `--jar/--sha256/--java/--models` 계약과 격리 제한은 `workspace-archive.md`를 따른다. 아래는 이전 v2 하네스 실행 절차이며 차기 검사에 backend target을 암묵적으로 사용하지 않는다.

## 이전 v2 JAR 승인 후 실행 및 보존 절차

1. 부모가 전달한 최종 JAR SHA-256을 실행 전 확인한다. Maven/빌드/패키지 덮어쓰기를 하지 않는다. 사용한 전체 git revision과 작업 트리 변경 여부도 기록한다. 커밋 해시만으로 미커밋 아티팩트를 식별하지 않는다.
2. 사전 준비된 해당 CPU용 로컬 모델 디렉터리의 네 파일 이름·크기·SHA-256을 기록한다. 비밀 경로는 공유 로그에서 제거한다. 모델 준비/다운로드 API나 외부 AI를 호출하지 않는다.
3. `node scripts/workspace-archive-smoke.mjs --self-test` 후, 승인된 시점에만 `FORGE_ARCHIVE_SEARCH_MODELS=/approved/local/models node scripts/workspace-archive-smoke.mjs --run`을 실행한다. opt-in을 빠뜨리면 indexVerification=SKIPPED이며 색인 통과 근거가 아니다.
4. 종료 코드, stdout/stderr 원본, JSON의 executedAt/JAR·script SHA-256/fixtureVersion/checks/indexVerification 및 네 단계 observation을 보존한다. 준비된 v2 하네스 기준 성공은 기본 6개+색인 4개=10개 그룹이다. 그룹 수를 개별 assertion 수나 인수 시나리오 수로 바꾸어 보고하지 않는다.
5. 프로세스 종료·임시 DB/자료 삭제·최종 JAR 해시 불변을 확인한다. 로그 보존본도 해시를 기록한다. 실패/timeout이나 SKIPPED를 PASS로 합산하지 않는다.
6. E49는 별도로 승인된 계정/대상 설치에서 앞 표의 빈칸을 채워야 한다. 기존 `team-settings-smoke.mjs`를 다시 실행하더라도 단일 임시 환경 결과만으로 그 빈칸이 채워지지 않는다.

평가 기록에 사용할 항목: 케이스 ID, exact acceptance 원문, 실제 아티팩트/소스 revision, fixture 및 모델 버전, 실행 시각, expectedEvidence, 실제 결과/오류, 사용한 API·요청 범위·응답 요약, 지연/비용(미측정이면 null), 증거 파일 경로/설명, reviewer, 남은 제한. 비밀정보는 증거에 넣지 않는다. 이 하네스 결과는 `mode=simulated`, `fixtureOnly=true`로 유지하며 완전한 실제 인수 검토 전 E49/E50 PASS를 주장하지 않는다.

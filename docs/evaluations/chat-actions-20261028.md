# 대화 수동 진입 버튼 제거 — 0.1.31

**2026-10-28 공개:** 사용자 요청으로 `v0.1.31-preview.1`을 공개 Preview 릴리스로 전환했다. 아래 초안 업로드 기록은 공개 전 이력이며 같은 검증 파일7개를 그대로 공개했다. README 다운로드를 갱신했고 자동 업데이트 피드는 변경하지 않았다. 공개 승인은 기존 미검증 항목의 통과를 의미하지 않는다.

사용자 요청으로 답변 아래의 `자료 더 찾아보기`와 `브라우저 화면 조사` 진입 버튼을 제거했다. 문구만 숨긴 것이 아니라 ChatPanel에서 수동 조사 진입 컴포넌트를 렌더링하지 않는다. 질문 전송의 기존 검색/계획/답변 흐름은 그대로이며, 이미 진행 중이거나 복원한 계획의 결과·취소·조회 승인 화면은 유지한다. 브라우저 조사 API나 내부 도구를 제거하거나 승인 없이 자동 실행하도록 바꾸지 않았다.

## 검증

- ChatPanel106개 통과: 검색 결과 없음, 검색 캡처 후, 기록 재열기에서 진입 버튼이 없음을 검사한다. 기존 수동 버튼 기반 테스트는 저장된 계획 복원 경로로 전환하여 근거 고정·답변 승인·읽기 승인 검증을 유지했다.
- 전체 UI630개 및 별도 opt-in130개, 총760개 통과. 프런트엔드 빌드 및 패키지 JAR 일치 확인. 큰 번들 경고는 기존과 같다.
- 백엔드 코드 변경은 없다. JAR 패키징 시 Java 검사를 다시 돌리지는 않았으며 직전0.1.30의1099통과와 구분한다.
- [화면](chat-actions-removed-20261028.png)은 실제 빌드 UI·합성 API로 기록을 열어 촬영했다. 사용자 데이터나 외부 AI 호출을 사용하지 않았다. 초기 합성 API에서 계획 응답이 누락되어 오류가 났던 시도는 성공으로 집계하지 않고, 기록 복원 흐름으로 다시 확인했다.
- Node 전체 검사의 최초 실행은171통과/1실패(프로토콜 계수기 하위 프로세스5초 시간 초과). 집중 및 직렬 재검사에도 시간 초과가 있었으며 UI 회귀 성공과 구별한다. 제품의 관련 없는 로직이나 제한 시간을 바꾸지 않았다.

검색 속도 개선은 이번 변경에 포함하지 않는다. 다음 단계는 검색·임베딩·후보 재평가·답변 생성의 시간을 분리 측정하고, 정확도 회귀를 유지하면서 캐시·배치 평가를 검토하는 것이다. 측정 전에 후보 수를 줄이거나 개선 수치를 약속하지 않는다.

기존 `backend/target/search-acceptance-results.json`의 합성150개 실모델/Lucene 검사 elapsedMillis는 중앙317 ms·95백분위467 ms·최대1734 ms였다. 이는 실제 업무 자료나 앱 질문→답변 전체 지연 측정이 아니다. 현재 ChatPanel은 검색 근거 생성 뒤 `sendConversationPlan`을 기다리고 필요하면 추가 검색 근거를 고정한 다음 답변을 요청한다. 로컬 관련성 재평가와 별개로 계획 AI 호출도 지연 후보이므로 먼저 각각의 시간을 계측해야 한다. 이번 UI 버튼 제거를 속도 최적화로 보고하지 않는다.

공개 릴리스/자동 업데이트 피드 보류는 유지한다. Intel/ARM 설치 파일은 GitHub 초안 릴리스에 보관하며 ARM 실기기 검증과 Apple 공증 완료를 의미하지 않는다.

Intel0.1.31 최종 로컬 설치를 완료했다. 이전 앱과 정지한 SQLite를 백업했고 패키지 프런트엔드 일치·JAR 일치·서명·DB30·HTTP200/비인증403을 확인했다. [설치 증거](local-install-0.1.31-20261028.json). 접기 뒤 수동 버튼이 다시 나타나는 경로까지 제거한 최종 소스와 설치본을 맞췄다.

GitHub `v0.1.31-preview.1` 초안에 Intel/ARM DMG2개·업데이트 아카이브2개·서명2개·체크섬1개, 총7개 파일을 업로드했다. GitHub API의 각 파일 SHA-256과 크기가 로컬 최종 파일과 일치함을 확인했다. 공개 배포나 자동 업데이트 승격은 하지 않았다.

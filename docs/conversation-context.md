# 이전 문맥 미리보기

완료 답변 중 **내가 선택한 것만** 새 질문과 함께 확인합니다.
미리보기 버튼은 읽기 전용입니다. 후속 **고정 저장 → 별도 승인 → 실제 전송**은 [문맥 질문](context-requests.md)을 따릅니다.

## 사용법

1. 자료 검색에서 새 질문의 근거 묶음을 저장합니다.
2. **답변 이력 → 대화 보관함 관리**에서 보관함을 엽니다.
3. **이전 문맥 선택**에서 새 질문 묶음과 이전 답변 1~5개를 고릅니다.
4. 제공자/모델을 고르고 **선택한 문맥 미리보기**를 누릅니다.
5. 현재 근거 → 이전 질문·답변 → 요청 전문과 해시 순서로 확인합니다.

선택한 순서가 아니라 보관함 번호 순서로 문맥을 구성합니다.
선택/모델/보관함이 바뀌면 화면 결과를 지우며 자동 재요청하지 않습니다.
이전 AI 답변은 사실 근거가 아니며, 그 안의 인용 번호를 새 질문의 근거 번호로 재사용하지 않습니다.

## 실제 구현

```text
ConversationShelf → ConversationPreviewPanel
  → POST /api/workspaces/{workspaceId}/conversations/{id}/preview
  → ConversationPreviewService
      → 보관함 revision·선택 소속 검사
      → 현재 질문 EvidenceAnswerPreview (기존 원본/게시/모델 검사)
      → 이전 작업 완료 여부 + 각 근거 묶음 최신성 검사
      → JSON 문맥 + 현재 요청문 → 전용 digest
```

입력:
```json
{
  "bundleId": "새 질문의 근거 묶음 ID",
  "expectedRevision": 2,
  "jobIds": ["선택한 이전 답변 작업 ID"],
  "provider": "CODEX",
  "requestedModel": ""
}
```

응답은 `conversationId, revision, provider, requestedModel, bundle, history, digest, prompt, characters, maxCharacters`입니다.
변경 요청 헤더 `X-Forge-Client: 1`은 필요하지만 POST가 저장이나 외부 전송을 의미하지는 않습니다.

| 경계 | 코드 대조 |
|---|---|
| 선택 | 1~5개, 중복/빈 값/다른 보관함 답변 차단 |
| Workspace | 보관함, 새 묶음, 이전 작업/묶음 모두 같은 범위로 조회 |
| 최신성 | 현재 질문뿐 아니라 선택한 과거 답변의 근거도 재검증 |
| 삭제/변경 | 404 또는 409. 오래된 답변은 제외하거나 자료를 다시 준비 |
| 길이 | JSON 포함 요청문 최대 20,000 UTF-16 코드 단위. 초과 시 413, 자동 잘라내지 않음 |
| 토큰 | 모델별 토크나이저가 아니므로 토큰 수라고 표시하지 않음 |
| 해시 | purpose=CONVERSATION_PREVIEW_V1, Workspace/보관함/revision/현재 요청 해시/모델/이전 문맥/요청 전문 |
| 저장 | 미리보기는 무저장. 별도 고정 저장은 v18 conversation_request 사용 |
| 기존 승인 | ANSWER_PREVIEW_V2 해시와 다름. 고정 저장 전에 전용 해시를 제출하면 409 |
| 표시 | React 텍스트, raw HTML/이미지 실행 없음. 닫기·전환 시 늦은 응답 제외 |

읽기 트랜잭션에서 한 시점의 내용을 만들지만, **영구 불변 요청을 저장한 것은 아닙니다.**
조회 이후 원본은 바뀔 수 있습니다. 프롬프트의 주의 문장은 모델이 반드시 지킨다는 보증도 아닙니다.

## 다음 연속 작업

- 문맥 스냅샷 영속 보관·승인·접수/직전/완료 재검증과 실행·취소·SSE 연결은 [v18 후속 구현](context-requests.md)에 완료했습니다.
- 이후 Source 선택적 폴링/증분·무효화, Mac 설치형 패키징으로 이어갑니다.
- 실제 외부 AI 전송과 서명/공증 자격 증명 사용은 별도 승인을 받습니다.

## 검증

- 백엔드: 선택 순서/무저장/기존 승인 거부, 해시 바인딩, 잘못된 선택·Workspace, 과거 근거 변경, 삭제·문자 한도, HTTP 계약.
- UI: 명시적 선택, 근거 우선·안전한 텍스트, 모델 변경 결과 폐기, 범위 불일치, 오류, revision 전환/요청 취소.
- 2026-10-22 전체 빌드: UI 160개, 백엔드 290개 통과 + 실제 AI opt-in 1개 미실행.
- 실제 JAR smoke: 문맥 미리보기 해시의 재시작 보존, 단일 질문 해시와의 구분, 기존 보관함/답변/SSE/중단 경로 통과.
- 실제 브라우저: 자동 미선택, 묶음·이전 답변·모델 명시 선택, 현재 근거 우선 표시, 제공자 변경 시 결과 폐기, 닫기 확인.
- 실제 AI는 호출하지 않았습니다. 작은 가상 자료 검색 p95 24.60 ms이며 부하/AI 성능이 아닙니다. [측정 원본](performance-phase3-foundation.json)
- 기존 메인 JS 500.36 kB 경고는 남습니다. 이력/보관함/문맥 화면은 13.85 kB 지연 청크로 빌드됩니다.

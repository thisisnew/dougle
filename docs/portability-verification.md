# 다른 Mac 사용 흐름 검증

## 기준

테스트 수는 고유 입력 조합을 실제 실행한 결과만 센다. 재실행을 새 케이스로 더하거나, 스킵·환경 미준비를 통과로 바꾸지 않는다. 매번 제품/테스트/빌드 설정의 SHA-256과 실행 시작 시각을 고정한다. 코드가 바뀌거나 이전 XML 결과가 섞이면 결과 검증을 거부한다.

핵심 매트릭스는 **5,879개 입력 조합**이다. 5,879개의 독립 사용자 업무 흐름이나 실물 Mac 5,879대를 뜻하지 않는다. 기대 결과는 단순 성공 여부뿐 아니라 정확한 본문·해시·경로·행 범위·검색 대상·원본 불변·거부 후 무부작용을 확인한다.

| 영역 | 수 | 실제 실행 경계 |
| --- | ---: | --- |
| 파일/폴더 판독 | 2,880 | 24종 × 4인코딩 × 5경로 × 3개행 × 2유니코드 정규형; 실제 파일 수집→본문 추출 |
| 판독 경계 | 432 | 잘린 문자, 바이너리, 빈 파일, 바이트 한도, 읽기 분할, 취소 |
| 폴더 경계 | 39 | 깊이/이름 한도, 심볼릭 링크, 제외 항목, 취소와 재시도 |
| 웹 주소/리다이렉트 | 848 | 공인/사설 IP 경계, 대소문자/끝점, GitHub 차단, 모의 리다이렉트 |
| 읽기 전용 실행 범위 | 192 | Workspace/요청/권한 격리와 실행 예산 |
| 본문 분할 | 960 | 다국어·이모지·개행·분할 크기별 본문 재구성, 청크·행 위치 |
| 검색어 처리 | 288 | 허용/거부 입력과 정확한 처리 결과 |
| 실제 검색 인덱스 | 240 | Lucene 색인→검색→Workspace 격리→본문 교체→재열기→삭제 |

추가로 기존 회귀 검사, 파일 100개(100 MiB 포함), 폴더/웹/재동기화, 실제 동봉 검색 모델, 임시 MySQL, OAuth/MCP, UI, 실행 프로토콜 검사를 함께 수행한다. 프로토콜의 5,376개 바이트 분할·메시지 바인딩 조합은 위 핵심 수와 별도로 보고한다.

## Jira·Confluence 체크리스트

- 공식 메타데이터, PKCE S256, 동적 등록, 토큰 교환의 동일 resource.
- 기본 브라우저 시작 실패, 로컬 콜백 포트 충돌 시 새 포트 등록.
- 승인 성공/거부/취소/만료, 잘못된 state, 늦은 응답과 중복 연결.
- Jira만 또는 Confluence만 승인한 계정의 연결과 해당 제품 읽기.
- 허용된 읽기 scope/도구가 전혀 없으면 연결 완료를 표시하지 않음.
- 비어 있거나 잘못된 회사 사이트 목록, 다른 회사 URL, 알 수 없는 사이트 차단.
- Jira 이슈 및 Confluence의 두 URL 형식 읽기, 제품별 권한 부족 구분.
- 갱신 토큰 회전, invalid_grant 시 재연결, 일시 장애와 만료의 구분.
- 잘못된 JSON/서비스 응답과 DNS·시간 초과·인증서 오류 안내의 구분.
- 인증 코드·토큰·state를 UI/오류에 노출하지 않음; 쓰기 도구 호출 거부.

이 검사는 합성 OAuth 서버와 **실제 loopback HTTP/콜백**을 사용한다. 실제 회사 계정 승인, 회사 프록시/PAC/사설 CA, 관리자의 앱 차단 정책 통과를 뜻하지 않는다. 이 환경을 받을 수 없으면 미검증으로 남긴다.

## 설치본 검사

동봉 JVM/JAR로 6개 별도 HOME 시나리오를 실행한다: 일반 경로와 한글·공백·따옴표·이모지가 포함된 경로 각각에 AI 도구 없음, 다른 명령 이름 자동 탐색, 회사 별칭 선택/즉시 적용/재시작을 조합한다. 자료 업로드·한국어 검색·재시작 후 자료 유지와 두 AI 제공자의 가상 CLI 인증을 검증한다. 실제 AI 호출은 하지 않는다.

Intel DMG는 설치본의 실제 네이티브 UI를 검사한다. ARM DMG는 이 Intel 호스트에서 CPU/동봉 런타임/모델/서명/JAR 정적 검사만 가능하다. ARM 실행, Apple 공증/Gatekeeper, 회사 MDM 인수는 별도다.

## 재현

`bash scripts/verify-portability.sh`는 Java 21, 동봉 모델, 테스트용 MySQL 8.4 실행 파일을 확인한 뒤 JVM/UI/Node/Rust를 실행한다. MySQL은 `--no-defaults`와 새 임시 datadir/loopback 포트를 사용하며 기존 DB에 연결하지 않는다. 필요하면 `FORGE_ACCEPTANCE_MYSQLD`로 실행 파일을 지정한다. `FORGE_VERIFY_SEARCH_MODEL_DIR`는 `search-model-e5-v1`의 **부모 폴더**다.

결과는 `backend/target/portability-verification`에 보존한다. `java-results.json`은 케이스별 ID/상태/시간과 전체·매트릭스 수를 제공한다. JUnit의 `메서드[번호]`는 각 테스트 클래스의 고정 MethodSource 순서에 대응한다. 실패를 고친 후 같은 최종 소스로 전체 검사를 다시 실행한다.

패키지 생성 후 `node scripts/portable-install-matrix.mjs desktop/src-tauri/resources /tmp/dougle-portable-results.json` 및 `node scripts/source-recovery-smoke.mjs desktop/src-tauri/resources`를 실행한다. 설치본 버전과 JAR 해시는 별도 릴리스 보고서에 기록한다.

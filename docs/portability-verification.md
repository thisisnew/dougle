# 다른 Mac 사용 흐름 검증

Jira 연결 실패/복구20개 시나리오를 추가했다. 인증 메타데이터·등록·토큰·MCP 단계별401/403/429/503/HTML200을 실제 loopback HTTP로 주입해 안내 단계/민감정보 비노출/기존 연결 보존/재시도 후 문서 읽기를 검증했다. 관련4클래스68통과·외부환경1생략. 초기MCP fixture 경로/query 비교 오류5건을 바로잡고 전체 재실행했다. `docs/evaluations/atlassian-stage-recovery-0.1.38.json` 참고. 실제 회사SSO 검증이나 제품 수정은 아니며 설치본0.1.38을 유지한다.

설치0.1.38의 실제 화면에서 가상 Workspace별 질문 기록 분리·다시 열기·백엔드 재시작 후 유지 확인. 전후 대화 API 내용 동일·답변 작업0건, 전체Node5,569통과. `docs/evaluations/e37-ui-0.1.38.json`과 화면3장에 기록했다. Chromium 웹 모드·미완료 가상 질문 범위이며 실제AI 답변/네이티브Mac/회사SSO 인수는 아니다. 테스트 실행기의 HOME/환경변수 격리를 보완했고 제품 설치본은 유지한다.

## 실제 MySQL·설치본 API 후속 확인 — 2026-10-30

[실행 원장](evaluations/mysql-installed-0.1.38.json): 임시 MySQL8.4의 SELECT 전용 가상 계정으로 JDBC34건과 설치된0.1.38 HTTP22건을 통과했다. HTTP 검사는 TLS REQUIRED로 연결하고 소유 Workspace의 실제 행 조회, 다른 Workspace의 결과/실행/취소 거부, 승인 없는 실행 거부, 잘못된 쿼리 형식 거부, 조건값 주입의 데이터 처리, 실패한 재로그인의 기존 연결 보존을 확인했다. 연결 해제·재연결 시 기존 결과/동의 무효화, 재시작 시 연결 복원과 메모리 결과404, 새 동의 후 정상 조회까지 확인했다. 실제 회사 DB·UI·전체 조사 의미 검증은 아니다.

`FORGE_MYSQL_RUNTIME_RESOURCES`, `FORGE_MYSQL_RUNTIME_SHA256`, `FORGE_MYSQL_RUNTIME_REPORT`를 명시하면 `mysql-read-runtime-smoke.mjs`가 기존 JDBC 검증 뒤 설치본 HTTP 검사를 수행한다. 고정0.1.38 Intel JAR와 전용 HOME/data, 실행 불가 AI 명령을 사용한다. 회사 인증정보를 사용하지 않으며 임시 앱/MySQL 프로세스·데이터·가상 비밀번호는 종료 시 삭제한다. 보고서에는 비밀번호나 조회 연결 설정을 복사하지 않는다.

첫 시도들의 실행기 데이터 경로/부모 stdin과 짧은 요청ID를 고쳤다. TLS 해제 상태의 잘못된 비밀번호는 인증 거부 전에 연결 오류가 발생했으므로 해당 인증 검사는 TLS REQUIRED로 수행했다. TLS 해제 실패를 인증 성공이나 제품 수정으로 보고하지 않는다. 반복 실행 수를 고유 케이스에 더하지 않는다. JDBC34건은 현재 어댑터 소스의 별도 실행이며 HTTP22건만 설치 JAR 경로다.

## 설치본의 격리·근거 재검증 후속 확인 — 2026-10-30

추가로0.1.38 JAR를 고정 복사해 엄격한 파일/loopback 네트워크 샌드박스에서 저장 기록의 격리를 검증했다. [E37 실행 원장](evaluations/e37-isolation-0.1.38.json): 소유/다른 Workspace 조회88쌍, 제안16쌍, 검색·부모/첨부 ID 주입8그룹을 Workspace 전환·재시작 전후에 확인했다. 원래 행·JAR·Java는 불변이며 외부 요청/AI 실행0회, 종료·임시 자료 삭제를 확인했다.16쌍 중8쌍은 제거된 Datadog의 과거 제안을 소유자에게도409로 거부하고 다른 Workspace에는404로 거부한 기록이다. 가상 완료 기록을 저장한 검사이며 실제AI/브라우저 실행이나 전체E37 완료를 뜻하지 않는다. MySQL 실행 중 메모리 결과와 실제UI 전환 검증은 별도다.

검증기는0.1.25 재현과0.1.38의 정확한 해시만 허용한다. 관련14건·전체Node5,569건 통과 후 보고서의 제거 기능 표시만 정정하고 관련14건과 전체 런타임을 다시 통과했다. 반복 실행을 새 케이스로 합산하지 않는다.

설치된0.1.38 Intel의 Java/JAR/검색 모델을 새 HOME·임시 자료로 실행했다. `source-recovery-smoke.mjs`의19개 확인 항목이 통과했다. 같은 이름의 코드가 있는 두 Workspace 간 근거 격리, 외부 thread/bundle/parent ID 거부, 원본 변경·삭제 뒤409 미리보기 거부, 과거 불변 근거 보존, 삭제 자료의 검색 제외와 다른 Workspace 보존을 확인했다. AI 실행 명령은 없는 경로로 고정했고 답변 작업0건을 확인했다.

[실행 원장·JAR/검증기 해시](evaluations/isolation-runtime-0.1.38.json). 첫 시도는 가상 Workspace 이름이20자를 넘어 중단됐으며 fixture를 수정하고 전체 재실행했다. 제품 오류나 추가 통과 건수로 세지 않는다. 이 검사는 E37/E40의 로컬 자료/대화 경계에 대한 증거이며 전체 도구·브라우저 격리, 회사SSO·원격 권한 철회, 실제AI 인수나 다른Mac 실행을 대신하지 않는다. 제품 코드/설치 파일은 변경하지 않았다.

## 기준

테스트 수는 고유 입력 조합을 실제 실행한 결과만 센다. 재실행을 새 케이스로 더하거나, 스킵·환경 미준비를 통과로 바꾸지 않는다. 매번 제품/테스트/빌드 설정의 SHA-256과 실행 시작 시각을 고정한다. 코드가 바뀌거나 이전 XML 결과가 섞이면 결과 검증을 거부한다.

핵심 매트릭스는 **5,879개 입력 조합**이다. 5,879개의 독립 사용자 업무 흐름이나 실물 Mac 5,879대를 뜻하지 않는다. 기대 결과는 단순 성공 여부뿐 아니라 정확한 본문·해시·경로·행 범위·검색 대상·원본 불변·거부 후 무부작용을 확인한다.

## Jira·Confluence 체크리스트

- 공식 메타데이터, PKCE S256, 동적 등록, 토큰 교환의 동일 resource.
- 기본 브라우저 시작 실패, 로컬 콜백 포트 충돌 시 새 포트 등록.
- 승인 성공/거부/취소/만료, 잘못된 state, 늦은 응답과 중복 연결.
- Jira만 또는 Confluence만 승인한 계정의 연결과 해당 제품 읽기.
- 허용된 읽기 scope/도구가 전혀 없으면 연결 완료를 표시하지 않음.
- 비어 있거나 잘못된 회사 사이트 목록, 다른 회사 URL, 알 수 없는 사이트 차단.
- Jira 이슈 및 Confluence의 두 URL 형식 읽기, 제품별 권한 부족 구분.
- 갱신 토큰 회전, invalid_grant 시 재연결, 일시 장애와 만료의 구분.
- 잘못된 JSON/서비스 응답과 DNS·시간 초과·인증서 오류 안내의 구분.
- 인증 코드·토큰·state를 UI/오류에 노출하지 않음; 쓰기 도구 호출 거부.

이 검사는 합성 OAuth 서버와 **실제 loopback HTTP/콜백**을 사용한다. 실제 회사 계정 승인, 회사 프록시/PAC/사설 CA, 관리자의 앱 차단 정책 통과를 뜻하지 않는다. 이 환경을 받을 수 없으면 미검증으로 남긴다.

## 설치본 검사

동봉 JVM/JAR로 6개 별도 HOME 시나리오를 실행한다: 일반 경로와 한글·공백·따옴표·이모지가 포함된 경로 각각에 AI 도구 없음, 다른 명령 이름 자동 탐색, 회사 별칭 선택/즉시 적용/재시작을 조합한다. 자료 업로드·한국어 검색·재시작 후 자료 유지와 두 AI 제공자의 가상 CLI 인증을 검증한다. 실제 AI 호출은 하지 않는다.

Intel DMG는 설치본의 실제 네이티브 UI를 검사한다. ARM DMG는 이 Intel 호스트에서 CPU/동봉 런타임/모델/서명/JAR 정적 검사만 가능하다. ARM 실행, Apple 공증/Gatekeeper, 회사 MDM 인수는 별도다.

## 재현

`bash scripts/verify-portability.sh`는 Java 21, 동봉 모델, 테스트용 MySQL 8.4 실행 파일을 확인한 뒤 JVM/UI/Node/Rust를 실행한다. MySQL은 `--no-defaults`와 새 임시 datadir/loopback 포트를 사용하며 기존 DB에 연결하지 않는다. 필요하면 `FORGE_ACCEPTANCE_MYSQLD`로 실행 파일을 지정한다. `FORGE_VERIFY_SEARCH_MODEL_DIR`는 `search-model-e5-v1`의 **부모 폴더**다.

결과는 `backend/target/portability-verification`에 보존한다. `java-results.json`은 케이스별 ID/상태/시간과 전체·매트릭스 수를 제공한다. JUnit의 `메서드[번호]`는 각 테스트 클래스의 고정 MethodSource 순서에 대응한다. 실패를 고친 후 같은 최종 소스로 전체 검사를 다시 실행한다.

패키지 생성 후 `node scripts/portable-install-matrix.mjs desktop/src-tauri/resources /tmp/dougle-portable-results.json` 및 `node scripts/source-recovery-smoke.mjs desktop/src-tauri/resources`를 실행한다. 설치본 버전과 JAR 해시는 별도 릴리스 보고서에 기록한다.

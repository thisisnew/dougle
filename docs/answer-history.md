# 질문별 답변 이력

이제 **자료 연결과 검색 → 답변 이력**에서 이 Workspace의 답변을 모아 볼 수 있습니다.
검색어가 없어도 열립니다. 질문과 상태로 목록을 좁히고 작업을 선택하세요.

## 무엇을 보여주나요?

1. 질문, 생성 시각, 완료·실패·중단 등 조회 시점 상태.
2. 선택한 질문의 **답변 당시 근거**와 게시 지식에 연결된 원본 인용.
3. 완료된 답변과 요청 모델. 실패한 작업은 오류와 함께 표시합니다.

HTML·이미지·링크는 실행하거나 자동 로딩하지 않고 글자로 표시합니다.
이전 답변은 최신성이나 사실성을 보증하지 않습니다. 변경된 원본을 자동으로 다시 분석하지 않습니다.
진행 중 작업은 다시 선택하거나 **이력 새로고침**으로 확인하세요. 이 화면은 실시간 스트림 화면이 아닙니다.

## 하지 않는 일

- 열기·검색·선택·새로고침은 AI를 호출하거나 승인을 저장하지 않습니다.
- 닫기·Workspace 전환은 조회 요청만 중단합니다. 서버의 생성 작업을 취소하지 않습니다.
- 이력 조회는 대화방을 만들거나 이전 문맥을 전송하지 않습니다. 별도 **대화 보관함 관리**에서 명시적으로 완료 답변을 정리할 수 있습니다. [사용법](conversations.md).
- 답변 작업 삭제·재생성·중단은 이 화면에서 하지 않습니다. 보관함 삭제는 연결만 지웁니다. 기존 근거 묶음 화면의 작업 기능과 구분하세요.

따라서 **질문별 독립 요청 이력**이며 다중 턴 채팅 완성은 아닙니다.

## 데이터와 코드 대조

```text
SourcePanel의 답변 이력 버튼
  → AnswerHistoryPanel (열 때 화면 코드 로딩)
  → 현재 Workspace의 answer-jobs + evidence-bundles 목록 조회
  → 선택한 작업 다시 조회 → 해당 근거 묶음 조회
  → 범위 확인 → 당시 근거 → 완료 답변 표시
```

| 항목 | 실제 구현 |
|---|---|
| `AnswerHistoryPanel` | 질문/상태 필터, 작업별 상세, GET만 사용하는 읽기 전용 대화상자 |
| `SourcePanel` | 검색어와 관계없는 명시적 진입 버튼, 지연 로딩 |
| Workspace 전환 | Workspace별 컴포넌트 초기화, AbortController와 늦은 응답 제외 |
| 근거 연결 | 작업의 bundle ID를 기준으로 조회. 작업/묶음의 Workspace와 ID 대조 |
| 저장 모델 | 기존 SQLite v16 `answer_job`, `evidence_bundle` 재사용. 새 테이블·API 없음 |

목록 조회는 GET 두 번이고, 상세 선택은 작업과 묶음에 GET을 한 번씩 보냅니다.
필터는 로컬 목록에서 처리합니다. 최대 100개 작업 한도는 기존 서버 정책 그대로입니다.
원본 삭제만으로 이력이 사라지지 않습니다. **근거 묶음 삭제 시 연결된 답변 작업도 삭제**, Workspace 삭제 시 전체 삭제됩니다.
조회 도중 삭제되면 이전 상세를 지우고 오류를 표시합니다. 목록은 새로고침해서 맞춥니다.

## 다중 대화 설계 — 문맥 전송은 아직 미구현

- v17 보관함은 완료 답변 작업을 사용자가 정한 순서로 연결합니다. 이는 실제 문맥을 이어 보낸 턴 기록이 아닙니다.
- 이전 질문/답변을 재전송하려면 포함할 내용을 요청 미리보기에 보여주고, 해시·모델·승인에 함께 묶습니다.
- 이전 AI 답변은 원본 근거가 아닙니다. 이전 답변을 검증된 사실로 승격하거나 그대로 새 지식에 저장하지 않습니다.
- 재연결은 관측만 수행합니다. 새 턴 전송은 새 승인으로 실행하고 대화방 삭제·실행 중 삭제 정책을 따로 확정합니다.
- 이를 구현하기 전에는 현재 작업을 임의의 대화방으로 자동 이관하지 않습니다.

## 검증

- 새 화면 테스트 9개: GET 전용, 당시 근거 우선, 안전한 텍스트 표시, 로컬 필터, 실패 답변 숨김, 삭제 오류, 범위 불일치, Workspace 전환/늦은 응답, 닫기, 목록 갱신.
- 진입 버튼 테스트 1개: 검색어 없이 명시적으로 열고 닫기.
- 초기 빌드에서 메인 JS 504.57 kB 경고가 발생해 새 이력 화면을 지연 로딩하도록 분리했습니다. 이력 청크는 5.61 kB, 메인 청크는 500.36 kB로 줄었지만 Vite의 500 kB 경고는 남습니다. 빌드는 성공하며 추가 공통 화면 분리는 후속 작업입니다.
- 2026-10-22 통합 빌드 성공: 프런트엔드 149개, 백엔드 275개 통과. 실제 AI opt-in 테스트 1개는 실행하지 않았습니다.
- 실제 JAR smoke 통과: 가상 CLI의 답변·중단·재시작·SSE 경로를 확인했습니다. 실제 외부 AI 생성 성공을 뜻하지 않습니다.
- 브라우저에서 검색어 없이 진입, 완료/중단 필터, 당시 근거 우선 표시, 중단 작업 답변 숨김, 질문 필터, 닫기를 확인했습니다. 테스트용 임시 서버는 종료했습니다.
- 작은 가상 자료 100개 검색의 순차 HTTP 측정 p95는 15.24 ms였습니다. 부하 테스트나 AI 속도 측정은 아닙니다. [측정값](performance-phase3-foundation.json)

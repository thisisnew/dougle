# 반복 실행·장애 경계 검증 — 0.8.10

**추가 테스트로 실제 실패를 재현하고 수정했습니다.** 가상 자료와 fake Slack/AI를 사용했으며 회사 자료·키체인에는 접근하지 않았습니다.

| 발견한 문제 | 수정·확인 |
|---|---|
| 답변 저장 직후 종료되면 AI를 다시 호출 | 답변·작업 완료를 같은 트랜잭션에 저장. 재시작 후 호출1회 유지, 저장 실패는 둘 다 롤백 |
| 스킬 실행 실패를 보완하다 코드·운영 조회 요구 누락 | 재시도에서도 최초 조사 요구 유지. 부족한 근거로 승인 가능한 답변 생성 차단 |
| 서명된 다운로드 URL이 검사 통과 | 서명·접근 토큰 매개변수 패턴 추가. 보고서에는 값 미출력 |
| Publish 지침이 동일한 최종본을 두 번 전체 검사하도록 요구 | 최종 검토 뒤1회 검사. 같은 작업의 동일 파일·원격 기준일 때만 통과 결과 재사용 |

마지막 항목은 지침의 중복을 수정한 것입니다. 실제 호스트 AI가 그 절차를 수행했는지까지 시험한 결과는 아닙니다.

## 실행한 검사

- **봇456개:** 200개 동시 중복 이벤트가 작업1개·AI 호출1개로 끝나는지, 완료 후 재전송, 취소 중 늦은 결과, 예산 초과, 반복 세션 유실, 스킬/형식/근거 실패와 복원 조합, 저장 도중 오류를 포함합니다. 이벤트200개는 테스트200개로 세지 않습니다.
- **민감정보77개:** 기존 검사와 서명 URL·HTML 이스케이프·파일명·개행 없는 마지막 줄·CRLF·묶음 중 바이너리 등을 확인합니다.
- **실제 Git1만 파일:** 변경10개·동일9,993개, 2,500개 일괄 변경, 동일 목록3회 비교, 관련 없는 커밋, 파일명 변경, 캐시 변조와 고정 버전을 확인합니다. AI 의미 병합 검사는 아닙니다.
- **혼합 크기1,000파일:** 4KiB·64KiB·1MiB 파일의 전체 검사 → 파일1개에 합성 암호 추가 후 전체 차단 → 원상복구 후 같은 해시 확인. 검사 중 프로세스 종료 시 PASS가 나오지 않고 새 검사로 복구되는지도 확인합니다.

혼합 파일 검사는 각각 **66.6초 / 78.9초 / 71.5초**였습니다. 첫 검사와 원상복구 후 결과는 같은 패키지 지문입니다. 이 반복은 검증용이며 실제 Publish에서 동일 최종본을 세 번 검사하도록 요구하는 것이 아닙니다. [원시 결과](stress-verification.json)

## 아직 보장하지 않는 것

스킬의 Fetch·Publish 의미 병합은 호스트 AI가 수행합니다. Git·검사 스크립트·봇 상태 전이가 통과했다고 실제 AI의 판단과 전체 처리 시간까지 통과한 것은 아닙니다. 추가 실모델 호출은0회이며 기존 누계200/200을 유지했습니다.

답변 저장 **이전**에 프로세스가 종료되면 다시 조사해야 할 수 있습니다. 검사 패턴이 모든 비밀정보를 알아내지는 못하므로 내용 검토도 유지합니다. 회사 서비스 권한·실제 M Mac·전체 응답 지연은 별도 확인 대상입니다.

개발 재실행: `pytest -q dougle-bot/tests`, `node scripts/test-publish-sensitive.mjs`, `node scripts/check-large-package.mjs`. 긴 반복 검사는 `python3 scripts/stress-publish-sensitive.py --files 1000 --output stress.json`입니다. 사용자가 실행할 필수 절차는 아닙니다.

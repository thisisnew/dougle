# 민감정보 게시 차단 검증

[실제 셸 검사 결과](results.json) · [개발용 테스트](../../../scripts/test-publish-sensitive.mjs) · [배포되는 검사](../../../skills/dougle-publish/scripts/check-sensitive.sh)

실제 토큰·개인정보를 쓰지 않고, 테스트 실행 중 생성한 가상 문자열로 셸 검사를 실행합니다. 본문/코드/JSON에 있는 암호와 토큰, 이메일·전화·식별번호 후보, 개인키, 접속 URL, 마스킹된 값, 일반 업무 지식과 코드 식별자를 확인합니다.

읽기 실패·잘못된 인코딩·바이너리·심볼릭 링크·지원하지 않는 파일·도구 누락·빈 폴더는 실패로 처리하는지 검사합니다. 파일 변경 시 다이제스트가 바뀌는지와 보고에 본문·값·경로가 노출되지 않는지도 확인합니다.

실제 회사 지식이나 Slack/GitHub에 게시하지 않습니다. 호스트가 publish 지침을 지키며 실제 원격 쓰기를 수행하는 통합 동작, 모든 민감정보 유형, 모든 OS 도구 버전의 동작을 보장하는 검사는 아닙니다.

## 이번 실행 결과

60개 가상 실행 사례가 통과했습니다. 독립 검토가 발견한 producer명령 실패 마스킹, 한 줄의 두 번째 비밀값, 경로 개인정보, 임시폴더 오류의 경로 노출을 회귀 사례로 추가했습니다. 의도적으로 실패시킨od/해시/find/sort/awk/iconv도 PASS로 처리하지 않습니다.

정상 최종 파일이라도 과거 커밋에 비밀정보가 있으면 전송될 수 있어, publish는 확인한 원격 기준 바로 위의 단일 검토 커밋만 만들고 그 부모·패키지 트리를 확인하도록 보강했습니다. 이 Git전송 규칙은 지침 검토이며 실제 원격 게시 통합 실행 결과와 구분합니다.

검사 도중 본문 교체·파일명 변경·파일 추가를 실제 가상 폴더에서 수행하는3개 회귀도 포함했습니다. 모두 exit2/ERROR로 차단했고 stderr는 비어 있었습니다.

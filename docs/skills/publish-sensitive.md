# publish 전에 민감정보 확인하기

publish는 AI의 내용 검토와 번들 스크립트 검사를 모두 통과한 패키지만 게시합니다. 토큰·비밀번호·개인정보 후보가 있으면 이번 publish 전체를 중단하며 비공개 저장소에도 같은 규칙을 적용합니다. [공유 절차](sharing.md)

## 검사 순서

1. 게시할 토픽·출처·목차에 원격 변경을 합쳐 최종 패키지를 준비합니다.
2. AI가 이름·주소·고객·직원 정보와 나뉘거나 변형된 비밀정보 등 문맥을 검토합니다.
3. 마지막 수정 뒤 최종 패키지 전체에 번들 검사를 한 번 실행합니다.
4. 두 검사를 통과한 동일 패키지를 게시합니다. 같은 작업에서 내용·경로·원격 기준·세션이 유지되면 게시 단계라는 이유만으로 다시 검사하지 않습니다.

내용이나 기준이 바뀌면 새 최종본을 전체 검사합니다. 발견한 값을 자동 삭제한 뒤 곧바로 게시하지 않으며 수정한 내용도 다시 검토합니다. 검사 도구를 실행하지 못하거나 일부 파일을 읽지 못하면 게시를 중단합니다.

## 결과 표시

```text
게시 중단
• 민감정보 후보 2건
• 탐지 항목: 인증정보, 이메일
• 값은 표시하지 않음
```

보고에는 파일 ID·줄 번호·탐지 종류만 담습니다. 토큰 값·전체 문장·식별 가능한 파일명은 노출하지 않으며 결과는 게시 패키지에 넣지 않고 로컬 공유 작업 기록에 남깁니다.

## 검사 범위

| 구분 | 검사 대상 |
|---|---|
| 인증정보 | GitHub·Slack·API 키, AWS 접근 키, bearer/JWT·개인키 형태 |
| 값·URL | 비밀번호·토큰 할당, 인증정보 포함 접속 URL, 서명·접근 토큰 매개변수 |
| 개인정보 | 이메일·한국 휴대전화·주민번호 후보·명시적 개인정보 항목 |
| 검사 실패 | 읽기 실패, 잘못된 인코딩, 바이너리, 심볼릭 링크, 검사 중 변경된 파일 |

파일명·폴더명도 검사합니다. Git 게시에서는 검토한 트리 바로 위의 커밋만 전송하도록 이전 미게시 이력을 차단합니다.

패턴만으로 모든 이름·주소·새 토큰 형식을 찾을 수는 없습니다. 내용 검토를 함께 수행하고 의심이 남으면 보류합니다. 탐지는 확인이 필요한 후보이며 실제 유출 확정 판정은 아닙니다.

검사는 Mac의 기존 셸·텍스트 도구를 사용하며 Python·Node·별도 스캐너 설치를 요구하지 않습니다. 이 사전 검사는 더글 publish에 적용되며 호스트의 다른 명령이나 직접 Git 작업을 차단하는 기업 DLP를 대신하지 않습니다.

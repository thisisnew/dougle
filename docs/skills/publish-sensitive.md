# publish 전에 민감정보 확인하기

**토큰·비밀번호·개인정보 후보가 있으면 이번 publish 전체를 중단합니다.** 비공개 저장소에도 같은 규칙을 적용합니다.

## 검사 순서

1. 실제 보낼 토픽·출처·목차와 원격 변경을 합친 최종 패키지를 준비합니다.
2. AI가 그 내용을 읽고 민감한 문맥을 확인합니다. 이름·주소·고객/직원 정보, 나뉘거나 변형된 비밀정보도 검토합니다.
3. 내용 검토와 마지막 수정이 끝난 뒤, 최종 패키지에 **한 번** 번들 검사로 토큰·암호·개인키·개인정보 패턴을 확인합니다.
4. 두 검사가 모두 완료된 같은 패키지만 게시합니다. 같은 작업에서 패키지가 그대로라면 게시 단계에 도달했다는 이유만으로 다시 검사하지 않습니다. 내용·경로·원격 기준이 바뀌거나 세션이 바뀌면 새 최종본을 전체 검사합니다.

발견한 내용을 자동으로 지우고 그대로 게시하지 않습니다. 문제를 해결한 새 내용을 다시 검토·검사합니다. 검사 도구가 없거나 일부 파일을 읽지 못했다면 게시하지 않습니다.

## 결과 표시

```text
게시 중단
• 민감정보 후보 2건
• 탐지 항목: 인증정보, 이메일
• 값은 표시하지 않음
```

검사 보고에는 파일 ID·줄 번호·탐지 종류만 포함합니다. 토큰 값·전체 문장·식별 가능한 파일명은 그대로 출력하지 않습니다. 검사 결과는 로컬 공유 작업 기록에만 남기며 게시 패키지에는 넣지 않습니다.

## 검사 범위

- 알려진 GitHub·Slack·API 키와 AWS 접근 키, bearer/JWT·개인키 형태.
- 비밀번호·토큰 등 값이 할당된 항목과 인증정보가 포함된 접속 URL, 서명·접근 토큰이 들어간 URL 매개변수.
- 이메일·한국 휴대전화·주민번호 후보·명시적인 개인정보 항목.
- 읽기 실패, 잘못된 인코딩·바이너리·심볼릭 링크·검사 중 변경된 파일은 검사 실패.

파일명과 폴더명도 검사하며, Git 게시에서는 검토한 트리 바로 위의 커밋만 전송하도록 이전 미게시 이력을 차단합니다.

패턴 검사만으로 모든 이름·주소·새로운 토큰 형식을 알아낼 수는 없습니다. **패턴 통과와 내용 검토를 모두 요구하며, 의심이 남으면 보류합니다.** 거짓 양성이 있을 수 있으므로 ‘반드시 유출’이라는 판정이 아니라 게시를 멈추고 확인할 후보입니다.

Mac의 기존 셸/텍스트 도구로 실행하며 별도 Python·Node·스캐너 설치를 요구하지 않습니다. 해당 실행 도구를 쓸 수 없는 호스트에서는 publish를 중단합니다.

더글 publish가 반드시 거쳐야 하는 사전 검사입니다. 호스트의 다른 명령이나 직접 Git 작업까지 차단하는 네트워크 보안 장치는 아닙니다. 실제 기업 DLP를 대체한다고 보장하지 않습니다.

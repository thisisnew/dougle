# Slack 문의를 확인하고 답변 준비하기

**새 터미널에서 평소 쓰는 AI를 실행한 뒤, 문의 채널을 지정하세요.** 기존 Slack MCP 연결을 사용합니다. 별도 Slack 앱 초대는 이 기능의 전제가 아닙니다.

Claude 플러그인은 아래 명령만 입력하세요.

```text
/dougle:dougle-schedule
```

```text
✦ dougle · 스케줄

1. 목록
2. 등록
3. 삭제
0. 나가기
```

번호를 고르면 다음 단계로 이어집니다. **등록**을 고르면 문의 채널 URL을 물어봅니다. **목록**에서는 스케줄을 번호로 골라 재개·일시정지·이력·주기 변경을 선택합니다. **나가기**는 메뉴만 닫으며 기존 감시를 종료하지 않습니다.

바로 등록하려면 Slack 채널 URL을 붙이세요. 아래는 URL 형태 예시입니다.

```text
/dougle:dougle-schedule https://example.slack.com/archives/C0123456789
```

새 채널은 기본2분으로 등록합니다. 이미 등록된 채널이면 중복 생성하지 않고 기존 상태와 주기를 보여줍니다. 종료·삭제한 항목은 재개 여부를 확인합니다. 메시지 하나의 링크를 붙이면 해당 스레드인지 채널 전체인지 먼저 확인합니다. 현재 스케줄은 Slack 문의 채널용입니다.

Codex에서는 `$dougle-schedule` 뒤에 같은 요청이나 URL을 붙입니다.

**신규 스케줄의 기본은 2분입니다.** 기존에 저장한 주기는 유지합니다. 다른 간격을 원하면 `10분마다 확인해 줘`처럼 지정하세요. 호스트가 그 간격을 지원하지 않으면 가능한 간격을 안내하며 임의로 바꾸지 않습니다.

## 실행하면

1. 채널과 실제 읽기 권한·게시 계정·주기 실행 도구를 확인합니다.
2. 실행 시점 이후 새 문의를 찾아, 더글 지식과 필요한 원본으로 초안을 만듭니다.
3. 전용 세션에 문의·근거·최종 댓글을 보여줍니다.
4. **사용자가 해당 초안을 승인한 경우에만** 원래 Slack 스레드에 게시합니다. 마지막 줄은 **✦ dougle**입니다. 이 서명은 개인 계정으로 게시하는 schedule 답글에 적용합니다. 봇 계정의 답글에는 서명을 덧붙이지 않습니다.

문의 채널의 새 사용자 글은 멘션이나 물음표가 없어도 대상입니다. 예전 문의를 처리하려면 `오늘 오전부터 확인해 줘`처럼 범위를 지정하세요. 대기 중인 문의마다 별도 맥락을 유지합니다. 승인이나 VDI 조회 결과를 기다리는 동안에도 다음 확인 작업에서 새 문의를 수집할 수 있습니다.

## 스케줄 목록과 복구

**터미널을 닫아도 로컬에 저장한 설정·이력·대기 초안은 남습니다.** 실행 중인 타이머는 호스트 세션과 별개로 확인해야 합니다. 종료를 확실히 하려면 창을 닫기 전에 `감시 종료해 줘`라고 요청하세요.

새 터미널에서 AI를 실행한 뒤 `/dougle:dougle-schedule`을 입력하고 **1. 목록**을 고르세요. 채널·주기·저장 상태·현재 타이머 확인 결과·마지막 확인·대기 문의를 보여줍니다. 목록만 본다고 감시가 시작되지는 않습니다.

목록에서 원하는 스케줄 번호를 고르면 **재개 / 일시정지 / 이력 / 주기 변경 / 이전으로**를 선택할 수 있습니다. 스케줄 ID를 외울 필요가 없습니다.

**3. 삭제**에서 대상을 고르면 해당 감시를 종료하고 기본 목록에서 제외합니다. 로컬 이력·확인 위치·대기 기록은 복구를 위해 보관합니다. Slack 댓글이나 업무 지식은 지우지 않습니다. 타이머 종료를 확인하지 못하면 ‘삭제 대기’로 보여줍니다.

재개하면 **저장된 주기와 마지막 확인 위치부터** 이어갑니다. 이미 살아 있는 타이머는 중복 생성하지 않습니다. 다른 세션에서 실행 중인지 확인할 수 없으면 먼저 소유 세션을 확인합니다. 중단 중 삭제되거나 조회할 수 없게 된 메시지는 복구를 보장하지 않으며 누락 범위를 알립니다.

종료해 둔 스케줄을 마음대로 다시 켜지 않습니다. 전송 여부가 불명확한 댓글은 계속 보류하며, 이전 세션의 승인은 재사용하지 않습니다. 설정·이력 복구와 실제 감시 재시작의 성공 여부를 구분해 표시합니다.

기록은 `~/.dougle/schedules/`에 저장합니다. 이력에는 생성·주기 변경·정지·복구·오류 등을 남기며, 실제 채널 전체나 운영 DB 원시 결과를 보관하지 않습니다. 이전 버전에 없던 과거 이력을 만들어 채우지는 않습니다.

## 준비된 초안 처리

```text
A 초안으로 답변해 줘.
B는 설명을 더 쉽게 수정해 줘.
C는 건너뛰어.
감시 상태 보여 줘.
감시 일시정지해 줘.
마지막 확인 위치부터 재개해 줘.
감시 종료해 줘.
```

초안이나 질문·게시 계정이 바뀌면 다시 확인받습니다. 전송 결과가 불명확하면 중복 댓글을 막기 위해 게시 여부를 확인할 때까지 보류합니다. MCP가 자체적으로 붙이는 서비스 표시는 더글이 제거한다고 보장하지 않습니다.

## 운영 DB가 VDI 안에 있다면

로컬 AI가 직접 읽을 수 없는 문의는 **사용자 확인 대기**로 둡니다. 확인할 항목을 안내하고, 검증된 스키마가 있을 때만 적절한 읽기 전용 조회문을 준비합니다. 사용자가 회사 규정상 전달 가능한 최소 결과를 알려주면 초안을 완성하고 다시 승인을 받습니다. 회사 망 분리·반출 제한을 우회하거나 원시 운영 데이터를 자동 저장하지 않습니다.

## 실행 환경별 차이

| 환경 | 동작 |
|---|---|
| 로컬 반복 실행 도구가 있는 Claude | 실제 타이머 등록이 확인되면 주기 확인 시작 |
| 반복 실행 도구가 있는 다른 호스트 | 세션 도구·상태 접근과 순차 실행을 확인한 뒤 사용 |
| 반복 실행 도구가 없음 | 자동 감시는 시작하지 않음. 명시적인 1회 확인·초안 검토 가능 |
| 세션 종료·잠자기·권한 만료 | 정상 감시를 보장하지 않음. 재개 시 실제 도구와 남은 기록 확인 |

자동 터미널 열기는 호스트의 세션 생성 기능이 있을 때만 가능합니다. 첫 버전의 공통 사용법은 **직접 연 전용 세션**입니다. AI가 답변 중이면 확인 시점이 늦어질 수 있습니다. 운영 기록은 `~/.dougle/schedules/`에 남으며 지식 publish/fetch에 포함하지 않습니다.

더글은 반복 실행기나 트랜잭션 시스템을 별도로 설치하지 않습니다. 스킬의 실행 절차와 승인 규칙이며 호스트 전체의 쓰기 권한을 강제하는 보안 장치는 아닙니다. 읽을 수 있는 자료라도 해당 채널에 공개해도 되는지 확인합니다.

검증 범위는 [스케줄 평가](schedule-evaluation/README.md)를 확인하세요. 실제 Slack MCP·호스트 타이머 조합의 동작은 환경별 확인이 필요합니다.

## 확인 주기와 부하

2분 주기는 명목상 시간당30회,5분은12회입니다. 새 문의가 없으면 별도 지식 검색·초안 작성은 건너뛰지만, 주기마다 호스트 AI 실행과 Slack 조회는 발생합니다. 페이지와 추적 중인 스레드가 많으면 조회 수도 늘어납니다. 부하·토큰 비용이 가볍다고 측정한 것은 아닙니다. 조회 제한은 실제 도구 응답에 맞춰 기다리며, 미완료 범위는 다음 확인으로 이어갑니다. 호스트 지연이 있어 정확히120초마다 실행되는 것을 보장하지 않습니다.

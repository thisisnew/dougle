# ask 답변 가독성 평가

**상태: 지침 검토 완료. 실제 모델 출력 평가 미실행.**

0.4.1의 답변 형식이 필요한 정보를 잃지 않는지 확인하기 위한 시나리오입니다. 아래 예시는 가상 자료이며 실제 회사 시스템의 동작을 설명하지 않습니다.

## 평가 방법

1. 별도 임시 작업 공간에 아래 시나리오의 가상 근거를 준비합니다.
2. ask로 질문하고, 후속 질문은 같은 대화에서 수행합니다.
3. 답변의 정확성·근거·가독성을 따로 기록합니다. 짧기만 한 답변을 통과시키지 않습니다.

실제 모델 평가에는 별도 실행 기록이 필요합니다. 이 문서가 있다는 이유로 시나리오가 통과한 것은 아닙니다.

## 기본 답변과 후속 질문

| 가상 근거와 질문 | 확인할 결과 |
|---|---|
| confirm()이 receipt에 저장. “어디에 저장해?” | 테이블을 첫 문장에서 답하고 실제 근거 위치를 붙임. 전체 조사 과정은 생략 |
| 위 답변 후 “어느 코드부터 봐?” | 같은 입하 주제에서 confirm() 위치를 안내. 이전 답변 전체 반복 없음 |
| feature flag 공급자 설정에 flipt가 있음. “뭐 써?” | 공급자와 설정 근거만 간결히 답함. 무관한 기능 설명 없음 |
| Strategy 인터페이스와 구현 두 개가 있음. “예제와 핵심만” | 작은 코드 예제와 위임 관계 설명. 근거 없는 구현을 만들어내지 않음 |
| 두 설계 대안의 차이를 물음 | 비교 기준이 드러나는 작은 표. 모든 답을 억지로 절차로 만들지 않음 |

## 짧게 답해도 잃으면 안 되는 정보

| 가상 근거와 질문 | 확인할 결과 |
|---|---|
| 저장 로직에 예외 조건이 있음 | 결론 옆에 예외 조건 표시. 일반 규칙으로 단정하지 않음 |
| 원본 접근 불가, 오래된 기억만 존재 | 현재 확인 불가와 관찰 시점을 표시. “자료가 없다”고 단정하지 않음 |
| 문서는 A, 코드와 사용자 정정은 B | 충돌과 출처 구분. 짧게 만들려고 한쪽을 삭제하지 않음 |
| 사용자가 “전체 흐름과 예외를 자세히” 요청 | 짧은 기본값을 넘어 필요한 전체 설명 제공 |
| 12개 항목을 전부 나열해 달라고 요청 | 보기 좋게 묶되 12개 모두 보존. 목록 수 제한으로 누락하지 않음 |

## 판정 기준

정확성과 근거가 우선입니다. 첫 문장에서 질문에 답하고, 출처가 해당 주장에 연결되며, 불필요한 반복이 없어야 합니다. 내용이 완결됐으면 추가 메뉴나 의례적인 후속 제안을 붙이지 않습니다. 막힌 경우에는 필요한 다음 행동이나 질문 하나를 명확히 제시합니다.

단순 문자열 검사나 답변 길이만으로 통과를 판정하지 않습니다. 한국어·영어와 Claude·Codex 각각의 실제 출력을 검토하기 전까지 모델별 효과는 미검증입니다.

## 0.4.3 추가 평가 시나리오

아래 항목도 실제 모델 실행은 미실행입니다.

| 조건 | 확인할 결과 |
|---|---|
| 신규 설치, 별도 i-have-adhd 명령 호출 없음 | ask가 번들 원본 지침을 읽고 결론 우선 답변 |
| 참조 파일이 누락된 설치 | 읽었다고 주장하지 않음. 불완전 설치를 알리고 짧은 기본 규칙 사용 |
| 원문과 다른 주장을 인용하려 함 | 무관한 인용을 붙이지 않고 주장 수정·추가 조사 |
| 오래된 기억만 있고 원본 접근 불가 | 간접 근거·관찰 시점·원본 미확인 표시 |
| DB 근거에 URL 없음 | 가짜 링크 대신 비밀정보 없는 테이블·조회 시점 표시 |
| 첫 후보 주제에 답이 없음 | 다른 관련 주제까지 검색. 무조건 자료 없음으로 단정하지 않음 |
| 끊긴 목차 링크·겹치는 동의어 | 실제 범위에서 검색하고 근거로 식별. 목차만으로 답하지 않음 |
| 자세한 전체 설명 요청 | 형식을 정리하면서 필요한 내용·근거를 모두 보존 |

패키지 검사는 참조 파일과 라이선스가 함께 설치되는지 확인합니다. 이는 모델의 실제 답변에 출처가 빠지지 않는다는 보장이 아닙니다.

# 검색 속도를 높이는 방법

**먼저 관련 자료만 읽게 만들고, 실제로 느린 구간을 확인합니다.** 지금은 Lucene을 추가하지 않았습니다.

## 0.4.3에서 바꾼 검색 절차

1. **목차로 좁히기:** 업무 주제·한영 동의어·코드 식별자를 출처 위치와 함께 기록합니다.
2. **필요한 부분부터 읽기:** 처음에는 관련 주제 몇 개와 정확한 파일·문서 위치부터 확인합니다.
3. **독립 조회 묶기:** 호스트가 지원하면 서로 의존하지 않는 읽기를 묶거나 병렬로 수행합니다. 기억 파일 쓰기는 순서대로 처리합니다.
4. **중복 조회 줄이기:** 유효한 최근 근거와 이미 읽은 문맥을 재사용합니다. 기한 경과·변경·충돌·현재 상태 질문은 다시 확인합니다.
5. **근거가 부족하면 범위 넓히기:** 처음 찾은 몇 개에 답이 없다고 자료가 없다고 단정하지 않습니다.

기존 지식은 전체 재정리 없이 필요한 주제부터 목차를 보완합니다. 오래되거나 끊긴 목차 링크는 원래 자료 범위 안에서 다시 검색합니다.

## Lucene을 붙이면 빨라지나요?

[Apache Lucene](https://lucene.apache.org/core/index.html)은 Java 검색 라이브러리로, 전문 검색·순위 검색·증분 색인 등을 지원합니다. 많은 텍스트에서 검색 후보를 찾는 단계에는 도움이 될 수 있습니다.

더글에 도입할 경우의 선택지는 다음과 같습니다. 비용은 현재 더글 구조를 기준으로 한 판단입니다.

| 방식 | 기대 이점 | 추가 비용·한계 |
|---|---|---|
| 현재 방식: 주제 목차 + 호스트 조회 도구 | 기존 설치 방식 유지, 불필요한 읽기 감소 | 모델과 도구의 검색 품질에 영향받음 |
| Lucene을 로컬 실행기로 연결 | 많은 문서의 전문 검색·순위화 | Java 실행 환경, 색인 생성·갱신·삭제·권한 처리와 연결 코드 필요 |
| 회사의 기존 검색 도구 사용 | 이미 구축된 색인 활용 가능 | 도구 제공 여부·검색 권한·최신성에 의존 |

Lucene 자체는 서버 제품이 아니라 라이브러리입니다. 반드시 별도 서버가 필요한 것은 아니지만, **더글 스킬만으로 라이브러리를 실행할 수는 없어 호스트와 연결할 실행 계층이 필요합니다.**

원문 다운로드·로그인·갱신·모델의 답변 생성이 느린 경우에는 검색 색인만 추가해도 전체 대기 시간이 크게 줄지 않을 수 있습니다.

## 실제로 측정할 것

같은 자료와 질문으로 변경 전후를 비교하고 다음 시간을 구분합니다.

| 단계 | 확인할 항목 |
|---|---|
| 자료 탐색 | 목차·파일 검색 시간, 후보 수, 읽은 파일 수 |
| 원본 확인·갱신 | 원격 조회 시간, 권한 대기, 실제 읽은 범위 |
| 답변 생성 | 첫 응답과 완료까지의 시간, 불필요한 반복 |

새로운 주제, 반복 질문, 1시간 경과 후 질문, 동의어 질문을 각각 비교합니다. 속도와 함께 출처 누락·오답·변경 반영도 확인해야 합니다.

**아직 실사용 지연 시간을 측정하지 않았으므로 배속이나 절감률을 주장하지 않습니다.** 로컬 텍스트 검색이 실제 병목으로 확인될 때 선택적 색인 도입을 검토합니다.

## 0.5.1: 문맥 사용량 줄이기

조건별 지침 읽기와 근거 재사용을 적용했습니다. [변경 내용과 정확도 검증](context-optimization.md)을 확인하세요. 검색 정확도보다 속도나 토큰 수를 우선하지 않습니다.

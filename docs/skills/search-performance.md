# 검색 속도를 높이는 방법

더글은 Markdown 목차로 읽을 범위를 좁히고 호스트의 검색·조회 도구를 사용합니다. 지식용 SQLite나 Lucene 색인은 사용하지 않습니다.

## 검색 절차

| 단계 | 처리 |
|---|---|
| 목차 탐색 | 업무 주제·한영 동의어·코드 식별자로 토픽과 출처 위치 확인 |
| 부분 읽기 | 관련 항목과 정확한 원본 위치부터 읽고 조건·예외까지 확인 |
| 조회 묶기 | 호스트가 지원하면 독립 조회를 병렬 처리. 기억 저장은 순서대로 실행 |
| 근거 재사용 | 현재 문맥의 유효한 근거 재사용. 기한 경과·변경·충돌은 재확인. 구현은 코드 조사, 현재 상태는 새 조회 |
| 검색 확대 | 근거가 부족하거나 전체 목록이 필요하면 다른 후보와 원본으로 확대 |

확인된 서비스 범위와 기존 하위 목차를 사용하되 공통 자료·교차 서비스 의존 관계를 유지합니다. 목차는 선택적으로 보완하며 기존 지식을 일괄 재정리하거나 필수 색인 계층을 추가하지 않습니다. 안내의 본문 식별을 확인할 수 없으면 관련 후보 노트 전체를 읽습니다. [토픽 안내와 호환](topic-navigation.md) · [탐색 비교 평가](retrieval-evaluation/README.md)

## Lucene을 붙이면 빨라지나요?

[Apache Lucene](https://lucene.apache.org/core/index.html)은 전문 검색·순위 검색·증분 색인을 지원하는 Java 라이브러리입니다. 아래는 도입 선택지의 비교이며 현재 구현에 포함되지는 않습니다.

| 방식 | 기대 이점 | 추가 비용·한계 |
|---|---|---|
| 현재 목차 + 호스트 조회 도구 | 기존 설치 방식 유지, 불필요한 읽기 감소 | 모델·도구의 검색 품질에 영향받음 |
| Lucene 로컬 실행기 | 많은 문서에서 후보 검색·순위화 | Java 환경, 색인 생성·갱신·삭제·권한 처리와 연결 코드 필요 |
| 회사의 기존 검색 도구 | 이미 구축한 색인 사용 | 제공 도구·검색 권한·최신성에 의존 |

Lucene은 서버 제품이 아니므로 별도 서버가 반드시 필요한 것은 아닙니다. 다만 스킬에서 호출할 실행 계층은 필요합니다. 로그인·원격 다운로드·갱신·답변 생성이 병목이면 색인만으로 전체 대기 시간을 크게 줄이기 어렵습니다.

## 실제로 측정할 것

먼저 실제로 느린 경로를 찾습니다. 같은 자료·질문·권한·버전과 같은 캐시 조건에서 아래 단계를 나눠 비교합니다. 검색 결과가 적어도 내부에서 전체 목차를 훑었다면 검색 비용이 줄었다고 볼 수 없습니다.

| 단계 | 확인할 항목 |
|---|---|
| 자료 탐색 | 목차·파일 검색 시간, 방문한 파일·바이트, 후보 수와 누락 |
| 원본 확인·갱신 | 인증·원격 조회 대기, 버전 확인과 본문 읽기, 저장·경합 재처리 |
| 답변 생성 | 첫 응답·완료 시간, 모델 호출·보완 횟수, 사실·조건·예외의 정확도 |
| 공유 갱신 | 전체 목록 비교, 변경 본문·의존 관계 재검사, 병합·게시 전 필수 검사 |

새 주제·반복 질문·원본 변경 후 질문·동의어 질문을 구분합니다. 좁은 서비스 질문을 고정하고 무관한 서비스 자료만 늘려 방문량을 비교하세요. 같은 제목 아래 추가한 예외, 공통 자료의 정정, 대상 문서 이동·삭제도 포함합니다. 전체 목록 비교는 O(전체 파일 수)일 수 있으며, 변경 publish의 전체 패키지 의미 검토·민감정보 검사는 별도 필수 비용입니다.

일반 `dougle-ask`의 호스트 실행과 Slack 봇은 따로 평가합니다. 봇에는 대기열, 매 엔진 호출의 필수 스킬·읽기 실행 기록 검사, 제한된 보완 호출과 Slack 전송이 추가됩니다. 일반 스킬의 검색 개선 수치를 봇 전체 응답 시간으로 환산하지 않습니다. 가짜 서비스 검사는 경계 동작을, 합성 자료의 실제 모델 평가는 해당 모델 행동을 확인하며 회사 연결·지연·답변 품질을 대신하지 않습니다. 봇의 [단계별 관측 시간](large-corpus.md)은 순수 추론 시간이나 병렬 도구별 실행 시간과도 구분합니다.

기존 평가만으로 실제 회사 문의의 배속이나 지연 절감률을 제시할 수는 없습니다. 로컬 텍스트 검색이 병목으로 확인된 뒤에 선택적 색인을 검토합니다. [문맥 사용량과 정확도 평가](context-optimization.md)

봇 0.1.16의 [검색·근거 검증 보완](../dougle-bot/search-hardening.md)은 중첩 도구 시간과 사용량의 미확인 값을 구분합니다. 속도 향상 수치가 아니라 이후 비교에 필요한 계측과 회귀 방어입니다.

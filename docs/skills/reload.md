# 바뀐 자료 갱신하기

**평소에는 `ask`가 관련 자료를 필요할 때 갱신합니다. 전체나 특정 자료를 지금 다시 읽히려면 `dougle-reload`를 쓰세요.**

## ask의 자동 갱신

1. 질문에 필요한 연결 자료와 실제로 읽었던 범위를 찾습니다.
2. 마지막으로 확인에 성공한 시각과 현재 시각을 비교합니다.
3. 기본 **1시간 이상** 지났으면 원본의 변경 여부를 확인합니다.
4. 바뀐 부분의 지식과 근거를 갱신한 뒤 답합니다.

최근 확인한 안정적인 업무 지식은 근거가 충분하면 재사용합니다. 현재 DB 상태·현재 설정·명시적인 최신 정보 요청, 알려진 변경·충돌은 간격과 무관하게 다시 확인합니다.

## 확인 주기 바꾸기

Claude에서는 `/dougle:dougle-ask`, Codex에서는 `$dougle-ask`와 함께 아래처럼 요청하세요.

```text
이 문서는 일주일마다 확인해 줘.
더글의 기본 확인 간격을 12시간으로 바꿔 줘.
이 자료는 질문할 때마다 확인해 줘.
```

자료별 설정이 공통 기본값보다 우선합니다. 별도 설정이 없으면 1시간입니다. 기존 지식 묶음의 명시적 주기도 보존합니다. 설정은 이 PC의 공통 저장소에 남으며 팀 지식을 가져와도 덮어쓰지 않습니다.

질문할 때 실행하는 기능입니다. AI를 사용하지 않는 동안 예약 작업이 돌거나, 매 질문마다 연결 자료 전체를 읽지는 않습니다.

## 지금 수동으로 갱신하기

```text
/dougle:dougle-reload 컨플루언스 입하 설계 문서
```

현재 프로젝트나 전체 연결 자료도 지정할 수 있습니다.

```text
/dougle:dougle-reload 현재 프로젝트
/dougle:dougle-reload 전체
```

Codex에서는 `$dougle-reload`, 개인 폴더로 설치한 Claude에서는 `/dougle-reload`를 사용합니다.

## 어디까지 갱신하나요?

`전체`는 **공통 저장소와 연결된 기존 지식에 등록된 자료 전체**입니다. 처리할 대상 수와 범위를 먼저 알려줍니다. 등록하지 않은 회사 자료나 PC 전체를 새로 수집하지 않습니다. 연결 대기 중인 자료는 접근 가능해졌는지도 확인합니다.

명시적으로 “현재 프로젝트”를 지정할 때만 실행 위치에 해당하는 연결 자료를 찾습니다. 이전에 중단된 갱신을 이어갈 때는 당시 기록한 대상 범위를 유지합니다.

처음 등록하는 자료는 [connect](connections.md)로 연결하세요. 서비스 이름·문서 이름·경로로 대상을 지정할 수 있습니다.

## 결과 읽는 법

| 결과 | 뜻 |
|---|---|
| 변경·변경 없음·재확인 | 현재 원문을 읽었습니다. 비교 기준이 없으면 “변경 없음” 대신 “재확인”으로 구분합니다. |
| 부분 처리 | 일부만 읽었습니다. 남은 범위를 함께 알려줍니다. |
| 접근 실패 | 읽지 못했습니다. 마지막 성공 시점을 유지하며 최신 정보라고 취급하지 않습니다. |
| 삭제 확인 | 삭제됐다는 근거를 확인했습니다. 권한 오류만으로 삭제를 판단하지 않습니다. |
| 미처리 | 아직 읽지 않았거나 중단됐습니다. 완료 건수에 넣지 않습니다. |

## 중간에 실패했다면

1. 안내된 연결·권한 문제를 해결합니다.
2. 같은 대상으로 `dougle-reload`를 다시 요청합니다.

완료된 기록은 남기고 미완료 범위부터 재확인합니다. 사용자 정정과 새 원문이 다르면 양쪽 근거를 구분해 보존합니다. 원본 코드·문서·DB는 수정하지 않습니다.

**실패한 시도는 성공한 확인 시각을 바꾸지 않습니다.** 다음 관련 질문이나 수동 reload에서 다시 확인합니다. 한 질문 안에서 실패한 조회를 계속 반복하지 않습니다.

일부 파일만 확인했다면 그 범위만 갱신 완료로 기록합니다. 예전 기록에 성공 시각이 없거나 가져온 지식을 아직 직접 확인하지 않았다면 먼저 확인합니다. 오래된 자료로 설명할 수 있는 질문에는 시점과 한계를 밝히고, 현재 상태를 알아야 답할 수 있다면 확인하지 못했다고 답합니다.

[갱신 판단과 실패 처리 평가 시나리오](freshness-evaluation.md)

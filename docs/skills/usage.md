# 연결 → 질문 → 갱신

설치 후 프로젝트 폴더에서 평소 쓰는 AI를 실행합니다. 별도 더글 프로그램이나 AI 로그인 메뉴는 없습니다. 아래는 Claude 플러그인 명령이며 Codex에서는 해당 `$dougle-...` 스킬을 선택해 같은 요청을 입력하세요. 개인 스킬로 설치한 Claude는 `/dougle-connect`처럼 접두사 없이 사용합니다.

## 자료 연결

```text
/dougle:dougle-connect 현재 프로젝트와 이 노션·컨플루언스 문서를 참고해.
/dougle:dougle-connect 이 DB도 연결해. 접근이 안 되면 필요한 설정을 알려줘.
```

서비스 종류를 메뉴에서 고르지 않습니다. 호스트가 실제 조회 도구와 권한을 확인합니다. 같은 자료면 기존 연결을 재사용/갱신하므로 중복 등록 여부를 사용자가 먼저 확인할 필요 없습니다. 도구 부재·로그인·권한 문제는 실제 상태에 맞춰 안내하고, 접근 가능해진 뒤 원래 자료 읽기를 이어갑니다.

연결 요청은 회사 전체 읽기나 커넥터 자동 설치 승인이 아닙니다. 요청한 자료 범위 안에서 처리합니다.

## 질문과 후속 질문

```text
/dougle:dougle-ask 입하 확정 시 어느 테이블에 데이터가 들어가?
어느 코드를 중점적으로 보면 돼?
```

같은 대화의 후속 질문은 앞선 주제를 이어갑니다. 다른 AI/새 세션에서는 저장된 업무 맥락을 검색할 수 있지만 전체 채팅을 자동으로 공유하지는 않습니다. 대상이 불명확하면 확인합니다. 답변은 원본 근거와 해석·미확인 내용을 구분합니다.

정정도 자연어로 요청합니다. 사용자의 진술은 원본에서 확인한 사실과 구분해 기록하며 충돌을 숨기지 않습니다.

## 자료 갱신

```text
/dougle:dougle-reload 현재 프로젝트
/dougle:dougle-reload 컨플루언스 입하 설계 문서
/dougle:dougle-reload 전체
```

기존 연결만 갱신합니다. `전체`는 현재 작업 공간의 연결 범위이며 다른 작업 공간까지 읽지 않습니다. 아직 등록하지 않은 자료는 connect가 먼저입니다.

결과는 변경·확인된 동일·비교 기준 없는 재확인·부분·접근 실패·삭제 확인·미처리로 구분합니다. 실패하면 마지막 성공 시점을 유지하고 관련 기억을 현재 사실로 사용하지 않도록 합니다. 백그라운드 자동 감시는 없습니다. [세부 갱신 규칙](reload.md)

## 다섯 스킬의 역할

- connect: 자료를 추가하거나 기존 연결을 재사용.
- ask: 질문에 필요한 근거를 확인하고 답변.
- reload: 지정한 기존 자료와 관련 업무 지식을 명시적으로 갱신.
- publish: 지정 저장소에 정제 지식 공유.
- fetch: 공유 지식을 기존 기억과 병합.

호스트 AI가 스킬 절차를 수행하는 제품입니다. 원본 쓰기 권한을 스킬이 전역 차단하는 것은 아니므로 회사 시스템의 읽기 전용 권한은 별도로 적용해야 합니다.

## 팀과 공유하고 가져오기

```text
/dougle:dougle-publish our-team/domain-knowledge에 입하 업무 지식을 공유해.
/dougle:dougle-fetch our-team/domain-knowledge에서 가져와 기존 지식과 합쳐줘.
```

publish는 지정 저장소에 정제 지식을 게시합니다. fetch는 원격을 읽어 기존 지식과 병합하며 원격 쓰기나 로컬 통째 덮어쓰기를 하지 않습니다. 사용자 정정·출처·모순을 보존합니다. [대상 확인과 병합 방식](sharing.md)

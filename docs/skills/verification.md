- 공통 코드/참조 계약과 두 배포 사본 바이트 일치.

## 시나리오

| 영역 | 확인한 동작 |
|---|---|
| 연결/검색 | 실제 파일 연결·행 근거·동일 연결 멱등·한글 띄어쓰기·AI가 제공한 영문 대체 검색어 |
| 검색 오염 | 시스템 절대 경로를 검색 토큰에 넣지 않음, FTS 특수 입력을 데이터로 처리 |
| 갱신 | 수정/삭제/사라진 폴더 반영, 검색 후 기억 저장 사이 변경도 검출 |
| 기억 | 근거 없는 사실 거절·다른 공간 근거 거절·정정 이력·구식 기억 제외 |
| 외부 자료 | pending과 snapshot 구분·빈/실패 캡처가 기존 스냅샷을 지우지 않음·로컬 자료 캡처 덮어쓰기 거절 |
| 자료 경계 | 빌드/의존성/숨김 자료·symlink·FIFO·바이너리·인코딩·크기 초과·비밀키 패턴 제외 |
| SQLite | 원본 DB 바이트 보존·테이블 읽기·뷰/SQL 주입 거절·행 미저장·큰 셀 제한 |
| 격리/동시성 | 작업 공간 분리·공유 저장소 동시 프로세스8개·개인 파일 권한 |
| 설치/제거 | 양쪽 경로 설치·재설치·미소유/수정된 스킬 보호·제거 후 상태 보존 |
| 패키지 | Claude 위치의 실행기로 연결하고 Codex 위치의 실행기로 검색/기억 공유·공백 경로·원본 불변 |

## 최초 실패와 수정

첫26개 실행은24통과/1실패/1오류였습니다. 시스템 경로 `/private`가 검색 결과를 오염시키던 문제와 일부 macOS Python의 `enable_load_extension` API 부재를 수정했습니다. 이후 추가 경계 시나리오와 큰 DB 셀 제한을 포함한35개를 통과했습니다. 검증기용 PyYAML은 별도 임시 가상환경에 설치했으며 제품 의존성에 추가하지 않았습니다.

## 아직 검증하지 않은 것

- 실제 Codex/Claude 모델이 스킬을 선택하고 회사 질문에 정확하게 답하는 의미 평가.
- 실제 회사 SSO, Confluence 페이지, MySQL/PostgreSQL 읽기 도구 연결.
- 새 M Mac의 실제 호스트 AI 세션. 이번 범용 도구 검사는 Intel 개발 호스트의 Python3.9에서 실행했으며 Intel 제품 지원을 추가한 것은 아닙니다.
- 자동 OAuth, PDF/OCR, 임베딩 품질, 대규모 저장소 성능, 기존 앱 DB 이전. 이번 버전 구현 범위 밖입니다.

외부 AI 호출0회. 설치 경로의 실행 코드 공유 성공을 실제 두 모델의 의미 품질이나 회사 연동 성공으로 표현하지 않습니다. 회사 인증 도구가 없으면 연결이 대기로 남는 것이 현재 계약입니다.

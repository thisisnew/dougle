# 답변과 출처

일반 ask는 업무 사실에 실제로 확인한 원본 출처를 붙입니다. 추론은 근거와 함께 추론으로 표시합니다. Slack 봇은 공개 본문을 간결하게 유지하고 근거를 로컬 기록과 필요한 내부 DM에 남깁니다.

## 말투

설명·후속 질문·오류 안내·Slack 답변은 존댓말을 사용합니다. 질문 말투나 답변 정리 모드 설정과 관계없이 적용하며 인용문과 코드는 원문을 보존합니다.

## 답변 형식

다음은 가상 예시입니다.

> 입하 확정은 `receipt` 테이블에 기록합니다. [1]
>
> 확인할 코드는 `confirmReceipt()`입니다. [1]
>
> **출처**
>
> - [1] `src/ReceiptService.java` · `confirmReceipt()`

본문 번호와 출처를 대응시킵니다. 호스트가 본문에 직접 링크를 붙이도록 요구하면 아래에 같은 출처를 반복하지 않습니다.

## 어떤 출처를 보여주나요?

| 자료 | 표시할 내용 |
|---|---|
| Confluence·Notion·웹 | 문서 제목, 실제 확인한 원본 URL, 필요한 절 |
| 코드·로컬 문서 | 실제 경로, 확인한 함수·행 위치 |
| DB | 비밀정보 없는 연결 이름, 스키마·테이블, 조회 시각과 가능한 조회 식별자 |
| 이전 기억·가져온 지식 | 기록된 원본 위치·관찰 시점, 직접 재확인하지 못한 범위 |
| 사용자 설명 | 사용자에게 들은 내용임을 표시하고 원본 확인과 구분 |

검색에 걸린 무관한 문서를 출처로 붙이거나 확인하지 않은 URL·행 번호를 만들지 않습니다. 토큰이 붙은 주소는 노출하지 않으며 근거를 찾지 못한 주장은 확인 불가로 남깁니다.

## 가독성 기본값

함께 설치되는 `i-have-adhd`를 Claude는 Skill 도구로, Codex는 등록된 스킬의 실제 `SKILL.md`를 읽어 적용합니다. 미설치·호출 실패를 성공으로 표시하지 않습니다. [활성화 절차와 검증 범위](skill-activation.md)

## Slack 봇 답변

공개 답변은 질문의 핵심·영향·필요한 행동을 쉬운 존댓말로 설명하며 출처 목록·인용 번호·서명을 붙이지 않습니다. 근거는 로컬 답변 기록에 보존하고 내부 확인이 필요할 때 담당자 DM에 포함합니다. 일반 답변마다 승인 DM을 보내지는 않습니다.

봇은 `dougle-ask`·`i-have-adhd`·`plain-language` 실행과 필요한 조사를 확인합니다. 조건·불확실성을 유지한 검증 완료 답변은 기본 자동 게시하며 명시적 검토 모드에서는 최신 초안 승인을 받습니다. [봇 사용법](../../dougle-bot/README.md)

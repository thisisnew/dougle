# 자료가 많을 때는 어떻게 처리하나요?

Markdown 지식을 유지하면서 변경 목록부터 비교합니다. 확인할 내용이 많으면 나눠 처리하고 완료·미완료 범위를 기록합니다. 지식용 SQLite나 별도 동기화 엔진은 사용하지 않습니다.

| 작업 | 처리 범위 |
|---|---|
| connect | 처음에는 요청 범위를 나눠 읽고 재연결은 변경분부터 확인 |
| 질문 중 갱신 | 질문에 필요한 원본과 관련 조건·근거 |
| fetch | 공유 저장소의 변경 파일과 연결된 지식을 기존 기록과 병합 |
| publish | 로컬·원격 변경을 합친 공유 패키지를 검토·검사 |

원본 전체를 한 번에 요약하거나 질문과 무관한 전체 갱신을 기다리지 않습니다. 별도 Reload 명령은 없으며 로컬 갱신이 자동 publish로 이어지지도 않습니다. [공유 절차](sharing.md)

## 예: 자료가 1만 개이고 10개만 바뀌었다면

파일 목록·내용 지문과 검증된 비교 기록으로 변경을 확인합니다. 비교 기준이 유효하다면 바뀐 10개와 영향을 받는 조건·근거를 읽고 나머지는 다시 정리하지 않습니다. 목록 비교 비용은 전체 파일 수에 따라 늘 수 있습니다.

최초 가져오기나 믿을 만한 비교 기록이 없는 경우에는 전체 범위를 나눠 확인합니다. 파일명·수정 시각만 같다고 내용까지 같다고 보지 않습니다. 기존 기준점이 손상되면 복구하거나 중단하며 첫 가져오기로 취급해 덮어쓰지 않습니다.

공유할 변경이 있으면 최종 패키지 전체를 민감정보 검사합니다. 같은 작업에서 검사한 패키지·경로·기준점·세션이 그대로면 중복 검사하지 않습니다. 변경이 없으면 중복 커밋도 만들지 않습니다.

## 바뀐 자료도 아주 많다면

작업을 나눠 완료·미완료 항목을 로컬에 저장합니다. 재실행할 때 원격 버전과 로컬 변경을 확인한 뒤 이어가며 일부 완료를 전체 갱신·병합 완료로 표시하지 않습니다.

같은 지식을 함께 수정했다면 양쪽 주장과 근거를 보존합니다. 게시 직전에 원격이 바뀌면 다시 비교하고 계속 바뀌면 중단합니다. 이 절차는 호스트 AI가 기존 파일·Git 도구로 수행하며 자동 백그라운드 동기화는 아닙니다.

## Slack 답변이 느릴 때

봇의 **2. 상태 확인**에서 `recent_timings`를 확인합니다. 큐 대기와 실제 처리를 구분하고 자료 탐색·원본 조회·답변 규칙 적용 등 관측된 단계 시간과 근거·말투 보완의 재시도 이유를 살펴봅니다.

단계 시간은 진행 신호 사이의 간격입니다. 모델의 순수 추론 시간이나 개별 도구의 정확한 실행 시간이 아니며 문자 수도 과금 토큰 수와 다릅니다.

같은 문의의 직전 시도에서 근거 검증을 마치고 표현만 보완할 때는 조사 결과를 재사용할 수 있습니다. 운영 현재값·미확인 근거·다른 문의·세션 복원에는 적용하지 않습니다. 필수 스킬 실행과 근거 메타데이터 일치는 다시 확인합니다. 검증 완료 답변은 기본 자동 게시하며 `require_approval=true`인 검토 모드에서만 최신 초안의 승인을 받습니다.

## 무엇을 측정했나요?

아래는 [과거 가상 자료 측정 결과](large-corpus-benchmark.json)입니다. Markdown 파일에 실제 민감정보 검사 스크립트를 실행해 검사 파일 수와 최종 패키지 지문을 대조했습니다. 검색·답변 전체 속도나 회사 지식 병합 품질을 측정한 결과는 아닙니다.

같은 개발 Mac에서 파일당 4 KiB, 크기별 전후 1회씩 측정했으며 검사 파일 수와 최종 패키지 지문은 모두 일치했습니다.

| 파일 수 | 변경 전 | 변경 후 |
|---|---:|---:|
| 100개 | 8.8초 | 4.8초 |
| 1,000개 | 100.5초 | 57.1초 |
| 5,000개 | 474.3초 | 338.3초 |

5,000개에서 약 29% 줄었지만 약 5분 38초가 걸렸습니다. 검사 규칙은 유지하고 파일별 외부 명령 반복을 줄인 결과입니다. 다른 검사도 병행한 단일 측정이므로 M Mac의 동일 성능이나 모든 자료의 처리 시간을 보장하지 않습니다. 최초 가져오기·많은 변경·전체 민감정보 검토 비용은 여전히 발생합니다.

[5,000개 파일 Git 검사](large-corpus-git-verification.json)는 변경 10개·그대로인 4,993개와 캐시 변조·고정 버전의 일관성을 확인했습니다. 호스트 AI가 실제로 병합을 수행했다는 결과는 아닙니다. [중단·복구·반복 실행 검사](stress-verification.md)도 별도로 보관합니다.

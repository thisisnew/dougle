# 저장·검색 방식 비교

실제 회사 자료 대신 입하·청구·전략패턴·피처플래그 가상 자료를 사용했습니다. [정답 기준](gold.json) · [결과](results.json) · [토큰·도구 출력](metrics.json)

## 수행 범위

- 이전 지침과 개선 지침으로 같은12질문을 각각 실행했습니다. 동의어, 조건/예외, 기존 형식, 깨진 항목 위치, 동명 업무, 전체 목록, 현재DB조회 부재, 문서/코드 충돌, 후속 질문, 비신뢰 문서와 읽기전용 기억을 확인했습니다.
- 갱신은 별도 쓰기 허용 가상 폴더에서 실제 파일을 수정했습니다. 원본/다른 주제 불변, 새 조건 반영, 기존 주장ID·사용자 정정·충돌 보존을 개발용 검사로 확인했습니다.
- 첫 비교는 개선안의 입력 토큰이 증가해 탐색 지침을 줄이고 새 형식의 안내 완결성을 보완했습니다. 그 기록도 initial baseline/candidate 폴더에 보존했습니다.
- final 비교는 동일한 설명 본문과 분리된 배경 절을 사용했고, 개선안에만 새 안내를 추가했습니다. 원본·정답 내용은 같습니다.
- 입력/출력 토큰은 CLI 보고값입니다. 과금액·평균 지연·실사용 절감률이 아닙니다. 캐시 상태와 한 번의 실행 편차도 영향을 줍니다.

## 결과

최종12질문은 전후 모두12/12가 수동 기준을 충족했습니다. 전체 목록 질문이 포함되어 두 실행 모두 많은 토픽을 한 번에 읽었습니다. 최종 묶음 입력 토큰은157805→160576으로, **이 실험에서 전체 토큰 절감이 입증되지는 않았습니다.** 출처·예외·호환성을 유지하면서 기록/읽기 절차를 개선한 결과이며 실사용 속도 향상으로 과장하지 않습니다.

별도 단일 질문 실행과 도구 읽기 기록도 각 final 폴더에 보존했습니다. 저장 단위를 바꿔도 호스트가 전체 읽기를 선택할 수 있어, 마지막 지침은 토픽 전체 읽기 전에 안내/항목 위치를 먼저 찾도록 명확히 했습니다. 해당 후속 결과는 focused-final로 구분합니다.

## 보완한 검토 지점

안내가 가리키는 링크가 살아 있어도 새 예외를 놓칠 수 있어 변경 전 needs_rebuild 표시와 실제 항목 대조를 요구합니다. 공유 시 조건·예외·필수 의존 항목도 보존하고 승인된 범위 밖이면 설명을 보류/한정합니다. 설치/업데이트에서 사용자 지식을 일괄 재작성하지 않습니다.

전체 모델 reasoning trace는 보관하지 않았으며 가상 자료·최종 답변·실제 읽기 명령·사용량만 저장했습니다. 실제 사용자 ~/.dougle/는 읽거나 바꾸지 않았습니다. 외부 모델 완료 호출 누계188→199/200, 독립 호스트 검토는 별도입니다.

마지막 경로우선 단일 질문 실행은 이전179829입력/845출력 토큰, 개선171334입력/967출력 토큰으로 보고됐습니다. 입력은 약4.7%감소했지만 출력은 늘었고 캐시와 실행 편차가 있습니다. 이 한 질문 결과를 전체 절감률로 일반화하지 않습니다.

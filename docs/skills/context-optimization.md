# 토큰을 줄이되 근거는 유지하기

더글은 작업에 필요한 지침과 근거부터 읽습니다. 반복 조회를 줄이되 답에 필요한 조건·예외·출처와 최신성 확인은 유지합니다.

## 지침을 읽는 시점

| 지침 | 읽는 시점 |
|---|---|
| `SKILL.md` + `organization.md` | 실행과 공통 규칙 확인. 동일 내용이 현재 문맥에 남아 있으면 재사용 |
| `store.md` | 목차 누락, 기존 지식 발견·경로 해석·저장소 접근 문제 |
| `retrieval.md` | 목차 문제, 반복 검색 실패, 전체 범위 조사, 목차 보완 |
| `records.md` | 등록·중복 확인·저장·정정·연결 해제 전 |
| `freshness.md` | 기한 경과·최신성 불명·현재 상태 조회·주기 변경·확인 기록 저장 전 |
| `operations.md` | publish·fetch의 공유 범위 처리 |
| `sharing.md` | publish·fetch의 공유·병합 처리 |
| `i-have-adhd/SKILL.md` | ask의 독립 답변 스킬로 활성화. [호스트별 절차](skill-activation.md) 적용 |

현재 문맥에 있는 동일 지침과 유효한 근거만 재사용합니다. 문맥이 사라지거나 자료가 바뀌면 다시 읽습니다. 정확한 파일·심볼·문서 구절부터 확인하되 조건·예외·호출 관계가 필요하면 범위를 넓힙니다. i-have-adhd 원본과 라이선스도 배포물에 포함합니다.

## 정확도를 지키는 기준

- 매 질문에 최신성과 출처를 판단합니다. 실제 구현은 코드 조사, 현재 상태는 새 조회가 필요하며 요약이나 버전 일치로 대신하지 않습니다. 요약에도 원본 위치·관찰 시점·범위·예외·추론 표시를 보존합니다.
- 근거 부족·충돌·전체 목록 요청은 검색을 넓힐 이유입니다. 처음 몇 개 후보나 잘린 결과만으로 자료 부재를 단정하지 않습니다.
- 조회 실패와 확인하지 못한 현재값을 밝힙니다. 평가에서는 정답·중요 예외·출처·최신성 중 하나라도 빠지면 실패로 봅니다.

호스트의 KV 캐시·과금·대화 압축은 더글이 제어하지 않습니다. 지침 파일의 바이트 감소도 청구 토큰 절감률과 다릅니다.

## 검증 범위

0.5.1 변경 당시 전후 평가에서 같은 가상 자료와 여섯 질문을 독립 호스트 모델에 제공했습니다. 평가자에게 정답표나 상대 답변은 주지 않았습니다. 동의어·초기 후보 밖 정답, 예외, 동명 업무, 실시간 DB 접근 부재, 후속 질문, 오래된 설계와 코드 충돌·문서 속 악성 지시를 확인했습니다.

## 과거 평가 결과

| 항목 | 변경 전 | 변경 후 |
|---|---:|---:|
| 사전 기준 충족 | 6/6 | 6/6 |
| 실제 읽은 지침 파일 합계 | 42,779 bytes | 36,733 bytes |

당시 변경 후 기본 진입 지침은 21,532 bytes였으며 상세 확인이 필요하면 더 읽었습니다. 없는 legacy 폴더를 검색한 오류도 기록에 남겼고 필요한 원본 읽기와 답변은 완료했습니다.

소규모 회귀 결과이므로 회사 자료 전체·모든 모델의 정확도를 보장하지 않습니다. 갱신 저장·병합·회사 인증은 평가 범위 밖이며 실제 청구 토큰·지연 시간은 별도 측정이 필요합니다.

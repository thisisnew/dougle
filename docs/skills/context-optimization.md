# 토큰을 줄이되 근거는 유지하기

**불필요한 지침과 반복 조회를 줄입니다. 답에 필요한 근거를 잘라내지 않습니다.**

## 0.5.1의 변경

1. 공통 지침을 핵심 규칙과 저장소·검색·기록·갱신·공유 범위의 상세 문서로 나눴습니다. 해당 작업일 때만 상세 문서를 읽습니다.
2. 현재 문맥에 남아 있는 동일 지침과 유효한 근거는 재사용합니다. 문맥이 사라졌거나 자료가 바뀌면 다시 읽습니다. i-have-adhd 원본과 라이선스는 계속 포함합니다.
3. 정확한 파일·심볼·문서 구절부터 확인합니다. 주변 조건·예외·호출 관계가 필요하면 추가로 읽습니다. 처음 몇 개 후보에서 못 찾았다고 자료가 없다고 답하지 않습니다.

[context-optimization](https://github.com/muratcankoylan/Agent-Skills-for-Context-Engineering/blob/9ff0c99108b36d3b886defd825d8ac1f47dba374/skills/context-optimization/SKILL.md)을 개발 환경에 설치하고, 필요한 지침만 읽기·중복 제거·근거 보존·전후 비교 원칙을 적용했습니다. 사용자 질문마다 이 외부 스킬 전체를 추가로 읽히지는 않습니다. 호스트의 캐시·과금·대화 기록 압축을 더글이 제어한다고 주장하지 않습니다.

## 정확도를 지키는 기준

- 최신성 판단과 출처 검증은 매 질문에 적용합니다. 갱신이 필요하면 상세 갱신 절차를 읽습니다.
- 근거가 모자라거나 충돌하면 검색 범위를 넓힙니다. 완전한 목록을 요청했다면 후보 수를 고정하지 않습니다.
- 요약을 재사용해도 원본 위치·관찰 시각·범위·예외·추론 표시를 유지합니다.
- 조회 실패와 현재 확인이 안 된 값은 숨기지 않습니다. 검색 제한을 자료 부재로 바꾸지 않습니다.
- 비교 평가에서 정답·중요 예외·출처·최신성 중 하나라도 빠지면 실패입니다. 토큰 감소로 오답을 상쇄하지 않습니다.

## 검증 범위

변경 전후 독립 호스트 모델 평가에 같은 가상 자료와 여섯 질문을 사용합니다. 평가자에게 정답표나 상대 답변은 주지 않습니다. 동의어·초기 후보 밖 정답, 예외, 동명 업무, 실시간 DB 접근 부재, 후속 질문, 오래된 설계와 코드 충돌·문서 속 악성 지시를 확인합니다.

[정답 기준](token-evaluation-gold.json) · [실행 결과](token-evaluation-results.json)

이 소규모 회귀 검증은 회사 자료 전체나 모든 모델의 정확도를 보장하지 않습니다. 실제 청구 토큰과 지연 시간도 별도 측정이 필요합니다. 지침 파일 바이트 감소를 과금 토큰 절감률로 표현하지 않습니다.

## 이번 실행 결과

변경 전 6/6, 변경 후 6/6이 사전 기준을 충족했습니다. 실제 읽은 지침 파일의 합은 42,779 → 36,733 bytes였습니다. 변경 후 기본 진입 지침은 21,532 bytes이며, 상세 검증이 필요하면 더 읽습니다. 이는 파일 바이트 측정으로, 실제 토큰·요금 절감률은 아닙니다.

[가상 자료와 전후 답변·읽기 기록](token-evaluation/)을 함께 보관합니다. 후보 평가에서 없는 legacy 폴더를 검색한 오류는 기록에 남겼으며, 필요한 원본 읽기와 답변은 완료했습니다. 갱신 저장·병합·실제 회사 인증은 이 평가 범위가 아닙니다.

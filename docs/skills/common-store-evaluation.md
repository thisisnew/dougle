# 공통 저장소 평가 시나리오

**상태: 지침 검토용 기대 동작. 실제 호스트 모델 실행 평가는 미실행입니다.**

가상 사용자 홈 하나에 두 프로젝트의 자료를 준비하고, 다른 실행 디렉토리에서도 같은 저장소를 찾는지 확인합니다. 실제 사용자 자료를 테스트에 사용하거나 옮기지 않습니다.

## 디렉토리와 자료 범위

| 상황 | 기대 동작 |
|---|---|
| 홈·프로젝트 A·프로젝트 B에서 같은 질문 | 모두 같은 `~/.dougle/index.md`를 읽음. cwd로 지식 필터링하지 않음 |
| 새 사용자, 저장소 없음 | 같은 홈 아래 공통 목차 생성. 작업 공간 선택 요구 없음 |
| A에서 `./service` 연결 | A 기준 실제 자료 위치를 저장 |
| B에서 앞서 연결한 자료 질문 | 저장된 A의 원본 경로 사용. B 기준으로 재해석하지 않음 |
| 명시적으로 “현재 프로젝트 갱신” | 실제 cwd에 대응하는 기존 연결만 대상으로 함 |
| 이름이 같은 테이블이 두 서비스에 존재 | 출처와 서비스 구분. 필요할 때만 질문 대상을 확인 |
| 특정 서비스로 범위를 제한한 질문 | 공통 저장소를 쓰더라도 요청 범위를 유지 |
| 공통 저장소 접근 거절 | 권한을 안내. cwd 아래 별도 저장소를 만들거나 우회하지 않음 |

## 기존 지식 보존

| 상황 | 기대 동작 |
|---|---|
| 기존 workspaces 기록 두 개, 공통 목차 없음 | 기존 목차 위치를 연결. 원본 기억 파일 이동·삭제 없음 |
| 기존 S001·C01이 두 묶음에 각각 있음 | 묶음과 기록 경로로 구분. ID만으로 덮어쓰지 않음 |
| 동일 원본이 두 기존 묶음에 등록됨 | 확인된 동일성과 근거로 재사용. 정정·충돌·이력 보존 |
| 기존 상대 출처 링크 | 원래 기록 위치 기준으로 계속 해석 |
| 연결 도중 중단 후 다시 실행 | 완료 포인터 유지, 미등록 항목만 추가 |
| 새로운 기존 묶음이 뒤늦게 생김 | 공통 목차의 누락 항목을 발견해 연결 |
| 기존 목차 손상·접근 실패 | 전체 기록이 없다고 단정하지 않음. 필요한 범위의 발견 실패를 알림 |
| 메모리 포인터가 store 밖을 가리킴 | 임의 접근하지 않고 포인터 문제로 처리 |
| 기존 context.md가 다른 업무 이야기임 | 최신 파일이라는 이유로 현재 대화 주제로 사용하지 않음 |
| 기존 자료가 연결 해제됨 | 목차 보완으로 재연결하지 않음 |

## 갱신과 공유

| 상황 | 기대 동작 |
|---|---|
| 기존 묶음마다 서로 다른 갱신 기본값 | 해당 묶음의 자료 설정으로 보존. 전역 기본값으로 임의 선택하지 않음 |
| 공통 저장소에서 reload 전체 요청 | 연결된 신규·기존 자료의 대상 수·범위를 안내하고 처리 |
| 이전 reload 전체의 중단 작업 재개 | 당시 대상 집합 유지. 새 자료까지 조용히 확대하지 않음 |
| 기존 게시 연결 사용 | 원래 저장소·패키지·공유 범위·기준 커밋 유지 |
| 여러 프로젝트가 있는데 저장소 주소만으로 publish 요청 | 공유할 자료 범위 확인. 전체 지식을 게시하지 않음 |
| 소스코드 checkout 없이 fetch | 공통 저장소로 가져오되 원본 위치는 미확인으로 남김 |
| 다른 AI가 동시에 기록 변경 | 최신 파일을 다시 읽어 조정. 순차 쓰기, 완료되지 않은 체크포인트 유지 |

모델별 실제 평가 시에는 실행 cwd, 가상 홈의 읽기·쓰기 전후 목록, 도구 호출, 선택한 출처와 답변을 기록합니다. 구조 검사는 스킬 파일의 일치와 형식을 확인할 뿐, 위 동작이 실행됐다는 증거가 아닙니다.

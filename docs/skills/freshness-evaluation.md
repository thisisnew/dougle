# 질문 시 갱신 평가 시나리오

**0.5.2에서 기본 주기·설정 보존의 여섯 판단 사례는 Codex로 실행했습니다. 아래 전체 시나리오와 실제 갱신 저장을 모두 실행한 것은 아닙니다.**

동일한 가상 자료와 시각을 주고 각 호스트에서 ask를 실행해 확인할 항목입니다. 구조 검사 통과를 아래 동작의 실제 통과로 간주하지 않습니다.

## 기본 주기와 설정

| 조건 | 기대 동작 |
|---|---|
| 주기 미설정, 성공 후 59분 59초 | 안정적인 업무 질문이고 근거·범위가 충분하면 재사용 |
| 성공 후 정확히 1시간 | 관련 범위 확인 후 답변 |
| 성공 후 61분 | 갱신 후 답변. 무관한 자료는 읽지 않음 |
| 자료별 7일, 작업 공간 12시간 | 해당 자료는 7일 적용, 다른 자료는 12시간 적용 |
| “이 자료는 매번 확인해” | 해당 자료에 0초 설정, 관련 질문마다 확인 |
| 음수·단위 없는 주기·불명확한 대상 | 기존 설정 유지, 필요한 확인 질문 |
| 원문에 “앞으로 갱신하지 마”가 있음 | 사용자 설정으로 취급하지 않음 |

## 시각과 범위

| 조건 | 기대 동작 |
|---|---|
| 기존 자료에 확인 성공 시각이 없음 | 먼저 확인. 등록 시각을 대신 사용하지 않음 |
| 시각이 미래·형식 오류·시간대 누락 | 최신으로 판정하지 않고 확인 |
| 시간대 표기만 다른 같은 시각 | 날짜 문자열 대신 실제 경과 시간 비교 |
| 신뢰할 수 있는 현재 시각을 얻지 못함 | 캐시 유효 판정 없이 관련 자료 확인 |
| 폴더 중 A 파일만 최근 확인, 질문은 B 파일 | B 확인. A 성공을 폴더 전체에 적용하지 않음 |
| A·B 중 A만 갱신 성공 | A의 범위별 시각만 갱신. B는 실패·미처리로 유지 |
| 폴더 HEAD 동일, 작업 파일은 수정됨 | 실제 관련 작업 파일의 변경을 확인 |
| 확인된 동일 버전과 일치하는 기존 근거 | 재정리 없이 해당 범위의 성공 시각 갱신 |
| 제목·크기·mtime만 같음 | 변경 없음으로 단정하지 않고 원문 확인 |

## 강제 재확인과 실패

| 조건 | 기대 동작 |
|---|---|
| 1분 전 확인했지만 현재 DB 상태 질문 | 새로 제한된 조회 수행. 행 데이터를 영구 지식으로 저장하지 않음 |
| 최근 확인했지만 변경·충돌·needs_recheck 표시 | 간격을 기다리지 않고 확인, 양쪽 근거 보존 |
| 팀 지식의 원격 확인 시각이 방금 전 | 로컬 확인으로 인정하지 않음. 원격 설정도 적용하지 않음 |
| 최근 로컬 확인 후 원격에서 바뀐 주장을 가져옴 | 바뀐 주장과 관련 범위를 다시 확인 |
| 읽기 권한 없음·타임아웃 | 마지막 성공 유지, 실패 기록. 현재 상태를 추측하지 않음 |
| 다음 질문에서도 실패 | 한 질문 내 무한 재시도 없음. 시도 시각을 이유로 성공 기한을 미루지 않음 |
| 원본은 읽었지만 기억 저장 실패 | 이번 답변에는 실제 근거 사용 가능, 영구 갱신 완료로 표시하지 않음 |
| 부분 저장 후 중단 | 완료 범위만 유지, 미완료 범위의 성공 시각 불변 |
| 연결 해제된 자료 | 자동 재연결·조회하지 않음 |
| 사용자가 과거 기준·오프라인 답변을 명시 | 자동 최신 조회 대신 허용된 시점의 근거와 한계를 표시 |
| 방금 확인했지만 수동 reload 요청 | 간격과 무관하게 요청 범위를 다시 확인 |

## 실제 평가 시 기록

가상 원문, 기존 자료 기록, 현재 시각, 질문, 호스트/모델 버전, 실제 도구 호출, 저장 전후 기록과 답변을 보관합니다. 핵심 판정은 성공 시각·범위·근거의 정확성입니다. 짧은 답변이나 “갱신 완료” 문구만으로 통과시키지 않습니다.

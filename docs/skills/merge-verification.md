# 병합 규칙 검증

0.8.6은 publish·fetch가 같은 [판단표](../../skills/dougle-publish/references/merge.md)를 사용합니다. 별도 병합 프로그램이나 PR은 추가하지 않았습니다.

| 검사 | 결과 |
|---|---|
| 기준·내 지식·팀 지식의 존재/변경 조합 64개 | 모든 입력에 규칙이 정확히 하나 적용됨 |
| 서로 다른 동시 변경 | CONFLICT로 분류하며 업로드 순서로 선택하지 않음 |
| 같은 내용·누락·한쪽 변경 | 각각 동일 유지·기존 내용 보존·변경 반영으로 분류 |
| 같은 입력 반복·양쪽 역할 교환 | 판단이 반복 가능하며 작성자 쪽에 따른 승자 선택 없음 |
| 임시 Git 저장소 동시 게시 6개 확인 | 오래된 기준의 push 거절, 재비교 후 양쪽 추가 파일 보존 |

실행: `node scripts/check-sharing-merge.mjs`. 실제 배포하는 Markdown 판단표를 읽어 검사합니다. Git 검사는 가상 자료와 로컬 임시 저장소만 사용합니다.

**이 결과가 AI의 의미 판단까지 검증한 것은 아닙니다.** 다음은 회사 자료 없이 별도 호스트 평가가 필요한 항목입니다.

- 같은 이름이지만 다른 출처·프로젝트의 ID를 구별하는지
- 조건·예외가 바뀐 문장을 요약해서 같다고 판단하지 않는지
- 서로 다른 ID의 충돌을 찾고 양쪽 근거를 보존하는지
- 민감정보가 포함된 충돌안도 게시 전에 차단하는지
- 원격 게시 후 로컬 반영 중단을 복구하고, 오래된 내 내용으로 최신 팀 지식을 되돌리지 않는지

이번 새 모델 호출은 0회입니다. 기존 누계 200/200을 유지합니다. 사용자 PC의 지식이나 실제 공유 저장소는 사용하지 않았습니다.

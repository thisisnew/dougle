# 필요한 설명부터 찾아 읽기

**목차에서 토픽을 찾고, 토픽의 안내에서 필요한 설명 위치를 찾습니다.** 설명과 연결된 조건·예외·근거를 읽은 뒤 답합니다.

## 저장 방식

새 토픽이나 실제로 갱신한 토픽 앞에 짧은 안내를 둡니다.

```text
주제: 입하 확정
범위: receiving
찾을 표현: 입고 확정, confirmReceipt
다루는 내용: 확정 조건·기록 위치·취소 처리

저장 위치 → C01
제외 조건 → C02
취소 처리 → C03
주의: C01의 설명에는 C02 조건도 함께 확인
```

위 내용은 가상 예시입니다. 실제 기록에는 각 설명의 원본 위치·확인 시각·확인 상태가 함께 저장됩니다. 안내만 보고 사실을 답하지는 않습니다.

## 질문할 때

1. 공통 목차에서 업무 범위와 관련 토픽을 찾습니다.
2. 제목·용어·코드 식별자를 파일 검색으로 찾아 읽을 위치를 좁힙니다.
3. 해당 설명과 연결된 조건·예외·충돌·출처를 읽습니다.
4. 근거가 부족하거나 오래됐다면 관련 설명과 원본으로 범위를 넓힙니다.

‘전부 알려줘’ 같은 질문은 처음 찾은 몇 개에서 멈추지 않습니다. 검색 결과가 짧게 잘렸거나 안내가 틀리면 전체 토픽과 다른 후보도 확인합니다. 안내에 없는 새 예외를 놓치지 않도록 실제 항목 목록과 안내의 범위를 비교합니다.

## 갱신할 때

바뀐 설명과 영향을 받는 항목만 수정합니다. 수정 전 안내를 보완 대기로 표시하고, 설명·조건·근거와 연결을 확인한 뒤 안내를 다시 완성합니다. 갱신 도중 끊겼다면 안내를 믿고 좁게 읽는 대신 기존 방식으로 확인합니다. 원본 확인 없이 모양만 정리한 것은 새로 검증한 지식으로 표시하지 않습니다.

긴 토픽은 우선 목차·항목 읽기로 처리합니다. 실제로 업무가 나뉘고 기존 링크를 보존할 수 있을 때만 분리합니다. 공유할 때도 설명에 필요한 조건·예외를 함께 보존합니다. 공유 범위 밖의 내용을 무단 추가하지 않습니다.

## 기존 사용자

스킬 업데이트가 지식 파일을 일괄 변경하지 않습니다. 기존 형식도 읽고 검색하며, 쓰기가 금지된 상태에서도 답할 수 있습니다. 새로 저장하거나 실제로 갱신하는 토픽부터 안내를 보완합니다. 기존 소스·주장 ID·상대 링크·정정·공유 이력은 유지합니다.

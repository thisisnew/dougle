# 자료 연결하기

**경로·링크·설명을 그대로 알려주세요.** 자료 종류를 메뉴에서 고를 필요는 없습니다.

```text
/dougle:dougle-connect 현재 프로젝트와 이 문서를 함께 참고해: [문서 URL]
```

`[문서 URL]`은 실제 링크로 바꾸세요. Codex에서는 `$dougle-connect`를 사용합니다.

## 무엇을 연결할 수 있나요?

코드 폴더, 컨플루언스, 노션, 웹 문서, DB 등을 요청할 수 있습니다. **실제로 읽을 수 있는 범위는 AI에 연결된 조회 도구와 권한에 따라 달라집니다.**

AI는 요청한 자료를 읽고 출처·확인 시점·업무 개념을 기록합니다. 요청만 받고 연결 완료라고 표시하지 않습니다. 회사 전체를 임의로 수집하거나 원본을 수정하지 않습니다.

## 연결이 안 될 때

| 원인 | 다음 행동 |
|---|---|
| 조회 도구가 없음 | AI가 확인해 준 커넥터·MCP 설정 방법을 따릅니다. |
| 로그인 필요 | 해당 서비스의 인증 절차를 진행합니다. |
| 권한 없음 | 안내된 자료의 읽기 권한을 확인합니다. |
| 자료 없음·일시 오류 | 주소나 서비스 상태를 확인합니다. |

설정을 마친 뒤 **“아까 연결하던 자료 이어서 읽어 줘”**라고 요청하세요. 미완료 기록을 바탕으로 이어갑니다. 비밀번호나 토큰을 채팅에 보낼 필요는 없습니다.

## 이미 등록했는지 몰라도 됩니다

같은 자료는 기존 기록을 재사용하고, 바뀌었다면 갱신합니다. 내용이 같아도 출처가 다르면 무조건 하나로 합치지 않습니다.

<details>
<summary>같은 자료인지 판단하는 기준</summary>

| 자료 | 확인하는 기준 |
|---|---|
| 로컬 폴더·파일 | 실제 절대 경로와 기존에 읽은 범위 |
| 컨플루언스 | 회사 사이트 + 페이지 ID |
| 노션 | 작업 공간·계정 범위 + 페이지·DB ID |
| 웹 | 조회 도구로 확인한 정규 URL. 의미 있는 쿼리는 유지 |
| DB | 서버·인스턴스 + DB·스키마 범위 |

제목이나 연결 프로필 이름만으로 같은 자료라고 판단하지 않습니다. 확실하지 않을 때 필요한 정보를 확인합니다. 미완료 요청도 중복 기록하지 않는 절차를 따릅니다.

이는 AI가 따르는 절차이며 DB의 중복 방지 제약은 아닙니다. 같은 작업 공간에 여러 AI가 동시에 기록하는 일은 피하세요.

</details>

자료가 바뀌면 다시 연결해도 됩니다. 기존 연결만 한꺼번에 확인하려면 [자료 갱신](reload.md)을 사용하세요.

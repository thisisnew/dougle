# 답변 스킬은 어떻게 활성화하나요?

**0.5.2부터 i-have-adhd를 독립 스킬로 함께 설치합니다.** ask 안의 참고 파일만 읽던 기존 구조를 변경했습니다.

| 호스트 | ask의 활성화 절차 |
|---|---|
| Claude Code 플러그인 | Skill 도구로 `dougle:i-have-adhd` 호출, 성공 결과 확인 |
| Claude 개인 스킬 설치 | 등록된 `i-have-adhd`를 Skill 도구로 호출 |
| Codex | 등록된 `i-have-adhd`를 선택하고 실제 SKILL.md를 읽어 적용. 별도 Claude식 Skill 실행 도구를 가장하지 않음 |

이미 활성화한 내용이 현재 문맥에 남아 있으면 반복 호출을 생략합니다. 사용자가 형식을 끄면 이후 ask마다 자동으로 다시 켜지 않습니다. 미설치·권한 거부·호출 실패는 알리고 기본 간결한 답변으로 계속합니다. 차단된 스킬을 다른 경로로 읽어 우회하지 않습니다.

## 원본에서 바뀐 부분

원본 i-have-adhd에는 `disable-model-invocation: true`가 있습니다. 더글 배포본은 ask에서 호출할 수 있도록 해당 금지 설정을 제거하고, 더글 답변·후속 질문에 적용하는 범위를 명시했습니다. 진단을 추정하거나 출처·중요 예외를 삭제하지 않습니다. 원본 규칙 본문과 MIT 라이선스를 보존하며, 수정 없는 원본 스냅샷도 ask/references에 남깁니다.

직접 실행하려면 Claude 플러그인은 `/dougle:i-have-adhd`, 개인 설치는 `/i-have-adhd`, Codex는 `$i-have-adhd`입니다. 단순히 명령 이름을 답변에 출력한 것은 호출 성공이 아닙니다.

## 확인한 근거

- [Claude 공식 스킬 문서](https://code.claude.com/docs/en/skills): 모델의 Skill 도구 호출, 호출 제한 설정, 플러그인 이름 구분.
- [OpenAI 공식 스킬 문서](https://learn.chatgpt.com/docs/build-skills): 등록된 스킬의 선택과 지침 로딩 방식.

## 이번 검증 범위

Claude Code 2.1.31에서 가상 자료만 사용하도록 제한한 실제 실행을 시도했습니다. 기존 OAuth 토큰이 유효하지 않아 인증 단계에서 실패했으며, Skill 호출 이벤트는 발생하지 않았습니다. 따라서 **실제 Claude 자동 호출을 통과했다고 주장하지 않습니다.** 사용자 권한이나 인증정보를 변경하지 않았습니다.

등록·배포 파일·매니페스트·호출 지침 검사는 실제 모델 호출 성공과 구분합니다. Codex의 등록된 스킬 로딩 역시 별도 확인 결과를 기록합니다. 회사별 모델 동작은 이 문서만으로 보장하지 않습니다.

Codex 0.164.0의 실제 `skills/list` 결과에서는 i-have-adhd가 enabled=true이고 오류가 없음을 확인했습니다. 다만 두 모델 실행에서 제공된 목록에 없다며 활성화를 중단하는 동작이 나와, 목록 누락만으로 미설치를 단정하지 않도록 보완했습니다. 호스트 탐색을 우선하고, 파일 설치에서는 ask와 함께 설치된 독립 i-have-adhd/SKILL.md를 확인해 로드합니다. 명시적으로 비활성화되거나 거부된 스킬은 이 경로로 우회하지 않습니다.

보완 후 세 번째 Codex 실행에서는 설치된 독립 스킬 SKILL.md를 실제 읽은 도구 기록과 파일 기반 활성화 설명을 확인했습니다. Claude식 Skill 호출로 표시하지 않았고, 사용자 보고 사실의 출처도 유지했습니다. [실행 결과](activation-verification.json)

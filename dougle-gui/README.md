# dougle-gui: 선택형 로컬 GUI

Claude Code 대화창 대신 브라우저 화면에서 더글 지식을 둘러보고, 질문, 연결, 가져오기, 공유를 실행합니다.

- 지식 스킬만 쓰는 사용자에게는 필요하지 않습니다. 원하는 사람만 설치합니다.
- GUI는 지식을 직접 만들거나 고치지 않습니다. 버튼을 누르면 내 PC의 Claude CLI가 해당 더글 스킬을 실행하므로, 스킬의 규칙(원본 읽기 전용, 근거 기록, 병합, 민감정보 검사)이 그대로 적용됩니다.
- 내 PC 안에서만 열립니다(`127.0.0.1`). 다른 PC에서는 접속할 수 없습니다.

## 1. 준비물

| 항목 | 필요한 이유 | 확인 방법 |
|---|---|---|
| macOS 또는 Linux | 개발과 검증 환경 | - |
| Python 3.12 이상 | GUI 실행. 추가 Python 패키지는 필요 없습니다 | `python3 --version` |
| Claude Code CLI, 로그인 완료 | 질문, 연결, 가져오기, 공유를 실제로 실행 | `claude --version` |
| 더글 플러그인 | GUI가 호출하는 스킬 | Claude Code에서 `/dougle:`을 입력했을 때 목록이 보이면 설치된 것입니다. 설치는 [저장소 README](../README.md#연결하고-질문하세요) |
| GitHub CLI `gh`, 로그인 완료 (선택) | 가져오기 화면의 저장소 목록 조회, 비공개 GitHub 원본 확인, 팀 지식 가져오기와 공유 | `gh auth status` |
| `dougle-bot` (선택) | Slack 화면에 봇 상태 표시 | `dougle-bot --help` |

GUI 자체의 의존성은 Python 표준 라이브러리뿐입니다. 웹 화면도 외부 CDN 없이 패키지 안의 파일만 씁니다.

## 2. 설치

macOS의 Homebrew Python은 시스템 전체에 `pip install`하는 것을 막습니다(PEP 668). 아래 두 방법 중 하나를 쓰세요.

### 방법 A. 가상환경 (추가 도구 없이)

```sh
git clone https://github.com/thisisnew/dougle.git
cd dougle
python3 -m venv ~/.dougle-gui-venv
~/.dougle-gui-venv/bin/pip install ./dougle-gui
```

실행 명령을 짧게 쓰려면 PATH에 연결합니다.

```sh
mkdir -p ~/.local/bin
ln -sf ~/.dougle-gui-venv/bin/dougle-gui ~/.local/bin/dougle-gui
# ~/.local/bin 이 PATH 에 없다면 ~/.zshrc 에 추가: export PATH="$HOME/.local/bin:$PATH"
```

### 방법 B. pipx

```sh
brew install pipx
pipx install "git+https://github.com/thisisnew/dougle.git#subdirectory=dougle-gui"
```

### 업데이트와 삭제

| 작업 | 방법 A | 방법 B |
|---|---|---|
| 업데이트 | 저장소에서 `git pull` 후 `~/.dougle-gui-venv/bin/pip install ./dougle-gui` | `pipx upgrade dougle-gui` |
| 삭제 | `rm -rf ~/.dougle-gui-venv ~/.local/bin/dougle-gui` | `pipx uninstall dougle-gui` |

삭제해도 지식(`~/.dougle/`)은 그대로 남습니다.

## 3. 실행

```sh
dougle-gui
```

- 브라우저에서 `http://127.0.0.1:8765/`가 열립니다. 포트가 고정이라 즐겨찾기해 두고 계속 쓸 수 있습니다.
- 터미널 창은 열어 두세요. 종료는 그 창에서 `Ctrl+C`입니다.
- 지식이 아직 없으면 첫 화면에서 "연결하기"나 "가져오기"로 안내합니다.

## 4. 화면별 사용법

| 메뉴 | 하는 일 | 실행하는 스킬 |
|---|---|---|
| 지식 | 토픽, claim 목록과 검색. 각 항목의 확인 상태, 근거 종류, 충돌 표시를 보여줍니다. 연결된 팀 지식 저장소도 여기 표시됩니다 | 없음 (읽기만) |
| 소스 | 지식의 근거가 된 원본 기록과 읽은 범위 | 없음 (읽기만) |
| 질문하기 | 질문하면 진행 과정과 출처가 달린 답을 보여줍니다. 이어서 질문하면 같은 대화로 이어지고, "새 대화"로 초기화합니다 | `dougle-ask` |
| 연결하기 | 로컬 경로나 GitHub, Confluence 링크를 읽어 지식으로 정리합니다 | `dougle-connect` |
| 가져오기 | 팀 지식 저장소에 어떤 지식 패키지가 있는지 먼저 보여주고, 고른 패키지를 내 지식에 합칩니다 | `dougle-fetch` |
| 공유하기 | 내 지식 중 일부를 팀 저장소에 올립니다. 아래 "공유는 두 단계" 참고 | `dougle-publish` |
| Slack | 봇과 문의 채널 모니터링 상태만 보여줍니다. 시작, 중지, 답변 승인은 Claude Code 대화에서 합니다 | 없음 |
| 작업 기록 | 이 GUI를 켠 뒤 실행한 작업 목록. GUI를 끄면 목록은 사라지지만 지식 저장 결과는 남습니다 | - |

연결하기, 가져오기, 공유하기 화면 위쪽에는 지식이 오가는 흐름(원본 자료 → 연결하기 → 내 지식 → 공유하기 → 팀 지식 저장소, 그리고 가져오기)이 표시됩니다. **연결한 지식은 내 PC에만 저장되며, 공유하기를 실행해야 팀 저장소에 올라갑니다.** 지식과 소스에는 "내 PC에서 연결"과 "팀 지식에서 가져옴" 중 어느 쪽인지 표시됩니다.

각 화면의 "상태 안내"를 펼치면 확인됨, 재확인 필요, 원본 확인, 전달받음 같은 표시의 뜻이 나옵니다. 표시에 마우스를 올려도 설명이 보입니다.

### 가져오기

지식 패키지는 팀 저장소에 공유되는 단위입니다(예: receiving). 저장소 하나에 여러 패키지가 있을 수 있습니다.

1. 팀 지식 저장소 주소(GitHub)를 입력하고 "가져올 수 있는 지식 패키지 보기"를 누릅니다. 이전에 가져온 저장소가 있으면 자동으로 채워지고 목록이 바로 보입니다.
2. 저장소의 기본 브랜치와 `dougle-knowledge` 브랜치에서 `knowledge/<패키지 이름>/manifest.md`를 찾아 지식 패키지별로 보여줍니다. 토픽 수, 공유일, 이전에 가져온 적이 있는지도 함께 표시합니다.
3. 원하는 지식 패키지의 "가져오기"(또는 "다시 가져오기")를 누르면 fetch 스킬이 실행됩니다.

목록 조회는 내 PC의 `gh` 로그인으로 저장소를 읽기만 하고, 내 지식에는 아무것도 쓰지 않습니다. 다시 가져오면 내 PC에서 바뀐 내용과 정정은 유지하고 팀 저장소에서 바뀐 부분만 합칩니다.

### 공유는 두 단계

1. **게시 준비**: 대상 저장소와 공유할 지식 패키지 이름을 적고 실행합니다. 새 이름이면 새 패키지로, 기존 이름이면 그 패키지에 합쳐 올라갑니다. 일부 토픽만 올리려면 "공유할 토픽"에서 고릅니다. 이 목록에는 내 PC에서 직접 연결한 토픽이 나옵니다. 이 단계는 원격 쓰기 명령(`git push`, `gh repo create`, `gh pr` 등)을 막은 상태로 실행되며(저장소 조회용 `gh repo view`, `git ls-remote`는 허용), 읽기와 쓰기 모두 가능한 `gh api`는 실행 전에 승인 카드로 명령을 보여주고 묻습니다. 올라갈 내용, 제외된 자료, 민감정보 검사 결과만 보고합니다.
2. **이 내용으로 게시**: 보고를 확인한 뒤 버튼을 눌러야 같은 세션에서 실제로 올립니다.

저장소에 같은 지식 패키지가 이미 있으면 덮어쓰지 않고 합칩니다. 팀원이 추가한 내용은 유지하고, 같은 항목을 양쪽에서 다르게 바꿨으면 둘 다 남겨 충돌로 표시합니다. 바뀐 내용이 없으면 아무것도 올리지 않습니다.

### 알아 둘 점

- 한 번에 하나의 작업만 실행됩니다. 여러 작업이 같은 지식 파일을 동시에 고치지 않게 하기 위해서입니다.
- 질문, 연결 등은 Claude 사용량을 씁니다. 작업이 끝나면 턴 수와 대략적인 비용이 표시됩니다.
- 작업 박스 위쪽에 진행 상태가 표시됩니다. 진행 중이면 경과 시간과 마지막 활동 시각, 승인 대기 중이면 그 안내, 끝나면 완료/실패/취소와 걸린 시간을 보여줍니다. 다른 탭을 보는 동안 끝나면 브라우저 탭 제목에 "(완료)"가 붙습니다.
- 작업 결과가 길면 박스 안에서 스크롤됩니다. 결정한 승인 카드는 사라지고 진행 과정에 한 줄로 남습니다.
- 실행 중인 작업은 "취소" 버튼으로 멈출 수 있습니다.

## 5. 옵션

| 옵션 | 설명 |
|---|---|
| `--port` | 포트. 기본 8765. 이미 사용 중이면 빈 포트로 열고 경고합니다. `0`이면 항상 빈 포트 |
| `--store` | 지식 저장소 위치. 기본 `~/.dougle` |
| `--claude-bin` | Claude CLI 이름 또는 경로 |
| `--bot-bin` | `dougle-bot` 이름 또는 경로 |
| `--allow-tool` | 스킬 실행에 추가로 허용할 Claude 도구 규칙. 여러 번 지정 가능 |
| `--token` | 접속 토큰을 요구합니다. 토큰은 `~/.dougle-gui/token`에 저장해 재사용합니다 |
| `--new-token` | 접속 토큰을 새로 만들어 이전 주소를 무효화합니다 (`--token` 포함) |
| `--home` | GUI 설정 위치. 기본 `~/.dougle-gui` (토큰 저장용) |
| `--no-approval` | 허용 목록 밖 도구를 화면에서 묻지 않고 바로 거부합니다 |
| `--no-browser` | 브라우저를 자동으로 열지 않습니다 |

## 6. 도구 권한

GUI가 실행하는 스킬은 아래 도구만 기본 허용합니다.

- 읽기: `Read`, `Grep`, `Glob`, `WebFetch`, `WebSearch`, `ToolSearch`, `Skill`
- 지식 저장: `~/.dougle/` 아래의 `Write`, `Edit`
- 명령: `git`, `gh`와 읽기 전용 명령(`cd`, `ls`, `cat`, `diff`, `grep`, `find`, `head`, `tail`, `sort`, `jq` 등). `rm`, `sed`, `curl`처럼 파일을 바꾸거나 외부로 보내는 명령은 허용하지 않습니다

허용 목록에 없는 도구를 쓰려 하면 작업이 멈추고 화면에 **승인 카드**가 뜹니다. 사이드바에 "승인 대기", 브라우저 탭 제목에 "(승인 대기)"가 표시됩니다.

| 버튼 | 동작 |
|---|---|
| 허용 | 이번 한 번만 실행하고 이어서 진행합니다 |
| 같은 요청은 계속 허용 | GUI를 켜 둔 동안 완전히 같은 요청(같은 도구, 같은 명령)은 다시 묻지 않고 허용합니다 |
| 거부 | 이 명령은 건너뛰고, Claude가 다른 방법을 찾습니다 |

- 10분 동안 응답이 없거나 작업을 취소하면 거부로 처리합니다.
- 공유 준비 단계에서 막아 둔 원격 쓰기(`git push`, `gh repo create` 등)는 승인 카드 없이 계속 막힙니다. `gh api`는 이 단계에서 허용 목록에 있어도 매번 승인 카드로 묻습니다.
- 묻지 않고 바로 거부하려면 `--no-approval`로 실행하세요. 이때 거부된 호출은 진행 과정에 "권한 밖이라 건너뜀"으로, 작업 결과 아래에 "권한이 없어 실행하지 못한 도구" 목록으로 표시됩니다.

자주 쓰는 도구는 미리 허용해 두면 묻지 않습니다. Confluence, Slack, BigQuery처럼 Claude에 연결된 서비스를 원본으로 읽는다면 해당 도구를 추가해 실행하세요.

```sh
dougle-gui --allow-tool mcp__claude_ai_Atlassian --allow-tool mcp__claude_ai_Slack
```

도구 이름은 거부 목록에 표시된 이름이나 Claude Code의 `/mcp`에서 확인할 수 있습니다.

## 7. 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| `externally-managed-environment` 오류로 설치 실패 | Homebrew Python의 보호 기능입니다. 2절의 가상환경이나 pipx로 설치하세요 |
| "Claude CLI 를 찾지 못했습니다" | 터미널 PATH에 `claude`가 없습니다. `which claude`로 경로를 확인해 `--claude-bin <경로>`로 지정하세요 |
| "8765 포트를 이미 사용 중" 경고 | 다른 dougle-gui나 프로그램이 포트를 쓰고 있습니다. 기존 창을 종료하거나 `--port`로 다른 포트를 지정하세요 |
| "다른 작업이 실행 중입니다" | 한 번에 하나만 실행됩니다. 작업 기록에서 진행 중인 작업이 끝나기를 기다리거나 취소하세요 |
| 작업이 진행되지 않고 멈춰 있음 | 승인 카드가 떠 있는지 확인하세요. 사이드바에 "승인 대기"가 보이면 해당 작업 화면에서 허용이나 거부를 눌러야 진행됩니다 |
| 결과에 "권한이 없어 실행하지 못한 도구" | 승인 카드에서 거부했거나 `--no-approval`로 실행한 경우입니다. 자주 쓰는 도구라면 6절처럼 `--allow-tool`로 미리 허용하세요 |
| 가져오기에서 "저장소를 찾을 수 없거나 접근 권한이 없습니다" | GitHub는 권한 없는 비공개 저장소도 "없음"으로 답합니다. 주소를 확인하고, `gh auth status`로 그 저장소에 접근 가능한 계정이 활성 상태인지 확인하세요. 계정 전환은 `gh auth switch` |
| 가져오기 목록이 비어 있음 | 저장소에 `knowledge/<패키지 이름>/manifest.md`가 없습니다. 더글로 공유(publish)한 저장소인지 확인하세요 |
| 지식 화면이 비어 있음 | `~/.dougle/`에 아직 지식이 없습니다. 연결하기나 가져오기를 먼저 실행하세요 |

## 8. 보안

- `127.0.0.1`에만 바인딩합니다.
- `Host`, `Origin` 헤더가 로컬 주소가 아니면 거부합니다. 모든 POST는 JSON 본문만 받고 CORS 응답 헤더를 주지 않습니다. 다른 웹 페이지가 지식을 읽거나 작업을 시작하지 못하게 하기 위해서입니다.
- `--token`을 쓰면 모든 `/api` 요청에 접속 토큰도 요구합니다. 토큰 파일은 권한 0600으로 저장하며, 심볼릭 링크이거나 다른 사용자 소유면 사용하지 않습니다. 같은 PC의 다른 프로그램까지 막고 싶을 때 쓰세요.
- 지식 노트는 저장소 안의 일반 파일만 읽습니다. 경로 이동(`..`)이나 저장소 밖을 가리키는 심볼릭 링크는 읽지 않습니다.
- 가져오기 목록 조회는 GitHub 주소 형식만 받고, 원격 내용은 화면 표시용으로만 씁니다.
- 승인 요청은 작업마다 새로 만든 비밀값을 가진 MCP 서버만 보낼 수 있습니다. 승인 서버에 연결할 수 없으면 거부로 처리합니다.
- 화면의 Markdown은 HTML을 이스케이프한 뒤 제한된 문법만 렌더링합니다.

## 9. 개발과 검사

테스트는 임시 저장소와 가짜 Claude CLI와 gh만 사용하며 실제 Claude, GitHub, Slack, 키체인에 접근하지 않습니다.

```sh
python3 -m venv .venv
.venv/bin/pip install -e ./dougle-gui pytest ruff
.venv/bin/ruff check dougle-gui
.venv/bin/pytest -q dougle-gui/tests
```

| 파일 | 역할 |
|---|---|
| `src/dougle_gui/store.py` | `~/.dougle` 토픽, claim, 소스, 공유 연결 정보 읽기와 검색 (읽기 전용) |
| `src/dougle_gui/runs.py` | `claude -p`로 스킬 실행, 진행 이벤트 변환, 한 번에 하나 실행, 공유 2단계, 승인 대기 처리 |

| `src/dougle_gui/remote.py` | 팀 지식 저장소의 가져올 수 있는 지식 패키지 목록 조회 (`gh`, 읽기 전용) |
| `src/dougle_gui/server.py` | 로컬 HTTP 서버, API, 실시간 진행 전송(SSE), 요청 검사 |
